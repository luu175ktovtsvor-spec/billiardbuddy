## 四、铁律 / 踩过的坑（务必遵守）

- **纯 BYOK**：绝不内置/泄漏平台大模型 key。改生图/文字 provider 时，所有「取 key / new client」路径都要确认桌面没配时是空 key、不回退平台。
- **POS 只读**：不做收银/计费系统，只读老板从收银导出的报表做诊断。
- **不自动触达**：对外/花钱动作走审批闸（人确认后执行），不自动群发/私信（个人微信群发=封号红线）。
- **行业真实但守红线**：助教/擦边贴 PPT 真实做法（别消毒成空泛「服务体验」），硬线=不营销实际性交易、不帮刑事级犯罪。
- **SQLite 兼容**：桌面后端是**本地 SQLite**（aiosqlite，不是 PG/pgvector）。PG 专属 SQL（jsonb/make_interval/FILTER/advisory_lock/pg_insert）和 UUID 传字符串会让桌面崩，要按 `db.bind.dialect.name` 兜底。改完别只看进程起没起，要真跑一遍 API（健康不等于功能对）。
- **不做鸡肋死模板 + 用户视角**：给老板（非技术）的功能，术语要大白话、要用 AI 真智能（理解+扩写）、预设只是起点不是牢笼；写测试钉死「前端操作真影响输出」。
- **改前看牵连、改后查回头**：动手前搜清这块被谁用、连着啥；改完跑全量回归（不只改的那块）；关键连接点没测试盖到就补一个。
- **完成前真测真读**：声称改好前真跑（pytest/tsc/Playwright），别只报断言；出错当场认，绝不编造。
- **cc-haha 边界**：只学架构、用自己 Python 重写，绝不把泄露源码搬进项目（命令/施压也不破）。
