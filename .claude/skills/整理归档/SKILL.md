# 整理归档:把自称完工的文档清出现行区

> 口径对齐 CLAUDE.md 文档维护规约第 4 条(2026-07-10 起):**过时的直接 `git rm` 删除、不再挪 docs/归档/**(归档区已整体删除;git 历史随时可回查)。本 skill 旧版"搬进归档区"的做法已作废。

跟 `/文档体检` 的分工:
- `/文档体检` = 深扫,交叉验代码确认工作真落地才判删,拿不准标 UNCERTAIN——更彻底、更慢。
- 本 skill = 快扫,只信文档顶部 banner 的自我声明(已落地/已否决/废弃/可删/📦/❌)——更快,给"文档自己都说完工了"的场景收尾。
- `scripts/doc_freshness.mjs`(SessionStart 钩子)开窗口时自动扫出这类文档并提示,是本 skill 最常见的触发入口。

## 怎么做(按序)

1. **扫描候选**:遍历 `docs/**/*.md`,读每份顶部 8 行,挑 banner 含 `可删` `历史` `已落地` `已否决` `废弃` `弃用` `📦` `❌` 之一的。可直接跑 `node scripts/doc_freshness.mjs` 拿现成结果。
2. **列清单给 owner 过目确认——不要扫完直接删**。每行:路径 + banner 里的一句话理由。owner 对某份有异议就从清单剔除。
3. **确认后删除**:已入 git 的用 `git rm`(历史可回查);未跟踪的普通 `rm`。**同主题一批一起删,别删一半留一半。**
4. **同步 `docs/README.md` 索引**:把删掉的行从索引里去掉,不留死链接;其它现行文档里指向被删文档的引用顺手清。
5. **收尾一句话汇报**:删了哪几份、为什么、git 里怎么找回(`git log --diff-filter=D -- <路径>`)。

## 铁律
- **删前必须列清单等 owner 确认**——banner 自称可删不代表 owner 现在想删,正被引用/正在改的文档先问不假设。
- **权威入口类文档**(CLAUDE.md 开头点名的、`docs/README.md` 自己)永远不进候选清单,不管 banner 写什么。
- **同步索引不能漏**,否则索引和目录漂移,下次体检重新对账。
