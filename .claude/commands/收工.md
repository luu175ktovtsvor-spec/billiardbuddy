现在收工。完整读取并执行仓库的 `AGENTS.md`、`CLAUDE.md` 和 `.agents/skills/verify-modular-change/SKILL.md`，然后按以下顺序完成：

1. **核对范围**：检查 `git status`、`git diff` 和本次改动说明，确认没有覆盖用户已有改动，也没有把无关模块混入当前提交。
2. **清理产物**：直接删除本次任务产生且不应入库的截图、日志、临时包、缓存和测试文件，不建立归档副本。
3. **验证行为**：先运行受影响模块的聚焦测试，再从仓库根运行 `bash scripts/quality_gate.sh`。失败必须修复或明确报告，不能用文档说明代替。
4. **维护文档**：只有稳定架构、部署、产品约束或工程规则发生变化时才更新现行文档；不记录进度、迁移经过、会话流水或测试数量。已完成且没有长期价值的任务文档直接 `git rm`，不建归档目录。
5. **提交**：边界清晰的模块分别提交到当前 `main`。用户要求完成任务即包含正常的本地提交，不重复询问；除非用户明确要求，不推送、不发布。
6. **报告**：用大白话列出实际改动、提交、验证结果、未验证项和剩余风险。
