# BilliardBuddy 官方网站

该目录保存 BilliardBuddy 官方产品网站，与桌面应用、Gateway 和服务器服务保持独立。

网站以一个连续的产品故事展示 BilliardBuddy 的三项核心能力：

- 桌面任务空间；
- 图片工作台；
- 视频工作台。

三者共享同一个桌面，但不是固定流水线：任务空间处理会话、工具和真实文件，图片工作台处理参考、候选与版本，视频工作台处理已有素材、证据与时间线。它们可以单独开始，也只能由用户按当前工作需要组合；官网不能暗示后台会自动把一个工作台的结果转交给另一个工作台。

正式页面保持简洁：产品价值只解释一次，三项能力用真实界面直接说明，不重复堆叠理念，不使用开发验收或内部架构措辞。

正式页面把三个工作台组织成“一条任务主线、两条创作分支”：任务空间留下发布简报、讲解稿、画面要求与镜头要求；图片分支读取画面要求和参考图片，独立产出主视觉；视频分支读取讲解稿与镜头要求，并由用户导入真实视频和口播，独立产出成片。页面明确写出“图片不变成视频”，两条分支最后只在交付层汇总，不暗示图生视频、后台自动跳转或共享一套项目状态。

主流程完成后，页面用完整功能地图把正式产品能力按实际工作顺序展开，而不是再挑少量案例概括。功能地图依次覆盖开始与组织、任务空间、图片工作台、视频工作台、控制与扩展五个章节：先说明如何建立和找回工作，再逐层展示输入、理解、执行、运行中调整、审阅恢复、生成编辑、版本管理、旁白混音、字幕、预览导出以及模型、权限和扩展设置。每个章节都先给出连续工作顺序，再列出其中的细分能力；不把尚未实现的想法写成产品功能。

视频工作台节目预览使用围绕同一款便携桌面灯制作的 10 秒竖版产品短片。短片延续图片候选中的产品结构、米白场景、钴蓝玻璃和红色几何点缀，并以带版本号的自托管 MP4 提供，素材更新后不会继续命中旧浏览器缓存，也不依赖第三方运行时地址。

`/` 是正式落地页。`/agent`、`/studio` 和 `/company` 保留为兼容入口，展示同一份官方产品页面。

## 安装包发布边界

官网当前只承担正式产品介绍，不提供或跳转到任何 Windows、macOS 安装包；`/download` 回到产品首页，两个平台下载路径以 `410 Gone` 失败关闭。网站结构化数据和站点地图也不声明下载地址。

安装包发布是独立、显式的发布动作。只有确认桌面代码基线、版本、静态产物审计和更新清单全部一致后，才重新设计并开放下载入口，不能因为服务器上留有旧产物就自动向新用户公开。

## 视觉素材

产品界面全部依据 BilliardBuddy 的真实功能与界面语言用 HTML/CSS 重绘，不依赖尚在开发中的桌面应用截图。

工作台内的静态摄影素材使用内置 ImageGen 为 BilliardBuddy 单独生成，并围绕一套虚构的便携桌面灯工业设计发布项目保持产品结构、材质、主体和色彩一致：

- `luma-candidate-hero.webp`：完整产品主视觉；
- `luma-candidate-side.webp`：同一产品的侧面构图；
- `luma-candidate-top.webp`：同一产品的俯拍场景；
- `luma-candidate-macro.webp`：蓝色玻璃、金属与暖光的材质细节。

四张素材来自一次连续候选生成，图片工作台会自动切换，也可以直接点击比较；当前封面把文字作为独立图层叠加，不把生成图中的伪文字冒充编辑能力。

`billiardbuddy-workspace-og.png` 是当前社交分享图：用一个真实工作者的桌面和抽象的任务、图片、视频分区表达产品范围，不使用生成图冒充产品截图，也不继续沿用旧题材或包含错误文字的历史卡片。

视频工作台演示使用自托管的竖版产品短片，配合素材证据、备选方案、时间线与导出界面，表现产品当前的“导入现有视频、理解素材、组织时间线、预览与导出”流程。完整功能地图继续展开正式产品已有的旁白生成与导入、克隆声音、原声压低、字幕轨、SRT 和输出核对能力。官网视频只作为界面中的演示素材，不进入产品运行时，也不被表述为 BilliardBuddy 的视频生成能力。

这些视频不表示 BilliardBuddy 已具备文生视频或图生视频能力；官网展示的正式产品能力是导入、理解、组织、预览、渲染和导出现有视频素材。

官网中的桌面工作面是网站自己的静态说明，不是桌面应用的运行时、Agent 执行证据或另一套状态来源。它遵循产品的信息架构，但不会引用或保留已退役的桌面页面、任务协议和前端状态实现。
