# 微信/飞书接入调研 — 本机无公网 IP 的桌面 Agent 怎么让用户在 IM 里对话

> 📌 状态:✅现行 · 调研日期 2026-07-11 · 外部调研子代理产出
> 场景:桌面本机 AI Agent(Electron + 本地 sidecar,跑在用户电脑上,无公网 IP),让用户在微信/飞书里跟自己电脑上的 agent 对话。

## 一句话大白话结论

**三条官方路全部免公网 IP、免中转服务器,本机 sidecar 直接对外拨出去连就行**:①微信 2026 年 3 月官方上线了「ClawBot 插件」(iLink 协议),个人微信扫码就能把消息路由到自己电脑上的 agent——这是为我们这种产品形态量身定做的官方通道,微信主路线就选它;②企业微信「智能机器人 API 模式 + 长连接(WebSocket)」,官方明说面向内网/本机部署、个人免费开 5 人以下小团队就能用,当微信灰度没轮到时的备选;③飞书「企业自建应用 + 长连接(WebSocket)」,官方 Node SDK 现成,个人免费建企业即可。**不要碰的**:wechaty/iPad 协议/PC hook 这类灰色个人微信方案(封号 + 腾讯起诉先例,官方 ClawBot 出来后毫无必要)、微信公众号(必须公网 HTTPS + ICP 备案域名,个人号权限还阉割)、微信客服(必须企业认证)。

---

## 二、核心问题直答:无公网 IP,消息怎么进得来?

原理上只有四种收消息模式,三大平台官方都提供了"本机主动向外拨连接"的模式,这正是无公网 IP 桌面软件需要的:

| 收消息模式 | 需要公网? | 谁提供 |
|---|---|---|
| Webhook 回调(平台 → 你的 URL) | **要**(公网 HTTPS,微信系还要备案域名) | 飞书 webhook / 企微回调 / 公众号(唯一模式) |
| **WebSocket 长连接(你 → 平台,拨出去挂着)** | **不要**,能上网就行 | 飞书长连接 / 企微智能机器人长连接 |
| **HTTP 长轮询(你 → 平台,getUpdates)** | **不要** | 微信 ClawBot / iLink Bot API(Telegram Bot API 风格) |
| 中转服务器(owner 服务器收 webhook 再转发给本机) | 本机不要,但要自己养服务器 + 本机↔服务器的桥 | 任何平台都可以这么架,但三条官方直连路都在,**没必要** |

## 三、逐路线详解

### 3.1 飞书 · 企业自建应用 + 长连接(WebSocket) — ✅ 推荐

**【官方文档,已逐条核实】**(open.feishu.cn《使用长连接接收事件》):

- **免公网**:原文"无需提供公网 IP 或域名、无需使用内网穿透工具",只要求"运行环境具备访问公网的能力"。本机集成飞书 SDK,与开放平台建立 WebSocket 全双工通道,事件从这条通道推下来。
- **应用类型**:长连接**仅支持企业自建应用**,商店应用(ISV 上架)不支持——商店应用必须走公网 webhook。对我们没影响:每个用户在自己企业里建自建应用即可;将来若做"飞书应用商店上架版"才需要服务器。
- **限制**:每应用最多 50 个连接;集群模式不广播(同一应用多个客户端只有随机一个收到——单机桌面场景无碍,反而天然防多开冲突);事件需 3 秒内处理完且不抛异常(收到先 ack、异步跑 agent 即可)。
- **SDK**:官方支持 Go/Python/Java/Node.js。Node 是 `@larksuiteoapi/node-sdk` ≥1.24.0 的 `WSClient`,`wsClient.start({ eventDispatcher })` 注册 `im.message.receive_v1` 即收私聊/群聊消息,回复用 `client.im.v1.message.create`。(Bun 下跑该 Node SDK 需真机验一次,预计无碍。)
- **卡片交互也能走长连接**:官方《卡片回传交互回调》文档写明卡片回调默认 Webhook,但"你也可以选择使用长连接接收回调"。⚠️ 网上大量 2025 年前后的二手文章说"卡片回调只能 webhook"——已过时,以官方现行文档为准。这意味着**审批卡片(点按钮批准/拒绝工具调用)也能全程免公网**。
- **配置路径**:开发者后台 → 事件与回调 → 订阅方式选"使用长连接接收事件"。

**个人可用性**【官方+二手一致】:开发应用必须先是"企业用户",但**个人可以免费创建一个飞书企业/团队**(官方帮助中心《创建企业》),在自己企业里建自建应用,无需企业认证。个人自用(自己企业里只有自己 + 机器人)完全成立。

**费用**【二手,来自飞书官网政策转述,建议接入前再核对一次】:2024-10-31 起飞书基础免费版 API 累计调用 1 万次/月。个人自聊场景(发一条回一条,回复算调用、收事件不算)≈ 每天 300 多次调用额度,自用够;重度用户或多媒体上传频繁会碰顶。

**主动推送**:自建应用机器人可随时主动给可见范围内用户发消息(im.message.create),**没有微信系的 24/48 小时窗口限制**——"任务跑完了主动告诉你"这类场景飞书体验最好。(官方 API 常识,本次未逐字复核额度条款。)

**接入工作量**:最小。官方 SDK 现成、文档全,难点只在 onboarding 摩擦:要引导用户去 open.feishu.cn 建应用、开权限(im:message 收发)、发版、拿 App ID/Secret 填进我们软件。预估 1~2 天打通 + 引导 UI。

### 3.2 微信 · 官方 ClawBot 插件(iLink Bot API) — ✅ 微信主路线

**这是 2026-03-22 腾讯官方发布的新东西,首次合法开放个人微信 Bot 能力**【官方发布,IT之家/腾讯新闻/知乎等多方一致报道】:

- **是什么**:微信 App「我 → 设置 → 插件 → ClawBot」。用户在插件页拿到一条 CLI 安装命令/扫码,把自己的微信和自己设备上的 agent 绑定;之后在微信里跟 ClawBot 会话聊天,消息直接路由到自己电脑上的 agent。腾讯发布了《微信 ClawBot 功能使用条款》:腾讯只做消息传输通道、不存储对话内容、传输内容过安全审核,违规拦截。
- **官方生态不止 OpenClaw**:IT之家原文——"腾讯云旗下的'养虾车间'云端服务 Lighthouse(含企业版 Claw Pro)、自研的 WorkBuddy 工具以及本地版 QClaw,这些产品均可通过不同路径接入微信"。即官方就是奔着"多家 agent 接微信"设计的。
- **协议细节**【社区逆向文档 + 两个成熟开源项目已验证跑通,非官方公开文档】(hao-ji-xing/openclaw-weixin,275★,内含 `weixin-bot-api.md`/`protocol.md`):
  - 接入域名 `ilinkai.weixin.qq.com`,**HTTP 长轮询** `getupdates`(服务器 hold 住连接最多 35 秒,有新消息才返回)——"与 Telegram Bot API 的 getUpdates 一模一样",**免公网 IP**。
  - 鉴权:`get_bot_qrcode` 生成二维码 → 用户微信扫码确认 → 轮询 `get_qrcode_status` 拿 `bot_token` → 后续 `Authorization: Bearer ${bot_token}`。
  - 形态:**独立 Bot 身份**(用户 `xxx@im.wechat`,Bot `xxx@im.bot`),不接管本人账号;每条收到的消息带 `context_token`,回复必须原样带回以关联会话窗口。
  - 消息类型:文本/图片/语音/文件/视频完整支持;多方报道提及支持流式输出。
- **第三方自研 agent 能不能接**:能——AstrBot(官方文档《接入个人微信》明说"基于腾讯微信官方 openclaw-weixin 接口实现,使用扫码登录和长轮询收发消息,不需要配置公网回调地址")和 CowAgent(原 chatgpt-on-wechat,文档明说"Backed by WeChat's official API; scan to log in, no public IP required",要求手机微信 iOS ≥8.0.70 / Android ≥8.0.69)都已作为非 OpenClaw 的第三方接入并发布为正式通道。绑定是"微信号 ↔ agent 实例一对一,消息不经任何第三方服务器"。
- **限制**【多方一致】:①**灰度放量中**——部分用户微信里还看不到插件入口(这是当前最大的不可控项);②一个微信号只能绑一个 agent 实例;③当前版本**仅私聊**,不支持群聊(API 有 group_id 字段,权限未放开);④国际版 WeChat 不可用,仅国内微信;⑤内容过腾讯安全审核。
- **风险**:官方合法、无封号风险(与协议机器人有本质区别);真正的风险是 **API 尚无正式公开开发者文档**,我们的实现要基于社区逆向文档(hao-ji-xing 仓库,无 license,只能参考协议、代码别直接抄)+ CowAgent/AstrBot 的开源实现(MIT/AGPL 可查),接口有变动可能;以及灰度节奏不由我们控制。
- **接入工作量**:中。长轮询 HTTP + 扫码 UI + 凭证持久化 + 断线重连,TS 手写客户端预估 2~4 天;onboarding 是三条路里最丝滑的(用户扫个码就完事,不用建任何应用)。

### 3.3 企业微信 · 智能机器人 API 模式 + 长连接(WebSocket) — ✅ 备选/企业场景

**【官方文档,已逐条核实】**(developer.work.weixin.qq.com《智能机器人长连接》):

- **免公网**:WebSocket 连 `wss://openws.work.weixin.qq.com`,用 BotID + Secret 发 `aibot_subscribe` 订阅完成身份校验。官方写明推荐场景就是"开发者服务部署在内网环境,无法配置公网可访问的回调 URL"。相比 webhook 模式还"无需加解密"。
- **官方给本机 agent 铺好了路**:企业微信有 OpenClaw 官方接入专页(work.weixin.qq.com/nl/index/openclaw)和帮助中心教程——客户端工作台 → 智能机器人 → 创建 → **API 模式** → 连接方式选「使用长连接」(官方原话:"无需域名/IP 即可接收消息并返回结果")。与微信 ClawBot 一样,是官方明确支持"agent 跑在个人设备上"的形态。
- **个人可用**【官方帮助中心标题原文】:"企业微信面向 5 人及以下的个人企业,提供 API 模式智能机器人的文档、日程、会议等个人企业 MCP 能力,以满足个人提效场景"。个人免费"个人组建团队"注册企业微信即可,无需企业认证。
- **限制**【官方】:每个智能机器人同一时间只能保持 **1 条**有效长连接;发消息 30 条/分钟、1000 条/小时(按会话);支持文本/图片/语音/文件/视频/消息卡片。【二手】未认证企业:客户上限 200 人、机器人对外接待累计 100 客户后停回(认证解除)——自用(机器人只跟企业内自己聊)不受此限;有 24h 回复窗口 + 主动发送额度概念(OpenClaw-Wechat 插件实测)。
- **关键短板**【二手,多来源一致】:智能机器人**不能进外部群、不能私聊微信个人用户**。要让"微信"用户触达,只有两条:走「微信客服」(必须企业认证,个人不行)或让用户自己装企业微信 App。→ 所以这条路的真实含义是"**用户装企微 App 跟自己的 agent 聊**",体验成立但比微信原生差一个 App 的距离。
- 对照:企微「自建应用」的经典回调模式必须公网 HTTPS URL(官方回调配置文档),不适合我们,略。
- **接入工作量**:中低。官方文档全(WebSocket + JSON,含心跳/重连规范),预估 2~3 天;onboarding 中等(用户在企微工作台点几下创建机器人,把 BotID/Secret 填进我们软件)。

### 3.4 微信公众号 — ❌ 不适合本机形态

【官方+二手】只有 Webhook 一种模式:必须公网 HTTPS 服务器 URL(Token/AESKey 验签),**域名须 ICP 备案**,无任何长连接/轮询选项 → 本机桌面软件必须配中转服务器才能接。且个人订阅号(未认证)接口权限阉割(无客服消息等,被动回复 5 秒超时);认证服务号才有完整能力(企业主体);客服消息有 48 小时窗口。除非将来 owner 想做"官方公众号统一入口 + owner 服务器桥接到各家桌面端"的云产品,否则不碰。

### 3.5 个人微信协议机器人(wechaty / iPad 协议 / PC hook) — ❌ 明确排除

【二手,多方一致】web 协议 2017 年后新号不能登录,基本死亡;iPad/Mac 协议是灰色逆向产业(付费 puppet,如 padlocal),**有封号风险,且腾讯对商用协议团队有法律行动先例**;PC hook(wcferry 等)本机注入微信客户端,虽免公网但同样违反使用条款、封号风险、且随微信 4.x 版本更新反复失配。wechaty 框架本身(Apache-2.0,22.9k★)无罪,但可用 puppet 都在灰色地带。**官方 ClawBot 出来之后,这条路对我们已经完全没必要**——合规产品别把用户的微信号置于封号风险里。

## 五、推荐架构(最优解)

**总原则:三通道全走"本机拨出"直连,零中转服务器、零公网暴露;消息桥是 B 线确定性代码,收到消息塞进 A 线标准会话,回复原路发回。**

```
用户微信 App ── ClawBot插件(iLink) ──┐
                                      │  HTTPS 长轮询 getupdates(拨出)
用户企微 App ── 智能机器人(API模式) ──┤  WSS openws.work.weixin.qq.com(拨出)
                                      │  WSS 飞书开放平台(拨出)
用户飞书 App ── 自建应用机器人 ───────┘
                                      ▼
                        本机 sidecar「消息桥」模块(B线)
                    通道client×3 + 会话映射 + 媒体转换 + 断线重连
                                      ▼
                     A 线标准 agent 会话(现有 cc 循环,不改内核)
```

**落地顺序建议**:
1. **第一优先:飞书长连接**——官方 Node SDK 现成、文档最全、风险最低,先把"消息桥 → A 线会话"的骨架用它跑通(1~2 天)。
2. **第二:微信 ClawBot(iLink)**——用户价值最大(微信原生聊天窗口),参考 openclaw-weixin 协议文档 + CowAgent/AstrBot 开源实现自写 TS 客户端(2~4 天);产品上要处理"未灰度到"的兜底文案。
3. **第三:企微智能机器人长连接**——作为微信未灰度用户的官方备选(2~3 天)。
4. 不做:公众号、微信客服、协议机器人。

**设计要点/坑**:
- **每通道一个出站 client,凭证(bot_token/BotID+Secret/AppID+Secret)存本机**,走现有配置持久化;断线重连 + 指数退避是三条通道共同刚需。
- **飞书 3 秒 ack**:收到事件立即返回,agent 异步跑,跑完用 API 主动发结果;企微/微信同理(长任务先回"在做了",完成再推)。
- **审批闸在 IM 里的形态**:飞书可用交互卡片(卡片回调也支持长连接,全程免公网);企微支持消息卡片;微信 ClawBot 只有文本/媒体,审批做成文字确认(回复"同意"/"取消")。初版可给 IM 会话单独一档更保守的权限预设。
- **本机 agent 的固有属性要向用户说清**:电脑关机/断网 = IM 里的 agent 离线。要"关机也在线"只能 owner 服务器托管 agent,那是另一个产品形态,本轮不做。
- **飞书免费版 1 万次/月 API 额度**、企微 30 条/分/会话限速,消息桥里做好限速与"额度用尽"的大白话提示。
- Bun 跑 `@larksuiteoapi/node-sdk` 的 WSClient 需首个真机冒烟验证(预计兼容,未验前不承诺)。
