# AI 自动剪视频工作台 · 外部调研报告

> 📌 状态:✅现行 · 外部调研(GitHub + 产品形态) · 2026-07-11
> 调研对象:桌面 AI 助手的剪视频看板。现状 = 选本地视频 → PySceneDetect 思路切镜头 + FFmpeg → VLM 打标签挑镜头 → 卡点配乐 → 出 MP4;有口播模式(whisper 转写)和氛围模式;已有「可编辑 plan 真相源 + 渲染器 + edit_agent 对话改」。

---

## 一、大白话结论(先看这里)

1. **咱们「plan JSON(真相源)→ 渲染」的架构完全对路**——这就是全行业的统一做法:好莱坞的 OpenTimelineIO、商业 API Shotstack、开源 editly、auto-editor 的 v3 格式、连剪映自己的工程文件(draft JSON)全是「一份声明式时间轴 JSON → 确定性渲染」。没有一家是"模型直接指挥 FFmpeg"。方向不用改,只需校准 schema 细节(见 §四)。
2. **「文字稿驱动剪辑」(Descript 模式)已经不是先锋,是行业标配**——Premiere Pro、DaVinci Resolve、CapCut、Riverside 全部内置了"删转写文字=删视频"。**但它只适合口播模式**;氛围模式(没人说话)的主流形态是另一套:**候选片段宫格 + 用户勾选**(OpusClip 形态)。
3. **小白确认剪辑结果的最优形态不是时间轴**。三种主流形态按门槛排:①候选片段挑选(缩略图宫格+分数+理由,勾选/删除)最低门槛;②文字稿删句(口播场景)第二;③专业多轨时间轴门槛最高、自研成本最大——**别自研专业时间轴,打不过免费的剪映**。
4. **所有头部产品都是"非破坏性 + 秒级虚拟预览"**:改 plan 不重新渲染,播放器按 plan 跳播模拟成片,确认了才真出 MP4。这是咱们当前体验差距里性价比最高的一块。
5. **AI 打分当参考、别当卖点**:OpusClip 的病毒分(0-99)被用户大量吐槽不准(40 分的片段跑赢 85 分的;单人内容选段准确率 6-7 成,多人对话掉到 4 成)。行业教训 = 分数用来排序候选,最终必须人挑——与既有决策「确定性检查 + 用户一眼挑,不靠 AI 自评」完全互证。
6. **中国用户的"专业接管"逃生舱 = 导出剪映草稿**。pyJianYingDraft(3.9k★,活跃)专门干这个,NarratoAI(10.2k★)也把"导出剪映草稿二次编辑"当正式功能。比自研精修界面便宜一个数量级。
7. Descript 2025-2026 押注的 **Underlord(对话式 AI 协作剪辑代理)**,形态与咱们的 edit_agent(大白话指指点点→改 plan)一致——对话是加速层、确定性工作台保下限,这条路线再次被头部验证。

## 三、产品形态:小白怎么确认剪辑结果

### 3.1 三种主流确认形态

**形态 A:候选片段挑选(OpusClip / AI-Youtube-Shorts-Generator)**
- 流程:上传→AI 全自动出 N 个候选短片,每个带缩略图、病毒分(0-99)、hook 句、入选理由,按分排序。
- 用户动作 = 浏览宫格 → 点开预览 → 挑几个要的 → 微调字幕 → 导出。**用户从不见时间轴**。
- 已知坑(用户公开吐槽):分数不可靠(低分片段常跑赢高分)、多人对话选段准确率掉到 ~40%。**结论:分数当排序辅助,挑选权必须留给人**。

**形态 B:文字稿驱动(Descript / Gling / Premiere / CapCut)**
- Descript 核心交互:转写全文即文档,**选中文字按删除=视频里那段消失**;非破坏性(删了还在,只是隐藏);填充词("嗯""啊")自动检测、蓝色下划线标出,侧栏列成清单**逐条预览可单删可全删**。
- Gling(5 万创作者在用)的布局:**左=文字稿,右=预览,底=简化时间轴**;60 分钟素材 5 分钟出粗剪;剪完可导 XML 给 Premiere/FCP/Resolve 精修(逃生舱)。
- 该模式 2023 起被 Premiere、DaVinci、CapCut、Riverside 全部跟进,**已是行业标配**。
- **适用边界:只对"有人说话"的内容成立**。氛围片(卡点混剪、无口播)没有文字稿可删,必须回到形态 A。

**形态 C:对话代理(Descript Underlord / videodb Director)**
- Underlord = 确定性编辑器之上的 agentic co-editor:一句"删掉所有重录、节奏收紧",它识别坏条、留好条、缩短间隙;能串整条流水线(粗剪→统一视觉→配 B-roll→特效);带模型选择器(含 Claude Sonnet 4.5)。
- Director 全 chat + 内置播放器,连时间轴 UI 都不做。
- **共识:对话是加速层,叠在确定性工作台上,不取代形态 A/B 的可视确认**。

### 3.2 「文字稿驱动是不是主流最优?」——回答

**口播内容:是,且已是标配,咱们该做**(whisper 词级时间戳已有,缺的只是 transcript 面板交互)。
**氛围内容:不是**,最优是候选片段宫格 + 勾选重排。
**总最优 = 按模式分形态**:口播模式→文字稿删句;氛围模式→候选宫格;两者之上叠 edit_agent 对话改(咱们已有)。这正好跟咱们"口播/氛围双模式"的既有产品切分对上,不用推翻任何东西。

## 四、plan JSON 架构对不对 + 别人的数据结构长什么样

### 4.1 判定:对路

行业从老 EDL 到今天,全部收敛在「声明式时间轴数据 → 确定性渲染器」:

| 方案 | 数据形状(核心字段) |
|---|---|
| **auto-editor v3** | `{version:"3", resolution, timebase:"30/1", samplerate, background, v:[[clip]], a:[[clip]]}`;clip=`{name, src, start(时间轴位置), dur, offset(源内位置), speed, stream, volume}`;**所有时间=timebase 下的整数帧数** |
| **OpenTimelineIO** | Timeline→Stack→Track→Clip`{media_reference:{target_url, available_range}, source_range:{start_time, duration}}`;时间=RationalTime(value,rate) 有理数 |
| **剪映 draft**(pyJianYingDraft 还原) | 轨道→片段→素材三层;segment=`{target_timerange(成片内), source_timerange(素材内), speed}`;素材独立成表被片段引用 |
| **Shotstack**(商业 JSON→video API) | `{timeline:{background, tracks:[{clips:[{asset:{type,src}, start, length, transition, effects}]}]}, output:{format, resolution}}` |
| **editly** | `{clips:[{duration, layers:[{type:'video',path},{type:'title',text}], transition:{name,duration}}]}`(场景序列+层叠) |

### 4.2 所有成熟格式的三条共同不变量(咱们 schema 按这个校准)

1. **双时间域**:每个片段同时记「素材内哪一段」(source/offset)和「成片内落在哪」(target/start)——变速、复用同一素材、逐段重剪全靠它。剪映、OTIO、auto-editor 三家字段名不同、语义一致。
2. **时间用整数(毫秒或 timebase 帧数),不用浮点秒**:auto-editor 全整数帧、OTIO 有理数,就是为了防几十个片段累计的浮点漂移导致音画错位。
3. **素材表与片段分离**:素材(路径/时长/探针信息)单独成表,片段只存引用——同素材引用 N 次不重复,换素材只改一处(剪映 draft、OTIO media_reference 皆如此)。

### 4.3 额外一条值得加的自家字段

AI-Youtube-Shorts-Generator 的 LLM 输出每个候选段带 `score + hook句 + 入选理由`;OpusClip 每个 clip 带分数与维度。**建议 plan 每个片段挂一个 `evidence` 字段**(VLM 标签、转写文本、入选理由、分数)——UI 用它向用户解释"为什么选这段",edit_agent 用它做逐段重剪的上下文,成本几乎为零。

## 五、最值得抄的体验(按值钱程度)

1. **虚拟预览(不渲染就能看)**:Descript/Gling/CapCut 全是非破坏性——播放器按 plan 顺序跳播各片段模拟成片,改 plan 即时生效,确认才真渲染。实现便宜:前端 `<video>` 按片段表 seek+play 编排即可(转场/花字降级不显示或贴角标),彻底消灭"改一次等一次渲染"。
2. **候选片段宫格(氛围模式主界面)**:每镜头缩略图 + VLM 标签 + 入选理由,选中的进成片、灰的是备胎;点开单段预览;勾选/拖拽重排 = 直接改 plan。
3. **口播模式文字稿面板**:转写全文可读可删,删句=删视频段;静音/填充词单独列清单,逐条预览、一键全清(Descript 的填充词侧栏是抄袭范本);布局照 Gling(左稿/右预览/底简化条)。
4. **字幕样式 = 3-5 套预设**(大字粗体/关键词高亮/逐字卡拉OK,whisper 词级时间戳现成),ASS/drawtext 烧进去;绝不做自由字幕编辑器。
5. **逃生舱:导出剪映草稿**:照 pyJianYingDraft 的 draft 结构在 TS 侧生成草稿文件夹,"到剪映里精修"顶替自研专业时间轴;注意剪映 7+ 无法程序化导出成片,用户需在剪映里手点导出(可接受,本来就是精修场景)。

**明确不抄的**:自研专业多轨时间轴(成本巨大、剪映免费碾压);病毒分当核心卖点(OpusClip 反面教材);MoneyPrinterTurbo 的纯生成线(不同物种,只借它"一键+少参数"的心智)。

## 六、落地建议(按性价比排序)

1. **plan schema 校准(半天级,先做防后患)**:双时间域字段 + 毫秒整数时间 + 素材表分离 + 每段 `evidence`。这是后面一切 UI 的地基,趁 plan 消费方还少赶紧定死。
2. **虚拟预览播放器(几天级,体验提升最大)**:按 plan 跳播的预览编排器,改 plan 秒级反馈;最终确认才走 FFmpeg 渲染。所有头部产品的共同底座。
3. **候选片段宫格 + 勾选重排(氛围模式确认界面)**:缩略图(FFmpeg 抽帧现成)+ 标签 + 理由 + 勾选拖排;与 edit_agent 互通(对话改和手点改都落到同一份 plan)。
4. **口播模式文字稿删句 + 静音/填充词清单**:whisper 词级时间戳已有,补 transcript 面板与"删句→改 plan"映射;这条做完,口播模式就达到 Gling/Descript 的核心体验。
5. **导出剪映草稿逃生舱(可后置)**:抄 pyJianYingDraft 结构生成草稿,给"最后 10% 想精修"的用户一条出路,替代一切"要不要做高级编辑功能"的纠结。
