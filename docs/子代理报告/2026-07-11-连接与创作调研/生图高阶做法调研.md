# 生图高阶做法调研 — 开源生态 + 产品实践,对「店主做海报」怎么取舍

> 📌 状态:✅调研完成 · 2026-07-11 · 外部调研子代理产出 · 配套底稿见 `docs/子代理报告/2026-07-11-生图视频调研地基/`(竞品 15 款 survey + 能力细分,本文不重复、只补"高阶做法"这一层)

## 〇、大白话结论(只看这段也够)

把全球最火的生图开源项目和产品翻了一遍,结论很清楚:**对"不懂技术的店主做海报"这个场景,真正值钱的高阶做法只有四样——①风格预设(把专业参数藏起来,只留"点一下就像样"的场景按钮)、②一次出几张挑一张、③把用户的白话自动扩写成导演级提示词、④拿参考图锁住同一个人/同一种风格。** 这四样分别被 Fooocus(5.1 万星)、Midjourney、DALL-E 3、Seedream 4.5/Ideogram 验证过,而且我们后端地基基本都有了,差的主要是"把开关放到用户面前"的那层壳,工作量都可控。

反过来,**开源圈最炫的东西恰恰是我们最不该做的**:ComfyUI 那种节点连线画布(12 万星,但用户是技术极客)、负向词输入框(SD 时代遗产,新一代 API 模型正在删掉这个参数)、LoRA 训练/ControlNet 姿势控制(店主一辈子不碰)。ComfyUI 唯一值得借的是它的**思想**:把一套出图流程沉淀成可复用的 JSON 模板——我们拿这个思想做"内部预设",绝不把节点露给用户。

## 二、产品侧最佳实践逐项(是什么 / 谁验证的 / 对店主值不值)

### 2.1 提示词扩写/改写(LLM 预处理用户白话)⭐ 增益

- **谁在做**:DALL-E 3 用 GPT-4 强制改写所有提示词(API 返回 `revised_prompt`,官方说法是"更详细的提示词显著更好",且默认不可关);Fooocus 用离线 GPT-2 扩写;Azure OpenAI 把这层叫 prompt transformation;即梦社区总结的出图公式本质也是"结构化改写"。
- **行业共识**:图像模型每次生成互相独立、没记忆,所以单条提示词必须自带全部信息(用途/主体/风格/光线/构图/文字内容);把"避免出现 X"直接写进正文比负向词参数更通用。
- **我们现状**:A 线已经天然有——`make_poster` 工具描述就要求模型"把用户请求扩写成具体中文视觉提示词"(`ts/src/media/mediaTools.ts:164`),主模型就是改写器。**缺口在 B 线工作台**:CreationPage 输入框里店主打的白话("搞个周末打折的图")直发模型,没有扩写这一跳。
- **判断**:对店主是真增益(他们写不出"红金配色、居中排版、留出主标题区域"),工程量=网关一跳便宜 LLM + 一行可编辑的"我帮你润色成了…"。**照 DALL-E 3 的透明模式:扩写结果展示出来、可改可关**,别做成黑箱。

### 2.2 负向词(negative prompt)❌ 鸡肋(作为 UI)

- **事实**:负向词是 SD 时代 CFG 机制的产物。GPT-image 系 API 根本没有 negative_prompt 参数;Seedream 官方方舟文档主打单 prompt(第三方封装有 negative_prompt 字段,而 **Seedream 5.0 Lite 官方刻意删掉了 negative_prompt/seed/guidance_scale**,把这些收进模型内部)——趋势明确:模型自己管。
- **判断**:**不做负向词输入框**。要"别出现英文/别有水印/不要卡通"这类排除,让 2.1 的扩写器把排除句折进正文即可,零额外 UI。

### 2.3 多候选一次出 N 张挑一张 ⭐ 增益(而且我们基本做完了)

- **谁验证的**:Midjourney 立身之本就是 2×2 四联格——"探索→挑中→精修"三步;其 V7 draft mode 更进一步(半价 10 倍速起草 10-20 张,挑最好的点 Enhance 出成品)。竞品 survey(配套底稿)里 15 款工作台"出几张挑一张"出现率 90%+。
- **为什么对店主特别值**:这是**用人眼挑代替 AI 自评**的质量方案(和既定架构"质量=确定性检查+用户一眼挑"完全同构);店主不会改提示词,但一眼挑最像样的一张零门槛。
- **我们现状**:后端 `clampCount` 已支持 1-4 张(`ts/src/media/mediaJobs.ts:395`),生图看板已有"数量"参数和网格。**差的只是默认值(默认 1 张)和"换一批"按钮**。成本账:Seedream ¥0.3/张,默认 3 张=¥0.9,完全可承受。

### 2.4 风格预设 / 模板库 ⭐⭐ 增益(性价比之王)

- **谁验证的**:Fooocus 的 style 勾选;Ideogram 的 4 种 style type + 可保存复用的 Style Codes;Canva Magic Design(模板+品牌套件,OpenAI 官方披露其 Magic Studio 被用了 50 亿次);稿定设计(模板库+文案自动排版,电商场景吃死);即梦 3.0 社区最火的产出物就是"生图公式/提示词模板"。
- **本质**:预设=一段固化的提示词骨架+比例+数量+模型路由。用户点"美团店铺头图"比自己描述强十倍——**店主最大的障碍不是模型能力,是不知道该要什么**。
- **我们现状**:`mediaJobs.ts` 里 grep 不到任何 style/预设逻辑,工作台是裸提示词输入。**这是我们与"店主可用"之间最大的一块缺板,同时是工程量最小的一块**(一个 JSON 预设表+几排 chips+提示词拼接)。

### 2.5 参考图 / 一致性(同一个人换场景)⭐ 增益

- **谁验证的**:Seedream 4.5 官方支持最多 10 张参考图,主打跨图身份一致(角色立绘/多角度商品);Ideogram Style Reference(最多 3 张参考图锁风格);Midjourney omni-reference。这是 2025-2026 生图产品竞争最凶的一条线。
- **对店主的对应场景**:助教 IP 打造(同一个她:今天发海报、明天发活动图、后天发朋友圈,脸不能换人)、门店实景做底(拿店里真照片改成海报)。
- **我们现状**:管线已通——`make_poster`/`generate_image` 有 `reference_image_paths` + `reference_generation_ids`,且底层是 Seedream 4.5。**缺的是 UX**:工作台没有"锁定这个人/沿用这张风格"的持久选择,每次都要用户自己想起来传图。注意配套的真人肖像授权闸(portrait_consent)已存在,别绕开。

### 2.6 分步生成(草图→精修→放大)◐ 半增益(隐式做,不做成独立模式)

- **谁在做**:Midjourney draft mode(半价快速起草→Enhance 精修);Ideogram 的 Turbo/Default/Quality 三档速度。
- **判断**:这套的动机是 Midjourney 单张贵、要省 GPU。我们 Seedream ¥0.3/张已经是"草图价",**2.3 的多候选+挑一张+现有 upscale_image 4x 超分,合起来就是分步生成**(便宜多张→人挑→印刷前才放大)。不需要再造一个显式"草稿模式"开关——那是给我们用户添概念负担。唯一要守住的纪律:**默认出图别用最大分辨率,放大留到用户明确要印刷/高清时再做**(现有 upscale_image 工具语义已经是这样)。

### 2.7 画布局部重绘(inpaint canvas)◐ 做轻量版

- InvokeAI Unified Canvas / krita-ai-diffusion 是标杆,但全画布+笔刷是创作者工具。后端 `edit_image` 已支持 `mask_path` 局部重绘。**店主版=圈选(矩形/套索)→自动生成 mask→"把这块改成…"**,一个选区交互而已,不做图层/笔刷/画布。这与做齐方案里"就地圈选改图"口径一致。

## 三、增益 vs 鸡肋总裁定(店主做海报/宣传图场景)

| 做法 | 裁定 | 一句话理由 |
|---|---|---|
| 风格/场景预设库 | ⭐⭐ 必做 | 店主不知道要什么;Fooocus/Canva/稿定三方验证;工程量最小 |

## 四、落地建议(按性价比排序)

> 全部落在既定架构里:B 线工作台=确定性代码,A 线对话=模型循环,两线只靠工具/预置 prompt 相接。工作量为估算,以实际排期为准。

**1. 门店场景预设库(性价比最高,先做)**
- 做什么:一张 JSON 预设表(10-15 个:开业酬宾 / 周末台费折扣 / 会员卡促销 / 赛事对阵海报 / 招聘助教 / 节日热点 / 美团店铺头图 / 朋友圈九宫格 / 门口易拉宝-印刷模式…),每条=中文提示词骨架(留 `{活动内容}` `{门店名}` 占位)+ 默认比例 + 默认张数 + 模型路由;工作台顶部一排场景 chips,点选即填。台球包挂载时注入台球场景预设,通用模式给通用预设(借 ComfyUI"模板+占位符变量"的思想,只在内部)。
- 为什么值:直接消灭"店主面对空输入框不知道打什么"这个最大流失点;Fooocus 5.1 万星 + Canva 50 亿次使用验证的路线。
- 工作量:小(1-2 天):JSON + chips UI + 拼接逻辑,零新依赖。

**2. 工作台默认多候选 + 换一批(半天-1 天)**
- 做什么:海报类预设默认 count=3(后端 `clampCount` 1-4 已支持,改默认值即可);网格下加"换一批"(同提示词重跑);挑中一张后现有"放大 4x/改这张"接力。
- 为什么值:Midjourney 全流程的核心就这一步;把"AI 出的图不行"变成"三张里挑一张顺眼的",体验质变,成本每次多 ¥0.6。
- 工作量:极小,几乎纯前端。

**3. B 线输入框 LLM 扩写,透明可改(1 天)**
- 做什么:工作台"生成"前把白话提示词经网关便宜模型改写成结构化中文视觉提示词(主体/风格/配色/构图/画面文字/排除项),界面上显示"已帮你完善:…"、可编辑、可关;"不要出现 X"类需求折进正文,不加负向词框。
- 为什么值:DALL-E 3 官方强制做且给出理由(详细提示词显著更好);我们 A 线有这层、B 线没有,补齐后两线出图质量对齐。
- 工作量:小:一跳 LLM 调用 + 一行可编辑 UI;有现成网关。

**4. "锁定这个人/这种风格"参考图 UX(2-3 天含真机验)**
- 做什么:工作台加常驻参考位:从画廊或本机选 1-N 张(如助教照片/门店实景/满意的旧海报),打上"锁人物 / 锁风格 / 当底图"角色,后续每次生成自动带上(走已有 `reference_image_paths`,Seedream 4.5 支持至 10 张);真人照片沿用现有 portrait_consent 授权闸。
- 为什么值:助教 IP 一致性和门店品牌感是复购型需求(每周发图都要"还是那个她/还是这家店");2025-2026 竞品主战场,管线我们已通,纯差交互。
- 工作量:中:前端选择器+状态持久化+真机验证一致性效果。

**5. 画廊元数据召回(1-2 天,可并入 4)**
- 做什么:每张产出图落 meta(最终提示词/预设名/参考图/比例),画廊每张图三个动作:"照这张再来一批 / 沿用写法改两个字 / 拿它当参考图"。
- 为什么值:InvokeAI Boards 验证的复用模式;店主上周做过满意的图,这周活动只想换个日期——不该从零再来。
- 工作量:小-中:meta 已大半存在(generation 记录),主要是画廊动作接线。
