## 0. 头号方向(先看这一句)

**全方位对标 cc-haha,不做阉割版,能抄就抄。** 产品 = 装在用户电脑上的**通用本机 AI Agent 桌面软件**(强 coding agent 外壳);台球运营是可 `@挂载` 的领域包,不是产品边界。

对标"方式"同样是硬口径(容易做错):**内核直接照 cc 移植、发现分叉就掰回去**——不是"保留旧实现打补丁",而是内核(主循环/上下文/权限/工具/hooks/技能/命令/任务/mcp/记忆)直接照 cc 移植,现有实现跟 cc 有结构/行为分叉就拆掉、对齐 cc;老 Python 台球全栈已删 = 架构选了"替换非叠加"。唯一验收硬闸 = **行为对齐测试**(刁钻边界上判得跟 cc 一模一样)。

架构地图与七条主线思路的完整落地见 `docs/当前架构与状态-总览.md`(§一~§十)。本文只给目标、cc-haha 抄用口径和文档取舍。

## 1. 为什么是这个目标

coding agent 的底盘不强,上层的店铺问答、生图、真实素材剪辑、知识库和自动化都会变成不可靠的包装。因此当前阶段所有实现和文档都围绕四条主线收敛:

1. **Coding agent 性能和可靠性优先**:工具检索、读写文件、patch、回滚、项目指令、压缩恢复、子代理、后台任务、provider failover、trace 可观测性都必须扎实。
2. **cc-haha 可直接复制/抄/移植/改写,内核直接对齐**:`~/Desktop/cc-haha-ref` 的 LICENSE 已允许 use/copy/modify/distribute/publish copies;本项目直接参考、移植、改写其内核代码和测试边界,复杂能力用行为测试锁住同输入同决策,防止迁移遗漏或迁移失真。
3. **UI 三分法**:交互机制抄 cc-haha;配色抄 WorkBuddy(腾讯 CodeBuddy);用户可见文字用 WorkBuddy 中文写法。前端是 vanilla JS,抄"交互机制/行为"重写(抄不了 React 代码)。不要卡片墙、台球挂件、营销页。
4. **生图/真实素材剪辑是插件式延伸能力**:挂在同一个 Agent 工作台和审批/任务框架上,跟随主 UI 配色与交互,不另起一套产品皮肤;视频剪辑是自家产品、不对标 cc;CD/Seedance 2.0 这类模型直接生成视频能力已删、不再保留。

## 3. cc-haha 抄用边界

- **允许且推荐**:cc-haha 内核、工具、测试边界、状态机、UI 参考实现都可以直接抄、移植、改写进本仓库;优先保证功能齐全、边界一致、测试通过。
- **对齐方式**:内核直接照 cc 移植,现有实现与 cc 有结构/行为分叉就拆掉对齐(替换非叠加),不做"保留旧版打补丁"。
- **应该**:为复杂边界写测试,例如路径越界、工具调用配对、provider 降级、压缩恢复、权限同族工具绕过、文件改动实时预览;抄代码不是免测试,而是减少重复造轮子的失误。
- **区分**:WorkBuddy/Trae/Qoder 等闭源竞品只保留我们自己的分析、UI/交互/架构结论,不把它们的私有代码放进仓库。
- **发布口径**:文档里统一明确"cc-haha 可直接复制/抄/移植/改写";旧阶段的防搬限制不再作为当前施工依据。

## 4. 产品层边界(故意保持我们自己的、不对标 cc)

内核全方位对标 cc,但产品层有意保持我们自己的取舍(完整清单见总览 §三):白标命名 `BILLIARDBUDDY.md`/`.billiardbuddy`(绝不 `CLAUDE.md`/`.claude`)、网关藏 key、免登录单用户全本地、审批闸只卡对外/不可逆/花钱、台球领域包 PPT-only、生图双模型、视频剪辑走 video-use、UI 外观配色文案走 WorkBuddy。

- 专有知识库问答按来源分层:行业知识/领域包、店铺文件、门店记忆。默认是通用 coding Agent;用户在输入框挂载"台球运营专家"后,才把台球领域包上下文、推荐命令和专属工具带入本轮。店铺文件必须带来源和检索解释;资料库没有看到的事实要明确说没有看到。
- 文件修改要有流式可见性:工具开始、pending、完成 diff、失败态都要能在中间步骤和右侧预览里体现,不能等最终答复才暴露。

## 5. Main 分支口径

当前用户要求直接在 `main` 上改,不新建分支。历史文档里出现的 `ts-harness-rewrite`、`cc-haha-direct-port` 等分支名只代表当时施工记录,不再作为当前工作指令。

阶段性完成的标准不是"写了几个点",而是:需求矩阵能解释没有遗漏,关键能力有测试或真机/浏览器验证,文档口径不会误导下一轮实现。
