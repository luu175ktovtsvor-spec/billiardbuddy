# 当前目标与文档口径

> 状态:现行 · 最后核对 2026-07-07 · 适用范围:本仓库 `main`

## 1. 一句话目标

这个项目的第一性目标是做成一个 **coding 能力很强的桌面 AI Agent 外壳**。如果 coding agent 的底盘不强,上层的店铺问答、生图、生视频、剪辑、知识库和自动化都会变成不可靠的包装。

因此当前阶段所有实现和文档都围绕四条主线收敛:

1. **Coding agent 性能和可靠性优先**:工具检索、读写文件、patch、回滚、项目指令、压缩恢复、子代理、后台任务、provider failover、trace 可观测性都必须扎实。
2. **CC-Haha 可直接复制/抄/移植/改写,验收看能力完整度**:`~/Desktop/cc-haha-ref` 的 LICENSE 已允许 use/copy/modify/distribute/publish copies;本项目可以直接参考、移植、改写其内核代码和测试边界,复杂能力仍要用行为测试锁住同输入同决策,防止迁移遗漏或迁移失真。
3. **UI 走 Work Buddy/Codex 式低噪工具流**:主对话首屏克制,不要卡片墙、台球挂件、营销页;配色执行“走法 B”:砍蓝,绿只点缀,主按钮/用户气泡中性。
4. **生图/生视频/剪辑是插件式延伸能力**:它们挂在同一个 Agent 工作台和审批/任务框架上,跟随主 UI 配色与交互,不能另起一套产品皮肤;Python 能保留则保留,能 TS 化则以编译速度、运行速度、打包稳定性为准。

1. `docs/当前目标与文档口径-2026-07-07.md` - 本文件,给当前目标、CC-Haha 可直接复制/抄/移植/改写口径和文档取舍。
2. `docs/plans/TS-cc-haha-v0.4.5-内核迁移矩阵-2026-07-07.md` - 当前工程进度矩阵和下一批代码顺序。
3. `docs/design/桌面Agent-macOS设计规范.md` - UI/配色现行规范。
4. `docs/references/竞品拆解/04-对我们项目的借鉴-批判筛选.md` - Work Buddy/Codex/Claude Code 等竞品如何筛选借鉴。
5. `ts/CLAUDE.md` / `ts/AGENTS.md` - `ts/` 目录工程规则。

旧的 W1/W2/W3/W4 分窗计划、商品化收官、早期“全搬对照表”等是历史施工记录。它们可以查事实和缘由,但不能覆盖本文件和迁移矩阵的现行口径。

## 3. CC-Haha 抄用边界

- 允许且推荐:CC-Haha 内核、工具、测试边界、状态机、UI 参考实现都可以直接抄、移植、改写进本仓库;优先保证功能齐全、边界一致、测试通过。
- 应该:为复杂边界写测试,例如路径越界、工具调用配对、provider 降级、压缩恢复、文件改动实时预览;抄代码不是免测试,而是减少重复造轮子的失误。
- 区分:Work Buddy/Trae/Qoder 等闭源竞品只保留我们自己的分析、UI/交互/架构结论,不把它们的私有代码放进仓库。
- 发布口径:文档里统一明确“CC-Haha 可直接复制/抄/移植/改写”;旧阶段的防搬限制不再作为当前施工依据。

## 4. UI 与知识库口径

- 主窗口是工具流,不是营销首页。欢迎区只保留轻量起手动作;常态工作围绕输入框、状态线、工具步骤、右侧预览/画布。
- 专有知识库问答按来源分层:行业知识/领域包、店铺文件、门店记忆。默认是通用 coding Agent;用户在输入框挂载“台球运营专家”后,才把台球领域包上下文、推荐命令和专属工具带入本轮。店铺文件必须带来源和检索解释;资料库没有看到的事实要明确说没有看到。
- 文件修改要有流式可见性:工具开始、pending、完成 diff、失败态都要能在中间步骤和右侧预览里体现,不能等最终答复才暴露。
- 媒体工作台跟随主 UI token:中性主操作、绿色小点缀、紧凑面板,不加装饰性台球元素。

## 5. Main 分支口径

当前用户要求直接在 `main` 上改,不新建分支。历史文档里出现的 `ts-harness-rewrite`、`cc-haha-direct-port` 等分支名只代表当时施工记录,不再作为当前工作指令。

阶段性完成的标准不是“写了几个点”,而是:需求矩阵能解释没有遗漏,关键能力有测试或真机/浏览器验证,文档口径不会误导下一轮实现。

## 6. Python 退役口径

旧 Python 从现在起按模块分批退役,不是等最后统一清理。每一批删除都必须同时满足四个条件:

1. TS/Node/native 已有等价实现,且行为边界有测试或 smoke 覆盖。
2. 桌面端、前端 API、脚本或打包入口已经切到新实现,不会再直接调用该 Python 文件。
3. 文档和测试命令已同步更新,不会让下一轮继续把旧 Python 当主路径。
4. 删除后立即提交到 `main`,提交信息写清楚退役的模块。

当前不能直接删除的是仍在真实运行链路里的 FastAPI 主后端、媒体生成/剪辑、OCR、语音转写、RAG/店脑评测和打包入口。它们必须先由 TS/Node/native 接管并通过真机或等价 smoke 后再删。可优先删除的是离线样例生成器、旧付费 eval、已被 TS 测试和 TS sidecar 覆盖的边角脚本。
