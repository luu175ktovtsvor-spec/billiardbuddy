## 2. cc-haha 抄用边界

- **允许且推荐**:cc-haha 内核、工具、测试边界、状态机、UI 参考实现都可以直接抄、移植、改写进本仓库;优先保证功能齐全、边界一致、测试通过。
- **对齐方式**:内核直接照 cc 移植,现有实现与 cc 有结构/行为分叉就拆掉对齐(替换非叠加),不做"保留旧版打补丁"。
- **应该**:为复杂边界写测试,例如路径越界、工具调用配对、provider 降级、压缩恢复、权限同族工具绕过、文件改动实时预览;抄代码不是免测试,而是减少重复造轮子的失误。
- **区分**:WorkBuddy/Trae/Qoder 等闭源竞品只保留我们自己的分析、UI/交互/架构结论,不把它们的私有代码放进仓库。
- **发布口径**:文档里统一明确"cc-haha 可直接复制/抄/移植/改写";旧阶段的防搬限制不再作为当前施工依据。

## 3. 产品层边界与分支/退役口径(简记,完整清单见总览 §三)

- **产品层故意不对标 cc**:白标命名 `BILLIARDBUDDY.md`/`.billiardbuddy`、网关藏 key、免登录单用户全本地、审批闸只卡对外/不可逆/花钱、台球领域包 PPT-only、生图双模型、UI 配色文案走 WorkBuddy。
- **知识分层**:行业知识/领域包、店铺文件走 RAG 检索且必须带来源;门店信息不算检索式知识源,走 cc AutoMem 常驻注入(每轮必读、非检索),不进 RAG。
- **Main 分支口径**:直接在 `main` 上改,不新建分支;历史分支名(`ts-harness-rewrite` 等)不再作为工作指令。
- **Python 退役口径(已完成)**:老 Python 线(`server/`+老 `web/`+老 `desktop/`)已整体删除,唯一代码栈 = `ts/`,两台服务器也已删光老 Python 台球全栈。诚实缺口记总览 §四媒体能力节。
