# 当前架构与状态 · 总览

> 状态：现行 · 最后核对 2026-07-18

本文只记录当前源码已经成立的稳定边界，以及尚未完成的产品能力。具体字段、路径和完成度以源码、测试与实际运行结果为准。

## 1. 产品边界

BilliardBuddy 是面向球房经营者的桌面 Agent。它使用完整 Coding Agent 作为通用执行底座，让模型可以在用户授权范围内读写文件、运行命令、使用已配置的工具与专业 Skill，并通过工具结果继续完成任务。搜索、人工网页预览、Agent 网页自动化和 Computer Use 是不同能力，不能互相替代。

产品外层负责品牌、普通用户交互、业务入口、网关和专业工作台；它不重新实现一套较弱的 Agent 循环。台球知识、生图、视频和招聘属于按需业务能力，不常驻系统提示，也不改变 Agent 的通用身份。旧 BOSS 固定评分与机械自动跟进不属于当前产品，新的招聘 Skill 由 Agent 根据现场能力选择执行方式。

## 2. 当前代码边界

| 模块 | 位置 | 当前职责 |
|---|---|---|
| Agent 与本地服务 | `ts/src` | 会话、CLI 子进程、工具、子代理、Skills、Plugins、MCP、Hooks、权限、上下文和 Provider Proxy |
| 桌面应用 | `ts/desktop` | Electron main/preload、React renderer、sidecar 生命周期、IPC、窗口、终端、人工 Browser/Preview 和 Computer Use 设置链 |
| 共享契约 | `ts/shared` | 跨本地服务与桌面的公共类型和协议 |
| 模型网关 | `gateway` | 应用鉴权、三模型路由、容量保护、视觉桥接、图片任务转发和 Fun-ASR 转录 |
| 图片 relay | `relay` | 美国出口的图片生成/编辑异步任务、幂等、归属和持久化 |

旧 BilliardBuddy Agent、旧 renderer 状态链、IM adapters、dataeye、死 Tauri 宿主和无消费者网关路由不属于当前架构。

## 3. 桌面运行链

```text
Electron main
  -> 从产品配置和受保护环境读取启动参数
  -> 启动并监督 Bun sidecar
  -> 通过受限 preload 暴露桌面能力
  -> 加载唯一 React renderer

React renderer
  -> REST / WebSocket 访问 sidecar
  -> Electron IPC 使用终端、窗口、Browser/Preview 和系统能力
```

renderer 不直接持有上游模型密钥，也不直接获得任意 Node、文件或网络权限。当前前端改造只调整展示层，继续消费现有 store、REST、WebSocket 和 IPC，不建立第二套状态或 Agent 链路。

## 4. Agent 调用链

```text
Composer
  -> 会话服务
  -> Agent CLI 子进程
  -> 通用提示机制 + 项目指令 + 按需 Skill/MCP
  -> 模型循环
  -> 权限、hooks、sandbox 和工具执行
  -> 工具结果回灌
  -> transcript / event stream
  -> renderer 流式展示
```

系统提示、项目指令、Skill、权限和工具结果是不同的数据层。内部 system prompt、hook 注入、凭据和隐藏配置不能作为普通聊天消息显示。

## 5. 模型与语音链

桌面托管 Provider 经本地 Anthropic/OpenAI 兼容代理调用产品网关。网关当前支持：

- DeepSeek V4 Flash：默认文本模型。
- MiMo v2.5：唯一原生视觉模型，也为其它文本模型提供视觉桥接。
- Qwen3-Coder-Plus：可选文本模型。
- Fun-ASR-Flash：唯一语音转录上游。

普通图片由 MiMo 先转成结构化描述，再交给会话选定的文本模型；只有带原始截图且启用了真实 Computer Use 工具集的回合才整轮直达 MiMo，以保留像素、坐标和工具语义。这是显式能力路由，不是模型失败后的静默回退。

真实上游密钥只保存在网关服务器。桌面只持网关地址和可撤销应用令牌；令牌不进入 renderer、Provider 配置文件或 Agent CLI 子进程。模型失败显式返回，不在会话或工具循环中静默换供应商。

详细路由、容量和回滚边界见 `网关多模型与Agent内核接轨.md`；服务器入口见 `服务器与部署-当前拓扑.md`。

## 6. Skill 与专业工作台

Skill 是给 Agent 按需读取的任务编排说明，不是固定工作流引擎。Skill 可以说明目标、需要补齐的事实、可用能力、用户交接方式和成功证据，但不保存业务状态，也不替用户预设门店、岗位、账号或候选人事实。执行时 Agent 先看当前真实环境，可以复用连接器、MCP、可见浏览器、已有脚本和工作区代码，也可以为本次任务编写小程序；Skill 不绑定 Playwright 或任何唯一实现。

开放式任务由 Agent + Skill 完成；需要连续预览、编辑、版本和导出的能力由专业工作台承载。两者可以共享同一个确定性服务，但不能各自维护一套任务和数据。

| 能力 | 当前状态 | 目标边界 |
|---|---|---|
| Agent 通用工具与 Skill 机制 | 已在当前底座 | 保留内核机制，产品只做发现与展示 |
| 桌面语音输入 | 已接线 | 录音经 sidecar 与网关调用 Fun-ASR，转写只回填 Composer |
| 生图 | 草稿与假上游已验证，真上游待最终验收 | 图片 Skill、Tool 与工作台共享项目和幂等任务；用户复核草稿后触发付费提交 |
| 视频 | 基础剪辑源码已接线，真机媒体引擎待验收 | 视频 Skill 负责意图，工作台和本地 FFmpeg 服务负责素材、时间线与导出 |
| BOSS 招聘 | `招聘球房员工` Skill 已内置 | 整理真实岗位、分析候选人、起草沟通、用户登录接管、批次执行并读回结果；不迁移旧机械工作流 |
| 台球运营知识 | 4 层去身份化参考资源已内置 | 由 5 个球房运营 Skill 按任务渐进读取，不常驻提示、不启用强制 RAG |
| 球房运营工作流 | 5 个 Skill 已内置 | 经营复盘、活动、客户跟进、巡店整改和员工带教分别编排，共享台球知识资源 |

媒体 Skill 不等于媒体引擎。图片 Skill 负责理解用途、文字、画幅、参考事实和完成证据；视频 Skill 负责理解素材、顺序、剪辑范围和输出目标。Agent 可以选择现有图片/视频工具、脚本、代码、浏览器或工作台。服务负责 revision、幂等、任务状态、文件范围、取消和删除，工作台负责需要连续状态的预览与用户确认。字幕、ASR、音乐、转场、封面和镜头分析按真实素材和可用能力选择，不能写成每次必走的固定步骤。

台球知识来自旧代码领域包和本地 PPT 底本的去身份化提纯：旧代码可追溯到 5 个领域、29 条知识条目和 16 条历史参考数字，本地历史清单记录过 55 个细分主题。运行时只保留经营方法、场景手册和历史数字样本；第三方名称、人物、机构与案例归属不进入产品。知识与本店事实冲突时，以用户、本店资料和当前核验结果为准。

## 7. 能力成熟度

| 能力 | 当前边界 |
|---|---|
| 人工 Browser/Preview | Electron 中可导航、预览和检查；不是 Agent 自动化工具 |
| Agent 网页执行 | `WebBrowserTool` 当前是 feature-gated generated stub，默认 bundle 未启用；具体任务由 Agent 检查并选择用户已有浏览器会话、连接器、MCP、脚本、代码或其他真实可用能力，不把人工 Preview 或某个固定库冒充默认自动化 |
| WebSearch | DeepSeek/Qwen/MiMo 下需要用户提供 Tavily 或 Brave Key；两者都不是无限免费服务。Key 独立存储，renderer 只得到是否配置 |
| WebFetch | 可读取用户给出的 URL，不等于搜索引擎 |
| Computer Use | macOS/Windows 的源码、设置和权限链存在，仍依赖 Python/venv/运行依赖以及系统辅助权限；真机未验收前不标记为可用 |
| Plugins/MCP | 通用机制存在，但装机不等于预装任意外部工具。Claude.ai MCP 默认关闭 |
| 视频 | 当前是本地基础剪辑 MVP，不是自动成片或专业 NLE |

项目指令保持原生 `CLAUDE.md` 链，并追加从仓库根到当前目录的 `AGENTS.md`、`BilliardBuddy.md`。同目录 `BilliardBuddy.md` 后读；达到总长度限制时优先保留近目录指令，且内部指令不会进入普通聊天消息。

## 8. 桌面交互边界

桌面采用 BilliardBuddy 视觉和 Codex 式工作区信息架构：项目/会话导航、Agent 对话、审阅/预览、文件树和底部终端。技术能力可以放在高级设置，但不能因简化文案而从后端删除。球房老板或工作人员只需要描述业务目标，Agent 负责发现 Skill、选择工具和解释下一步；登录、扫码、素材选择、费用或批次确认再用自然语言交给用户。

模型路由由产品托管，桌面不提供 Provider 配置、模型名称选择或 Claude/ChatGPT 官方账号登录。协议与 Provider 兼容层仍保留在本地服务，供产品网关和 Agent 运行使用。

普通会话区遵守以下边界：

- 用户消息是紧凑右侧气泡，Assistant 正文直接排版。
- thinking 原文不展示，只显示必要运行状态。
- 工具调用默认是轻量活动行，详细输出、Diff 或终端结果按需展开。
- 图片、视频、Browser、Diff、文件和 Terminal 都属于工作区内容，不另建重复聊天壳。
- 亮色、暗色和跟随系统共享同一布局与信息层级。

## 9. 安全与发布边界

- 上游模型、转录和 relay 密钥只在服务器受保护环境文件中。
- 桌面控制令牌只用于本次本地进程通信，不持久化。
- 外部发送、发布、付款、删除等不可逆动作必须在执行前确认真实对象和内容。
- 安装包不连接旧产品私有服务或更新源；无确认的更新源时自动更新保持关闭。
- 第三方 LICENSE/NOTICE 按实际分发的依赖、字体、二进制和内嵌源码生成，不能因品牌清理删掉真实第三方许可。
- Tavily/Brave Key 不写普通 `settings.json`，不由设置 API 返回完整值。
- 视频安装包必须携带经哈希和构建参数校验的 LGPL FFmpeg/ffprobe 及许可证；缺失时打包失败，开发模式才允许回退系统 PATH。
