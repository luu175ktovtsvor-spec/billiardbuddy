# 当前架构与状态 · 总览

> 状态：现行 · 最后核对 2026-07-16

本文只保留系统的稳定边界和数据流。模块路径、接口字段、权限细节、功能完成度和测试数量以源码、共享契约、测试及实际运行结果为准。

## 1. 产品边界

球房运营 AI 助手是面向球房经营者的本地单用户桌面 Agent。用户用日常语言交代经营或电脑任务，Agent 在当前项目中理解目标、提出编排、调用能力并交付可检查的结果。用户选择一个工作文件夹作为项目，同一项目可以创建多个相互独立的会话；会话共享该项目中的文件和媒体项目，但各自保存消息、模型上下文、权限档和领域包状态。

Coding Agent harness 是产品必须保留的能力底座，而不是需要隐藏或削弱的临时实现。模型循环、文件与命令、任务恢复、工具协议、Skill、MCP、权限和沙箱共同提供通用执行力；代码和脚本是完成任务的手段，不把产品限制成只服务程序员的编码界面。产品的垂直性来自球房默认语境、业务 Skill、连接器、结果标准和普通用户能理解的交互，不来自分叉一套较弱的 Agent 内核。

系统只有两条执行主线：

| 主线 | 适用范围 | 基本机制 |
|---|---|---|
| Agent 对话 | 问答、文件、命令、搜索和开放任务 | 模型循环选择工具，工具结果回灌后继续推理 |
| 确定性产品功能 | 生图、剪视频、定时任务和设置 | 前端功能域调用本地服务，由明确状态机和异步任务执行 |

台球运营是可按会话挂载的领域知识包。球房发行版的新会话默认挂载该知识包，用户可以对当前会话显式关闭；它只增加知识、检索和球房任务建议，不改变通用 Agent 身份、权限或任务规划。

Skill 和 MCP 都属于 Agent 对话主线的渐进式能力，不构成第三条执行主线。用户只需要描述目标；Harness 根据技能描述发现合适 Skill，再由 Skill 追问必要事实并编排现有工具或连接器。

## 2. 部署边界

| 系统 | 代码位置 | 运行位置 | 边界 |
|---|---|---|---|
| 桌面产品 | `ts/` | 用户电脑 | React renderer、Electron main 和 Bun sidecar 同包交付 |
| 模型与转录网关 | `gateway/` | 大陆服务器 | 统一鉴权、容量调度、模型代理、搜索和可替换 ASR |
| 生图中转 | `relay/` | 美国服务器 | 图片生成与编辑的异步出口 |
| 数据服务 | `dataeye/` | 大陆服务器 | 诊断数据接收和只读看板 |

桌面同包组件可以原子升级；远程服务必须保持旧客户端兼容，并按服务端、客户端、清理阶段发布。服务器、端口、环境变量和运维命令只在 `服务器与部署-当前拓扑.md` 与对应 deploy runbook 维护。

## 3. 桌面运行结构

```text
Electron main
  -> 启动并监督 Bun sidecar
  -> 通过受限 preload 暴露系统能力
  -> 加载唯一 React renderer
  -> renderer 通过 HTTP / WS 访问 sidecar
```

- renderer 只依赖功能 API、store 和共享契约，不直接访问 Node 或 Electron。
- sidecar 负责 Agent、工作区、媒体、设置和持久化，不提供旧静态页面。
- 跨 renderer、sidecar 和 IPC 的字段放在 `ts/shared/contracts`，由 Zod 在边界解析。
- 本地业务状态使用 JSON/JSONL、原子写入和 revision，不引入 SQL。

## 4. Agent 数据流

```text
Composer
  -> Agent WS / HTTP
  -> 会话与回合服务
  -> 通用系统提示 + 项目指令 + 会话领域包 + Skill 索引
  -> 模型循环
  -> 按需读取 Skill / 搜索 MCP 与长尾工具
  -> 权限、hooks、sandbox 和工具执行
  -> 工具结果回灌
  -> transcript / event stream
  -> renderer 流式展示
```

系统提示、项目指令、权限运行时和领域知识分别装配。模型可以决定调用什么能力，但路径校验、审批、下载、重试、文件副作用和持久化必须由确定性代码负责。

## 5. Skill 与连接器边界

产品内置 Skill 是给 Agent 使用的可复用编排说明。名称和描述用于触发，完整正文只在相关任务中读取；不要把所有业务流程常驻系统提示。Skill 应说明目标、判断顺序、需要向用户补齐的事实、可用能力、成功证据和停止条件，不保存业务数据库，也不预设可能失真的门店数据、工资、班次、账号或候选人资料。

普通斜杠面板只展示适合用户主动选择的业务入口。开发、诊断、模型、权限、连接器和扩展管理等内部工作流使用 `user-invocable: false` 从用户发现面隐藏，但仍保留在模型发现面供 Agent 按需编排；隐藏不等于删除或削弱能力。用户安装或在当前门店定义的工作流沿用各自声明，不按名称做前端硬编码过滤。

Playwright、MCP、文件、命令和专用 CLI 是执行通道。连接器负责真实读取或动作，Skill 负责选择和编排；调用 Skill 不等于自动放开连接器权限。登录、验证码和账号安全验证交给用户；发消息、发布、付款、删除等对外或不可逆动作在执行前展示真实对象与内容，执行后由页面、接口或文件结果提供回执。

BOSS 招聘沿用这一边界：Agent 根据用户输入补齐岗位事实，并在本次会话内形成硬条件、优势证据和待确认项；平台排序、第三方 CLI 或外部评分不能替代本产品的筛选判断。专用 CLI 或 Playwright MCP 只负责登录交接、读取页面、定位会话和执行已确认的发送。用户亲自登录并在发送前确认候选人和完整正文。只有从同一候选人会话读回消息证据才算发送成功，证据不足进入 `uncertain` 并停止，不能盲目重试或绕过平台风控。

## 6. 媒体编排

四个用户入口共用两套后端媒体主责服务，不复制第三套聊天专用引擎：

| 入口 | 入口职责 | 共享真相源 |
|---|---|---|
| 生图工作台 | 表单、参考图、候选比较和画布编辑 | Image CreativeBrief、`MediaJobService`、`ImageWorkbenchStore` |
| Agent 做图 | 把自然语言与用户确认后的图片交给媒体工具 | 同一 Brief、任务、质检和图片项目库 |
| 视频工作台 | 素材导入、草稿比较、Scene 编辑和导出 | `VideoEditingService`、Scene/Timeline、项目 revision |
| Agent 剪视频 | 复述用户目标、创建草稿、等待确认后导出 | 同一视频服务、项目、证据和异步任务 |

图片和视频的稳定流程是：

```text
用户意图与真实素材
  -> 共享 Brief
  -> 素材证据与能力检查
  -> 规划或生成
  -> 有限质量检查与重试
  -> 项目持久化
  -> 预览、编辑或导出
```

生成式图片调用远程模型；视频分析和渲染优先在本地使用 FFmpeg/ffprobe，视觉证据使用当前多模态模型，语音转录默认走服务器。模型只声明能力需求，资产管理器负责下载地址、平台匹配、断点续传、SHA-256 校验、原子落位和就绪后续跑。

必须在客户端执行但不必进入安装包的组件由资产清单分发。应用启动只加载清单和本地状态；FFmpeg、ffprobe、字幕字体等组件在图片或视频功能首次真正需要时下载。Whisper 权重不属于默认客户端资产；只有显式本地离线模式才允许本地转录组件。

## 7. 数据与信任边界

```text
会话消息       -> JSONL transcript
会话与任务索引 -> JSON
文件修改       -> 工作目录 + 本地恢复记录
媒体项目       -> 项目 JSON + uploads / exports
可丢失偏好     -> renderer preference
```

- 工作目录是项目隔离边界；媒体项目列表和 Agent 媒体工具都按当前工作目录过滤。
- provider 密钥只保存在服务器或受保护的本地凭据存储，renderer 不接触真实密钥。
- renderer 不获得裸 IPC、任意文件或任意网络能力；所有不可信输入在执行边界再次校验。
- 诊断数据使用字段白名单和脱敏，不上传对话正文或门店资料。
