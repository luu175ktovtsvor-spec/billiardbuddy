# 当前架构与状态 · 总览

> 📌 状态:✅现行 · 最后核对 2026-07-15

本文只说明系统的稳定结构、模块责任和关键数据流。当前实现、可用状态和完成度以源码、测试与实际运行结果为准。

## 1. 产品与执行模型

球房运营 AI 助手是本地单用户桌面 Agent。业务状态保存在用户设备；模型请求通过自有网关或用户配置的 provider；运行时界面保持白标。

系统包含两类执行路径：

| 路径 | 适用场景 | 入口 | 执行方式 |
|---|---|---|---|
| Agent 对话 | 问答、文件、命令、搜索、开放任务 | `/agent/ws`、`/agent/run` | 模型循环自主选择工具并读取结果 |
| 确定性产品功能 | 生图、剪视频、定时任务、设置 | feature API、REST job、IPC | 产品代码按明确状态机执行 |

台球运营通过 `billiards` 知识包按需挂载。它只增加领域上下文和知识检索，不改变通用 Agent 身份、任务规划或权限。

## 2. 部署边界

| 系统 | 路径 | 运行位置 | 发布边界 |
|---|---|---|---|
| 桌面产品 | `ts/` | 用户电脑 | React renderer、Electron main、Bun sidecar 同一安装包 |
| 模型与转录网关 | `gateway/` | 大陆服务器 | 独立服务；转录 provider 可在服务器内部替换 |
| 生图 relay | `relay/` | 美国服务器 | 独立服务 |
| 数据服务 | `dataeye/` | 大陆服务器 | receiver 与 board 独立进程 |

桌面应用与远程服务通过版本化 HTTP 契约连接。桌面内部的 renderer、Electron 和 sidecar 随应用原子升级。

## 4. 桌面运行结构

### 4.1 启动

```text
Electron main
  -> 启动并监督 Bun sidecar
  -> 注册 preload IPC 白名单
  -> 加载 renderer
  -> renderer 通过 desktopHost 获取 sidecar 地址
  -> React 通过 HTTP/WS 访问本地服务
```

Electron 只加载 React 构建产物；开发态可通过受限为本机回环地址的 `ELECTRON_RENDERER_URL` 使用 Vite HMR。Bun sidecar 只提供 API/WS，不再承载旧桌面页面。

### 4.2 Agent 对话

```text
Composer
  -> /agent/ws
  -> SessionService / TurnRegistry
  -> system prompt + memory + enabled packs
  -> runAgentLoop
  -> model/proxy
  -> tool calls
  -> permission + hooks + sandbox
  -> tool results 回灌
  -> transcript / events
  -> renderer 流式展示
```

内核统一使用 content-block。OpenAI-compatible 请求在 proxy 层转换，工具调用和结果在进入模型前完成配对与清理。

### 4.3 确定性产品功能

```text
React feature
  -> feature API adapter
  -> shared Zod contract
  -> Bun route
  -> application service / job
  -> JSON 状态与本地资产
  -> poll 或事件进度
  -> React feature
```

页面不解释原始响应，也不直接访问 Electron 或 Node。API adapter 负责解析契约和归一化错误，store 管理业务状态，组件管理展示与临时交互。

## 5. 关键数据流

### 5.1 权限与工具执行

```text
tool call
  -> Zod 输入校验
  -> PreToolUse hooks
  -> permission mode / allow-deny rules
  -> forceConfirm 与用户交互要求（完全访问跳过 forceConfirm）
  -> workspace / sandbox 边界
  -> 执行
  -> 备份、事件和 tool_result
```

权限内核支持 `default`、`acceptEdits`、`plan`、`bypassPermissions`、`dontAsk`，renderer 的普通用户菜单只展示默认权限、接受修改和完全访问三档。renderer 按会话持久化当前档位；用户明确绑定工作目录的新会话默认使用 `acceptEdits`，工作区内普通文件修改直接执行，命令、越界和敏感修改仍按权限规则处理。开启 `bypassPermissions` 时，renderer 向 `run/approve/reject` 显式发送 `full_disk_access=true`；后端跳过普通审批和 `forceConfirm`，并在 worktree、前台子代理、后台任务及恢复链中保留全盘访问。显式 deny、无效输入或 SSRF 等 fatal 拒绝、以及必须由用户做选择的交互卡仍生效。后端不根据模式名称自动推断全盘访问。

联网能力分两层：主路径由 gateway 在 MiMo Chat Completions 请求中追加原生 `web_search`，默认最多 5 条查询、每条 5 个结果且不强制搜索，模型根据任务决定是否调用；MiMo 返回的 URL 引用经 proxy 校验、去重后进入最终正文。旧 `POST /v1/web_search` 和本地 `WebSearch` 工具只保留为兼容后备，gateway 不会同时披露两条搜索路径，也不设置搜索专属每日配额。`WebFetch` 继续抓取已知公网 URL，保留域名审批、SSRF、重定向、超时和响应大小限制。大陆现网已启用 MiMo 原生搜索；客户端不直连搜索厂商或公共搜索实例。

### 5.2 本地存储

```text
会话消息       -> JSONL transcript
会话与任务索引 -> JSON
工具大结果     -> session result store
文件修改记录   -> file history / backups
媒体项目       -> project JSON + uploads / exports
用户偏好       -> settings JSON 或可丢失的 renderer preference
```

桌面业务状态不依赖 SQL。写入使用原子文件替换、追加日志或明确的 revision 控制。

工作目录是顶层项目边界。同一工作目录下可有多个会话，并共享图片工作台和视频工作台项目；`conversation_id` 只记录创建来源，不把媒体项目锁死在单个会话。不同工作目录的项目列表和 Agent 媒体工具相互隔离，旧版未记录工作目录的媒体项目只在默认工作目录兼容展示。

### 5.3 生图

```text
描述与参考图
  -> CreativeBrief
  -> 本地输入检查与授权
  -> gateway
  -> Seedream 路径或 relay 异步任务
  -> 候选与检查结果
  -> ImageWorkbenchStore
  -> Fabric 画布、版本、PNG 导出和素材保存
```

### 5.4 剪视频

```text
本地真实视频
  -> 指纹、技术分析和可用证据
  -> CreativeBrief
  -> Scene/Timeline v2 规划
  -> 原子编辑与 revision
  -> 预览
  -> FFmpeg 正式渲染
  -> 导出清单和成片
```

### 5.5 诊断数据

```text
应用启动与崩溃日志
  -> 本地脱敏和字段白名单
  -> gzip batch + Bearer token
  -> dataeye /ingest
  -> receiver 去重
  -> board 展示
```

配置 `QF_DATAEYE_URL` 和 `QF_DATAEYE_TOKEN` 时启用。上传失败不影响应用启动，不发送对话内容或门店资料。

### 5.6 组件资产

```text
asset manifest
  -> 平台筛选
  -> Range 下载与断点续传
  -> size / SHA-256 校验
  -> 解包和原子落位
  -> 功能门自动继续
```

Tier 1 资产在启动后准备，Tier 2 资产按功能需要下载。状态通过 `/api/v1/assets/status` 和 WS 进度事件提供给前端。Whisper 权重不属于默认客户端资产；只有显式本地离线模式才使用兼容的 `whisper-cli`/模型资产。

三个产品界面、四条媒体编排路径不各自下载组件，而是共用同一能力门：

| 入口 | 本地必需 | 按需本地 | 始终远程 |
|---|---|---|---|
| 生图界面 | 应用内核 | FFmpeg 用于受控调整和高清尺寸放大 | 生图与生成式改图模型 |
| 剪视频界面 | FFmpeg/ffprobe | 稳定中文字幕字体 | MiMo 视觉判断和 ASR |
| Agent 聊天 | 不额外复制媒体组件 | 调用生图/视频工具时复用上述能力门 | 对话模型及上述远程媒体能力 |

Agent 只声明要使用的能力，不自行生成下载地址或运行下载命令。功能门负责平台匹配、断点续传、完整性校验、原子落位和就绪后续跑。当前服务器发布 macOS/Windows FFmpeg、ffprobe 和跨平台中文字幕字体；语音转录与生成式图片能力保持远程。

四条路径共享后端编排，不各自复制一套生成或剪辑引擎：

| 路径 | 入口适配 | 共享真相源 | 结果呈现 |
|---|---|---|---|
| 生图工作台 | 表单和画布输入 | Image CreativeBrief、MediaJobService、ImageWorkbenchStore、图片质检 | 候选、比较、画布、版本和导出 |
| Agent 做图 | 自然语言与图片工具 | 同一 Brief、任务、质检和图片项目库 | 对话摘要，并可继续在工作台编辑 |
| 剪视频工作台 | 素材导入和项目操作 | VideoEditingService、Scene/Timeline v2、项目 revision、渲染质检 | 项目预览、调整和导出 |
| Agent 剪视频 | `plan_video` / `render_video` | 同一 VideoEditingService、项目和 Job | 对话式复述方案；预览直接执行，正式导出前确认锁定版本 |

入口只负责编译用户意图和展示结果。资产等待、失败重试、断点续跑、低质量结果的有限重试以及项目持久化由后端统一负责。

### 5.7 语音与口播转录

```text
麦克风录音或视频音轨
  -> 本地 sidecar
  -> gateway /v1/audio/transcriptions
  -> app token、大小、格式、限流、单并发
  -> whisper.cpp 或受保护的上游 ASR
  -> 文本/时间戳共享契约
  -> 聊天输入或视频字幕缓存
```

视频在本地用 FFmpeg 抽取 16kHz 单声道 FLAC 后上传，不传原视频。服务器 provider 由环境配置选择，客户端不感知 Whisper、Qwen 或供应商名称。

## 6. 核心机制

| 机制 | 当前实现 |
|---|---|
| 上下文压缩 | microcompact、工具结果落盘、结构化摘要、最近文件与技能恢复 |
| 会话恢复 | append-only transcript、事件回放、turn checkpoint、rewind |
| 记忆 | `BILLIARDBUDDY.md` 分层上下文、memdir、`save_memory` |
| 领域知识 | enabled packs 注入知识目录，并注册挂载入口和只读知识检索工具 |
| 提示词分层 | 通用系统提示、项目指令、权限运行时和会话领域知识独立装配；领域知识不参与权限决策 |
| 子代理 | 同步 agent、后台任务、fork context、团队消息和任务恢复 |
| 扩展发现 | 已启用插件的 skills、commands、hooks 和 MCP 通过同一运行时装配进入主回合、审批恢复、预热和发现接口 |
| Provider | 活跃 provider、候选降级、健康冷却、流式超时和白标错误；gateway 当前以单个 MiMo 容量池执行 RPM、全局/单用户在途、公平队列和退避重试，后续供应商按独立容量池扩展 |
| 白标 | 系统提示约束、公共名称映射、流式与最终输出脱敏 |
| 凭据 | 服务器密钥隔离；Electron safeStorage 可用时加密本地 provider 凭据 |

## 7. 前端功能域

React renderer 按功能域组织：

- 聊天与会话
- 工作区、文件树、Git 和终端
- 扩展、技能、插件和 MCP
- 已安排任务
- 生成图片
- 剪视频
- 设置与门店资料
- 应用外壳、导航和全局命令

前端设计遵守 `design/桌面Agent-macOS设计规范.md`，使用浅蓝强调色和中性灰阶。需要对照外部产品时直接读取其当前源码或运行证据，不沿用静态逆向快照。用户文案隐藏 provider、模型和内部状态名。

## 8. 远程服务

| 服务 | 入口 | 当前职责 |
|---|---|---|
| `gateway` | nginx `/gw` -> `127.0.0.1:8799` | 应用令牌鉴权、容量调度、用量记录、文本/图片代理、联网搜索和语音转录 |
| `relay` | nginx `/relay/imgtasks/` -> `127.0.0.1:8790` | 美国出口的图片生成与编辑异步任务 |
| `dataeye receiver` | `:9100/ingest` | gzip 批量接收、鉴权、幂等和数据分层 |
| `dataeye board` | `:9200/board` | 诊断和运营指标展示 |

详细变量、进程、发布和资产托管见 `服务器与部署-当前拓扑.md`。

## 9. 当前边界

- 自动更新渠道尚未开放；Windows CI 生成 artifact，macOS 可本地构建受控测试包。
- React renderer 是唯一桌面入口，桌面改动必须通过完整 Electron 冒烟。
- 远程服务协议变更需要保持向后兼容，并按服务端、客户端、清理阶段发布。
- 媒体的真实远程调用、模型质量和平台签名使用显式 live smoke 验证，不进入默认离线测试。
- 当前任务由代码、测试和用户明确引用的验收规格共同约束；本文件不记录任务流水。
