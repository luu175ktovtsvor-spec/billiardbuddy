## §0 一分钟看懂 + 模块地图

### 一分钟看懂

用户在 Electron 窗口输入一句话 → **本地 Bun sidecar**(`ts/src/server/index.ts`,监听 `127.0.0.1:8850`)跑起 **ReAct 主循环**(`harness/loop.ts`):模型想一步 → 有工具调用就过**权限闸**执行(读写文件/跑命令/查网/生图/派子代理)→ 结果回灌 → 再想,直到收敛。模型出口有两种:**ProxyModel**(OpenAI 兼容,翻译成 content-block)对接国产模型,**AnthropicMessagesModel** 对接 Anthropic 格式;真实请求都发到**大陆网关 qfgw**(藏 key + 三层阀门),生图慢调用再转到**美国 relay**(异步 submit/poll,绕过跨境 60s 掐断)。所有会话/任务/记忆以**文件式 JSONL + JSON** 落在 `~/.billiardbuddy/state`。前端只看到"能力档代称",看不到真实模型名。

## §2 逐模块详解(主体)

> 每模块:**职责 / 数据怎么走 / 关键机制 / 关键文件+端点+env**。

### 2.1 内核层

#### 2.1.1 数据契约(types/ + shared/contracts/)——一切的地基

- **职责**:定义内核消息和跨层传输结构。`ts/shared/contracts` 是 renderer、sidecar、Electron IPC 的单一真相源；使用 Zod 做运行时解析并推导 TypeScript 类型，禁止两端新增手写镜像。
- **消息格式 = Anthropic content-block**(`types/message.ts`):`Message` 只有 `role:'user'|'assistant'`(**没有 `role:'tool'`**),`content` 恒为 `ContentBlock[]`。块类型:TextBlock / ThinkingBlock(thinking+可选 signature)/ ImageBlock(base64,限 png/jpeg/gif/webp)/ ToolUseBlock(id/name/input)/ ToolResultBlock(tool_use_id/content/可选 is_error)。`ToolResultBlock.content` 兼容旧纯 string 或多模态块数组(text|image,图片走 vision 通路)。**system 不是一条 role:'system' 消息,单列走 `ModelStepInput.system`**。
- **Model 接口**(`types/model.ts`):`Model.step(input) → AssistantStep`,一个小接口做依赖注入(真模型 ProxyModel/AnthropicMessagesModel;测试用 scriptedModel fake)。`ModelStepInput={system?,messages,tools,signal?,onDelta?}`;`onDelta` 是 token 级流式回调(真模型触发、fake 不触发)。**AssistantStep 的 kind 由"有没有 tool_use"决定,不看 finish_reason**:`tool_calls`(带 calls)/ `final`(纯文本收敛)。`thinking` 仅展示不回灌;`notices` 系统旁白(如截断提示)。常量 `MODEL_OUTPUT_TRUNCATED_NOTICE`。
- **事件流**(`shared/contracts/agent-events.ts`,`agent-websocket.ts`):`AgentEvent`、会话回放、Client/Server WS 信封共用 Zod Schema；renderer WS 入口解析未知 JSON，sidecar 解析客户端消息。`types/events.ts` 和 renderer `types/events.ts` 只做兼容重导出。
- **IPC**(`shared/contracts/desktop-host.ts`):main/preload/renderer 共用通道常量和 `DesktopHost` 类型，renderer 只从 `lib/desktopHost.ts` 接触原生能力。

#### 2.1.3 ReAct 主循环 `runAgentLoop`(`harness/loop.ts`,核心)

- **职责**:真 ReAct 循环——`想→有 tool_use 就过权限闸执行(只读安全批可并行)→ 一批 tool_result 装单条 user 消息回灌→再想`,直到 `kind==='final'` 收敛或 `max_turns`(默认 12)。
- **退出信号 = 看有没有 tool_use 块**(`step.kind==='tool_calls'`),**不信 finish_reason**(内核铁律)。
- **入口装配**:transcript 加载 + `sanitizeResumeMessages` 清残尾 → 还原 contentReplacement 状态 → 恢复已调技能 → 装 ToolContext → 应用初始 permissionUpdates/allowedTools → 激活 worktree 会话 → SessionStart/UserPromptSubmit hooks → 组首条 user 消息。
- **流式驱动**(`streamModelStep`):queue+race 交错——onDelta 到达的增量 push 进 queue,generator 边等边 `yield content_delta`(前端打字机);await 结束 return 完整 step。非流式模型队列恒空,行为等价 `await model.step()`。
- **每轮分支**:final 分支依次判 ①截断续写 ②steering 插话 ③pendingPlanVerification 拦截 ④StopHook 续跑 ⑤真收敛;tool_calls 分支合成 thinking(每步≤1条)→ assistant 历史块(thinking 不进历史)→ 逐个过闸执行 → 一批 tool_result 装单条 user 回灌。
- **工具执行**:`gateOneCall` 单调用闸(见 §4.2);并行只读批 `prepareParallelReadOnlyCall`(纯只读+无任何权限元数据+无hook 才进,`mapWithConcurrency` 并发,上限 env `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY` 默认 10);`sameCallLimitForTool`(核心工具 4、扩展/mcp 40)防打转。
- **max_turns 兜底**:轮次耗尽先 yield `max_turns_reached`,再 `model.step({tools:[]})` **空工具强制收敛**(照 cc `_FINAL_NUDGE`)。
- **独立审批恢复**:`executeApproved`(给 `/agent/execute`,先验 HMAC token 再跑,不信前端回传 args)、`handleReject`(给 `/agent/reject`)。
- ⚠️ **迁移锚点**:loop.ts 大量注释直引 `cc-haha src/query.ts:167/1196-1229` 等;改逻辑须同步核对 cc 参考实现。`task#15「后端底盘全量对齐 cc-haha」`仍 in_progress。

#### 2.1.4 模型出口(proxy/ + model/)

- **ProxyModel**(`proxy/ProxyModel.ts`):OpenAI 兼容出口,对接 MiMo/豆包/DeepSeek/GLM/Kimi 等。流程 `ensureToolResultPairing(normalizeMessagesForAPI(messages))` → `toOpenAiChatRequest` → `runOnce`(fetch+超时+读流累积)→ `toAssistantStep`。端点 `POST ${baseUrl}/chat/completions`,header `authorization: Bearer`。**退出看 toolCalls 有无、不看 finishReason**;截断第一级恢复:纯正文截断且无 tool_calls → 升 `max_tokens` 到 `ESCALATED_MAX_TOKENS=64_000` 重试一次(不传 onDelta 防重影)。`max_tokens` 默认**故意不带**(交上游默认,大值易超国产上限)。
- **双向翻译层**:`toOpenAiChatRequest.ts`(出方向:system→首条 system 消息、tool_result→独立 `{role:'tool'}` 消息、tool_result 图像顺延进尾随 user 的 image_url、thinking 不回灌)、`streamAccumulate.ts`(SSE 累积,reasoning 三方言归一 reasoning_content/reasoning/thinking_blocks,中途 error 帧抛 `StreamProviderError`)、`openaiChatToAnthropic.ts`(非流式兜底)、`messagePairing.ts`(补孤儿 tool_use/删孤儿 tool_result/去重 id/补占位保交替,**不清洗国产模型会 400 卡死**)、`streamIdleTimeout.ts`(流空闲超时 re-arm)、`toolArguments.ts`(参数容错)、`usage.ts`(cache 换算)、`types.ts`。
- **AnthropicMessagesModel**(`model/AnthropicMessagesModel.ts`):Anthropic 原生出口(apiFormat==='anthropic')。端点 `POST .../messages`,`anthropic-version:2023-06-01`,`max_tokens` 默认 4096。认证五档 `headers()`:api_key/auth_token/auth_token_empty_api_key/dual_same_token/dual_dummy。截断恢复把 `model_context_window_exceeded` 也并入续写路径。**不发 reasoning_effort**(Anthropic 用 thinking budget)。
- **模型工厂/配置/降级**(`model/`):`modelFactory`(apiFormat 选出口)、`providerConfig`(env→出口配置,五档 auth,`redactedProviderSummary` 只脱 key **仅后端内部**)、`FallbackModel`(多出口按序降级,preferredIndex 粘住上次成功,`sanitizeError` 清 Bearer/key)、`fetchRetry`(出口内瞬时重试,**默认关**,靠 cfg.retry 显式开)、`networkSettings`(代理 direct/system/manual+超时 clamp,loopback 恒不走代理)、`reasoningEffort`(low/medium/high,max→high)、`envLoader`(`DEFAULT_MODEL_ENV_FILES=['../desktop/bundled.env']` 内置 key 来源)。
- ⚠️ **usage 依赖上游**(国产不回 usage 则无 usage_update,task#47 pending);**thinking 不回灌**(多轮不携带 reasoning 上文,故意简化);**上下文窗口表硬编码快照**(`modelContextWindows.ts`,查不到走 env `CLAUDE_CODE_MODEL_CONTEXT_WINDOWS` 或无 context_percent)。

#### 2.1.5 上下文管理与抗失忆(context/)

- **职责**:防"聊长了失忆"。抗失忆 = 三级压缩 + 超长工具结果落盘 + 轨迹 JSONL 落盘/续接 + 压缩后重读最近文件/恢复已调技能 + prompt-cache 断裂检测 + steering + 持久记忆注入。全对标 cc-haha(注释逐条标行号)。
- **压缩触发**(`compaction.ts`):`AUTOCOMPACT_RATIO=0.7`;**token 级优先**(`lastInputTokens >= floor(窗口*0.7)`)、字符级兜底;冷却 30s、无进展跳过、连续失败 3 次熔断;`force=true` 绕过一切。⚠️ `contextWindowChars` 几乎恒 undefined(客户端不传)→ 压缩实际全靠 token 路径。
- **三级压缩**:①**microcompact**(`microcompactReadOnlyToolResults`,旧只读工具结果就地折成一行占位,幂等、**破坏性不可回读**,多模态图像不折)②**超长工具结果落盘**(`toolResultStorage.ts`,单条 >24K 且属白名单工具落盘,上下文只留头尾各 1000 字符 + 可回读 path,回读工具 `read_stored_tool_result` 带 realpath 越界护栏;`read_file` 故意不落盘保 vision)③**逐消息聚合预算**(一批工具结果 >200K 挑最大几条落盘,`content-replacements.jsonl` sidecar 持久化保 resume 后替换一致、prompt-cache 前缀不漂移)。
- **全量摘要**:切点保护 `splitForAutocompact`(不产生孤儿 tool_result,`KEEP_RECENT_MESSAGES=12`)→ 9 节结构化中文摘要 prompt `COMPACTION_SYSTEM_PROMPT`(**dev 明确要求保留真实模型/provider 名**,压缩保真需要,白标在前端/输出流层做)→ `extractCompactionSummary`;摘要请求本身超限走 PTL 收缩重试(砍最旧一半,`MAX_COMPACT_SUMMARY_RETRIES=3`);空摘要保护(绝不丢旧消息只留占位)+ 失败降级(这轮不压下轮再试,不做硬截断兜底)。
- **压缩后恢复**:`recentFileContext.ts` 重读最近 5 文件真实当前内容(实时 stat 比对标 `changed_since_read`,防对着旧记忆改文件);`invokedSkills.ts` 恢复已调技能全文。
- **prompt-cache 断裂检测**(`promptCacheBreakDetection.ts`):cache_read 骤降 → 归因(system/tools/model 变更 hash 比对)→ context_note 告警。⚠️ TTL(5min/1h)推断分支实际走不到(`lastAssistantAgeMs` 恒 0/null,留口未接真实时间戳)。
- **usage 上报**:`usageUpdateEvent` 每 step 后算 `currentInputTokens=input+cache_read+cache_creation`,发 usage_update + `context_percent`。

#### 2.1.6 工具·权限·安全护栏

- **职责**:模型每次调工具 → `gateOneCall` 先跑 hooks,再 `resolvePermission` 算 allow/ask/deny;工具 execute 里再各自复核硬红线。**三层叠加:①硬红线(fatal 拒)②审批闸(ask,只卡对外/不可逆/花钱)③本机护栏(沙箱写围栏+备份+工作区边界)**。

## §4 关键机制怎么做的

### 4.1 ReAct / content-block

内核只认 Anthropic content-block(§2.1.1),OpenAI 端点走 proxy 双向翻译(§2.1.3)。主循环退出看有无 tool_use 块、不信 finish_reason;工具 use/result 严格配对(`ensureToolResultPairing` 补孤儿/删孤儿/去重/补占位,不清洗国产模型会 400);工具报错一律 `<tool_use_error>` 回灌不崩循环。

### 4.2 权限五档 + 审批三类 + gateOneCall

五档 default/acceptEdits/plan/bypassPermissions/dontAsk;`gateOneCall` 单调用闸顺序:未知工具报错→交互工具内联处理→`validateToolInput` schema 闸→PreToolUse hooks(可 deny/改 input/强制 ask)→`resolvePermission`(deny 回灌/ask 吐审批卡占位不阻塞/allow 执行)。审批只卡对外触达/不可逆/花钱三类;审批 token HMAC-SHA256 签名,`verifyApproval` timingSafeEqual,不信前端回传 args。

### 4.3 文件护栏 + 备份

沙箱双层写围栏(mac/linux `@anthropic-ai/sandbox-runtime` seatbelt/bwrap allow-only,⚠️ Windows 恒失效占位)+ 改文件前自动备份(轻备份 .backups + 快照链 fileHistory 可 restore_file 回滚)+ 工作区边界(`..` 越界抛错、TOCTOU 护栏、symlink realpath 防护)+ 危险命令红线(POSIX/Windows/PowerShell 三套锚,执行点双保险)。

### 4.4 记忆(cc AutoMem)+ 领域包 @挂载

SessionStart 注入项(领域包✅ / 安全红线⚠️部分缺口,§2.1.8;门店信息不另立注入层,统一走 cc AutoMem 的 BILLIARDBUDDY.md Project 层常驻注入,已删 storeMemoryContext 检索式店脑)。领域包 @挂载走 SessionStart hook:请求带 `enabled_packs`→`resolveEnabledPacks`→`createDomainPackHookRegistry`→loop 里 `applySessionStartHooks` 把 `pack.sessionStartContext` 追加到基座系统提示后(`<hook_context event="SessionStart">`)。命令/技能清单另经 `skillListing` 按约 1% 预算注入系统提示(让模型"看清单→自动调")。

### 4.5 压缩抗失忆

三级压缩(microcompact 折叠 / 超长结果落盘 / 聚合预算)+ 全量摘要(9 节结构化中文 prompt,切点保护不产生孤儿)+ 压缩后重读最近文件/恢复已调技能 + prompt-cache 断裂检测。详见 §2.1.4。

### 4.6 子代理 + 任务
