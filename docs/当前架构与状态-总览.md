## 一、产品定位 · 头号方向 = 全方位对标 cc-haha

- **头号方向,一句话**:**全方位对标 cc-haha,不做阉割版,能抄就抄。** 产品 = **装在用户自己电脑上的通用本机 AI Agent 桌面软件**,本质是一个**强 coding agent 桌面外壳**。对标参考 = `~/Desktop/cc-haha-ref`(`NanmiCoder/cc-haha`,LICENSE 允许 copy/modify/distribute,可直接复制/抄/移植/改写)。
- 用户一句话 → AI 大脑(ReAct 循环)自主调工具把事做完:读写/改本机文件、跑命令、上网查抓、生图、列任务清单、把大任务派子代理。面向不懂技术的用户:说大白话、给能直接用的结果。
- **台球运营不是产品边界,是可 `@挂载` 的领域知识包**;默认不挂 = 通用电脑助手。生图、真实素材剪辑是**可挂载的延伸能力**,挂在同一个 Agent 的工具/审批/媒体任务框架上,不是独立产品。
- 免登录、单用户、全本地;模型 key 全内置(走网关藏 key),用户零配置开箱即用。

## 二、对标"方式" · 内核直接对标 cc、发现分叉就掰回去(重要口径)

这一节定"怎么对标",跟"对标谁"同样重要,是新会话最容易做错的地方。

- **替换非叠加,不是打补丁**:内核(主循环/上下文/权限/工具/hooks/技能/命令/任务/mcp/记忆)**直接照 cc 移植**,不是"保留旧实现 + 打补丁凑功能"。老 Python 台球全栈已整体删除 = 架构已经选定"替换非叠加"这条路。
- **发现分叉就拆掉、对齐 cc**:现有 TS 实现只要跟 cc 有**结构或行为分叉**(比如权限判定绕过、hooks 信任门缺失、工具默认口径不一致),不做"和稀泥保留",而是拆掉分叉实现、掰回 cc 的做法。
- **验收硬闸 = 行为对齐测试**:唯一验收标准是"刁钻边界上判得跟 cc 一模一样"——复杂能力先用可观察行为写失败测试(路径越界、工具配对、provider 降级、压缩恢复、权限同族工具绕过…),再迁移到同输入同决策跑绿。抄代码不免测试,是减少漏项。
- **规格源 = 源码本身**:cc-haha 源码是可执行规格;逐模块 cc 差异矩阵 + 本轮对齐进度见 `plans/TS-cc-haha-v0.4.5-内核迁移矩阵-2026-07-07.md`(§2 模块矩阵、§3.401/§3.405 本轮 P0 进度)。
- **工作方式**:子代理实现 + 子代理对抗式审查(刁钻边界逐条挑刺)+ 主代理编排/决策;直接在 `main` 上施工。
