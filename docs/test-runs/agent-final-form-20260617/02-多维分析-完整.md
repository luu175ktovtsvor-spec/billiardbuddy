## D2:对外动作/"一键发布"的最终形态裁决

**关键发现**:

- 【一键发布的真相已被坐实】调研R1直接证明:小豆芽/易媒助手等"一键多平台发布"工具99%靠自研RPA(指纹浏览器多开+Playwright类脚本模拟登录+Cookie代发),不是官方API授权。开源同款(social-auto-upload等)技术栈直接坐实=Playwright/patchright反检测自动化。这是灰产盘子,小红书2024一个月清退125万账号即证其脆弱。我们做的是面向门店老板的SaaS,赔不起把客户账号搞封——RPA/群控/模拟登录路线必须钉死为永久红线,绝不做。
- 【我们既定P3边界完全正确,无需调整】当前形态=AI备好平台定制内容(make_platform_content抖音/小红书/快手/视频号文案 + make_groupbuy_content美团/抖音团购套餐)→一键复制/引导老板去App后台手动发。这是"handoff"(交接),不是"自动发"。代码已落地:三个对外/花钱工具(make_poster/make_platform_content/make_groupbuy_content)都走审批闸,make_poster标requires_approval=True走proposal模式。"内容到位+引导"反而是对冲对手"能自动发但随时封号"的安全感差异化卖点。
- 【真发只有两条合规路,且都重】路A=官方API代发(抖音create_video/快手photo/publish/企微group群发):需公司主体拿企业开发者认证+公函盖章+"代替用户发布"权限审批(可能被驳回)+每个商家逐号OAuth/管理员授权两层缺一不可。路B=唤起SDK(小红书openSDK/快手KwaiOpenSDK):内容预填→唤起对应App→用户手动点发,合规但硬依赖原生App壳(H5/微信WebView接不了)。两条都不是现阶段该上的。
- 【平台资质门槛分三档,决定永远引导还是值得接API】①永远只引导(官方根本无代发API):小红书发笔记(开放平台只有电商/蒲公英商单,无发笔记API)、美团/大众点评团购上架(无内容发布API,只能走商家后台)、视频号(官方无发布API)。②门槛极高基本不办:抖音来客团购上架(需生活服务服务商,注册资本≥100万+保证金+城市限制)。③有规模时值得逐个评估:企微群发(ISV,但必须成员手机端手动点确认)、抖音create_video代发、快手photo/publish——都需企业资质+逐号授权,且体验路A仍要审核、路B要原生壳。
- 【个人微信是绝对红线,不分场景】微信个人号官方规范白纸黑字把"一键转发插件/外挂/自动群发"列为违规,处罚直至永久封号。这条与"AI直接操作桌面软件"(Computer Use,OSWorld成功率仅38-72%)叠加最危险——绝不能因"小豆芽能发/小龙虾能操作软件很酷"动摇。企业微信群发可做但有门槛(需ISV+成员手动确认+应用消息频率限30条/分),且只能推已纳管员工/客户,推不到陌生老板。
- 【原生壳衔接点已厘清】纯内容+一键复制+引导=零资质零原生壳,H5/微信WebView当天能做、已做。必须等原生App壳(feat/miniprogram)的能力是:小红书openSDK唤起、快手KwaiOpenSDK唤起、抖音"好体验"代发。深链/URL Scheme唤起App在微信WebView里受限,部分要靠小程序跳转或原生壳。所以"唤起App预填"这一层是原生壳上线后的增量,不是现在。

**建议(action|priority)**:

- [强化|P0] AI备平台定制内容(make_platform_content:抖音脚本/小红书笔记/快手/视频号文案,按平台调性差异化格式)+一键复制 — 已落地且方向对。这是handoff的核心抓手,零资质零原生壳、当天可用、覆盖全平台。强化点=每平台格式精修(小红书emoji+话题标签+分段、抖音口播脚本+分镜节奏、视频号克制),让"复制即可发、几乎不用改"。这是对冲对手"自动发但随时封号"的安全感卖点。
- [强化|P0] 美团/抖音团购套餐内容(make_groupbuy_content:引流款9.9-19.9定价策略+高毛利附加+标题/卖点/规则+引流钩子)+引导去商家后台上架 — 团购是台球到店引流主战场,加盟商69.9%最想要营销推广策略。官方无团购发布API(美团)/门槛极高(抖音来客需服务商≥100万注册资本),所以"真上架"永远引导老板自己后台做。我们补"选品策略+达人对接话术+转私域SOP"的操盘深度,而非只写文案。
- [不做|NA] 自研RPA/群控/指纹多开/模拟登录/Cookie代发(任何平台) — R1坐实这是小豆芽/易媒等工具的灰产底层,随时被平台风控清退(小红书2024一月清退125万账号)。我们是面向门店老板的SaaS,客户账号被封赔不起。永久红线,任何形式不碰。
- [不做|NA] 个人微信自动群发/一键转发/自动私信/外挂 — 微信个人号规范白纸黑字=永久封号红线。已是既定红线,继续严守,与桌面化"不做Computer Use"一致(AI直接操作软件最易踩此线)。

- [不做|NA] 美团/大众点评团购 真上架(API代上架) — 无内容/团购发布开放API;真上架走商家后台(开店宝);经API替商家上架需生活服务服务商(≥100万注册资本+保证金+城市限制)门槛过高。核销已有POS在接。永远只做"备文案+引导后台"。
- [保留|后续] 小红书openSDK / 快手KwaiOpenSDK 唤起App预填(内容预填→唤起→用户手动发) — 合规真发路径,但硬依赖原生App壳(H5/微信WebView接不了),与feat/miniprogram绑定。原生壳上线后才做,且仍是"用户手动点发"(我们不替发)。现在不做,留作原生壳后的体验增量。
- [保留|后续] 抖音create_video / 快手photo/publish API代发 — 技术上能真发到授权账号,但需公司主体拿企业开发者认证+公函+"代替用户发布"权限审批(可能被驳回)+每商家逐号OAuth。重投入,只在有规模/明确需求且拿到资质后逐个评估。现阶段不做。
- [保留|后续] 企业微信群发(add_msg_template)/客户朋友圈(add_moment_task)ISV接入 — 企微是唯一合规的"群发"路径(区别于个人微信红线),但需接企微ISV/自建应用+成员手机端手动点确认+应用消息频率限30条/分,且只能推已纳管员工/客户、推不到陌生老板。门槛中等,有私域规模需求时优先评估的第一个"真发"能力。现阶段不做,标为有规模后首个候选。
- [保留|P0] 对外动作审批闸(requires_approval=True→proposal模式弹确认卡片,人点头经/agent/execute才执行) — 已落地(loop.py审批闸+approval_request,make_poster走proposal)。这是"花钱/对外动作绝不自动执行"的制度保障,也是将来即便接了企微群发等真发API时"逐号授权+人确认"的执行框架。任何对外/花钱工具一律挂此闸。

**对最终形态的贡献**:对外动作的最终形态钉死为"AI备内容→人去发"的handoff,不是"自动发"。我们把每个平台(抖音/小红书/快手/视频号/朋友圈/美团团购/抖音团购)的定制内容(含选品/达人/转私域操盘深度)+配图打包到位,配一张"去哪发→粘哪→配图→话题标签→发完打钩"的发布清单引导,微信WebView里复制必校验、图片走长按保存——把"最后那一下发布"做到老板复制即发、几乎不改。所有对外/花钱动作一律走审批闸(人点头才跑)。坚决不碰自研RPA/群控/模拟登录/个人微信自动群发(封号红线),这恰是对冲对手"能自动发但随时被封"的安全感差异化卖点。"真发/真上架"分三档:官方无API的(小红书发笔记/美团团购上架/视频号)永远只引导;门槛极高的(抖音来客团购服务商)不办;有规模时才逐个评估的(企微群发ISV→首选、抖音create_video代发、快手代发)都需企业资质+逐号OAuth授权。其中小红书/快手唤起SDK、抖音好体验代发硬依赖原生App壳——这些能力必须等feat/miniprogram原生壳上线后才能做,现阶段H5/微信WebView只做零资质的"内容+一键复制+引导"。


## D3:桌面化 + 本地能力 + GUI 的最终形态裁决

**关键发现**:

- 回答用户的核心问题『它是能直接修改电脑软件的类型吗?』——明确不是。我们的桌面版是『把网站装进一个桌面窗口里』(PWA→Electron 套壳连云后端),不是 OpenClaw/Computer Use/RPA 那种『AI 自己去点你电脑上的软件、改文件、跑命令』。对台球老板,后者是错的:① 可靠性硬伤——OSWorld 基准上通用电脑操作成功率仅 38%~72%(Operator 38%、早期 Computer Use 22%、最新 Claude 4.6 才 72%),意味着 1/4~1/2 任务会失败;让 AI 自己去点美团后台/抖音发布/微信,出错就是真金白银亏钱或封号,而我们的用户是会因误操作直接亏钱的老板,不可接受。② 个人微信自动群发=封号红线,『AI 直接操作软件』最容易踩这条线。③ 门槛与支持负担——OpenClaw 要配 server/命令行/API key,23 万实例被暴露、有人花 499 代装,非技术老板根本扛不住,支持成本会爆炸。这恰好反向印证产品已定的『对外/花钱动作走审批闸、人点头才执行』是正解。
- Computer Use/RPA 路线坚决不学,但 OpenClaw 的『记忆系统工程』可借鉴一点:本地 .md 日记→分块(~400 token,80 重叠)→嵌入→向量检索→今昨常驻+旧记忆按需语义召回。这与 P2 要做的 pgvector 店脑高度同构,可作分块/检索策略参考。但我们记忆放云端 DB、人在环可看可改,比它更适合多端 SaaS——『操作路线坚决不学,记忆工程可借鉴』。
- 桌面化两步走,与战略文档第三节一致:第一步 PWA(manifest+Service Worker,Next.js 加几个文件成本≈0,自动随网站更新无签名问题,附带最大价值=Web Push 推送)→ 第二步 Electron remote-URL 套壳(win.loadURL 线上站、前端代码零改仍连云后端,electron-builder 打 .exe/.dmg)。坚决不选 Tauri 套壳——Tauri 加载远程 URL 后 native bridge(window.__TAURI__/invoke)失效已被官方 issue #5088 证实,白装 Rust。
- 『装成桌面应用』对台球老板的真实增量价值有限:核心只有桌面图标/独立窗口/常驻托盘/系统通知,不解决任何新业务能力。所以 Electron 应缓做、可选,只在确有『要安装包/要常驻托盘』信号时再上;PWA 先上、稳赚。
- Electron 签名成本不低且持续:macOS=Apple Developer Program $99/年(含 Developer ID 证书+公证);Windows OV 代码签名证书约 $215-420/年(EV 更贵),或微软 Trusted Signing 云签约 $10-100/月(比买 OV 证书更省事)。不签名会被 Gatekeeper/SmartScreen 拦、劝退非技术老板。做时务必把签名+公证并入 CI。
- 本地能力只做『轻的』三件,现有 Web 技术栈就能覆盖:① 推送通知(PWA Web Push,最高价值);② 导出到桌面(日报 Excel openpyxl 已有 + File System Access API 让用户选存储位置);③ 读本地图片做海报(已有多图直传)+ 记住上次 Logo/二维码(后端存免重传)。坚决不碰:文件系统读写、跑命令、读收银 POS 文件、Computer Use/本地 Agent——对台球不必要且违反『不重做收银系统』红线。
- 推送通道的合规现实直接制约 P4 主动出击:Web Push 在微信内置 WebView 中不可用(官方证实),且 iOS 上 Web Push 需先『添加到主屏幕』(PWA)再从主屏打开才生效——微信内打开拿不到这个通道。所以『微信里也会提醒你』不能承诺。微信生态的替代通道都不是真主动群发:服务号一次性订阅消息=每次推送都要用户先点授权、同 scene 多次授权不累积(只能发 1 条)、需认证服务号(¥300/年)+备案域名;企业微信应用消息限 30 条/分钟、群机器人需用户先发过消息;个人微信群发=封号红线。短信是唯一无平台资质捆绑的主动触达,但有签名报备+按条计费门槛,适合关键提醒(到期/重要),非日常运营推送。
- 推送产品定位必须收敛:主推渠道是『本机/桌面 PWA 通知 + 站内提醒』(该发朋友圈了/周五约台);微信内明确告知拿不到推送、引导『用浏览器/桌面版打开可开通提醒』;微信内的强价值节点(到期/重要)走『服务号一次性订阅(用户每次点授权换一条)』。这与产品 P3『只 AI 备内容+一键复制、真发靠人』的合规边界一致。

**建议(action|priority)**:

- [保留|P0] 明确产品边界:桌面版=PWA→Electron 套壳连云后端,不做 Computer Use/RPA 操作桌面软件,不做本地 Agent — 回答用户『能直接改电脑软件吗』=不是,也不该是。OSWorld 38%~72% 成功率对会因误操作亏钱/封号的台球老板不可接受;且最易踩微信群发封号红线。审批闸『人点头才执行』就是这个判断的落地。这是方向裁决,不是新功能。
- [加入|P1] PWA installable(manifest + Service Worker),Next.js 加几个文件 — 成本≈0、无签名问题、自动随网站更新,先验证老板愿不愿装桌面版;且是 Web Push 的载体。低风险高确定性,桌面化第一步。
- [加入|P1] Web Push 推送通知(仅系统浏览器/桌面 PWA 场景启用) — 台球最值钱的轻本地能力(该发朋友圈/周五约台),与 PWA 一箭双雕。但必须明确告知微信内拿不到、引导浏览器打开,定位为『本机/桌面提醒』不承诺微信内提醒。
- [强化|P1] 读本地图片做海报 + 记住上次 Logo/二维码(后端存,免重传) — 多图直传已有,补『记住 Logo/二维码』省去每次重传,是高频小痛点的轻补丁,纯 Web 技术栈,符合反过度设计。
- [加入|P2] 导出到桌面(日报 Excel 已有 + File System Access API 选存储位置) — openpyxl 导出已有,加 File System Access API 让用户选存储位置是体验提升,非新业务能力,可缓。
- [保留|P2] 借鉴 OpenClaw 记忆工程(分块~400token+近期常驻+旧记忆语义召回)到 pgvector 店脑 — 操作路线坚决不学,但记忆分块/检索策略与 P2 pgvector 店脑同构,可作参考。归属 P2 记忆建设,不是独立动作。

- [不做|NA] Tauri 套壳 — 加载远程线上站后 native bridge(window.__TAURI__/invoke)失效(官方 issue #5088 证实),白装 Rust 工具链,Electron 套壳完全覆盖其场景。
- [不做|NA] Computer Use / RPA / 本地 Agent / 读收银 POS 文件 / 跑命令 / 碰用户文件系统 — 可靠性硬伤(38%~72%)+ 最易踩微信群发封号红线 + 非技术老板门槛与支持负担爆炸(OpenClaw 23 万实例被暴露/¥499 代装)+ 违反『不重做收银系统』红线。三重否决,坚决不碰。

**对最终形态的贡献**:桌面化:产品最终形态是『一个能装到电脑桌面的运营助手窗口』,本质仍是连云后端的同一个 Web 应用——先 PWA(成本≈0、自带桌面图标+系统通知),需要『买来的软件』信任感时再 Electron remote-URL 套壳(前端零改、签名后打 .exe/.dmg),坚决不选 Tauri。它明确不是『能自己操作你电脑软件、改文件、跑命令』的那类 AI:对会因误操作亏钱/封号的台球老板,38%~72% 成功率的 Computer Use/RPA 是负资产,且最易踩微信群发封号红线;『对外/花钱动作走审批闸、人点头才执行』就是这个边界的落地。本地能力只做三件轻的——桌面/本机推送通知(该发朋友圈了)、导出到桌面、读本地图片做海报并记住 Logo/二维码——绝不碰文件系统、命令、收银 POS 文件、Computer Use。推送上,主渠道是 PWA/桌面通知+站内提醒;微信内坦诚拿不到 Web Push、引导用浏览器或桌面版开通,强价值节点(到期)走服务号一次性订阅,这一现实让 P4 主动出击的触达定位为『本机提醒为主、微信内合规补充』,而非全网主动群发。


## D4:全局功能"增/减"清单(反过度设计)

**关键发现**:

- 护城河资产已清晰：96卡技能货架(63个精修prompt模板)+审批闸+北极星eval+店脑记忆+BYOK，这五块是横向大厂(微盟/有赞/美团)结构性做不到的，全部保留并强化，不是砍。最高性价比融合动作=给Agent的write_operation_content加可选prompt_key入参，复用全部63个精修模板，覆盖度30%→接近卡片，几乎零迁移。
- 行业调研锁定真空地带：台球垂直无人做'门店运营内容层'(谈小娱/小铁/易启都是硬件IoT做C端体验)，差异化护城河=垂直深度(6岗位×场景库×行业铁律)。但落后于行业标配的几块必须补：①AI出提案→人确认→一键执行闭环(P3已规划)②智能客服/FAQ话术库③对话式问数据/经营分析④主动推荐(P4)。
- 最确定的'该加'增量是新客群专属内容(青少年/亲子招生、女性场、团建包场、职场拼台)——客单高、淡季补量、蹭中式八球奥运级IP热度，且家长'放下手机练专注力'卖点确定性极高。但实现路径应优先用门店画像加'客群标签/业态标签'让现有管道吐差异化内容，而非无脑堆卡(反过度设计)。
- 24h无人自助店是全新业态画像(无前厅无助教，重私域+短视频+自助引导)，84%美团玩乐订单增长印证风口。应在门店画像加'无人店'标识、屏蔽前厅/助教类卡、强化自助+私域内容——又一个'画像标签驱动'而非'堆卡'的例子。
- 所有'AI直接操作桌面/RPA自动发布'类功能(Computer Use/操作美团抖音后台/指纹多开/cookie代发/个人微信群发)都是'看起来酷但对台球老板有害'的诱惑功能：OSWorld成功率仅38%~72%、小红书2024一月清退125万账号、个人微信群发=白纸黑字封号红线。坚决不做，反而把'内容到位+合规引导'打磨成对台球老板的安全感差异化卖点。
- 桌面化PWA稳赚先做(成本≈0)，Electron套壳缓做(签名维护成本Mac$99/年+Win$215-420/年只在确有'安装包'需求时才值)；推送定位收敛为'本机/桌面提醒'，不承诺微信内主动推送(微信WebView无Web Push、个人号群发封号、服务号订阅消息reactive需认证)。
- 平台团购需补'操盘深度'而非只写文案：选品策略(引流款9.9-19.9/时+高毛利附加)、达人探店对接话术、短视频脚本矩阵、团购客转私域复购SOP——这是加盟商69.9%最想要的'营销推广策略'，是P3内容侧抓手。

**建议(action|priority)**:

- [加入|P4] 主动出击P4(排程引擎+门店状态监测+合规推送：淡季/节日/日报未写/本周流量低→主动弹具体行动建议) — 垂直Agent调研一致结论=向导+审批+主动推送三件套，微盟'主动推营销主题'是行业标配，我们今日推荐已有雏形。这是'被动工具→主动助理'的核心差距。但推送通道必须合规(站内/PWA通知为主，微信内只能服务号一次性订阅用于强价值节点)，且依赖P0-P2地基，故排P4。
- [加入|P0] Agent工具透传prompt_key(write_operation_content加可选prompt_key入参，复用63个精修模板) — 最高性价比融合动作：让Agent覆盖度从30%跳到接近卡片(96卡)，几乎零迁移、不碰合规配额底线。是'卡片护城河资产100%保留'落地为Agent能力的关键一步，性价比碾压一切其它增项。
- [加入|P1] 向导式输入推广('说一句话填日报'扩到活动/周报/促销：几个选项+1自由框，AI扩写) — 降非技术老板冷启动焦虑，给小店主的运营Agent主流形态。已有日报范式可复用，实现成本低、确定性高。
- [加入|P1] 客群/业态标签驱动差异化内容(门店画像加'青少年/亲子/女性/团建/职场拼台'客群标签 + '无人店'业态标签) — 新客群是最确定的增量(客单高、淡季补量、蹭中式八球IP热)，无人店是新业态风口。关键：用画像标签让现有管道吐差异化内容，而非无脑堆卡——既补内容又守反过度设计(三个相似卡能合并就别过早抽象)。
- [强化|P3] 平台团购操盘深度(选品策略+达人探店对接话术+短视频脚本矩阵+团购客转私域SOP) — 加盟商69.9%最想要的就是营销推广策略；现有团购只停在写文案，要补到操盘建议。是P3对外平台路线的内容侧抓手，对冲对手'能自动发但随时封号'的脆弱卖点。
- [加入|P2] 智能客服/FAQ话术库(客户常见问题一键回复，非自动应答) — 美团方言前台、SCRM自动应答已是行业标配，不补显落后。但只做'话术库+一键复制回复'文字层，不碰自动应答/自动分发(那是企微生态特权+越界)。
- [强化|P2] 对话式问数据/经营分析(诊断/日报做成对话式问答) — 美团袋鼠参谋、有赞五大类型都含'问数据'，是行业标配。我们日报/诊断有基础，做成对话式即可，不新增系统，符合'只读数字写判断'边界。
- [加入|P2] 赛事全流程编排(周/月/会员赛+赛季制衔接官方大赛+看世运会等看球活动) — 中式八球已是奥运级IP(2025世运会Heyball)，门店运营内容应能蹭官方大赛热度。'看球活动'和'赛季制衔接'是现有场景明显空白，确定性高。优先在现有卡片/工具基础上补，不另起复杂状态机。
- [加入|后续] 自定义工作流(店主把常用复合操作如'每周一:拉新裂变+活动预告+日报'存成私有工作流) — 垂直Agent演进方向、卡片的进化、沉淀私有经验=留存钩子。但属锦上添花，依赖Agent成熟后才有意义，且要防过度设计成'工作流编辑器'，故排后续。
- [强化|P2] 店脑显性化(店脑页显示'AI已学N条经营习惯、识别到高峰时段/主力客群') — '越用越懂'显性化增强留存，店脑记忆已是护城河，只需在已有store-brain页加展示层，成本低价值实。
- [加入|P4] 客户分层维护提醒('某客户7天没来→提醒约台话术'，文字层提醒+模板) — 客户分级(ABCD/6类标签)知识库已有，提醒是文字层可做的轻补丁。但需配合P4主动层和数据来源(从日报/POS只读取)，故随P4落地。只做提醒+话术，不做CRM系统。
- [加入|P3] 排班/对账/采购轻工具(排班通知模板、耗材采购清单、月度对账复盘话术、设备维护提醒) — 店长真实日常职责，数字归POS但'模板/话术/提醒'是文字层可做的轻补丁。铁律:不做库存/排班系统，只做提醒和模板，符合反过度设计。
- [保留|P3] 跨平台发布handoff(make_platform_content/make_groupbuy:AI备平台定制内容+一键复制/唤起App，人工发) — 已做完且真机验证。这是对冲'小豆芽能自动发但随时封号'的合规体验差异化卖点，对台球老板讲安全感。坚持只备内容+引导，绝不做RPA代发。
- [加入|P3] 企微群发(合规:门店用企业微信→走官方add_msg_template，成员手机端手动确认才发) — 企微官方API本身就是human-in-the-loop设计，合规。但需企微ISV授权+门店实际用企微才有意义，门槛使其只对部分门店适用，作P3可选项，不强推。
- [保留|P0] 96卡技能货架(63个精修prompt模板) — 产品真护城河资产、Agent的工具库+快捷入口+新手货架。卡片与Agent是入口层两种范式不是替代，service层共享同一管道。100%保留，定位重排为'技能货架+快捷入口'。
- [保留|P0] 审批闸(对外/花钱动作弹确认人点头才执行，proposal模式) — P3对外+生图花钱的安全前提，也正好印证'AI直接操作桌面成功率仅38-72%'下'人确认才执行'是正解。台球老板会因误操作直接亏钱/封号，审批闸不可削弱。
- [保留|P0] 北极星eval体系(3门店×80场景×31谓词+LLM裁判，GREEN率97.5%) — 改prompt/换模型前后跑、盯GREEN率的可重复验证基建，是'防御强'的根基。换GLM大脑A/B必须靠它量化，绝不能砍。
- [强化|P1] BYOK(门店自带大模型key，自担成本/并发，Fernet加密) — 头部因有交易流水补贴AI成本、不做BYOK，对我们是独有轻资产打法=优势。继续押。强化点:CC Switch借鉴(厂商预设卡片网格只填key/动态拉模型列表/测速)，让非技术老板配得动。
- [强化|P2] 店脑记忆(pgvector语义召回升级+情景记忆+对话滚动总结) — '越用越懂这家店'是垂直深度护城河。OpenClaw记忆工程可借鉴(分块~400token/近期常驻/旧记忆语义召回)，但放云端DB+人在环可看可改，比它更适合多端SaaS。零新增基础设施(PG14已在)。
- [加入|P1] PWA(installable+Service Worker+桌面图标+Web Push本机推送) — 成本≈0、低风险高确定性，先验证老板愿不愿装桌面版，附带最值钱的本地能力(运营提醒推送)。前端加几个文件即可。
- [加入|后续] Electron remote-URL套壳(连云后端前端零改，给安装包信任感) — 方向正确(loadURL线上站)，但'装成桌面应用'对台球老板真实增量有限(只图标/常驻/通知)，签名维护成本(Mac$99/年+Win$215-420/年+CI公证)只在确有'要安装包'需求时才值。缓做、可选。
- [不做|NA] Tauri套壳 — Tauri加载远程线上站后native bridge失效(官方issue坐实)，白装Rust工具链。要套壳选Electron。
- [不做|NA] Computer Use / AI直接操作桌面软件 / 截图视觉点击(操作美团抖音后台、点软件) — 诱惑功能(看起来酷但有害):OSWorld通用电脑任务成功率仅38-72%，台球老板会因误操作直接亏钱/封号，不可接受。也正好印证'对外动作走审批闸人点头'才是正解。门槛+支持负担(OpenClaw要配server/命令行/API key、23万实例被暴露)会爆炸。
- [不做|NA] RPA自动发布/指纹多开/cookie代发/模拟登录(对标小豆芽/易媒助手一键多平台发) — 诱惑功能:那是别人随时被封的灰产盘子(小红书2024一月清退125万账号)。我们面向门店老板的SaaS，赔不起把客户账号搞封。坚持'AI备内容+一键复制/引导'的合规路径，反而是差异化安全感卖点。
- [不做|NA] 个人微信自动群发/自动私信/一键转发 — 白纸黑字封号红线(《微信个人帐号使用规范》1.2.6，处罚直至永久封号)。已是既定红线，任何第三方自动化工具都踩线，绝不因'酷'动摇。
- [不做|NA] 收银/计费/开台/灯控/库存/会员充值/一卡通余额/上钟计时系统 — 美萍/茗匠/乐馆+这类POS的硬地盘，我们只'读数字写判断'不碰控制。这是产品定位边界铁律，越界=与成熟POS正面竞争且偏离'内容/运营赋能'护城河。
- [不做|NA] 可视化Prompt编辑器 / 海报拖拽编辑器 — CLAUDE.md明确不做。台球老板不需要、维护成本高、偏离'说句话事就办'的Agent形态。Prompt改YAML即可，海报走AI生图+引导。
- [不做|NA] 多Agent框架/子代理/tool-search/hooks插件框架/复杂状态机(CrewAI/AutoGen/LangGraph) — 单领域、工具可控，自研轻量白盒ReAct循环最省、最稳、易调试。多Agent对单领域是过度设计(AutoGen已进维护模式)，复杂状态机留给未来真有需求时。反过度设计:三个相似行>一个过早抽象。
- [不做|NA] 硬件/电子裁判/进球自动剪辑/无人化IoT(对标谈小娱/小铁/易启) — 壁垒高且烧钱，与'不做收银计费灯控'红线一致。这些垂直硬件玩家做台子上C端体验、我们做老板手里运营大脑，是错位互补不是对手，可考虑成为其'运营内容层'合作方。
- [不做|NA] 读本地用户文件系统/跑命令/MCP给到用户端 — 台球老板没那个心智模型，搬过去只有误操作风险+支持负担。本地能力只做轻的(推送通知/导出到桌面/读本地图片做海报)，坚决不碰文件系统不跑命令。
- [不做|NA] 国际化 / 微服务 — CLAUDE.md明确不做。单体应用够用，面向中国台球房无国际化需求，纯过度设计。

**对最终形态的贡献**:最终产品形态在功能取舍上应是"垂直深、边界清、不越界、不堆功能"的台球房运营Agent：① 入口三层并存——96卡技能货架(新手发现+确定性入口)/对话管家(老手一句话)/今日推荐+主动出击(主动层)，service层共享同一run_generation管道；② 能力增量全部落在'内容/话术/策划/判断'文字层，且优先用门店画像的'客群标签(青少年/亲子/女性/团建/职场拼台)+业态标签(无人店)'驱动差异化，而非无脑堆卡——新客群内容、赛事全流程、平台团购操盘深度、智能客服话术库、对话式问数据是确定性增项；③ 五块护城河(96卡精修模板/审批闸/北极星eval/店脑pgvector记忆/BYOK)保留并强化，BYOK是头部结构性不做的轻资产优势；④ 对外动作永远是'AI备好平台定制内容+一键复制/唤起App+审批闸'，把'内容到位+合规引导'打磨成对冲灰产工具'随时封号'脆弱性的安全感卖点；⑤ 桌面化PWA先上(成本≈0、带本机推送)、Electron套壳缓做、Tauri不选；⑥ 一切'AI直接操作桌面/RPA代发/个人微信群发/Computer Use/收银计费灯控/可视化编辑器/多Agent框架'坚决砍掉——它们看起来酷，但对会因误操作直接亏钱/封号的台球老板只有害处、支持负担和越界，是最该警惕的诱惑功能。一句话:把垂直行业Know-how焊进prompt和工作流做到极致，守住POS只读不控与封号红线两条边界，反过度设计贯穿始终。


## D5: 什么才算台球门店"实用性很好的智能体" + 商业竞争力/留存

**关键发现**:

- 【北极星可操作化定义】一个'实用性很好的台球门店Agent'应同时满足5条可检验标准:①一句话办成(不懂运营的老板说'明天周五客少帮我搞个活动',Agent自主选玩法→出文案+海报+群公告,办到'就差点头发布'那一步,人不需要懂运营术语);②办到差点头发布(对外/花钱动作停在审批卡片,一键复制到对应平台,真发靠人——这恰是合规护城河而非缺陷);③越用越懂这家店(店脑记住价格/客群/助教/历史活动效果,下次自动套用,店脑页可见'已学N条');④对的时机推对的动作(淡季/节日/日报没写/周末上钟低→主动弹具体行动,不是等人来问);⑤覆盖一线不只老板(店长/教练/助教管理/前厅都有日活入口,不是老板一个人的玩具)。当前GREEN率97.5%证明'内容到位'这条已达标,瓶颈在④主动层(P4未启动)和⑤一线日活(助教/前厅是被代写,本人非直接用户)。
- 【护城河:押垂直Know-how+合规审批,不押技术】R4竞品调研铁证:微盟WAI(15Agent/58场景/40万商户)、有赞、美团袋鼠参谋全是横向通用(覆盖零售/餐饮/美业几十行业),为覆盖广必须做浅;台球/棋牌线下娱乐垂直只有硬件IoT玩家(谈小娱/小铁),'懂台球房岗位+运营动作的内容/决策Agent'是真空。我们能把行业铁律(一卡通/助教提成/PK机制/台呢维护/助教不擦边)焊进prompt和工作流——这是横向大厂结构性做不到的成本壁垒。北极星eval(3门店×80场景×97.5%GREEN)是把'懂台球'变成可量化可防回退的工程能力,这本身是第二层壁垒。
- 【护城河第二支柱:BYOK是我们独有的轻资产打法】R4调研:微盟/有赞/美团把AI捆进既有SaaS订阅当免费钩子,因为它们有交易流水能补贴AI成本;BYOK在头部未见。我们没有交易闭环,BYOK(门店自带key自担成本/并发)反而把'平台零token成本'变成结构性优势——头部不做、对我们是优势,继续押。但BYOK也是把双刃剑:配置门槛会劝退老板,必须用CC Switch式厂商卡片网格(选厂商自动填base_url,老板只填key)把门槛压到最低。
- 【'装上就离不开'的钩子=店脑记忆+主动推送+日报闭环】店脑记忆是最强留存钩子:迁走=丢掉AI对这家店的全部认知(价格/客群/活动效果/助教档案),沉没成本随使用线性增长,这是通用Agent给不了的。其次是运营日报自动化(已上线4张岗位日报)——一旦店长养成'每天说一句话出日报'的习惯,日报数据又反哺店脑,形成飞轮。主动推送(P4)是把'被动工具'变'主动助理'的最后一跃,装上后'到点提醒该发朋友圈/周五约台'让产品常驻心智。
- 【一线员工日活是最大短板】现状:96卡里助教管理15卡、前厅21卡、教练20卡,但'助教本人'不是直接用户——是'助教管理'岗代写。R5调研:助教是台球房最大营收增量(计费50-200/时),前厅承担收银/咨询/台呢维护/客户加微。要让一线成日活,不能让他们学Agent对话,而要给'极轻的固定入口':助教=今日约客话术/朋友圈推广文案/服务SOP速查(死守不擦边);前厅=客户常见问题一键回复话术库/排班通知模板/台呢维护提醒。让一线用'卡片货架'(零学习),老板/店长用'对话+主动推送'。
- 【行业标配缺口=智能客服/对话式问数据】R4调研:美团方言24h智能前台、SCRM自动应答已是门店运营AI标配;美团袋鼠参谋、有赞都含'对话式问数据'。我们日报/诊断有基础但未做成对话问答,客服话术库未成型。这两块不补会显得落后于横向大厂——但要守边界:智能客服只做'话术库+一键回复内容',不碰自动应答接管(那会踩个人微信红线);问数据只读POS数字写判断,不碰收银。
- 【新客群/新业态内容空白=高确定性增量】R5调研+架构评估第六点一致指出:女性场/亲子青少年招生/团建包场/24h无人店是结构性空白。中式八球已是奥运级IP(2025世运会),青少年培训报名翻倍,加盟商69.9%最想要'营销推广策略'。补法不是无脑堆卡——优先用门店画像加'客群标签/业态标签'(无人店/有助教/亲子主打)让现有管道吐差异化内容,符合反过度设计。
- 【绝不被'小豆芽能一键发'动摇】R4调研坐实:小豆芽/易媒等一键多平台发布全是RPA/指纹多开/cookie代发的灰产盘子(小红书2024一个月清退125万账号),个人微信一键转发=官方明令永久封号。我们是面向门店老板的SaaS,赔不起把客户账号搞封。坚持'AI备好平台定制内容+一键复制/引导手动发',把'内容到位+合规安全感'打造成对台球老板可讲的差异化卖点,对冲对手'能自动发但随时封号'的脆弱。

**建议(action|priority)**:
