# 外部查证(5路)· 完整结果


## R1. 一键多平台发布工具(小豆芽/易媒助手等)的技术真相:官方资质 vs 自研RPA

**总结论**:二选一的答案是:绝大多数是『自研(浏览器自动化/RPA/指纹多开/模拟登录)』,不是平台官方接口授权。小豆芽、易媒助手这类靠的是『多账号管理面板+指纹浏览器+Playwright类脚本模拟真人发布』,本质是规避风控的反检测自动化;抖音/快手虽有官方代发API但门槛高(企业资质+代发权限审批+OAuth),这类轻量工具基本不走;小红书根本没有官方发笔记API;微信个人号一键转发被官方规范明令禁止、直至永久封号。所以它们活在『灰色地带』:能用但随时可能被平台风控清退(小红书2024一个月清退125万账号即证)。

**对我们的含义**:这恰好印证我们P3路线的正确性,不要被『小豆芽能一键发,我们为什么不能』动摇:1)坚持只做『AI备好平台定制内容+一键复制/引导老板去App手动发』,绝不做RPA模拟登录/指纹多开/cookie代发——那是别人随时被封的灰产盘子,我们是面向门店老板的SaaS,赔不起把客户账号搞封;2)个人微信自动群发/一键转发=官方白纸黑字封号红线(规范1.2.9),已是我们既定红线,继续严守;3)真要做『替商家真发』,唯一合规路径是走官方API+企业资质+商家OAuth逐号授权,且小红书/快手唤起SDK还需原生App壳(与feat/miniprogram绑定)——这是重投入,只在有规模/明确需求且我们拿到资质后逐个评估,现阶段不做;4)可把『一键复制到各平台+格式适配』打磨到极致(已做的make_platform_content方向对),用'内容到位+引导'的合规体验,对冲对手'能自动发但随时封号'的脆弱卖点——这反而是我们对台球房老板可讲的安全感差异化卖点。

## R2. 能"直接操作电脑软件+带记忆"的桌面AI(OpenClaw/小龙虾及同类路线)调研,及其对台球房Agent的启示

**总结论**:用户说的是 OpenClaw(小龙虾,名字记错一字母),它是开源的\"个人电脑操作层\"AI Agent——自主调工具/写脚本/读写文件操作电脑,\"记忆\"是本地markdown日记+向量检索(非模型真记忆);技术路线属\"AI直接操作桌面\"大类,与Anthropic Computer Use/OpenAI Operator(截图视觉点击)、字节UI-TARS(纯视觉GUI)、RPA+LLM(可控流程)同族。但这条路线当前可靠性不足(通用桌面任务成功率仅约38%~72%)、对非技术用户门槛高、安全风险大。

**对我们的含义**:初判:我们不该走\"AI直接操作桌面软件\"这条路线,继续坚持已定的轻桌面方向(PWA→Electron套壳连云后端,本地只做推送/导出/读本地图片,不碰文件系统、不跑命令、不做Computer Use)是对的,理由有三:①可靠性硬伤——OSWorld上通用电脑操作成功率仅38%~72%,让AI自己去点美团后台/抖音发布/微信会大概率出错,而我们用户是会因误操作直接亏钱/封号的台球房老板,不可接受;这也正好印证产品已定的\"对外/花钱动作走审批闸、人点头才执行\"是正解。②个人微信自动群发=封号红线已被我们明确禁止,\"AI直接操作软件\"恰恰最容易踩这条线,绝不能因为\"小龙虾能操作软件很酷\"而动摇。③门槛与支持负担——OpenClaw要配server/命令行/API key、23万实例被暴露、有人花499代装,非技术老板根本扛不住,支持成本会爆炸。可借鉴的只有一点:OpenClaw的\"记忆系统\"思路(本地markdown日记+分块嵌入+向量检索+今昨常驻/更早按需检索)与我们P2要做的pgvector店脑高度同构,可作为店脑分块/检索策略的参考(分块~400token、近期记忆常驻、旧记忆语义召回);但我们的记忆放云端DB、人在环可看可改,比它更适合多端SaaS。一句话:操作路线坚决不学,记忆工程可借鉴。

## R3. 面向非技术台球门店主的桌面AI形态选型(技术路线+签名成本+推送通道)

**总结论**:维持已定方向:第一步PWA(installable+Service Worker,成本≈0),需要"安装包信任感"时再上Electron remote-URL套壳(loadURL线上站、前端零改连云后端);坚决不选Tauri套壳(加载远程站后native bridge确实失效,白装Rust)。但"装成桌面应用"对台球老板的真实增量价值有限(主要是图标/常驻/系统通知),Electron的签名+维护成本(Mac $99/年公证 + Windows OV证书约$215-420/年 + 每次CI打包公证)只在确有需求时才值得——所以Electron应缓做、可选;PWA先上、稳赚。

**对我们的含义**:先做(本期):1) PWA installable(manifest+Service Worker),Next.js加几个文件、成本≈0,先验证老板愿不愿装桌面版——这是低风险高确定性的一步。2) Web Push只在'系统浏览器/桌面PWA'场景启用,明确告知微信内拿不到推送,在微信内引导'用浏览器打开可开通提醒'。3) 推送的产品定位收敛为'本机/桌面提醒'(该发朋友圈了/周五约台),不要承诺'微信里也会提醒你'。\n\n缓做(看信号再上):4) Electron remote-URL套壳——只有当出现明确的'要安装包/要常驻托盘'需求时再做;做时务必走签名(Mac $99/年公证 + Windows优先评估微软Trusted Signing云签$10-100/月,比买OV证书更省事),并把签名+公证并入CI,否则Gatekeeper/SmartScreen会劝退非技术老板。前端零改、连云后端的套壳路线本身正确。\n\n不要做:5) 不选Tauri套壳(远程站native bridge失效,已被官方issue证实);6) 不要把'微信内主动推送'当成可行的运营触达——服务号订阅消息是reactive单次、要认证(300元/年)+备案域名,企业微信只能推已纳管的员工/客户、不能推陌生老板,个人微信群发是封号红线。真要在微信内提醒,最现实的是'服务号一次性订阅(用户每次点授权换一条)'用于强价值节点(如到期/重要提醒),日常运营提醒仍靠站内/PWA通知。这与产品P3'只AI备内容+一键复制、真发靠人'的边界一致。


**要点证据**:

- [官方] Tauri套壳加载远程线上站后,native bridge(window.__TAURI__/invoke)确实不可用——项目文档的说法成立
  - 证据:Tauri官方issue #5088(2022起的feature request,至今未实装)记录维护者立场:'目前基本无法让外部网站直接与Tauri通信';invoke从iframe已不可用(仅Windows同源例外);把native命令权限开放给任意远程URL是被强烈劝阻的(RCE/数据泄露风险)。结论:Tauri为'本地打包前端'设计,套壳远程站会丢掉它唯一的卖点(轻量+native能力)。CC Switch用Tauri是因为它是原生本地应用,不是套壳现有网页,场景不同。

## R5. 台球/线下娱乐门店真实运营痛点与数字化现状(R5调研)——补全台球门店使用者场景全集

**总结论**:台球门店运营场景全集 = 5 大经营层 × 岗位:(1)流量层「平台拓客」(美团/抖音团购选品·探店达人·短视频矩阵)+「私域转化」(加微/进群/拼台搭子/复购);(2)产品层「台费基本盘」(空台促活·淡旺季·散客留存)+「助教钟数」(推广/约客/转化,擦边红线)+「教练带训」(青少年/成人课时/赛事)+「商品费」(酒水零食小推车);(3)赛事IP层(周/月/会员赛·抢一·中式八球体系·看球·亲子团建女性新客群);(4)团队层(日报/排班/招聘/培训/PK/绩效);(5)经营决策层(对账诊断/投资回报/竞对应对)。我们Agent的边界=只做「内容/话术/策划/判断」文字层,POS(开台计费/灯控/收银/一卡通余额/上钟计时/库存对账数字)是收银系统的事,我们只读不控。当前96卡已覆盖该骨架约85%,主要缺口在:平台团购选品与达人对接的「操盘」深度、青少年/亲子/团建/女性新客群专属内容、24h无人店这一新业态形态、采购对账/排班/库存这类管理动作(部分属POS边界但「话术/模板/提醒」可做)。

**对我们的含义**:边界(必须守住,别做):开台/计时/计费/灯控/收银/一卡通余额/上钟计时/库存盘点数字——全是美萍/茗匠/乐馆+这类POS的硬地盘,我们只'读数字写判断',Agent绝不碰控制。助教内容死守'专业陪练不擦边',这是行业法律红线也是我们的品牌护城河,任何放松都是踩雷。\n\n最可能漏掉的【客群】(优先补):①青少年/亲子培训招生——暑期/考级招生文案、家长沟通话术(讲'放下手机练专注力'卖点)、亲子体验活动,对应世运会/中式八球青少年热,是高确定性增量;②女性场/女生友好——女性客群崛起,需非擦边的'女生场/闺蜜局'内容;③团建/企业包场——团建活动策划+企业对接话术+包场套餐文案,客单高、淡季补量利器;④职场拼台/搭子——写字楼/社区店的碎片化拼台社交内容。\n\n最可能漏掉的【业态/岗位】:①24h无人自助店——这是全新画像:无前厅无助教,运营重心=小程序自助引导/扫码进店话术/异常远程处理提醒/纯私域+短视频拉新,建议在门店画像加'无人店'标识、屏蔽前厅/助教类卡、强化自助+私域内容;②采购/排班/对账这类店长管理动作——数字归POS,但'排班通知模板、耗材采购清单、月度对账复盘话术、设备维护提醒'是文字层可做的轻补丁,符合反过度设计(不做库存系统,只做提醒和模板)。\n\n最可能漏掉的【操盘深度】:平台团购不能只停在'写文案',要补'团购选品策略(引流款9.9-19.9/时+高毛利附加)、达人探店对接话术、抖音/美团短视频脚本矩阵、团购客转私域复购SOP'的操盘建议——这正是P3对外平台路线的内容侧抓手,且加盟商69.9%最想要的就是'营销推广策略'。\n\n赛事IP衔接:中式八球已是奥运级IP(2025世运会Heyball),门店运营内容应能'蹭官方大赛热度'(看世运会/大师赛活动、门店赛季制衔接官方赛事、冠军/晋级宣传),建议把'看球活动'(现标缺模板)和'赛季制衔接'补上。\n\n不要做:不做收银/计费/灯控/库存/会员充值系统;不做自动群发;助教擦边内容一律不碰。新增场景一律走'内容/话术/策划/提醒'文字层,三个相似卡能合并就别为新客群过早抽象出一堆卡——优先用门店画像加'客群标签/业态标签'让现有管道吐差异化内容,而非无脑堆卡。
