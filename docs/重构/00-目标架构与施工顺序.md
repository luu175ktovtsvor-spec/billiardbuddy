# 当前架构与后续顺序

## 已确定的产品边界

BilliardBuddy 只有一个 Agent 后端：随桌面包分发的 OpenAI Codex Rust `codex-app-server`。同 revision 的 `codex-code-mode-host` 只是 Core 的配套 companion，不是第二个 Agent。Rust Core 拥有 Agent Loop、Thread/Turn/Item、上下文压缩、工具、沙箱、审批、MCP、Skills、Hooks、插件、本地协作与恢复。

```text
Renderer（当前为空，后续重建）
  -> Electron Main
      -> codex-app-server（Rust）
          -> codex-code-mode-host（按 Core feature gate）
      -> 本地图片 / 视频 Sidecar

codex-app-server
  -> 托管 DeepSeek：本机代理 -> Gateway /v1/responses
  -> 个人 Responses：本机代理 -> 用户 endpoint
  -> 个人 Chat：本机转换器 -> 用户 endpoint
```

Electron Main 不是第二个 Agent：它只管理窗口、受信 IPC、安全存储、App Server 生命周期，以及原生 JSON-RPC 的转发。Gateway 不是 Agent 服务：它只处理托管模型的身份、额度、用量、路由和 SSE。图片、视频 Sidecar 也不持有 Agent 状态。

## 当前状态

- 旧 React Renderer、旧 TypeScript Agent Engine/Worker、旧 ProductTask/Run 账本和旧 Agent HTTP/WS 路径已退出正式运行路径。
- `ts/desktop/src` 保留空 Renderer 入口，供后续新前端使用；它不是遗留前端。
- Codex Rust 源码锁定在 `third_party/codex-engine`，并经构建、补丁和协议校验后随桌面包发布。
- 图片、视频仍是 BilliardBuddy 自研领域服务；这不是旧 Agent 代码。语音不在当前产品范围。

## 后续建设顺序

1. 先在本地完成锁定源码、协议、Electron/Gateway、App Server/Code Mode Host staging、本地插件、打包审计和旧代码边界的总检查。
2. 本地门禁全部通过后，只推送一次收口提交并运行 macOS/Windows 构建；失败时只修真实的平台构建或打包问题，不改 Codex 原生 Agent 语义。
3. 以真实桌面旅程验证原生 Thread、Turn、工具、审批、恢复，以及托管与个人模型两条协议路径。
4. 重建前端：只消费 Rust App Server 的 Thread/Turn/Item/通知和媒体领域 API；不引入自己的 Agent 状态机。
5. 分别完善图片、视频工作台，再做安装、升级和签名发行验证。

每个模块单独提交、单独验证。源码存在或单个平台构建成功都不等于用户旅程完成。
