# 模型与远程能力平台

本文只定义用户可见路线和服务边界；模型目录、物理账号准入、产品额度和密钥归属的权威契约见 [模型资源治理分层](./模型资源治理分层.md)。四层必须分开：目录只描述能力，capacity policy 只保护 Provider 账号，quota policy 只管产品权益，credential store 只存所属进程的密钥。

## 三条模型路线，一个 Agent

```text
Codex Rust Core（只发送 Responses）
  -> 托管模型：本机凭据代理 -> Gateway /v1/responses -> DeepSeek
  -> 用户 Responses：本机凭据代理 -> 用户 /v1/responses
  -> 用户 Chat：本机转换器 -> 用户 /v1/chat/completions
```

三条路线最终都服务同一个 Codex Thread/Turn。Gateway 不保存 Agent 会话；Chat 转换器也没有任何会话或执行状态。

## 托管模型

Gateway 是薄模型网关：安装鉴权、额度、用量、物理账号准入、幂等和 SSE 转发。托管文本入口为 `/v1/responses`；图片建议使用独立 `image_advice` workload。付费图片生成不再经 Gateway 转发；Gateway 只通过私网 `/internal/v1/auth/introspect` 为两个 Relay 验证短生命周期安装身份。它不提供 Agent Chat API，不保存 Agent 或图片 Project/Candidate/Canvas 事实，也不托管模型权重。

图片生成固定走：`Image Sidecar → https://zzyppz.cn/image-generation/v1/images/tasks → Image Relay → GPT Image 2 / Seedream 4.5`。Sidecar 只携带 Electron Main 注入的短生命周期安装 bearer；Image Relay 使用独立 service credential 回查 Gateway，并只信任内省得到的 owner。桌面端不获得 service credential 或 Provider key。Relay 结果只有在 Sidecar 将验证后的字节、CAS、Candidate Group 与 Operation 事务提交后才 ACK；ACK 失败只重试 ACK，不重新发起付费请求。

视频不经 Gateway 中转媒体：`Video Sidecar → Video Media Relay → 北京 OSS / DashScope`。Video Media Relay 只用 Compose 私网调用 Gateway `/internal/v1/auth/introspect` 验证安装身份；Gateway 不转发视频字节、OSS、长 ASR 或 Provider 结果。Image Relay 与 Video Media Relay 拥有不同凭据、容量池、额度桶和结果协议。

图片理解与非阻断视觉评估固定走：`Sidecar → Gateway /v1/image/reasoning → Qwen3-VL-Flash`。它不得覆盖通用 MiMo `/v1/media/reasoning` 或 `/v1/visual/evidence`。请求和返回均使用版本化严格 schema，并受图片数、输入字节、输出字段/数组/文本长度与超时限制。Gateway 只保存服务端 Qwen 凭据、鉴权、独立容量/额度与可重放 operation result；不保存图片 Project/Candidate/Canvas。Qwen 只产生带 receipt/confidence 的建议，不能改变 Candidate、Version 或工作指针，确定性 Release Check 仍是发布门禁。

## 视频远程分析是独立路径

视频 Sidecar 仅在项目已记录 `RemoteAnalysisConsent` 和预算 reservation 后，调用独立的 Video Media Relay。Relay 使用 Gateway 的私网只读内省确认安装会话，但不复制 Gateway 的签名 key、会话库或用户表；它持有北京地域的 Provider 凭据与临时对象租约，按 `VisualEvidence`、`MediaReasoning`、`SpeechTranscription` 和 `SemanticEmbedding` 执行 Qwen、Fun-ASR 与 `text-embedding-v4`。

Gateway 不接收新视频媒体上传、不代理视频 ASR/embedding、不保存 Video Media Relay receipt。图片 Relay、既有产品语音和 Agent 文本路径保持原有所有权。Video Sidecar 是 Project、Timeline、Consent、项目预算和本地 Operation/Event 的唯一 writer；Relay 只保存请求幂等、账户额度、上游 task/usage receipt 和短期对象租约。

## 用户自填 Key

个人 Provider 配置由 Electron Main 保存到系统安全存储。产品提供主流厂商和 Coding Plan 的预设：官网申请 Key 链接、文档链接、默认 endpoint、认证方式和支持协议。对支持 OpenAI-compatible `/models` 的厂商，可在用户临时输入 Key 后发现模型名；Key 不跟随重定向，不因发现请求保存，也不会由模型列表推断上下文窗口或最大输出。

预设只降低填写成本，不代表厂商保证任意模型都与 Codex 所需的 Responses/工具/SSE 语义兼容。用户选择 Responses 时走直通代理；选择 Chat 时才启用无状态转换。没有第三条 Messages/Anthropic 适配路线。

## 不做的事

不要求用户填写 token 窗口、最大输出、压缩阈值或模型能力表。Codex 原生上下文管理与压缩机制不被产品覆写。也不向 Gateway 上传个人 Key，不把个人模型变成平台额度，也不为模型请求建立额外的 Agent 重试/缓存/会话层。
