# 视频工作台

## 用户结果

用户创建视频作品项目，导入真实素材，看到可追溯的文件信息、视觉证据和转写；据此选择并调整方案，在可操作时间线编辑片段，生成可取消、可恢复的预览与最终渲染，保存版本并导出经过校验的视频。

交互研究 OpenShot 等成熟桌面剪辑工具的素材库、时间线、播放头、裁切、预览、渲染和导出，不复制其代码或品牌。BilliardBuddy 的优势是把素材理解和门店创作目标接入上述确定性媒体链路。

## 源码参考与适配边界

本模块研究 [OpenShot Qt 应用](https://github.com/OpenShot/openshot-qt/tree/9cd2b3f3ee9024c3496487a2de30a402515ed659) 的项目数据、时间线、预览 worker 和渲染分离；它是 GPL-3.0-or-later。固定只读参考已放在本机 `openshot-reference/`，HEAD 必须为 `9cd2b3f3ee9024c3496487a2de30a402515ed659`；它被 `.gitignore` 排除，不进入产品构建、运行时或提交。其 [libopenshot](https://github.com/OpenShot/libopenshot) 为 LGPL-3.0-or-later，并有独立商业授权选择。两者都只能作为结构和用户旅程参考：不得复制 Qt 应用代码、界面、预设、资源或品牌；若将来考虑接入 libopenshot，必须先单独完成许可证与桌面打包审计。

可学习的是项目事实与播放器分离、时间线快照提交给预览器、预览独立停止/seek/缓存生命周期、以及从固定项目快照创建独立渲染实例。不能照搬的是可变项目 JSON 加 undo/redo 的实现：BilliardBuddy 还必须为每次渲染保存不可变时间线版本、源指纹、操作终态和重启恢复判断。

## 领域边界

视频项目拥有：原始素材及指纹、探测元数据、转写和视觉证据、创作方案、场景选择、时间线、预览、渲染任务、时间线版本和导出验证。FFmpeg/ffprobe 或等价本机媒体工具拥有真实媒体处理；模型只提供带来源的理解和建议。

正式对象至少分为 `VideoProject`、`VideoSource`、`VideoEvidence`/`TranscriptEvidence`、`VideoEditPlan`、`VideoTimelineVersion`、`VideoOperation`、`VideoPreviewAsset`、`VideoExportArtifact` 和 `VideoEvent`。证据产生剪辑建议，剪辑建议生成可编辑时间线版本，预览/渲染只消费固定版本；模型建议绝不能直接成为媒体事实或导出结果。

视频项目不共享图片的画布/候选状态，也不把 Agent 对话、模型文字或脚本当作视频输出。Renderer 不拥有时间线真相，服务器的版本记录才是可恢复编辑基础。

## 正式链路

```text
导入素材 -> 指纹、时长、轨道和元数据探测
  -> 转写/视觉证据/方案（均保留来源）
  -> 场景选择与可编辑时间线版本
  -> 本机预览或渲染持久任务
  -> 文件、媒体元数据和 hash 校验后的导出
```

预览和渲染使用独立任务记录、进度事件、取消语义和恢复判定。执行进程退出不等于成功；任务须以存在且通过验证的输出文件或明确失败/需要恢复终态结束。

## 完成范围

1. 素材导入、来源记录、指纹、时长、轨道与损坏文件错误；
2. 视觉证据和语音转写，且每个结论可追溯到对应素材；
3. 场景方案、锁定、替换和来源明确的调整；
4. 拖动、裁切、排列、播放头、预览和可编辑时间线；
5. 时间线版本的保存、比较、回滚和恢复；
6. 持久预览、渲染、进度、取消和重启后恢复；
7. 导出文件、媒体元数据和 hash 的验证。

## 重构要求

视频领域从泛媒体服务中拆出独立服务、持久仓库、媒体执行器和 API；它可复用共享资产、操作生命周期和诊断，不得与图片共用项目状态机。先保持用户现有素材可迁移，确认正式消费者已切换后删除旧路径。

### 当前代码到正式模块的迁移

当前 `mediaProjectService.ts` 同时保存视频项目、图片项目、两类任务、事件、预览资产和删除回收。视频的新正式路径固定为下表；这是状态归属，而不是把现有类名原封不动搬家：

| 现有职责 | 正式归属 | 切换条件 |
| --- | --- | --- |
| 视频项目、素材证据、场景、时间线和版本 | `VideoWorkbenchService` + `VideoWorkbenchRepository` | 视频项目读写不再经过图片类型、图片锁或泛媒体项目目录 |
| 素材探测、分析、预览和渲染操作 | `VideoWorkbenchRepository` 的 operation/event journal + `VideoWorkbenchService` | 每次操作先落自己的 journal；进程退出只按可验证输出或明确中断终态收口 |
| 原始素材引用、预览资产和导出校验 | `VideoWorkbenchService` + `videoExecution.ts` | 原始文件保持外部来源和指纹；预览由视频域目录管理；最终导出重新读取并验证媒体元数据和 hash |
| `/videos/*` HTTP/IPC 入口 | `videoWorkbench.ts` API 适配层 | Renderer 只读取视频投影，不接触 `MediaProjectService`、图片任务或 FFmpeg 子进程 |
| FFmpeg/FFprobe、诊断、桌面能力确认 | `videoExecution.ts` 共享本机执行基础设施 | 不拥有视频项目、时间线或渲染终态 |

迁移开始后，新视频写入只落 `billiardbuddy/videos/`。旧 `billiardbuddy/media/` 目录仅作有期限的导入/兼容读取来源；导入应保留已有外部素材路径、源指纹、时间线版本和已验证结果，不能把缺失文件伪造成可恢复素材。旧的图片分支已经收口为独立图片域，视频迁移完成后再将泛媒体服务整体退役，而不是维持两份永久正式状态机。

## 完成验收

导入真实素材，完成证据与转写，编辑和保存多个时间线版本，创建预览和最终渲染，验证导出文件；覆盖取消、进程中断和重启。仅有文本分镜、静态时间线、脚本命令或模型声称“视频已完成”均不算完成。
