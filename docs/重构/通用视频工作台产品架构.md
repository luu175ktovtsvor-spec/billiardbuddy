# 通用视频工作台产品架构

本文冻结视频工作台面向普通创作者的产品定位。它不替代
[视频工作台合同](./视频工作台.md)中的持久化、权限、媒体与交付约束，而是规定这些
能力怎样形成一个易开始、可解释、可撤销的通用创作产品。

## 结论

BilliardBuddy 视频工作台不是“让通用 Agent 随意操作 FFmpeg”的壳，也不是把一句
Prompt 直接变成不可追溯剪辑结果的工具。它的正式入口是 **Creation Brief**：用户用
用例、观众、分发形态、风格、节奏、字幕和必须保留的内容描述想要的成片；系统再把
它编译为可检查的 Delivery Intent，结合真实素材事实生成可接受的 Timeline Draft。

```text
Creation Brief（用户要什么）
  -> Delivery Intent（时长、覆盖与编辑策略）
  -> Source / Transcript / Visual Fact（真实素材能证明什么）
  -> Content Segment Candidate（可被选择的素材单元）
  -> Storyboard Selection（为何选、按什么叙事顺序）
  -> Video Director LLM（有证据的剪辑方案和备选）
  -> Host Validator（来源、时间范围、证据、锁定与预算）
  -> Scene Assembly -> Timeline Draft
  -> 用户接受的 CommandSet -> 不可变 Version -> Preview / Render / 质量报告
```

Creation Brief 还保存一组可审阅的 `creative_direction`：叙事语气、情绪弧、原声/音乐/旁白策略、旁白人格和字幕节奏。它是导演约束，不是模板，也不是“自动生成旁白”的授权；默认保留用户原始声音，`narration_after_review` 必须先显示脚本、声音和费用，再由用户确认后才允许进入后续执行。

普通用户只需先完成 Brief；素材分析、预算/同意与草稿的真实状态由工作台展示。高级
用户可以覆盖 Delivery Intent、范围、CommandSet 或交付变体，但这些能力不会成为
另一条写入链。高级用户的具体 Delivery Intent 与 Brief 冲突时，以前者为准并把冲突
写入规划 gaps。

### 先建议、再确认、后执行

普通创作者的最短路径不是“选一个模板然后自动导出”，而是四个可见阶段：

1. 用户用自然语言说明用途、受众、时长、节奏和必须保留的内容；这就是最小 Brief。
2. LLM 结合已验证的转写、镜头和视觉事实，返回带证据、时间范围和理由的候选方案；这
   一步只创建 Operation 和 Timeline Draft，不写正式时间线。
3. 用户逐项查看、删改或接受候选，必要时补充要求；创作会话的普通消息只是备注，只有显式的“生成建议”动作才启动证据约束的分析 Operation。接受动作显式生成 CommandSet。
4. Host 校验 CommandSet 后创建不可变 Timeline Version，之后才进入字幕、构图、音频、
   预览和渲染。后台 Operation 的动作名、阶段和百分比持续显示，用户能知道当前是在分析、
   组织候选、写入时间线还是渲染。

模板可以作为交付规格或风格预设，帮助填充画幅、字幕样式和编码参数，但不能替代 Brief、
事实证据或用户对候选的确认，也不能成为第二条 Timeline 写入源。

## “场景”不是选择模型，Storyboard 才是

原有 `Scene` 是一个很容易误解的技术词：它既可能指镜头切点，也可能指素材的某个时间
范围，还可能被误当成用户需要先学会选择的编辑对象。它不适合作为大众入口。

本产品现在固定为三层，且不可混用：

| 层级 | 是什么 | 谁产生/修改 | 不能做什么 |
| --- | --- | --- | --- |
| `Content Segment` | 由转写主题、镜头、静音、运动或人工边界得到的可验证素材单元 | Facts 管线或人工范围决定 | 不能直接成为成片。 |
| `Storyboard Candidate` | 用 Creation Brief、显式保留决定和可锚定事实进行排序的候选；记录分数、理由、故事角色 | 本地确定性选择器或受约束 Director | 不能写 Timeline。 |
| `Scene` | 选中候选在叙事顺序中的剪辑装配，可关联一个或多个 Content Segment | Draft 编译器 | 不能被当作“真实世界发生了什么”的证据。 |

因此普通用户的说法应是“我要做一条 **台球高光 / 教程 / 访谈 / 产品演示**，先放关键
进球，用问题-解决方案或时间顺序讲清楚”，而不是“帮我选几个场景”。`use_case`、
`story_structure`（时间顺序、钩子-价值-回收、问题-解决、教程、高光集锦）和
`selection_focus`（转写、动作、视觉、人物、产品）是正式的创作语言；镜头/场景只是它
之后的可审查实现。

### 时间线中的 A/V Link 细节

成熟剪辑器不会只靠“恰好相同的时间范围”猜测视频和源音频的关系。正式 v2 条目现在
可带 `linked_av_group_id`，它是不可变 Version 中的 AVSplit 身份：视频和源音频共享同一
组，切分后前半段保留原组，后半段创建新组。这样重启、回退或范围变化后，关联仍然是
持久事实，而不是 UI 缓存推断。

- 对任一 A/V 侧提交一次 `split`，Editorial 会在同一个 CommandSet 中切开两侧并生成
  两个完整的一对一 A/V 组；调用方不需要猜测新生成的另一侧条目 ID。
- 对任一 A/V 侧执行 `lock`，会锁定整个 link group，避免只锁画面却留下可修改源音频
  的半锁状态。
- `trim`、`reorder` 和 `replace` 仍要求调用方显式提交两侧的精确范围/位置；如果一侧
  被单独改变，版本校验会失败关闭，不会用默认时间或隐式补偿掩盖 A/V 错配。
- `ripple_delete` 以 link group 为原子删除单位，缺少另一侧时直接拒绝；跨轨道的 gap
  位移仍由同一 CommandSet 计算。

## 三次交叉验证与反向审计

### 1. 产品交叉验证：文本、搜索与成片目标必须同时存在

调研 [Descript 的文本式编辑](https://help.descript.com/hc/en-us/articles/37585546799757-The-editor-interface)、
[Adobe Premiere 的素材理解搜索](https://helpx.adobe.com/cn/premiere/desktop/organize-media/file-organization/search-for-media-using-ai-powered-media-intelligence.html)
和 [OpusClip 的长片转短片工作流](https://help.opus.pro/docs/introduction) 后，可归纳出三个
互补而非互斥的产品入口：

1. **语义入口**：转写、搜索与文字驱动的取舍，解决“我知道要找什么”的素材检索。
2. **视觉入口**：镜头、主体、画幅与自动重构，解决“我不知道怎么把横片变成竖片”。
3. **成片入口**：以平台、时长、节奏、开场、字幕与受众定义结果，解决“我只想得到
   一条能发的视频”。

反向检查旧路径，工作台已有前两类事实与完成层，却把第三类压缩成 `goal + duration +
coverage`。这会让普通用户面对编辑术语，也让规划模型看不到受众、平台与节奏。正式
修正是版本化 `Creation Brief`，并把它和 Delivery Intent 一起送入受控规划，而不是
增加一个无边界聊天框。

### 2. 模型反向审计：LLM 只能导演，不能成为剪辑事实或执行者

多模态视频编辑研究常把语言模型用于把自然语言目标转换为结构化编辑计划，例如
[LAVE](https://arxiv.org/abs/2402.10294) 与
[From Shots to Stories](https://arxiv.org/abs/2505.12237) 使用语言化的素材中间表示来
辅助规划。它们提示的风险也同样明确：模型会幻觉镜头、越过素材边界，或把“看起来合理”的
回答当作可执行结果。本产品因此做相反验证：假定模型输出完全不可信，仍必须保证结果正确。

- LLM 只输出严格 JSON 的 Brief、Scene 和 Alternative 建议；固定 Qwen 规划模型不由
  客户端选择。
- 每个 Scene 必须引用 Host 已有的 Transcript 或 Visual Fact，且时间范围必须与来源
  相交；用户意图只作为 `delivery_intent` 约束，禁止被伪造为素材证据。
- 模型不能写 Timeline、Version、Preview、Export、路径、对象 URL、预算或 Provider
  配置。Host 只在 CommandSet 接受时创建正式版本。
- 缺少事实时返回 `gaps` / `needs_review`；本地退化路径保留已验证的素材顺序，不用
  幻觉填补故事。

这使“模型质量提升”成为可替换的 Director 能力，而不会把产品正确性押在单一模型上。

### 3. 消费者失败反向审计：不自动覆盖、不隐藏成本、不伪造 AI 动作

从普通用户最容易失望的反例出发审计：

| 失败反例 | 必须保持的产品行为 |
| --- | --- |
| 一键生成把重要内容删掉 | `must_preserve`、锁定条目和范围决定优先；冲突显式显示。 |
| “AI 已改好”但实际没动 | 创作备注明确标记是否调用模型；只有 Operation、Draft、Version 是状态事实。 |
| 模型选错镜头却无法解释 | 每个建议绑定 Evidence ID、来源和时间范围；无依据的计划拒绝。 |
| 自动调用远端后才发现付费 | 远端分析先经过范围、预算、同意、逐 Operation reserve/settle/release。 |
| 预览和导出与建议不一致 | 只能从冻结 CommandSet/Delivery Variant/ExecutionPlan 进入 Preview、Render 和输出验证。 |

### 4. 可审计源码交叉验证：分段、选择和时间线必须分离

本轮还对三个可公开读取的工程实现做了反向源码审计，而不是只参考产品宣传：

- [auto-editor](https://github.com/WyattBlue/auto-editor) 的 `edit.nim` 将音频、运动、黑帧、字幕等分析表达式先归一为保留/删除掩码；`timeline.nim` 再将其编译成独立的 Clip/Track/Effect 时间线。这证明“分析信号”和“执行时间线”不能是同一个可变对象。
- [LosslessCut](https://github.com/mifi/lossless-cut) 的 `segments.ts` 让 Segment 成为可排序、可合并、可反选、可导出的选择集合，而不是渲染命令本身。这对应本产品中 Content Segment/范围决定的稳定身份。
- [OpenCut](https://github.com/OpenCut-app/OpenCut) 当前公开分支的桌面 Timeline 仍是壳层，不具备可复用的媒体事实、版本、恢复或渲染内核；因此不把“有一个时间线 UI”误判为可复制的架构。

反向检查现有代码发现：持久化 Version、CommandSet、ExecutionPlan 已经正确；缺口在
`createEditorialPlans` 与 Quick Create 曾按原始片段顺序/显式范围生成，缺少“为什么先选这
段、为什么按此顺序”的中间事实。本轮补上 Storyboard Selection，而不另起一条 Timeline writer。

## Agent、Skill 与视频工作台的边界

通用 Agent（包括可以加载“剪辑 Skill”的 Agent）适合完成跨应用的开放式任务：理解
用户文字、搜集信息、调用已授权工具、组织步骤。它不是媒体项目的事实库，也不应拥有
用户的视频路径、Provider 凭据、Timeline head 或导出位置。

视频工作台是一个有状态的媒体产品：它持久化素材指纹、PTS、转写修订、视觉事实、
同意与预算、Timeline/Variant Version、ExecutionPlan、输出 hash 与质量确认。它的
价值不在于“会调用 FFmpeg”，而在于无论桌面或模型进程如何重启，都能证明哪段素材、
哪次同意、哪个版本产生了哪份成片。

因此允许的关系是：

```text
General Agent / Skill
  -> 请求已公开、带 capability 的 Video Workbench Command
  -> 读取安全 Project / Operation / Draft 投影

Video Workbench
  -> 保留 Project 唯一 writer、预算、权限、证据与 Version 规则
  -> 选择固定 Video Director / Vision / ASR / Embedding 工作负载
```

Agent 可以帮助用户填写 Creation Brief、解释 Draft 的证据、建议下一步；它不能持有
Relay/OSS/Provider Key，不能绕过 consent/budget，不能把自然语言直接变成导出文件。
这种分工让 Skill 成为可选的协作入口，而不是用户数据与质量保证的替代品。

## 当前固定模型的明确动作

交付 Profile 首版支持常见 1080p 与 UHD 4K：横向 `1920×1080` / `3840×2160`，竖向 `1080×1920` / `2160×3840`，均通过偶数尺寸、4K 像素上限、编码器和输出验证门槛。源素材低于目标尺寸时只允许按明确的 Profile 放大并在质量报告中保留事实，不把放大结果冒充原生 4K；真实 4K 输出仍需在具备相应 FFmpeg/硬件资源的环境执行。

输入与输出必须分开理解：用户选择素材文件，系统按实际字节和 FFprobe 事实识别容器、视频/音频流、PTS、旋转、颜色和原始主视频流时长，不要求用户为每个输入编码做选择。首版接受常见的 MP4、MOV、M4V、WebM、MKV、AVI、MPEG/TS、3GP、OGV、FLV 和 MXF；无视频流、事实不完整或无法解码时失败关闭。用户确认的是交付预设：竖/横屏 1080p 或 UHD 4K，以及最终文件格式。默认使用 MP4 + H.264 + AAC；专业母版可选择 MOV + ProRes 422/422 HQ + PCM。帧率、字幕模式和音频策略属于高级交付选项，均进入不可变 Export Profile 并由实际输出验证；源素材不会因为输出选择而被覆盖，低分辨率放大也会在质量报告中标记。

| 能力 | 固定模型/本地能力 | 允许动作 | 不允许动作 |
| --- | --- | --- |
| Video Director | Qwen planning | 基于 Brief 与 Facts 生成 Scene/Alternative JSON | 直接写 Timeline 或导出。 |
| Vision | Qwen vision | 生成窗口化视觉事实与不确定性 | 声称未采样画面事实。 |
| Speech | Fun-ASR | 生成 PTS 保留的 Transcript 修订 | 覆盖原音轨或修改时间线。 |
| Retrieval | text-embedding-v4 + FTS | 找到带来源/范围/generation 的事实 | 充当成片决策或隐式改剪辑。 |
| Host compiler | SQLite + FFmpeg/FFprobe | 验证、编译、预检、渲染、输出校验 | 推断缺失事实或静默降级质量。 |

## 本轮正式变化

1. `PUT /api/videos/projects/:id/creation-brief` 持久化大众化创作 Brief，并在同一
   Project revision 编译出保守 Delivery Intent 和时长可行性。Brief 记录其自动生成的
   Intent 版本；一旦高级用户另行保存 Delivery Intent，后续 Brief 修改不会覆盖该显式
   时长、范围或策略。
2. 远端规划请求将 Creation Brief 和 Delivery Intent 作为不可引用的约束传给 Relay；
   prompt v2 要求场景只引用真实 transcript/visual fact，并明确处理 gaps。
3. Creative Message 不再伪装成已调用模型的“AI 回复”。它会明确说明该消息只是备注；
   真正模型工作只能通过分析 Operation 产出受验证的 Draft。
4. 模型、原始媒体、路径、预算和最终写入权仍在 Video Sidecar / Relay / Main 的原有
   边界内，未把通用化改造成共享 Agent 或泛化媒体路径。
5. Creation Brief 新增 `story_structure` 与 `selection_focus`。`/editorial-plans` 将
   Content Segment 产出带 `selection_rank`、`selection_score`、`selection_reasons` 和故事
   角色的 Storyboard；Quick Create 优先生成推荐叙事 Draft，必要时再给原始时间顺序
   Draft 对照。被编译的 Scene 保留其 `content_segment_ids`，所以接受后的 CommandSet
   Version 仍可追溯选择来源。

## 非目标

- 不做 text-to-video 生成器，也不以 Prompt 替代用户素材。
- 不让模型自动接受 Draft、移动 Timeline head、发布导出或确认质量报告。
- 不让 Renderer、Agent 或 Skill 获取本机路径、OSS URL、Relay token 或 Provider Key。
- 不将所有专业 NLE 控件塞进大众入口；专业操作保留为 Versioned CommandSet 的渐进
  披露能力。

## 验证证据

- API 回归覆盖 Creation Brief 的持久化、自动 Delivery Intent 与过期 revision 拒绝，及
  “关键进球”动作事实被排序为高光 Storyboard 的第一候选；Quick Create 仍只写 Draft，
  不推进正式 Timeline。
- API/领域回归覆盖持久化 A/V link group、单侧 split 自动联动两条流、切分后前后半段
  的一对一关系，以及单侧 lock 自动锁定整个 group。
- Provider contract 覆盖规划 prompt v2、固定模型、创作约束传递及 `delivery_intent`
  不可当作场景证据的指令。
- 既有 Fact/CommandSet/ExecutionPlan/输出验证回归继续证明模型建议不能绕过正式版本链。

本轮研究的参照包括 Descript 的文本式编辑、Adobe Premiere 的素材理解、OpusClip 的
自动短片产品路径，以及多模态语言模型生成结构化视频编辑计划的论文方向。它们用于
检验“意图入口 + 素材事实 + 受控生成”的产品原则，不作为 BilliardBuddy 的运行时依赖。
