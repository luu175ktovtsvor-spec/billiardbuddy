# 共享运行时与桌面壳

## 这个模块解决什么

这是三条工作面共用的最小地基，不是另起一套万能工作流框架。用户打开桌面应用时，应当只看到 BilliardBuddy：明确的项目、任务或作品位置，正在运行的事情，以及可验证的成果。Renderer 不保存业务最终事实，也不持有 provider 凭据。

## 领域边界

共享运行时只拥有以下能力：

1. Electron Main、preload、受控 IPC 与本地 Product Server 的启动、关闭和错误呈现；
2. 安装身份、安全存储、能力状态、用户权限和远程能力访问；
3. 操作身份、幂等回执、取消、超时、资源释放、诊断和重启恢复；
4. 可追溯的附件、资产与导出成果引用；
5. 桌面导航、标签页、窗口恢复、通知、主题和无障碍的视图状态。

它不拥有 Agent 的会话/回合，也不拥有图片的画布/候选或视频的时间线/渲染。这些事实分别留在三个工作面。

## 单一事实来源

| 事实 | 最终拥有者 | Renderer 的职责 |
| --- | --- | --- |
| 本机服务和受控能力 | Electron Main 与本地 Product Server | 请求状态、展示修复入口 |
| 有副作用的操作 | 对应领域服务的持久记录与回执 | 发命令、订阅快照和事件 |
| Agent 运行 | Agent 工作台的任务账本 | 渲染活动、审批和结果 |
| 图片作品 | 生图工作台的图片项目 | 渲染画布和版本 |
| 视频作品 | 视频工作台的视频项目 | 渲染时间线和预览 |

任何跨 IPC、HTTP 或 Worker 的变更命令必须有操作身份；任何可恢复异步任务必须能给出已接受、运行、等待用户、成功、失败、已取消或需要恢复中的准确终态。不能用前端临时变量、模型文本或进程是否还活着代替该终态。

## 正式边界

```text
Renderer
  -> 受控 IPC / 本地 HTTP 命令
Electron Main
  -> 受限宿主能力、秘密存储、sidecar 生命周期
Local Product Server
  -> 领域状态、操作回执、事件投影、恢复与诊断
Private Worker / FFmpeg / 浏览器等执行者
  -> 受能力与权限约束的实际执行
Gateway / Relay
  -> 托管远程能力、容量、用量和异步结果，不保存本地项目真相
```

私有凭据不得进入 renderer、浏览器可见 WebSocket、任务提示词、日志或模型启动的子进程环境。平台托管能力必须经过 BilliardBuddy 服务；用户主动选定的个人 Key 只在本机服务中直连上游。

## 完成条件

- 桌面壳可恢复窗口和工作面，且只展示服务真实状态；
- 本地服务只监听受控本机地址，崩溃、启动失败和能力不可用都能给出可执行说明；
- 三条工作面都通过自己的领域 API 写入事实，Renderer 没有第二份持久 Store；
- 跨进程动作可取消、可追踪、重启后可恢复或明确标为需要恢复；
- 任一模块替换内部实现时，不需要把其业务状态强塞进另一个模块。

## 实施次序

这个模块只在某个工作面确实需要共享边界时改动。不得为了“先搭地基”而暂停用户可见的 Agent、生图或视频旅程，也不得引入没有正式消费者的通用抽象。
