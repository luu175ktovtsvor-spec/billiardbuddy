# 迁移与发行

## 迁移原则

旧自建 Agent、旧 Renderer、ProductTask/Run 账本与旧 Agent API 已删除，不提供兼容运行路径。新 Agent 会话由 Codex Rust Thread Store 保存和恢复。

图片、视频和凭据仍可能有历史用户数据。对应迁移必须是单向、可验证且有明确退出条件：新 writer 只写入所属领域；旧目录只能临时读取或导入；确认数据连续后删除旧 reader。不得用删除用户作品或项目来掩盖迁移失败。

## 安装包内容

正式 Electron 安装包必须包含：空 Renderer 入口、Electron Main/preload、BilliardBuddy Sidecar、媒体工具链、锁定构建的 App Server 与同 revision 的 Code Mode Host、锁定源码官方清单对应的 `rg`、BilliardBuddy 本地 Agent 插件市场、第三方许可与完整性清单。macOS/Windows 正式构建入口都必须在打包前按目标平台 staging Computer Use、Chrome Control、Browser Use 与 Record & Replay；安装包审计会拒绝旧 Agent 字符串、缺失受管资源和非正式运行入口。

## 发行验证

macOS arm64 与 Windows x64 分别构建和验证。每个平台至少验证：

1. 安装、首次启动和安全存储；
2. Rust App Server 启动、Thread 创建/恢复、Turn、工具、审批和中断；
3. 托管 Responses、个人 Responses 与个人 Chat 路线；
4. 图片、视频 Sidecar 的启动、恢复和输出，包括视频流程内部所需的音频转写与迁移期既有语音兼容路径；
5. 安装包内容审计、升级、更新中断恢复和卸载边界。

构建成功、源码搜索或未签名目录包都不是发行完成。签名、公证和更新源仅在对应凭据与真实安装验证具备后声明完成。
