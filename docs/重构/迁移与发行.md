# 迁移与发行

## 角色

这是三个工作面完成后的收口模块，不抢在产品能力之前。它负责把旧路径、数据连续性、安装与更新变成可证明的产品结果，而不是为了提前出包冻结重构。

## 迁移规则

- 旧 reader 只在仍支持的用户升级范围内存在；每个 reader 必须写清输入版本、输出版本、失败策略和退出条件；
- 新旧路径不能无限并行。某领域的正式消费者全部切换并确认数据连续后，删除旧 writer、旧 UI、旧路由、旧 fixture 和专用依赖；
- 不删除用户项目、任务、作品或远端生产数据来掩盖迁移问题；
- 迁移、幂等、恢复和最终清理各自拥有清楚操作回执。

## 发行范围

Windows x64 为第一正式发行目标，macOS arm64 保留完整代码、构建与更新入口。每个平台分别验证：安装包内容、首次启动、升级、更新中断恢复、回退、权限、私有凭据、sidecar、Agent、生图、视频及诊断。签名、公证和真实更新源只有在对应凭据具备后才能宣称完成。

## 完成验收

三条工作面的正式用户旅程均已通过整体复审；没有已知会导致错误结果、数据丢失、重复副作用、权限越界或不可恢复的生产缺口；旧路径有明确支持期或已删除；再进行真实安装、升级和更新验收。构建成功、未签名临时包或源码搜索都不等于发行完成。
