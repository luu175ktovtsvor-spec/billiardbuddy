# 生图 · 当前能力与设计

> 📌 状态:✅现行 · 最后核对 2026-07-15
>
> 本文只记录生图的稳定产品边界、质量原则和验证入口。当前实现以源码、测试和运行结果为准。

## 1. 产品边界

生图是 B 线确定性产品功能，不把 provider、质量重试或项目存储织入 Agent 主循环。用户既可以进入“生成图片”工作台，也可以在聊天中让 Agent 调用同一套生图能力。

工作台保留两个创作模式：

- **制作海报**：自由描述画面和文字，可附参考图、Logo、二维码和必须原样出现的文字。
- **照片优化**：基于本人或已授权人物照片做自然优化，保留可辨识特征和正常比例。

首期不做：

- 不做无限画布、专业图层软件或复杂模板市场。
- 不把换脸、公众人物代言或身份冒充包装成能力。
- 不让 renderer 选择真实模型、供应商或远程端点。
- 不把内部质检、网关、模型路由和重试术语直接展示给用户。

## 2. 用户流程

### 2.1 初始态

页面以 Codex 的任务输入方式组织，不再把所有能力铺成三栏表单：

1. 选择“制作海报”或“照片优化”。
2. 用自然语言说明目标。
3. 按需添加参考图或固定文字。
4. Logo、二维码、比例、张数和清晰度收在次级设置中。
5. 点击生成后进入“结果”阶段。

初始态正文宽度受限，输入区是第一视觉焦点；历史图片折叠，不与当前任务争夺注意力。

### 2.2 结果态

结果按任务流展示：

- 后台任务进度、取消、失败和重试。
- 系统对需求的简短理解。
- 1-4 张结果及当前选择。
- 人像参考图与结果对照。
- 两张结果的并排比较。
- 继续修改或直接下载。

生成结果不会同时展开所有编辑控件。用户确认图片后再进入“修改”。

### 2.3 修改态

修改阶段围绕当前图片按需展示：

- 用一句话修改整张图片。
- 框选或涂抹后修改局部区域。
- 添加、删除、撤销、重做和调整文字。
- 切换历史版本。
- 生成高清图片、下载 PNG、保存到图片库。

宽屏下图片保持为主视图，修改工具在右侧出现；窄屏只显示当前阶段，避免压缩画布。

## 3. 共享编排

```text
生图工作台 / Agent 图片工具
  -> 统一 CreativeBrief
  -> 统一后台任务和模型路由
  -> gateway 或 relay
  -> 统一质量检查和有限重试
  -> 统一图片项目、资产与版本存储
  -> 工作台或对话按入口展示结果
```

聊天路径不是第二套生图后端：

```text
自然语言 / 本机参考图
  -> generate_image / edit_image
  -> ImageBriefCompiler / MediaJobService
  -> 同一 gateway 或 relay
  -> 同一质量检查与有限重试
  -> ImageWorkbenchStore 登记真实候选
  -> 对话返回摘要，工作台继续编辑同一项目资产
```

renderer、sidecar 和远程服务共用经过运行时解析的 Schema，不维护手写镜像；具体文件位置和当前字段直接从源码确认。

## 4. 核心机制

### 4.1 创作理解

用户原始需求先编译成 provider-neutral CreativeBrief，再由各图片通道适配。编译层可以补结构和约束，但不能引入用户未提供的价格、活动、品牌承诺或门店事实。

参考图必须带用途：

- 主照片、补充角度。
- 场景参考、风格参考、人物参考、品牌参考、主体图片。

角色进入共享契约和项目存储，不能只存在于前端临时状态。

### 4.2 模型路由与异步任务

renderer 只提交图片意图、质量、比例和参考资产。真实模型路由由后端完成：

- 国内图片通道承担中文文字、海报和常规生成。
- 海外图片通道承担适合其能力的复杂创意或编辑。
- 海外慢调用通过 relay 的 submit/poll 任务绕开长连接超时。
- 通道不可用或能力不匹配时由后端降级，并将错误归一化成用户语言。

前端支持取消和重试，但不解释原始 provider 响应。

### 4.3 海报质量链

海报质量不是单一分数，至少检查：

- 画面与需求是否一致。
- 主体、构图和留白是否可用。
- 用户要求的文字是否存在且可读。
- Logo、二维码和固定文字是否保持原样。
- 比例和导出尺寸是否正确。
- 是否存在明显视觉缺陷或需要人工确认的细节。

模型负责画面生成；Fabric 固定画布负责可控文字、品牌资产、最终尺寸和 PNG 导出。不能依赖模型保证精确排版。

### 4.4 人像质量与授权

真人照片输入必须先确认使用授权。纯文字生成虚构人物不触发授权闸；上传真人照片进行优化时触发。

人像流程要求：

- 1-3 张同一人物的已授权参考图。
- 不只靠外貌文字重建某个真实身份。
- 不支持换脸、公众人物代言或身份冒充。
- 检查清晰度、曝光、遮挡、过度压缩和可用性。
- 自动检查只能发现风险，最终“像本人”由用户确认。

### 4.5 项目、版本与导出

项目事实以后端文件存储为准：

- 每个项目保存 CreativeBrief、参考资产、固定画布、文字层、图片层和当前版本。
- 修改、局部修改、高清和文字导出形成版本。
- 画布自动保存带 revision，冲突失败关闭，不静默覆盖新版本。
- PNG 导出和图片库保存使用真实资产文件，不用浏览器截图冒充最终成品。

### 4.6 两个入口的一致性

- 工作台和 Agent 都先编译同一种 CreativeBrief，再进入同一个 MediaJobService。
- Agent 默认生成 3 个候选；工作台可以按当前任务设置 1-4 张，但候选质检和模型路由相同。
- 低质量结果的自动再生成最多发生一次，并由原后台任务负责；前端或 Agent 不另起一笔重复付费任务。
- Agent 生成的真实候选自动登记到 ImageWorkbenchStore，后续修改、版本和导出不另建影子项目。
- 本机参考图先由 Agent 视觉读取并遵守提交数量上限；真正提交远程图片服务前由运行时展示原图和用途，避免模型从目录中盲选。

## 5. 前端设计口径

生图页面跟随 Codex 的信息架构，而不是传统 SaaS 表单：

- 顶部只保留当前任务需要的模式。
- “描述 / 结果 / 修改”是阶段，不是三栏常驻区域。
- 正文以 13-14px 为主，12px 用于次级信息，10px 只允许极少量图片元数据。
- 技术设置折叠；主要动作只出现一个。
- 图片是结果态和修改态的视觉中心。
- 按钮、错误和状态使用普通中文，不显示模型、网关、端点、质检和蒙版等内部词。

## 6. 兼容与失败边界

- 旧命令 `/生图工作台` 继续兼容，但界面统一显示“生成图片”。
- 旧项目由共享 Schema 填入安全默认值。
- 任务取消、通道失败、组件未就绪和版本冲突都保留恢复入口。
- 远程 live 结果具有网络和上游不确定性，不用本地 E2E 伪造效果结论。
- 组件资产未安装时显示准备状态，不要求用户手工安装依赖。

## 7. 验证

桌面真机验收使用 Computer Use 操作当前 `main` 构建出的 Electron 开发版，并以普通用户自然语言验证：

- 初始态在宽屏和 720px 下无横向溢出。
- 取消、失败和重试。
- 生成、挑图、比较、下载。
- 整图修改、局部修改、文字编辑和版本切换。
- PNG 导出、图片库保存和重启恢复。

截图只记录用户可见状态；生成是否成功必须同时核对任务接口、运行日志和真实资产文件。

完成、提交或合入前统一运行：

```bash
bash scripts/quality_gate.sh
```
