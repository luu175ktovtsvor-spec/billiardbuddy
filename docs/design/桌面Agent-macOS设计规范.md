# 桌面 Agent 界面规范

> 状态：现行 · 最后核对 2026-07-15

## 1. 唯一界面来源

桌面产品只保留一套 React renderer：

- 源码：`ts/desktop/renderer-react/`
- 构建产物：`ts/desktop/renderer-dist/`
- Electron 加载入口：`ts/desktop/electron/main.ts` 的 `loadRenderer()`
- 页面骨架：`src/components/layout/AppShell.tsx`
- 设计 token：`src/theme/globals.css` 与 `src/theme/workbuddy-tokens.css`

`renderer-dist` 是 `renderer-react` 的 Vite 构建结果，不是第二套界面。sidecar 不提供静态前端，应用也没有通过查询参数注入假会话或假文件树的预览模式。

本规范只描述当前产品事实。

## 2. 四栏结构

聊天工作区在右侧面板打开时由四个连续区域组成：

```text
┌──────────────┬────────────────────────┬────────────────────┬──────────────┐
│ 项目/会话侧栏 │ 聊天与 Agent 活动       │ 当前文件预览         │ 工作区文件树   │
│ Sidebar      │ TopBar + ActiveSession │ Preview surface    │ Workspace tree│
└──────────────┴────────────────────────┴────────────────────┴──────────────┘
```

1. 项目/会话侧栏负责主导航、项目、项目内会话和设置入口。
2. 聊天区负责用户消息、流式回复、工具活动、审批、产物和输入框。
3. 文件预览区负责当前标签页内容，包括文本、图片、视频、PDF、表格和文档。
4. 文件树负责工作目录浏览、筛选和打开文件。

右侧面板收起时，聊天区使用释放出的空间；这不是另一版页面。生成图片、剪视频、已安排、插件和设置由同一应用壳切换内容，不建立独立前端入口。

## 3. 尺寸与响应

- 左侧栏默认 240px，可在 200px 至 420px 之间拖动。
- 右侧工作区面板默认 640px，可在 440px 至 960px 之间拖动。
- 右侧文件树固定 232px，剩余宽度用于文件预览。
- 聊天区必须保留可用的输入宽度；窗口不足时优先允许用户收起侧栏或右侧面板。
- 固定格式区域使用稳定宽度、`min-width`、`max-width` 和滚动容器，动态内容不得把相邻栏挤出窗口。

## 4. 信息架构

### 侧栏

- 顶部保留收起和搜索图标。
- 主导航按“新建任务、生成图片、剪视频、已安排、插件”排列。
- 项目等同于工作目录；项目下面展示同目录的多个会话。
- 项目和会话状态必须来自真实 store 与 sidecar，不展示示例记录。
- 设置和主题入口固定在底部。

### 聊天区

- 最终回复是主内容，工具活动和等待状态是辅助信息。
- 原始思考正文不直接展示；只展示简短、可理解的阶段状态。
- 工具明细默认折叠，运行中的真实输出可展开查看。
- 媒体产物不埋在折叠活动中，应与最终回复保持可见。
- 审批只在真实权限决策需要时出现，不用命令卡片充当装饰。
- 输入框保留附件、权限档、语音和发送四类核心控制。

### 文件预览与文件树

- 点击文件树项目后，在预览区打开标签页；同一文件不重复创建标签。
- 切换项目、文件或工作表时，较慢的旧请求不得覆盖当前选择。
- 二进制文件不得走文本读取接口。
- 图片使用可检查的完整画面；视频显示原生播放控制；表格显示工作表切换和二维数据。
- 加载、空态、失败、关闭和重新读取必须有明确状态。

## 5. 视觉语言

- 参考 Codex 的安静、紧凑和工具化表达，不做营销首页或卡片墙。
- 正文以 13px 至 14px 为主；紧凑面板标题小于页面标题。
- 主按钮使用中性近黑或近白；蓝色只用于链接和键盘焦点，绿色只用于成功状态。
- 用户消息使用中性浅灰，助手正文以内容排版为主。
- 分隔主要依靠背景层级和细边线，不用厚重阴影。
- 卡片圆角不超过 8px，只有弹窗和确实独立的工具容器可以更明显。
- 图标按钮优先使用已有图标库，并提供 `title` 或 `aria-label`。
- 不使用渐变球、装饰性光斑、大面积单色或与任务无关的插画。

## 6. 状态与反馈

- 启动只允许“连接 sidecar、就绪、错误”三种真实阶段。
- 发送后必须尽快显示等待或活动反馈；长时间只显示“正在处理”属于待优化问题。
- 停止任务后明确显示“任务已中断”，不能伪装成成功。
- 工具局部失败与回合最终结论分开表达，不能把成功回合整体染成错误。
- 模型回复声称创建文件时，界面只在真实文件可访问后提供文件入口。

## 7. 代码边界

- 页面与组件通过 feature API 和 store 使用后端能力，不在组件里拼接路由或解释原始响应。
- renderer、preload、Electron main 和 sidecar 的共享字段放在 `ts/shared/contracts`，由 Zod 在边界解析。
- `AppShell` 只负责应用启动、全局布局和顶层状态，不灌示例业务数据。
- 新功能进入现有应用壳和功能域，不新增 HTML 入口、静态旧页面或另一套 renderer。

## 8. 验证

- 机械行为由单元、契约、集成和后端 E2E 验证。
- 桌面用户路径用当前 `main` 构建出的开发版和 Computer Use 验证。
- 真机输入使用普通用户自然语言；截图只证明可见状态，文件与媒体产物还要核对真实落盘内容。
- 每次启动必须确认 URL 指向 `ts/desktop/renderer-dist/index.html`，并确认不存在旧静态页面或假数据预览入口。
