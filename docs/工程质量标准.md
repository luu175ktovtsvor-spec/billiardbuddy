# 工程质量标准

> 📌 稳定规则文档。只写三层质量门、权威命令、运行时机、通过标准、live 边界与失败分类原则。
> 具体测试数量、通过清单、修改流水一律以源码与实际运行结果为准，本文件不复制。

BilliardBuddy 当前底座是整体导入的 CC-Haha（Claude Code）Agent 内核（`ts/`）加上产品外层服务（`gateway/`、`relay/`）。质量体系因此分两层：

- **内核质量**由 CC-Haha 自带的 `bun run check:*` / `quality:*` 原生入口负责，不重写、不迁就旧标准。
- **产品外层质量**由 `scripts/quality/*` 与 `gateway/relay` 测试负责。

顶层入口 `scripts/quality_gate.sh` 只做“组合调用”，不重复实现原生 runner。

## 三层质量门

| 档位 | 命令 | 用途 | 覆盖 |
|---|---|---|---|
| 快速 | `bash scripts/quality_gate.sh --quick` | 单模块开发、中间提交自检 | 工程 Skill 校验、工作流引用校验、密钥扫描、架构边界、gateway/relay、`git diff --check` |
| 集成（默认） | `bash scripts/quality_gate.sh` | 跨模块任务完成、PR、声明功能完成 | 快速档全部 + CC-Haha `check:server`、`check:electron`、`check:desktop`（`check:adapters` 在依赖已装时纳入） |
| 发布 | `bash scripts/quality_gate.sh --release [--allow-live]` | 制作安装包、正式交付 | 集成档全部 + `check:native`（sidecar 构建、Electron `--dir` 打包、package smoke）；`--allow-live` 时叠加原生 provider/desktop live smoke |

单模块开发时也可直接用 CC-Haha 原生按面入口，无需过全门：`check:server`（server/tools/utils/provider/MCP/OAuth/WS）、`check:desktop`（renderer lint+test+build）、`check:electron`（Electron 主/预加载）、`check:native`（打包）、`check:adapters`（IM 适配器）。这些是内核 `ts/AGENTS.md` 的权威验证路由，质量门只是把它们组合进离线闸口。

## 运行时机

- 改完单个模块、中间提交前：`--quick` + 该模块的原生按面检查。
- 跨模块任务收尾、要声明“完成/可合并”前：集成门（默认）。
- 打安装包或正式交付前：发布门 `--release`；具备真实凭据与真机时加 `--allow-live`。
- CI 与本地共用同一权威入口 `scripts/quality_gate.sh`，避免两套判定。

## 通过标准

- 默认（快速 / 集成）在干净基线上必须稳定 `exit 0`，且完全离线、确定性、可重复。
- 引用不存在的目录、package script 或已退役结构（`renderer-react`、`ts/shared`、旧 harness）应被检查器直接判失败，不允许“显示通过实则空扫”。
- CC-Haha 基线偏差审计默认只报告 `unchanged/modified/added/deleted`；**一旦出现上游原始路径被删除即阻断**，必须单独说明或另立上游升级任务。产品接轨的 modified/added 属预期，不算失败。

## live 测试边界

- 默认质量门（含 `--release` 不带 `--allow-live`）**不得产生任何付费 / 真实上游请求**。
- 所有 live 项必须显式开启：
  - Provider 连通性等 live 用例以环境变量门控（如 `RUN_LIVE_PROVIDER_CONNECTIVITY=1`），默认在 `check:server` 中跳过。
  - 原生 live 冒烟：`bun run quality:smoke` / `quality:providers` / `quality:gate --mode release --allow-live --provider-model <provider:model>`。
  - 网关 / 语音 / 图片与真机 Agent 工具循环、服务器健康/部署/回滚验证需各自凭据与真机，手动执行并显式报告实际出口、费用与不确定性。

## 失败分类原则

check:server 等导入基线出现失败时，先归类再处理，**不得为让旧检查变绿而修改 CC-Haha Agent 内核（Loop/Tools/Skills/Hooks/权限/上下文/系统提示）**：

1. **测试环境 / 依赖缺失**（缺 `rg`、代理变量、临时目录、端口）：修测试环境或用产品自带的确定性回退（如 `CLAUDE_CODE_USE_NATIVE_FILE_SEARCH=1` 走原生文件搜索）。
2. **测试隔离**（共享缓存未清、测试顺序、并发污染）：修隔离，不改产品行为。
3. **外部网络 / live**：改用确定性 fake upstream，或把 live 断言移到显式开启的 live 通道；不把 live 混进普通门。
4. **真 bug**：最小修复并补回归测试。
5. **拟退役能力**：只提交分析与影响范围，等用户决定，不在质量门任务里擅自删除。

依赖真实工具或网络才能成立的用例（如 ripgrep 回退、私网 LAN 可达性），在该前提不满足的环境按既有约定确定性跳过，在满足的环境（CI）照常断言——跳过要可见，不静默掩盖。
