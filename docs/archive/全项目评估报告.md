## 维度二：知识库调用逻辑

### 现在的链路（已修好）
```
用户输入/点卡 → 定岗位 → 加载岗位规则+按场景筛选的知识+客户规则+门店画像+few-shot
            → 拼 system prompt → DeepSeek → 输出过滤 → 返回
```
- **岗位→知识分层正确**：每个岗位拿不同知识。
- **意图筛选已修好**（本轮）：free_intent 路径 + prompt_key 主力路径（52/54 卡）都按用户意图筛选知识，manager 典型场景知识段 -41%，既省成本又提相关性。

### 你的判断对不对？
你说"这部分逻辑对了，DeepSeek 质量就会偏高"——**方向正确**。补一句：决定质量的还有"知识浓度"。之前每次全量灌入，真需求被淹没（lost in the middle）；筛选修好后，相关知识占比上升，输出会更贴需求。这给了你一个**可验证的预测**（见维度三的评估方法）。

### 仍存的缺口
- **5 个专项服务（diagnosis/performance/sop/games/outreach）调用 `_append_guardrails` 时传空意图** → 退化成全量注入。修法：把各自的问题描述/场景作为 intent_text 传入（和我本轮给主链路做的一样）。

## 维度三：行业知识注入与如何评判

### 知识质量：A-（91/100），这是项目最值钱的资产
基于通读核心知识 + 核验那份 248 文件原料（含"台球行业真实运营逻辑"PPT）：
- **PPT 大方向被忠实吸收**：营销=识别→创造→传播→交付、五步法、四类客户、定价铁律、合规转译，知识库内容与 PPT 一致，无跑偏。
- **真材实料**：助教 SOP 细到分钟和对白、定价逻辑跨文件一致、合规转译框架（追分→台费局）、赛事让条件、绩效考核维度——从业者一眼能认出是内行货。
- **本轮已补的结构性短板**：诊断决策树、顶层营销框架、前线话术速查、开业战略框架。

### 这个项目该怎么评判（回答你的核心问题）
你的产品假设（行业知识够好→从业者觉得有用）**成立概率高**，因为知识本身是 A- 级。把"觉得有用"变成可测，建议三层：

1. **金标准题集（现在就能做，最便宜）**：每岗位挑 5-8 个真实高频场景，固定门店画像跑结果，找**真实从业者**按四维打分：①能否直接复制发出 ②有没有说外行话 ③有没有违规 ④比自己写省不省事。这套题集留作每次改动的回归基线。
2. **消融对比**：同批题，带知识 vs 不带知识盲评，验证知识到底有没有被有效利用。
3. **使用行为指标（上线后）**：复制率（最强的"真在用"信号）、重新生成率（越低越好）、各岗位周留存。**你们已有"效果好/差"反馈系统 + 生成历史，现在就该拉出来看差评集中在哪——那就是真该补的薄弱点。**

> 结论：瓶颈不在"知识多少"（已经很够），而在"知识怎么进 prompt（浓度）"——本轮已大幅改善。

## 维度四：多 Agent 设计

项目里有**两套**"每岗位一个 Agent"：

### ✅ 系统一：岗位工作台 — 正确且成熟
6 岗位 × 规则 YAML × required_knowledge × 54 卡片，每岗位拿不同知识/语气/任务。这是"岗位 Agent"的正确实现（角色化 prompt 组装）。前端 49 个 promptKey 与后端模板零断链。**这套是对的。**

### ❌ 系统二：协作页（collaborate）— 空壳 + 越权
`orchestrator.py` 的 `run_agent` 每个"岗位 Agent"人设只有一句话，**完全不加载知识库/岗位规则/门店画像/合规**，且：
- **越权**（orchestrate.py:48-69）：查/取消任务只验登录不验门店，任务存全局内存 `_tasks`，拿 task_id 能看别家门店内容
- 内存存储（重启丢失、多进程 404、无清理）
- 无配额/注入/过滤/落库；`store_id` 传入却未使用
- 前端轮询无 res.ok、无超时，任务丢失会无限卡"等待中"

**后果**：用户在工作台拿到内行内容，一进协作页拿到通用 AI 水平的泛泛之谈——同产品两种质量，比没有更伤信任。

### 建议（三选一）
- **A. 修好接知识库**：`run_agent` 复用 `_append_guardrails`（岗位规则+知识+画像）+ 补四件套 + 修越权 + 改持久化
- **B. 先下线**：隐藏协作入口，等想清楚再做
- **C. 最小修（推荐）**：① `run_agent` 接知识库（质量瞬间拉齐工作台）② 修越权校验；内存持久化暂不动。30% 成本拿 80% 价值
