## 六、域名和 URL 规划

当前推荐同域名部署，降低复杂度。

例如：

```text
https://app.example.com
```

规划：

```text
前端页面：
https://app.example.com/

后端 API：
https://app.example.com/api/v1/...

上传文件：
https://app.example.com/uploads/...
```

前端生产环境：

```env
NEXT_PUBLIC_API_URL=https://app.example.com
```

后端 CORS：

```env
CORS_ORIGINS=https://app.example.com
```

请说明：

- 同域名部署可以减少 CORS 复杂度。
- Nginx 负责把 `/api/` 转发到 FastAPI。
- Nginx 负责把 `/uploads/` 转发或直接映射到持久化目录。
- 后续商业化可以拆成 `app.example.com` 和 `api.example.com`。

## 七、端口规划

请给出端口规划：

```text
80     Nginx HTTP
443    Nginx HTTPS
3000   Next.js 前端，仅监听 127.0.0.1
8000   FastAPI 后端，仅监听 127.0.0.1
5432   PostgreSQL，仅监听 127.0.0.1
```

要求：

- 外网只开放 80 / 443。
- 3000 / 8000 / 5432 不对公网开放。
- PostgreSQL 只允许本机访问。
- 后续可用防火墙限制。

## 八、Nginx 反向代理规划

请给出伪配置，不要真的创建配置文件。

推荐结构：

```nginx
server {
    listen 80;
    server_name app.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /uploads/ {
        alias /opt/billiards-ai/uploads/;
    }
}
```

请注意说明：

- `location /api/` 的路径不要写错。
- 如果 FastAPI 本身挂载 `/uploads`，也可以 proxy 到 `127.0.0.1:8000/uploads/`。
- 当前更推荐 Nginx 直接 `alias` uploads 目录，访问更简单。
- 生产要启用 HTTPS，可以用 Certbot。

## 九、PostgreSQL 部署规划

当前试用期建议继续使用 Docker PostgreSQL。

建议：

```bash
docker compose up -d postgres
```

或单独的生产 compose。

要求说明：

- 端口绑定 `127.0.0.1:5432:5432`
- 数据卷持久化
- 数据库密码必须强密码
- 不允许公网访问 PostgreSQL
- 定期备份

请说明数据库迁移：

```bash
cd server
uv run alembic upgrade head
```

如果当前项目迁移命令不同，以项目实际为准。

## 十、后端 FastAPI 生产启动方案

不要使用：

```bash
uv run fastapi dev main.py
```

生产建议：

```bash
cd /opt/billiards-ai/app/server
uv run uvicorn main:app --host 127.0.0.1 --port 8000
```

或：

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

但如果由 Nginx 反代，建议监听：

```text
127.0.0.1
```

请说明：

- 后端通过 systemd 管理。
- 日志可以用 `journalctl -u billiards-backend -f` 查看。
- 后端环境变量从 `/opt/billiards-ai/env/server.env` 读取。

## 十二、systemd 服务规划

请给出两个 systemd 服务伪配置：

### 后端服务

```ini
[Unit]
Description=Billiards AI Backend
After=network.target docker.service

[Service]
WorkingDirectory=/opt/billiards-ai/app/server
EnvironmentFile=/opt/billiards-ai/env/server.env
ExecStart=/usr/bin/env uv run uvicorn main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 前端服务

```ini
[Unit]
Description=Billiards AI Frontend
After=network.target

[Service]
WorkingDirectory=/opt/billiards-ai/app/web
EnvironmentFile=/opt/billiards-ai/env/web.env
ExecStart=/usr/bin/env pnpm start --hostname 127.0.0.1 --port 3000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

注意：

- 这只是方案，不要实际创建。
- 实际路径要根据服务器安装的 `uv` / `pnpm` 路径调整。
- systemd 环境 PATH 可能和 shell 不同，后续部署时要处理。
