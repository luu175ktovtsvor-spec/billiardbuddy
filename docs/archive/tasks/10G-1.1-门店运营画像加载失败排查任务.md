## 三、重点排查项

请按顺序排查，不要跳步。

### 1. 后端是否已重启

确认当前后端进程是否加载了最新代码。

如果后端仍在旧进程中，请重启后端。

### 2. migration 是否执行

重点确认数据库中 `stores` 表是否已有：

```text
operation_profile
```

如果没有，请执行本地 migration。

要求：

- 不要删除数据
- 不要重建数据库
- 只执行正常 migration
- 记录执行命令和结果
- 如果 migration 报错，记录完整错误

### 3. GET `/api/v1/stores/me`

确认是否返回 200。

重点检查：

- 是否出现 `column stores.operation_profile does not exist`
- 是否出现 Pydantic response validation error
- 是否出现 JSON serialization error
- 是否出现认证 / token 异常
- 是否返回了 `operation_profile`

### 4. PUT `/api/v1/stores/me`

用一个最小 operation_profile 测试保存。

建议测试内容：

```json
{

    "private_domain_groups": {
      "member_group": { "enabled": true },
      "competition_group": { "enabled": true }
    },
    "content_style": {
      "moments_tone": "熟人自然"
    }
  }
}
```

确认：

- 是否返回 200
- 是否保存成功
- GET 后是否能回显

### 5. 前端门店资料页

确认：

- 页面不再显示 `加载门店信息失败`
- 基础门店资料可加载
- AI 运营画像字段可显示
- 会员群 / 竞技群可勾选
- 保存后刷新仍能回显

### 6. Workbench 降级

- Workbench 不报错
- `profile_context` 为空也能正常渲染

## 四、可能根因参考

重点检查以下常见原因：

### 根因 A：migration 未执行

典型报错：

```text
column stores.operation_profile does not exist
```

处理：

- 执行本地 migration
- 重启后端
- 再测 GET / PUT

### 根因 B：schema 字段类型不兼容

例如：

- `operation_profile` 返回 dict，但 schema 期望其他类型
- `Any = None` 在项目 Pydantic 配置下不兼容
- response validation 失败

处理：

- 按项目 schema 风格修正类型
- 保证 GET / PUT 正常

### 根因 C：前端解析异常

例如：

- `operation_profile` 为 null 时前端没有兜底
- 嵌套字段不存在时报错
- 保存时传了不兼容结构

处理：

- 前端增加默认空结构
- 解析函数安全兜底

### 根因 D：API 路径 / 认证问题

如果 `/stores/me` 不是 500，而是 401/403/404，需要区分处理。
