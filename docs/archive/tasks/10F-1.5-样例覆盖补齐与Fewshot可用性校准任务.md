### 任务 4：重新评估 suitable_for_fewshot

请逐条审查 `workbench-结构化优质样例库.yaml` 中所有样例。

不要默认全部 `true`。

适合 `suitable_for_fewshot: true` 的样例应该满足：

1. 内容短，150-350 字内
2. 可泛化到类似场景
3. 不依赖大量具体门店数据
4. 不包含过多占位字段
5. 不会带偏模型乱编
6. 语气自然，行业感强
7. 可作为运行时正例

应改为 `suitable_for_fewshot: false` 的样例包括：

1. 长方案类
2. 数据依赖强
3. 复盘/日报占位字段过多
4. 管理机制较复杂
5. 更适合测试或产品大脑沉淀，不适合运行时注入
6. 可能让模型输出过长的样例

要求：

- 不要为了数量好看全设 true
- 最终 true 数量建议控制在 12-18 条
- false 样例仍可保留，用于产品大脑、测试或后续人工参考

---

### 任务 5：新增 few-shot 使用策略字段

请为每条优质样例增加以下字段：

```yaml
fewshot_use_case:
  - "runtime_positive_example"
  - "product_brain_reference"
  - "regression_reference"

injection_style: "short_snippet" # 可选：short_snippet / rule_only / not_runtime
```

字段说明：

### fewshot_use_case

可多选：

- `runtime_positive_example`：适合后续运行时 few-shot 正例
- `product_brain_reference`：适合产品大脑沉淀
- `regression_reference`：适合作为回归测试参考

### injection_style

只能选：

- `short_snippet`：可注入短片段
- `rule_only`：不注入正文，只提炼规则
- `not_runtime`：不建议运行时注入

要求：

1. `suitable_for_fewshot: true` 的样例，通常应包含 `runtime_positive_example`，且 `injection_style` 为 `short_snippet`。
2. `suitable_for_fewshot: false` 的样例，通常 `injection_style` 为 `rule_only` 或 `not_runtime`。
3. 日报 / PK / 长方案类样例可以保留，但更可能是 `rule_only` 或 `not_runtime`。
