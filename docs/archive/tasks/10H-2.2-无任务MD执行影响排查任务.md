# 10H-2.2：无任务 MD 执行影响排查与代码差异审计任务

## 任务定位

你现在只负责【10H-2.2：无任务 MD 执行影响排查与代码差异审计】。

本任务不是新功能开发，也不是继续修 bug，而是一次“安全审计 / 影响排查”。

背景：

在 10H-2 阶段，曾经有一次没有正式任务 MD 的情况下，仅基于短提示词执行了修复任务。随后发现 10H-2 报告声称已修复 `user_intent` 自动填入，但浏览器截图复验显示实际未修复。因此需要单独开一个审计任务，确认那次“无任务 MD 执行”是否对项目造成了不必要、超范围或错误影响。

当前 10H-2.1 正在执行或已执行，用于修复真实的 `user_intent` 未填入问题。  
10H-2.2 的重点不是重复修复，而是检查：

1. 无任务 MD 执行到底改了什么
2. 是否有超范围改动
3. 是否有错误报告或假验收
4. 是否对旧 4 个 Tab、岗位工作台、导航、Workbench 状态造成影响
5. 是否需要回滚、补丁或重新整理报告
6. 是否为后续流程增加防护规则

## 三、核心审计目标

### 目标 1：确认无任务 MD 执行改了哪些文件

请使用 git 工具和文件历史尽可能判断：

1. 10H-2 阶段实际修改了哪些文件
2. 是否只有报告里写的 `generate/page.tsx`
3. 是否额外修改了：

   - `role-workbench-config.ts`
   - `sidebar.tsx`
   - `mobile-nav.tsx`
   - 类型文件


如果项目没有 git 或 diff 不完整，请说明原因，并改用文件内容对照。

### 目标 3：检查 10H-2 报告是否有不准确结论

重点检查：

1. 报告说“4 张卡片跳转填参全部通过”，是否只是静态检查，而不是浏览器真实验证
2. 报告说“user_intent 已修复”，是否与截图复验冲突
3. 报告是否写明真实 URL、textarea 绑定 state、浏览器验证方式
4. 报告是否误把“配置有 userIntentTemplate”当作“页面真实填参成功”
5. 是否需要在审计报告中明确标记旧 10H-2 报告不可作为最终验收依据

---

### 目标 4：检查 generate/page.tsx 当前状态是否安全

重点检查：

1. `role_workbench` 分支是否只处理来自岗位工作台的跳转
2. 普通用户打开 `/dashboard/generate` 是否不会被错误预填
3. 普通切换旧 4 个 Tab 是否仍按原逻辑
4. `switchTab` 是否仍用于普通 Tab 切换
5. `workbenchIntent` 或 textarea 实际绑定 state 是否唯一清楚
6. URL 参数异常是否安全忽略
7. 是否存在无限 useEffect / 重复覆盖 / 状态竞争
8. 是否存在用户输入后被 URL 参数二次覆盖的问题
9. 是否有残留调试代码或 console 噪音
10. 是否仍不自动生成
