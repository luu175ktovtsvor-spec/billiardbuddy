# 阶段 7B：海报历史接入任务文档

请先阅读项目根目录中的：

1. `CLAUDE.md`
2. `architecture-design.md`
3. `docs/tasks/阶段7A-整体产品冒烟测试与问题清单.md`

你现在只负责【阶段 7B：海报历史接入】。

当前项目状态：

- 阶段 7A 整体冒烟测试已完成
- 唯一 P0：首页 `/` 返回 500 已通过清理 `.next` 缓存解决
- 当前 MVP 无 P0 阻断问题
- 核心流程已经跑通：
  - 注册 / 登录
  - 门店资料
  - Logo / 二维码上传
  - AI 文案生成
  - 生成历史
  - 海报生成
  - 海报预览 / 打开 / 复制 / 下载

当前阶段目标：

让【海报生成】也进入【生成历史】闭环。

也就是：

用户生成海报  
→ 后端写入 `generations` 表  
→ 海报接口返回 `generation_id`  
→ 历史页面能看到海报记录  
→ 历史详情能展示海报图片  
→ 可以打开原图 / 复制链接 / 下载图片

本阶段是对已有功能的打磨，不做新大模块。

---

## 一、本阶段优先修复的问题

来自 7A 冒烟测试的 P1 问题：

### P1-3：海报生成不写 generations 表

现状：

- `/api/v1/posters/generate` 可以生成海报
- 返回 `poster_url`
- 但没有写入 `generations` 表

目标：

- 海报生成成功后，写入 `generations` 表

建议写入：

```text
type = "poster"
sub_type = template
input_params = 请求参数
prompt_used = ""
result = poster_url
model_used = "pillow"
tokens_used = 0
store_id = 当前门店 ID
user_id = 当前用户 ID
```

---

### P1-4：PosterGenerateResponse 不含 generation_id

现状：

```json
{
  "poster_url": "/uploads/posters/xxx.png",
  "template": "daily_invite",
  "created_at": "2026-05-10T21:27:09Z"
}
```

目标：

```json
{
  "generation_id": "uuid",
  "poster_url": "/uploads/posters/xxx.png",
  "template": "daily_invite",
  "created_at": "2026-05-10T21:27:09Z"
}
```

## 五、后端修改要求

### 1. PosterGenerateResponse 增加 generation_id

修改：

```text
server/schemas/poster.py
```

增加：

```python
generation_id: UUID
```

响应字段：

```python
class PosterGenerateResponse(BaseModel):
    generation_id: UUID
    poster_url: str
    template: str
    created_at: datetime
```

---

### 2. poster_service 写入 generations 表

修改：

```text
server/services/poster_service.py
```

要求：

1. 海报图片成功保存后，再写入 `generations` 表。
2. 写入失败时，需要考虑是否删除已生成图片。P0 阶段可先不删除，但要记录日志。
3. 写入 Generation 时必须使用当前 `user.id` 和 `store.id`。
4. 不允许前端传 `store_id`。
5. 不允许前端传 `user_id`。
6. `result` 字段存储 `poster_url`。
7. `model_used` 固定为 `pillow`。
8. `tokens_used` 固定为 `0`。
9. `prompt_used` 使用空字符串或 `None`，不要写假 Prompt。
10. 返回 response 时带上新生成的 `generation_id`。

---

### 3. generation 历史接口支持 poster 类型

阶段 5A 的历史后端接口已经支持按 `type` / `sub_type` 查询。

本阶段需要确认：

- `GET /api/v1/generations?type=poster` 可返回海报记录
- `GET /api/v1/generations?type=poster&sub_type=daily_invite` 可返回对应模板
- 详情接口可返回海报记录详情

如果后端当前类型没有枚举限制，则无需改。

如果前端类型定义有限制，需要前端扩展。

### 3. generation-history 类型支持 poster

修改：

```text
web/src/types/generation-history.ts
```

当前可能是：

```ts
export type GenerationType = "copywriting" | "activity"
export type GenerationSubType = "moments" | "group_notice" | "planning"
```

需要扩展为：

```ts
export type GenerationType = "copywriting" | "activity" | "poster"

export type GenerationSubType =
  | "moments"
  | "group_notice"
  | "planning"
  | "daily_invite"
  | "activity_promo"
  | "tournament_notice"
```

---

### 4. 历史页面支持 poster 展示

修改：

```text
web/src/app/dashboard/history/page.tsx
```

要求：

1. 筛选区增加：
   ```text
   海报
   ```

2. 筛选映射：
   ```text
   type=poster
   ```

3. 列表中 `type="poster"` 时：
   - 类型标签显示：海报
   - 摘要显示：海报链接或“海报图片”
   - 模型显示：pillow
   - tokens 显示：0 或隐藏

4. 详情中 `type="poster"` 时：
   - 不把 poster_url 当普通长文本显示
   - 使用 `api.resolveUrl(content)` 展示海报图片
   - 显示完整图片预览
   - 提供：
     - 打开原图
     - 复制链接
     - 下载图片

5. `content` 字段仍然是后端返回的内容字段。
   - 对 poster 来说，`content` 实际是 `poster_url`
   - 前端根据 `type === "poster"` 决定渲染为图片

6. 不展示：
   - `prompt_used`
   - `store_id`
   - `user_id`
