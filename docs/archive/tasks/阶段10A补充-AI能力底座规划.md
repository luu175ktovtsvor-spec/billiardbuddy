## 二、为什么要规划 AI 能力底座

当前项目已经接入 DeepSeek 文本模型，能生成：

- 朋友圈文案
- 群公告
- 活动方案
- 海报文案

但未来产品方向会扩展到：

- 台球房经营场景内容生成
- 助教推广内容
- 助教招聘内容
- 搭子局 / 竞技局话术
- 周赛 / 月赛内容
- 大客户维护话术
- 前厅 SOP
- AI 图片背景
- 助教图片美化
- 助教宣传图
- 视频发布素材包
- 后期 AI 视频 / 自动剪辑

所以需要提前设计一个清晰的 AI 能力底座，避免以后接图片、视频、素材库时推翻重来。

核心原则：

```text
架构一次性想清楚
功能分阶段落地
```

不是现在一次性把所有 AI 图片 / 视频功能都开发完，而是先把能力抽象和未来扩展路径设计好。

## 三、AI 能力分层设计

请在报告中规划以下能力层。

---

### 1. TextProvider：文本模型能力

当前已有能力：

- DeepSeek
- 朋友圈文案
- 群公告
- 活动方案

未来文本能力应扩展到：

- 团购客户转化话术
- 助教推广文案
- 助教招聘文案
- 助教每日任务
- 助教客户邀约话术
- 搭子局 / 竞技局话术
- 教练赛事文案
- 周赛 / 月赛报名文案
- 大客户维护话术
- 前厅 SOP 文案
- 短视频标题
- 视频号文案
- 抖音文案
- 小红书文案
- 拍摄脚本
- 封面文案

请说明：

- TextProvider 应统一封装文本模型调用。
- 当前 DeepSeek 是 TextProvider 的第一个实现。
- 未来可以替换模型或增加其他文本模型，而不影响业务层。
- 业务层不应该直接依赖 DeepSeek。
- 不同经营场景应该通过 PromptBuilder 生成不同 prompt。

---

### 2. ImageProvider：图片模型能力

未来可能接入：

- Nano Banana / Gemini 图片模型
- GPT Image
- 即梦 / 火山引擎
- 通义万相
- 其他图片生成 / 图片编辑模型

ImageProvider 未来服务场景：

- 海报背景生成
- 门店活动背景图
- 赛事海报背景图
- 招聘海报背景图
- 助教照片美化
- 助教宣传图
- 助教预约海报
- 朋友圈配图
- 短视频封面图
- 门店氛围图

请重点说明一个原则：

```text
不要让 AI 图片模型直接生成完整商业海报。
```

正确策略：

```text
AI 图片模型生成背景 / 氛围图 / 美化图
+
程序叠加真实中文、Logo、二维码、价格、门店地址、电话
=
最终可发布素材
```

原因：

- 中文容易错
- 价格不能错
- 二维码不能错
- Logo 不能变形
- 门店地址和电话必须准确
- 助教姓名、标签、预约信息必须准确

当前 Pillow 海报合成能力不应该废弃，而应该继续作为最终合成层。

---

### 3. VideoProvider：视频模型能力

视频能力先做规划，不要近期开发。

请按短期 / 中期 / 长期规划。

#### 短期

不做 AI 视频生成，只做：

```text
视频发布素材包
```

用户上传门店视频 / 助教视频后，系统生成：

- 视频标题
- 朋友圈视频配文
- 抖音文案
- 视频号文案
- 小红书标题
- 封面标题
- 话题标签
- 拍摄建议
- 下一条视频选题

#### 中期

可以考虑：

- 视频封面图生成
- 视频脚本文案
- 分镜建议
- 素材归档
- 视频素材库

#### 长期

再考虑：

- AI 视频生成
- AI 自动剪辑
- 多平台发布辅助
- 一键发布

请说明为什么视频不能太早做：

- 成本高
- 生成慢
- 稳定性不够
- 人物一致性难
- 真人肖像和授权风险更高
- 视频文件大
- 存储和带宽压力大
- 审核风险更高

---

### 4. PromptBuilder：经营场景 Prompt 编排层

当前系统更像按内容类型生成：

```text
生成朋友圈
生成群公告
生成活动方案
```

未来应该升级成按经营场景生成：

```text
团购转私域
助教推广
助教招聘
搭子局 / 竞技局
周赛 / 月赛
大客户维护
前厅 SOP
门店视频发布
```

每个经营场景可以输出多种内容：

- 朋友圈
- 群公告
- 私聊话术
- 海报文案
- 视频标题
- 短视频配文
- 执行 SOP
- 员工提醒
- 店长待办

请说明这样做的价值：

- 不再像普通 AI 文案工具
- 不需要用户自己写复杂提示词
- 直接围绕台球房经营目标生成内容
- 方便未来接图片 / 视频能力
- 方便以后做“经营场景一键生成”

---

### 5. StorageProvider：素材存储抽象

当前系统使用：

```text
server/uploads/
```

未来可能接入：

- 阿里云 OSS
- 腾讯云 COS
- AWS S3
- Cloudflare R2
- 其他对象存储

StorageProvider 应统一管理：

- 门店 Logo
- 微信二维码
- 海报
- AI 生成背景图
- 助教照片
- 助教宣传图
- 门店照片
- 门店视频
- 视频封面
- 视频发布素材包

请说明：

- 当前本地 MVP 可以继续使用 uploads。
- 上线试用期也可以先本地持久化。
- 商业化后再接 OSS / COS / S3。
- 设计上要避免以后从本地 uploads 迁移 OSS 时大量改业务代码。
- 本阶段只规划，不开发。

## 四、未来 AI 工作流设计

请在报告中给出典型工作流。

---

### 工作流 1：AI 海报背景生成

```text
选择经营场景
→ 系统生成图片 prompt
→ ImageProvider 生成背景图
→ 程序叠加标题、正文、Logo、二维码、门店信息
→ 保存到 StorageProvider
→ 写入生成历史
```

适用场景：

- 活动促销
- 充值活动
- 周赛 / 月赛
- 搭子局
- 招聘助教
- 助教预约

---

### 工作流 2：助教宣传图生成

```text
选择助教
→ 读取助教资料和照片
→ 选择用途：朋友圈 / 群推荐 / 预约海报 / 封面
→ ImageProvider 美化照片或生成背景
→ 程序叠加助教昵称、标签、预约话术、门店二维码
→ 保存并进入历史
```

注意：

- 使用真实助教照片。
- 不建议凭空生成虚构助教。
- 涉及真人照片时需要门店获得授权。
- AI 只负责美化 / 背景 / 风格，不应篡改关键信息。

---

### 工作流 3：视频发布素材包

```text
上传门店视频 / 助教视频
→ 系统读取视频基本信息
→ TextProvider 生成标题、配文、话题、封面文案
→ 可选 ImageProvider 生成封面背景
→ 保存为视频素材发布包
```

短期先做标题和配文，不做 AI 视频生成。

---

### 工作流 4：经营场景一键生成

```text
选择经营目标：团购转私域 / 助教推广 / 搭子局 / 周赛
→ PromptBuilder 生成多内容任务
→ TextProvider 生成文案和话术
→ ImageProvider 生成海报背景或封面
→ 程序合成海报
→ 保存到历史 / 素材库
```

目标：

```text
不是让用户自己想提示词
而是系统按球房经营目标自动生成一套可执行内容
```
