## 六、MVP 范围建议

请重点比较两种方案：

### 方案 A：新建独立岗位工作台页面

例如：

`/dashboard/workbench`

优点：

- 信息架构清晰
- 不挤压现有 generate 页面
- 后续可扩展成真正岗位系统

缺点：

- 需要新增页面和导航
- 初期工作量稍大

### 方案 B：继续在现有 generate 页面内增加岗位工作台区域

优点：

- 工作量小
- 快速上线
- 复用现有 Workbench

缺点：

- 页面可能越来越复杂
- AI 工作台和岗位工作台层级容易混乱

请结合当前代码实际，给出推荐。

我的倾向：

> 10H-1 先在现有 generate 页面中做轻量岗位工作台入口，或新建一个非常轻的岗位工作台页面，但所有任务最终仍复用 Workbench 填参生成。不要一上来做复杂独立系统。

## 七、岗位任务卡片设计

每个岗位任务卡片应包含：

```ts
{
  id: string
  role: Role
  title: string
  description: string
  userIntentTemplate: string
  targetCustomerType: TargetCustomerType
  outputPackage: OutputPackage[]
  sceneTags: string[]
  requiredProfileModules: string[]
  priority: "P0" | "P1" | "P2"
}
```

点击卡片后：

1. 自动切到 AI 工作台 / Workbench
2. 自动填入 role
3. 自动填入 target_customer_type
4. 自动填入 output_package
5. 自动填入 user_intent
6. 如门店画像缺少 requiredProfileModules，显示补充提示，但不阻塞生成

## 八、门店画像联动

岗位工作台应使用 10G 已完成能力：

### 1. profile_context

生成时继续由 Workbench 注入。

### 2. profile_suggestions

如果任务需要助教体系、会员群、竞技群、桌型设备等资料，但门店资料未完善，应提示用户补充。

### 3. 门店资料完整度

岗位工作台首页可显示轻提示：

```text
AI 运营画像完整度 83%，已适合生成大部分内容。
建议补充：赛事活动、助教预约规则。
```

### 4. 私域群矩阵

会员群 / 竞技群 / 搭子群 / 助教客户群必须作为岗位任务的重要场景。

### 5. 桌型设备

乔氏 / 独牙 / 斯诺克 / 普通台球桌应进入教练/赛事、竞技客户、门店特色任务。
