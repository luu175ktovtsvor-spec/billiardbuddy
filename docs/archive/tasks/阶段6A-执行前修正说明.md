## 二、暂时不要写入 generations 表

你原计划把海报生成记录写入 `generations` 表：

```text
type = "poster"
result = poster_url
model_used = "pillow"
```

这一点本阶段先不要做。

原因：

1. 阶段 5B 的生成历史前端目前只适配：
   - `copywriting`
   - `activity`
2. 现在如果写入 `type="poster"`，历史页面的“全部”列表可能出现前端还没适配的类型。
3. 阶段 6A 当前目标只是跑通后端海报合成最小闭环，不要求历史记录。

所以本阶段要求：

- 不写入 `generations` 表
- 不新增 `poster_records` 表
- 不新增数据库迁移
- 只返回 `poster_url`
- 等 6B 海报前端页面完成后，再统一设计海报历史记录

## 三、Logo / 二维码路径解析必须谨慎

门店里的 `logo_url` / `qrcode_url` 可能是类似：

```text
/uploads/logos/xxx.png
/uploads/qrcodes/xxx.png
```

请注意路径解析时不要拼成：

```text
server/uploads/uploads/logos/xxx.png
```

请实现安全解析逻辑：

1. 如果路径以 `/uploads/` 开头，应去掉 `/uploads/` 前缀，再拼到 `server/uploads/` 下。
2. 如果路径不是 `/uploads/` 开头，不要当作任意本地路径读取。
3. 必须通过 `resolve()` 检查最终路径仍然位于 `server/uploads/` 内。
4. 不允许读取 uploads 目录之外的任何文件。
5. Logo / 二维码加载失败时，只跳过该元素，不要让海报生成失败。
