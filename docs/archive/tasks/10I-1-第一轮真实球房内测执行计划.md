---

## 1. 阶段定位

10I-1 **不是开发任务**，不写代码、不改数据库、不改 Prompt、不调用 DeepSeek。

10I-1 的定位是：

> 在 10I-0 整理好启动包和模板之后，把“第一次去球房具体怎么执行”规划到可以直接照着做的程度。

10I-1 完成后，就应该**正式去真实球房做第一轮内测**，不再继续只在电脑里加功能。

---

## 2. 为什么做完 10I-1 后就应该去球房

当前产品状态：

- 6 岗位 44 张任务卡片全部就位
- 102 条真实调用测试通过（71 PASS / 1 BASIC_PASS / 0 FAIL）
- 岗位工作台跳转填参链路稳定
- inputHints 引导可用
- profile_context 注入 100%
- 核心安全指标全部通过
- 内测启动包、每日观察模板、录音转写模板全部就绪

**当前阻塞 10I 阶段的不再是代码或文档，而是缺少真实球房数据。**

继续在电脑里加功能的意义已经很小——不知道真实球房老板/店长/前厅到底怎么说话、怎么工作、怎么看这些 AI 输出，加再多功能也可能是自嗨。

第一轮 1 天内测的核心目标是**验证方向**，不是完整覆盖。

---

## 3. 第一轮建议观察时长

**1 天。**

第一轮不做一周，不做 3 天连续观察。原因是：

- 第一轮的目标是验证方向，不是完整覆盖
- 1 天足够看出：门店资料能否真实填写、岗位工作台是否一眼能懂、哪些卡片真实有用、AI 输出能不能直接发
- 第一天回来后由 ChatGPT 审查记录，再决定是否需要 3 天连续观察或一周观察
- 如果方向有问题，1 天后就能发现并调整，不会浪费 3-7 天

## 6. 第一阶段：门店资料填写（14:30-15:15，45 min）

### 操作方式

由操作者（产品方）在电脑上操作前端页面，向门店人员**提问式引导填写**。门店人员口述，操作者代为填写。

### 填写顺序

| # | 模块 | 核心问题 | 为什么重要 |
|---|------|---------|-----------|
| 1 | 基础信息 | 门店叫什么？在哪个城市？什么定位？多少张台？ | 所有生成的基础上下文 |
| 2 | 客户结构 | 主要是什么客户？团购多还是老客多？最想转化哪类？ | 决定内容策略和语气 |
| 3 | 私域群矩阵 | 有哪些群？会员群/竞技群/搭子群/助教客户群/赛事群/员工群？ | 决定生成内容的发布渠道 |
| 4 | 助教体系 | 有助教吗？几位？偏服务体验还是技术陪练？能做PK吗？ | 决定助教相关卡片是否可用 |
| 5 | 桌型设备 | 有什么桌型？普通台/独牙/乔氏/斯诺克？各几张？ | 防止 AI 编造设备 |
| 6 | 赛事活动 | 有固定周赛吗？做轻竞技/台费局吗？ | 决定赛事相关卡片可用性 |
| 7 | 内容风格 | 朋友圈什么语气？想写优惠吗？有什么禁用词？ | 决定生成语气 |
| 8 | 团购/价格 | 做美团/抖音团购吗？有会员体系吗？ | 决定前厅话术方向 |

### 记录要点

- 每个模块门店人员是否有迟疑/不清楚的地方
- 是否有当前画像字段无法描述的实际情况
- 完整度最终达到多少（建议 ≥70%）

### 测试操作规范

#### 门店人员亲自点的 7 张卡

- 让门店人员**自己看卡片标题和描述**，不要先解释

- 生成后**不要先给评价**，让门店人员自己看生成结果

#### 操作者代为测试的 5 张卡

- 由操作者在 textarea 中模拟一个合理的真实场景
- 生成后把结果给对应岗位的门店人员看，请其评价
- 如果门店人员说“我们不会这么说”，追问“你们会怎么说”

| 观察点 | 记录方式 |
|--------|---------|
| 下午到晚间最操心什么 | 观察记录 |
| 每天第一件事做什么（如果是上午到店） | 访谈或观察 |
| 怎么安排各岗位工作 | 观察记录 |
| 有没有发朋友圈（频率、内容、语气） | 截图/抄录 |
| 在各个群里发了什么消息 | 截图/抄录 |
| 怎么跟进老客户（微信私聊？电话？） | 观察/访谈 |
| 怎么写日报（格式、发给谁） | 索取样本（脱敏后） |
| 怎么处理投诉/客户不满 | 观察记录 |

### 8.2 观察前厅

| 观察点 | 记录方式 |
|--------|---------|
| 团购客户来了怎么接待（开场白、引导、加微信） | 录音/观察记录 |
| 客户问会员/助教/价格怎么回答 | **必须记录原话** |
| 怎么引导客户进群 | 观察记录 |

### 8.3 观察助教管理

| 观察点 | 记录方式 |
|--------|---------|
| 今天具体做了什么（安排助教任务？推广？PK？招聘？） | 观察/访谈 |
| 怎么推广助教服务（什么渠道、什么话术） | 观察记录 |
| 助教朋友圈/短视频拍了什么、发了什么 | 索取截图（脱敏后） |
| 助教上钟流程（签到、计时、结账） | 观察记录 |
| 助教预约流程（线上/线下/到店后） | 访谈 |
| 客户怎么表达对助教的需求 | **必须记录原话** |

### 8.4 观察运营/内容

| 观察点 | 记录方式 |
|--------|---------|
| 今天有没有发朋友圈/短视频 | 截图/抄录 |
| 不同群发的内容有什么差别 | 截图/抄录 |
| 活动海报怎么做（工具、流程、文案来源） | 访谈 |
| 怎么规划本周/本月内容 | 访谈 |

### 8.5 观察教练/赛事

| 观察点 | 记录方式 |
|--------|---------|
| 今天有没有周赛/活动 | 观察记录 |
| 周赛公告长什么样（格式、渠道、语气） | 截图/抄录 |
| 怎么组织报名（接龙？私聊？群公告？） | 观察记录 |
| 赛后战报怎么写（如有比赛） | 索取样本 |
| 怎么撮合约球搭子 | 观察/访谈 |

### 8.6 记录客户真实问题

用每日观察记录模板第 7 节的表格，记录客户问过的所有问题。

**特别关注以下类型的问题：**
- 怎么收费、有没有优惠、会员怎么办
- 有没有助教、助教怎么约、多少钱
- 有没有人一起打、能不能教我
- 环境怎么样、有没有停车、开到几点
- 能不能包场、能带多少人
- 有什么活动、最近有没有比赛
- **任何超出上述类型的问题（可能是新场景）**

### 8.7 记录私域群真实消息

用每日观察记录模板第 8 节的表格，记录各群的真实消息。

**优先记录：**
- 会员群的空台提醒、活动通知格式
- 竞技群的约局通知、接龙格式
- 助教客户群的推广频率和语气
- 员工群的管理通知格式

## 10. 第一天必须回传给 ChatGPT 的资料

### 必须回传（7 项）

| # | 资料 | 格式 | 要求 |

| 4 | 门店人员对 AI 输出的真实评价 | 文字记录（原话） | 正面和负面都要记录 |
| 5 | 发现的新行业信息/新岗位任务/新业务规则 | 清单 | 按录音转写模板第 4-5 节格式 |
| 6 | 明显不准/风险表达/低俗表达/乱编内容的 AI 输出 | 清单 + 原始输出 | 如有，标注严重程度 |
| 7 | 录音转写整理文档（如有录音） | Markdown（按模板填写） | 24 小时内完成 |

### 可回传

- 页面截图（生成过程、任务卡片、门店资料页）
- 普通生成结果（门店认为可用或稍改可用的）
- 用户口头反馈摘要（非逐字记录）
- 群消息脱敏摘要

### 只存档

- 原始录音文件（脱敏后删除）
- 没有新信息的完整转写全文
- 正常环境启动日志
- 无异常的截图

如果第一天出现以下情况，**暂停后续内测**，先回传 ChatGPT 审查后决定下一步：

- 超过 50% 输出被门店人员认为“完全不能用”
- 出现严重风险表达（赌博/追分/低俗）
- 门店人员完全看不懂岗位工作台
- 门店资料填写严重不符合球房实际情况

## 13. 已知边界问题重点观察

| # | 问题 | 第一天观察重点 |
|---|------|--------------|
| 1 | 大白话“美式那个”偶发输出“美式台” | 真实门店人员是否会说“美式台”，AI 是否正确转译为“普通台球桌/店里台子” |
| 2 | 助教管理岗位 inputHints 覆盖率偏低（1/8） | 助教管理在使用时是否因为没有引导而感到困惑 |
| 3 | 门店人员是否会乱填门店资料导致测试失真 | 门店填写时是否认真理解每个字段的含义 |

### 防止测试失真的措施

- 门店资料填写阶段，由操作者**逐一提问引导**，不让门店人员自己随便填
- 桌型设备只勾选门店实际拥有的，不要在“不确定”的情况下勾选
- 私域群矩阵只勾选门店实际运营的群类型
- 禁用表达和内容风格由门店人员口述确认
- 如门店人员说“随便填就行”，操作者应追问“实际上是什么情况”并如实填写
