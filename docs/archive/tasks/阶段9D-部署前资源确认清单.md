## 三、需要确认的现实资源

请按以下项目逐项检查并输出“已准备 / 未准备 / 待用户确认”。

### 1. 服务器

需要确认：

```text
云服务器是否已购买
服务器公网 IP
服务器系统版本
CPU / 内存 / 硬盘
是否能 SSH 登录
是否有 root 或 sudo 权限
```

推荐最低配置：

```text
2 核 CPU
4 GB 内存
40 GB SSD
Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS
```

更稳配置：

```text
2 核 CPU
8 GB 内存
80 GB SSD
Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS
```

---

### 2. 域名

需要确认：

```text
是否已有域名
准备用哪个子域名部署
是否完成备案，若使用中国大陆服务器
是否能修改 DNS 解析
```

推荐域名结构：

```text
https://app.example.com
```

本阶段建议同域名部署：

```text
前端：https://app.example.com
API：https://app.example.com/api/v1/...
uploads：https://app.example.com/uploads/...
```

---

### 3. 如果暂时没有域名

请提供 IP 试用方案：

```text
http://服务器公网IP
```

注意：

- 没有域名时，HTTPS 配置会比较麻烦。
- 浏览器可能提示不安全。
- CORS_ORIGINS 可以临时配置为：
  http://服务器公网IP
- NEXT_PUBLIC_API_URL 可以临时配置为：
  http://服务器公网IP
- 适合内部短期试用，不适合正式对外。

---

### 4. HTTPS / SSL

需要确认：

```text
是否有域名
是否准备使用 Certbot / Let's Encrypt
服务器 80 / 443 端口是否开放
```

建议：

- 有域名：部署后使用 Certbot 配置 HTTPS。
- 无域名：先 HTTP 内部试用，后续再切 HTTPS。
- 正式对外必须 HTTPS。

---

### 5. 生产环境变量

请列出部署前需要用户准备的真实值，但不要让用户直接在报告中写出来。

后端需要准备：

```env
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432
POSTGRES_USER=billiards
POSTGRES_PASSWORD=<强密码>
POSTGRES_DB=billiards

SECRET_KEY=<至少32位随机字符串>
ACCESS_TOKEN_EXPIRE_MINUTES=10080

CORS_ORIGINS=https://app.example.com

TEXT_MODEL_PROVIDER=deepseek
TEXT_MODEL_NAME=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=<真实 DeepSeek Key>

UPLOAD_DIR=/opt/billiards-ai/uploads
```

前端需要准备：

```env
NEXT_PUBLIC_API_URL=https://app.example.com
```

如果 IP 试用：

```env
CORS_ORIGINS=http://服务器公网IP
NEXT_PUBLIC_API_URL=http://服务器公网IP
```

---

### 6. 密钥安全确认

请提醒用户：

- 不要把 DeepSeek Key 发到公开地方。
- 不要把真实 `.env` 提交到 Git。
- 不要把生产 `SECRET_KEY` 发到聊天里。
- 可以让服务器上的 `server.env` 保存真实值。
- `.env.example` 只能放占位值。
- 日志中不要打印密钥。

---

### 7. 数据库准备

需要确认：

```text
生产数据库名
生产数据库用户
生产数据库密码
PostgreSQL 是否使用 Docker
数据卷挂载位置
数据库备份目录
```

推荐：

```text
数据库名：billiards
数据库用户：billiards
密码：强随机密码
数据目录：/opt/billiards-ai/postgres-data
备份目录：/opt/billiards-ai/backups/db
```

---

### 8. uploads 准备

需要确认：

```text
uploads 目录位置
是否持久化
是否由 Nginx 直接 alias
是否有备份目录
```

推荐：

```text
/opt/billiards-ai/uploads
/opt/billiards-ai/backups/uploads
```

注意：

- uploads 存 Logo、二维码、海报。
- 不能随着代码发布被覆盖。
- 试用期可以本地持久化。
- 商业化后建议迁移 OSS / S3 / R2。

---

### 9. 防火墙和端口

请确认端口规划：

```text
80：开放给公网
443：开放给公网
22：SSH，建议限制来源 IP
3000：只允许本机
8000：只允许本机
5432：只允许本机
```

如果使用云厂商安全组：

```text
入站规则只开放 22 / 80 / 443
不要开放 3000 / 8000 / 5432
```

---

### 10. 备份策略

请确认：

数据库备份：

```text
每天至少一次
保留最近 7-14 天
备份到 /opt/billiards-ai/backups/db
定期下载到本地或对象存储
```

uploads 备份：

```text
每天至少一次
保留最近 7-14 天
备份到 /opt/billiards-ai/backups/uploads
```

必须提醒：

```text
哪怕只是试用，也要备份数据库和 uploads。
```

## 四、部署模式选择

请根据用户当前资源情况，给出建议：

### 情况 A：已有服务器 + 有域名

建议进入正式 9E 部署执行。

### 情况 B：已有服务器 + 暂无域名

可以先用 IP 做内部试用部署，但要说明：

- 暂时没有 HTTPS
- 只适合熟悉用户测试
- 后续绑定域名后需要重新配置 CORS / NEXT_PUBLIC_API_URL / Nginx / SSL

### 情况 C：没有服务器

先不要进入 9E。先让用户购买服务器。

### 情况 D：服务器配置太低

如果低于 2C4G，不建议部署当前版本。
