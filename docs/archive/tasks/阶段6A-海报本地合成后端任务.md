当前阶段目标：

实现“海报本地合成”的后端最小闭环。

本阶段不接 AI 图片生成模型，不做 ImageProvider，不做在线设计器，只用：

本地静态背景图  
→ Pillow 合成文字 / Logo / 二维码  
→ 生成海报图片  
→ 保存到本地 uploads 目录  
→ 返回图片访问 URL  
→ 写入 generations 表或说明不写库的原因

本阶段重点是先跑通海报合成能力，为后续 AI 图片背景和前端海报页面打基础。

## 一、重要原则

本阶段只做 P0 海报合成，不做复杂设计器。

请严格遵守：

1. 先用本地静态背景图，不接 AI 图片模型。
2. 商业信息文字必须由 Pillow 合成，不让 AI 直接生成带文字图片。
3. Logo / 二维码必须由 Pillow 叠加，不让 AI 生成 Logo 或二维码。
4. 第一版只做 3 个固定模板。
5. 不做拖拽编辑器。
6. 不做自由图层编辑。
7. 不做前端页面。
8. 不接 OSS。
9. 文件存储先用本地目录。
10. 不做 SSE。
11. 不做支付。
12. 不做配额拦截。

## 四、本阶段允许实现

请实现以下能力：

### 1. 海报模板枚举

第一版只做 3 个模板：

```text
daily_invite       日常约球海报
activity_promo     活动促销海报
tournament_notice  比赛/周赛海报
```

每个模板固定结构：

- 背景图
- 标题
- 副标题
- 活动/文案正文
- 门店名称
- 门店地址，可为空
- 联系电话，可为空
- Logo，可为空
- 二维码，可为空

---

### 2. 本地背景图

如果项目中没有设计好的背景图，可以先用 Pillow 生成 3 张简单的静态背景占位图，放到：

```text
server/assets/poster_backgrounds/
```

建议文件：

```text
daily_invite.png
activity_promo.png
tournament_notice.png
```

要求：

- 背景图尺寸统一 1080 x 1440
- 风格可以先简单：渐变色 / 深色台球氛围 / 简洁商务风
- 不需要特别精美，P0 阶段先跑通合成流程

注意：

- 不要下载外部图片。
- 不要引入版权不明素材。
- 不要生成复杂 AI 图片。

---

### 3. Pillow 合成服务

可以新增：

```text
server/services/poster_service.py
```

功能：

```python
async def generate_poster(
    db: AsyncSession,
    user: User,
    store: Store,
    request: PosterGenerateRequest,
) -> PosterGenerateResponse:
    ...
```

核心流程：

1. 校验模板类型
2. 读取本地背景图
3. 读取门店资料
4. 渲染标题
5. 渲染副标题
6. 渲染正文
7. 渲染门店名称
8. 渲染地址 / 电话
9. 如果门店有 Logo，则叠加 Logo
10. 如果门店有二维码，则叠加二维码
11. 保存生成图片到本地 `uploads/posters/`
12. 返回图片 URL

---

### 4. 海报生成 API

新增：

```text
POST /api/v1/posters/generate
```

入参建议：

```json
{
  "template": "daily_invite",
  "title": "今晚约一局？",
  "subtitle": "约上搭子，来店里打几杆",
  "content": "适合朋友局、下班放松、新手练球。",
  "extra_note": "可选补充说明"
}
```

出参建议：

```json
{
  "poster_url": "/uploads/posters/xxx.png",
  "template": "daily_invite",
  "created_at": "2026-05-11T10:00:00Z"
}
```

要求：

- 必须登录
- 必须有当前门店
- 必须使用当前门店资料
- 不允许前端传 `store_id`
- 不允许生成到其他门店
- 返回的 `poster_url` 必须能通过浏览器访问

---

### 5. Schema 设计

可以新增：

```text
server/schemas/poster.py
```

建议：

```python
class PosterGenerateRequest(BaseModel):
    template: Literal["daily_invite", "activity_promo", "tournament_notice"]
    title: str
    subtitle: str | None = None
    content: str
    extra_note: str | None = None

class PosterGenerateResponse(BaseModel):
    poster_url: str
    template: str
    created_at: datetime
```

字段限制建议：

- `title`：1-30 字
- `subtitle`：0-50 字
- `content`：1-200 字
- `extra_note`：0-200 字

## 六、文字渲染要求

Pillow 合成文字时请注意：

1. 支持中文。
2. 自动换行。
3. 避免文字超出画布。
4. 标题字体较大。
5. 副标题字体中等。
6. 正文字体清晰可读。
7. 门店名称要明显。
8. 地址和电话可以小一些。
9. 如果字段为空，不要渲染 `None`。
10. 如果地址/电话缺失，可以不显示，不要编造。

字体处理：

- 不要从系统复制或打包字体文件给用户。
- 可以优先尝试系统字体路径。
- 如果找不到中文字体，要有 fallback，并在报告中说明。
- 不要把字体文件提交到项目里。

## 七、Logo / 二维码叠加要求

门店资料中如果已有：

- `logo_url`
- `qrcode_url`

请读取对应本地文件并叠加到海报中。

要求：

1. Logo 可选，没有 Logo 不报错。
2. 二维码可选，没有二维码 不报错。
3. 叠加前自动缩放。
4. 保持图片比例。
5. 对异常图片做容错。
6. 不要让 Logo / 二维码遮挡主要文字。
7. 二维码附近可以加小字：“扫码联系 / 进群咨询”，但如果没有二维码则不显示。

## 九、是否写入 generations 表

本阶段有两个选择：

### 推荐方案：写入 generations 表

可以把海报生成也记录到 `generations` 表：

```text
type = "poster"
sub_type = template
input_params = 请求参数
prompt_used = null 或 ""
result = poster_url
model_used = "pillow"
tokens_used = 0
```

优点：

- 后续历史页可以扩展显示海报生成记录
- 不需要新增 `poster_records` 表
- 不需要数据库迁移

### 备选方案：本阶段不写库

只返回 `poster_url`，不记录历史。

如果你选择不写库，请说明原因。

建议第一版采用“写入 generations 表”，但如果当前 schema 或历史接口对 `type` 有严格枚举限制，请先说明风险，不要硬改。
