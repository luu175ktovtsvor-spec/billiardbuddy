你现在只负责【阶段 9B：生产环境配置文件整理】。

当前项目状态：

- 阶段 9A 已完成部署准备与上线方案报告。
- 推荐部署方案是：低成本单服务器试用版。
- 当前项目本地运行正常，但生产上线前发现 4 个配置风险点：
  1. `server/main.py` CORS 目前硬编码 localhost。
  2. `server/config.py` 中 SECRET_KEY 和数据库密码等生产配置需要从环境变量读取并更换强值。
  3. `web/src/lib/api.ts` 默认 API 地址是 localhost，生产环境需要通过 `NEXT_PUBLIC_API_URL` 配置。
  4. `docker-compose.yml` PostgreSQL 端口当前可能绑定所有网卡，生产建议仅监听 `127.0.0.1`。

当前阶段目标：

只整理生产环境配置，不开发新业务功能。

本阶段可以做少量必要配置代码调整，但必须严格限制范围，目标是让项目具备部署准备条件。

## 一、本阶段要解决的问题

### 问题 1：CORS 不能硬编码 localhost

当前如果 `server/main.py` 只允许：

```text
http://localhost:3000
```

上线后正式域名会被 CORS 拦截。

目标：

- CORS origins 从环境变量读取。
- 本地开发仍支持 localhost。
- 生产可配置正式域名。

建议环境变量：

```env
CORS_ORIGINS=http://localhost:3000,http://localhost:3001,https://your-domain.com
```

---

### 问题 2：生产 SECRET_KEY 不能用默认值

目标：

- `SECRET_KEY` / `JWT_SECRET_KEY` 必须从环境变量读取。
- `.env.example` 只写占位值。
- 不打印、不提交真实密钥。
- 如果项目当前使用 `SECRET_KEY`，沿用当前变量名，不要强行改名。
- 如果项目当前使用 `JWT_SECRET_KEY`，沿用当前变量名。

---

### 问题 3：前端 API 地址必须通过环境变量配置

当前前端生产环境必须能配置：

```env
NEXT_PUBLIC_API_URL=https://your-domain.com
```

或者：

```env
NEXT_PUBLIC_API_URL=https://api.your-domain.com
```

目标：

- 检查 `web/src/lib/api.ts` 是否优先读取 `process.env.NEXT_PUBLIC_API_URL`。
- 如果已有逻辑，不要重复改。
- 如果 fallback 是 localhost，可以保留为本地开发 fallback。
- 不要把生产域名写死进代码。

---

### 问题 4：PostgreSQL 端口生产不应暴露到公网

如果 `docker-compose.yml` 中有：

```yaml
ports:
  - "5432:5432"
```

生产建议改为：

```yaml
ports:
  - "127.0.0.1:5432:5432"
```

目标：

- 如果当前 compose 是开发用，可以新增注释说明。
- 如果要直接用于单服务器生产试用，建议改成只监听本机。
- 不要引入新的数据库服务。
- 不要改数据库结构。

## 六、配置修改要求

### 1. 后端 CORS

建议实现逻辑：

```python
cors_origins = settings.cors_origins
```

或者如果当前配置是字符串：

```python
CORS_ORIGINS=http://localhost:3000,http://localhost:3001,https://your-domain.com
```

后端解析成 list：

```python
["http://localhost:3000", "http://localhost:3001", "https://your-domain.com"]
```

要求：

- 本地默认允许 localhost:3000 / localhost:3001。
- 生产可通过 `.env` 增加正式域名。
- 不要使用 `allow_origins=["*"]` 作为生产默认。
- 不要把真实域名写死。

---

### 2. SECRET_KEY

要求：

- 从环境变量读取。
- `.env.example` 中使用占位值，例如：

```env
SECRET_KEY=replace-with-a-long-random-secret
```

或当前项目使用的变量名。

不要把真实 secret 写入任何文件。

---

### 3. DATABASE_URL

要求：

`.env.example` 中提供占位示例：

```env
DATABASE_URL=postgresql+asyncpg://postgres:replace-password@localhost:5432/billiards
```

如果项目当前使用其他变量名，例如：

```env
POSTGRES_USER
POSTGRES_PASSWORD
POSTGRES_DB
```

请以当前项目为准，不要强行改。

---

### 4. DeepSeek 环境变量

`.env.example` 中保留占位：

```env
TEXT_MODEL_PROVIDER=deepseek
TEXT_MODEL_NAME=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=replace-with-real-deepseek-key
```

要求：

- 不打印真实 key。
- 不写入真实 key。
- 前端不出现 DeepSeek Key。

---

### 5. 前端环境变量

如果项目中没有 `web/.env.example`，可以新增。

建议内容：

```env
NEXT_PUBLIC_API_URL=http://localhost:8000
```

并注明生产示例：

```env
# Production example:
# NEXT_PUBLIC_API_URL=https://your-domain.com
```

不要写真实域名，除非用户已经明确指定。

---

### 6. docker-compose PostgreSQL ports

如果当前是：

```yaml
ports:
  - "5432:5432"
```

建议调整为：

```yaml
ports:
  - "127.0.0.1:5432:5432"
```

说明：

- 本机仍可访问数据库。
- 外网不能直接访问数据库端口。
- 更适合单服务器试用部署。
- 如果开发环境需要局域网访问数据库，可以临时改回，但生产不要暴露。
