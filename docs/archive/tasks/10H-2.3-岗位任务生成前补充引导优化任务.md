# 10H-2.3：岗位任务生成前补充引导优化任务

## 任务定位

你现在只负责【10H-2.3：岗位任务生成前补充引导优化】。

本任务是在 10H-2.1 跳转填参修复、10H-2.2 无任务 MD 执行影响审计之后，对岗位工作台体验做一层轻量优化。

当前岗位工作台点击任务卡片后，已经可以跳转 AI 工作台并自动填入：

- role
- target_customer_type
- output_package
- user_intent

但人工体验发现一个新问题：

> 某些任务卡片默认填入的 user_intent 仍然偏泛。真实门店用户如果不补充更多细节就直接生成，结果可能不够精准。

例如：

```text
好久没联系老客户了，帮我发几句话约他们来打球，不要太刻意
```

这个提示能用，但如果用户补充：

- 多久没联系了
- 是私聊还是朋友圈
- 今天有没有空台 / 助教 / 活动
- 语气想熟人一点还是正式一点

生成结果会更准。

本轮目标不是改 AI 生成能力，而是在前端给用户增加“生成前补充引导”，让用户知道怎么把需求说得更具体。

## 三、核心目标

### 目标 1：任务卡片增加 inputHints

在 `RoleWorkbenchTask` 中增加可选字段：

```ts
inputHints?: string[]
```

每张任务卡片最多配置 3-4 条。

这些提示用于告诉用户：

```text
想让结果更准，可以补充哪些信息？
```

### 目标 2：AI 工作台显示“让结果更准”提示卡

当用户从岗位工作台跳转到 AI 工作台时，如果 URL 中：

```text
source=role_workbench
taskId=...
```

则在 Workbench 表单附近显示一个轻提示卡。

示例：

```text
让结果更准，可以补一句：
- 这批客户大概多久没来了？
- 想发朋友圈，还是私聊？
- 今天有没有空台、助教或活动可以顺带提？
- 语气要熟人一点，还是正式一点？
```

要求：

- 不阻塞生成
- 不自动改写用户意图
- 不进入 AI 生成正文
- 用户不填也可以直接点生成
- 用户可以手动参考提示去改“我想做什么”或“补充说明”

### 目标 3：不同任务显示不同提示

不要所有卡片都显示一模一样的提示。  
至少对以下任务做针对性引导：

1. 今日朋友圈
2. 老客户回访
3. 会员群空台提醒
4. 竞技群约局通知
5. 助教到店推广
6. 今日助教可约通知
7. 团购核销后加微信
8. 客户问助教怎么回
9. 开店 / 闭店检查表

## 四、建议 inputHints 内容

### 店长：今日朋友圈

```ts
inputHints: [
  "今天门店有什么可说的？比如空台、氛围、台子状态、天气。",
  "想发 1 条还是 2 条？语气要熟人自然还是品牌感一点？",
  "有没有不想写的内容？比如别写优惠、别写价格。"
]
```

### 店长：老客户回访

```ts
inputHints: [
  "这批客户大概多久没来了？一周、半个月还是一个月？",
  "想生成私聊话术、朋友圈，还是两者都要？",
  "今天有没有空台、助教可约、周赛活动可以顺带提？",
  "语气要熟人一点，还是礼貌一点？"
]
```

### 店长：会员群空台提醒

```ts
inputHints: [
  "今天哪个时间段空台多？下午、晚上还是全天？",
  "要不要提醒会员提前说一声，方便留台？",
  "是否明确不写优惠、不写会员专属权益？"
]
```

### 店长：竞技群约局通知

```ts
inputHints: [
  "大概几点约？今晚、下午还是周末？",
  "是轻松约球、练球局，还是周赛前热身？",
  "门店有没有乔氏、斯诺克或指定桌型需要提？"
]
```

### 店长：助教到店推广

```ts
inputHints: [
  "是新助教到店，还是今日助教可约？",
  "想发朋友圈、群公告，还是私聊客户？",
  "助教偏服务体验型，还是技术陪练型？"
]
```

### 助教管理：今日助教可约通知

```ts
inputHints: [
  "今天哪些时间段可约？下午、晚上还是指定时段？",
  "是发朋友圈、助教客户群，还是私聊客户？",
  "要不要强调提前预约，避免客户白跑？"
]
```

### 前厅：团购核销后加微信

```ts
inputHints: [
  "客户刚到店、刚核销，还是已经打完球？",
  "想要自然加微信话术，还是顺便引导进群？",
  "不要强推会员卡或充值，可以写清楚。"
]
```

### 前厅：客户问助教怎么回

```ts
inputHints: [
  "客户是第一次问助教，还是已经有意向预约？",
  "想要简短回复，还是详细介绍助教服务？",
  "要不要提醒到店后帮他看时间和合适助教？"
]
```

### 前厅：开店 / 闭店检查表

```ts
inputHints: [
  "是开店检查、闭店检查，还是卫生检查？",
  "要不要按前厅、台球桌、卫生、设备分组？",
  "需要适合员工群发布，还是内部执行清单？"
]
```

## 五、UI 实现建议

### AI 工作台提示卡位置

建议放在：

```text
“我想做什么”输入框下方
```

或者：

```text
补充说明上方
```

不要放太靠下，否则用户看不到。

### 标题建议

```text
让结果更准，可以补一句：
```

### 形式

简单卡片或浅色提示框即可。

示例：

```text
💡 让结果更准，可以补一句：
- 这批客户大概多久没来了？
- 今天有没有空台、助教或活动可以顺带提？
- 语气要熟人一点，还是礼貌一点？
```

### 按钮/交互

MVP 不强制做“点击自动追加”。  
如果实现成本低，可以把每条 hint 做成可点击 chip，点击后追加到“补充说明”中。  
但这不是必做项。

本轮 P0：

```text
能显示任务对应 inputHints
```

P1：

```text
点击 hint 追加到补充说明
```

如果 P1 会增加复杂度，先不做。
