## 五、新增文档 1：结构化优质样例库

请新增：

`docs/product-brain/workbench-结构化优质样例库.yaml`

要求从现有优质样例库中整理 20 条样例。

每条样例建议结构：

```yaml
examples:
  - id: "G001"
    source_case_id: "C15"
    title: "赛后战报朋友圈"
    role: "coach"
    target_customer_type: "competition"
    output_package:
      - "moments"
      - "group_notice"
    scene_tags:
      - "tournament"
      - "post_match_report"
    risk_tags: []
    user_intent: "刚打完周赛，帮我写个赛后战报"
    extra_note: ""
    good_output_snippet: |
      ...
    why_good:
      - "没有编造奖金和比分"
      - "语气适合朋友圈"
    reusable_rules:
      - "赛事战报未知信息必须占位"
    suitable_for_fewshot: true
    priority: "P1"
    max_injection_chars: 350
```

### 必填字段

每条必须包含：

- `id`
- `source_case_id`
- `title`
- `role`
- `target_customer_type`
- `output_package`
- `scene_tags`
- `risk_tags`
- `user_intent`
- `good_output_snippet`
- `why_good`
- `reusable_rules`
- `suitable_for_fewshot`
- `priority`
- `max_injection_chars`

### 重点要求

1. `good_output_snippet` 不要太长，控制在 150-350 中文字左右。
2. 不适合做 few-shot 的样例，保留但标记 `suitable_for_fewshot: false`。
3. 优先保留短、稳、行业感强、不乱编的样例。
4. 不要把长篇完整方案全文塞进 snippet。
5. 每条至少有 1 个 scene_tag。
6. 如果样例涉及风险边界，比如免费助教、金额、会员、老客户历史，必须标 risk_tags。

## 六、新增文档 2：结构化反例库

请新增：

`docs/product-brain/workbench-结构化反例库.yaml`

要求从现有反例库中整理 30 条典型反例。

每条反例建议结构：

```yaml
anti_examples:
  - id: "B001"
    source_case_id: "R21"
    title: "办卡送免费助教"
    role: "manager"
    target_customer_type: "new"
    output_package:
      - "moments"
      - "execution_tips"
    scene_tags:
      - "membership"
      - "assistant_service"
    risk_tags:
      - "free_assistant"
      - "assistant_as_gift"
    user_intent: "办卡送球杆、送免费助教一小时"
    wrong_output_summary: "把助教服务作为赠品输出"
    error_types:
      - "free_assistant"
      - "assistant_as_gift"
    why_wrong:
      - "助教服务是付费增值服务，不能默认作为办卡赠品"
    correct_approach: "转译为助教服务咨询 / 助教预约权益，具体规则以门店为准"
    runtime_rule_summary: "助教服务不能作为免费赠品或办卡赠品输出"
    regression_test: true
    runtime_prompt_eligible: false
    priority: "P0"
```

### 必填字段

每条必须包含：

- `id`
- `source_case_id`
- `title`
- `role`
- `target_customer_type`
- `output_package`
- `scene_tags`
- `risk_tags`
- `user_intent`
- `wrong_output_summary`
- `error_types`
- `why_wrong`
- `correct_approach`
- `runtime_rule_summary`
- `regression_test`
- `runtime_prompt_eligible`
- `priority`

### 重点要求

1. `wrong_output_summary` 只写摘要，不要长篇复制错误输出。
2. `runtime_prompt_eligible` 默认必须为 `false`。
3. 只有极少数高风险规则摘要可作为后续运行时提示，不允许注入反例全文。
4. 每条反例都必须能转化成测试或规则。
5. 高优先级反例必须覆盖：
   - 乱编优惠/充值
   - 乱编金额/奖品/报名费
   - 总预算自动拆金额
   - output_package 未响应
   - 老客户历史乱编
   - 免费助教/送助教课
   - 美女助教/点助教/陪玩低俗输出
   - 全城最低价/包教包会/保证赢球
   - 投诉安抚经济承诺
   - 员工管理擅自安排动作
