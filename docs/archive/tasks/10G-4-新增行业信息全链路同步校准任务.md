# 10G-4：新增行业信息全链路同步校准任务

## 任务定位

你现在只负责【10G-4：新增行业信息全链路同步校准】。

本任务是 10G 门店运营画像阶段之后的系统同步校准任务。

背景：10G-1 到 10G-3 已经把会员群、竞技群、私域群矩阵、桌型分类等信息接入了门店运营画像和 profile_context，但这还不等于整个系统所有内置配置、样例库、反例库、Prompt 规则、前端快捷场景都已经同步。

本轮目标是把新增行业信息同步到整套 Workbench 体系，避免出现：

- 门店画像懂会员群，但前端快捷场景没有会员群
- profile_context 懂竞技群，但样例库/反例库没有竞技群边界
- 门店资料能填乔氏/独牙/斯诺克，但内置文案场景仍不知道桌型分类
- Prompt 规则没明确禁止“未提供桌型时编乔氏/新设备”
- few-shot 标签体系没有会员群、竞技群、桌型相关标签
- 后续测试用例没有覆盖这些新增行业场景

本任务允许小范围修改文档、前端 Workbench 配置、结构化样例库/反例库、标签字典和少量 Prompt YAML 边界规则。

## 一、必须吸收的新增行业信息

### 1. 私域群矩阵

台球房私域群不只是“客户群”，还包括：

- 客户群
- 会员群
- 竞技群
- 搭子群
- 助教客户群
- 赛事群
- 员工群

其中会员群和竞技群必须单独作为场景处理。

#### 会员群

主要用途：

- 会员维护
- 老客户复购
- 空台提醒
- 会员活动通知
- 节假日关怀
- 周赛 / 活动提醒
- 助教可约通知

边界：

- 不得自动编造会员专属优惠
- 不得自动编造充值规则
- 不得自动编造会员权益
- 不得自动编造会员专属价格

#### 竞技群

主要用途：

- 约局
- 竞技客户维护
- 轻竞技活动
- 周赛 / 月赛报名
- 赛后战报
- 找搭子
- 临时缺人补位
- 练球局 / 友谊局

边界：

- 不得写赌博
- 不得写追分
- 不得写大额输赢
- 不得写搞钱局
- 不得引导高风险对局

---

### 2. 桌型分类

台球行业当前设备分类先按以下 4 类处理：

1. 普通台球桌
2. 独牙台球桌
3. 乔氏台球桌
4. 斯诺克

重要规则：

> 除独牙、乔氏以外的中式八球台球桌，都归为普通台球桌。

边界：

- 未提供桌型时，不得编造乔氏、独牙、斯诺克
- 未提供新设备 / 升级信息时，不得写“新到台球桌”“新换台球桌”“设备升级”
- 桌型未知时可使用“店里台子”“来打两把”等通用表达
- 不要新增“中式八球台、美式台、英式台、比赛台、娱乐台”等作为标准枚举

## 四、核心检查与同步目标

### 1. 产品大脑同步

检查并补充：

- 私域群矩阵
- 会员群运营逻辑
- 竞技群运营逻辑
- 桌型分类原则
- 不编会员权益 / 不写赌博追分 / 不编新设备边界

### 2. 岗位场景库同步

检查并补充不同岗位如何使用这些场景：

#### 店长

- 会员群空台提醒
- 会员群活动通知
- 竞技群约局通知
- 竞技群周赛报名
- 桌型特色内容

#### 运营负责人

- 会员群内容维护
- 竞技群赛事转化
- 私域群矩阵内容规划
- 桌型相关内容策划

#### 前厅

- 新客户 / 团购客该进入什么群
- 竞技客户是否引导进竞技群
- 会员客户是否引导进会员群
- 不乱承诺会员权益

#### 助教管理

- 助教客户群
- 会员群里的助教可约通知
- 不能把助教服务写成免费赠品

#### 教练 / 赛事负责人

- 竞技群周赛通知
- 乔氏 / 斯诺克相关训练或约局内容
- 不写赌博追分
