# 10G-0：门店运营画像 / 门店资料模块升级方案任务

## 任务定位

你现在只负责【10G-0：门店运营画像 / 门店资料模块升级方案】。

本任务是 10F few-shot 体系验证通过后的下一阶段规划任务。

目标不是直接改代码，而是设计一套更完整的“门店运营画像 / 门店资料模块”，让 AI 后续能更懂每一家球房的真实情况，从而生成更像本店、更加可用的内容。

本任务只做方案设计和现状阅读，不改代码，不改数据库，不改 Prompt YAML，不调用 DeepSeek。

---

当前项目已完成：

1. 10D：AI 工作台 / Workbench 主能力打通
2. 10E：AI 工作台前端产品化、结果展示、历史记录优化
3. 10F-0：产品大脑链路校准
4. 10F-0.5：Prompt YAML 同步补丁
5. 10F-1：样例库 / 反例库结构化
6. 10F-1.5：样例覆盖补齐与 few-shot 可用性校准
7. 10F-2：Workbench 轻量 few-shot 选择器接入
8. 10F-3：120 条真实调用评估通过，few-shot 建议保留

现在下一步要升级“门店资料模块”。

当前门店资料相对基础，可能只覆盖：

- 门店名称
- 地址 / 城市
- 营业时间
- 简单介绍

但产品未来要做成完整的台球房 AI 运营工作台，仅有基础资料不够。

门店资料应该升级为：

它需要支撑：

## 五、建议字段体系

请基于项目现状和产品需求，设计以下字段分组。

### 1. 门店基础信息

建议字段：

- 门店名称
- 城市 / 商圈
- 详细地址
- 营业时间
- 台桌数量
- 台桌类型
- 门店定位
- 门店一句话介绍
- 门店主要卖点
- 是否允许内容中带地址
- 是否允许内容中带电话
- 是否允许内容中带营业时间

### 2. 经营目标

建议字段：

- 当前最想提升的目标
  - 拉新
  - 老客户回流
  - 团购客转私域
  - 助教预约转化
  - 提升周赛人气
  - 提高朋友圈发布频率
  - 提升前厅转化
  - 提升助教上钟
  - 搭子群活跃
- 本月重点
- 当前门店卡点
- 不希望 AI 推荐的方向

### 3. 客户结构

建议字段：

- 主要客户类型
  - 团购客
  - 新客户
  - 老客户
  - 助教客户
  - 竞技客户
  - 轻竞技客户
  - VIP / 大客户
  - 单人练球客户
- 目前最想转化哪类客户
- 团购客常见问题
- 老客户维护方式
- 新客转化方式
- 搭子群情况
- 客户群情况

### 4. 助教体系

这是重点。

建议字段：

- 是否有助教
- 助教数量
- 是否有助教管理
- 助教类型
  - 服务体验型助教
  - 技术陪练型 / 高级助教
  - 两者都有
- 是否经常有新助教到店
- 是否允许写“新助教到店”
- 是否允许写“今日助教可约”
- 助教服务如何预约
- 助教服务是否单独收费
- 是否禁止写免费助教
- 是否禁止写助教价格
- 是否有助教照片 / 视频素材
- 是否做助教短视频
- 是否做助教 PK
- 助教推广希望的风格
- 助教推广禁用表达

注意：

内部可以理解“美女助教 / 点助教 / 陪玩”等行业口语，但对外字段不建议直接叫“美女助教推广”。前端字段建议专业化表达。

### 5. 会员 / 团购 / 价格规则

建议字段：

- 是否做团购
- 团购平台
- 团购客到店后的转化目标
- 是否有会员体系
- 是否允许 AI 写会员
- 是否允许 AI 写充值
- 是否允许 AI 写优惠
- 是否必须用占位符写价格
- 价格 / 优惠是否需要人工补充
- 是否禁止“全城最低价”
- 是否禁止“充多少送多少”自动生成

### 6. 赛事 / 活动

建议字段：

- 是否固定周赛
- 是否固定月赛
- 常见赛事规模
- 常见活动类型
- 是否有搭子群
- 是否做轻竞技
- 是否允许 AI 写奖金
- 是否允许 AI 写报名费
- 奖品 / 奖金未知时是否必须占位
- 赛后战报风格

### 7. 前厅 / SOP

建议字段：

- 前厅是否负责加微信
- 团购核销后是否引导加微信
- 客户问会员怎么处理
- 客户问助教怎么处理
- 客户投诉处理边界
- 是否允许承诺补偿
- 是否禁止前厅乱报价
- 开店检查重点
- 闭店检查重点
- 卫生检查重点

### 8. 内容风格

建议字段：

- 朋友圈语气
  - 熟人自然
  - 轻松幽默
  - 高端商务
  - 年轻潮流
  - 简短直接
- 私聊语气
- 群公告语气
- 是否喜欢 emoji
- 是否限制 emoji 数量
- 是否不要太官方
- 是否不要太销售
- 是否不要长文
- 是否用老板口吻
- 是否用店长口吻
- 常用表达
- 禁用表达

### 9. 安全 / 合规 / 禁用规则

建议字段：

- 禁止写优惠
- 禁止写价格
- 禁止写电话地址
- 禁止写免费助教
- 禁止写美女助教直白表达
- 禁止写赌博 / 追分
- 禁止写保证赢球
- 禁止写包教包会
- 禁止写全城最低价
- 禁止承诺退款 / 免单 / 赔偿
- 禁止编客户历史
- 禁止编门店变化
- 禁止编助教姓名 / 价格 / 照片 / 档期

### 10. AI 使用偏好

建议字段：

- 默认输出长度
- 默认输出类型
- 默认是否带执行建议
- 默认是否提示缺失信息
- 遇到信息不足时：
  - 直接生成安全通用版
  - 先列需要补充的信息
  - 使用占位符
- 是否启用 few-shot
- 是否启用门店画像增强
- 是否启用更严格合规模式

门店资料不能像一张很长的表单吓跑用户。

请设计：

### 1. 快速配置

- 3 分钟完成
- 首次进入引导
- 默认值
- 多选项
- 标签化选择
- 少量文本输入

### 2. 完整配置

分组 Tab 或折叠区：

- 基础信息
- 经营目标
- 客户结构
- 助教体系
- 会员 / 团购
- 赛事活动
- 前厅 SOP
- 内容风格
- 禁用规则
- AI 偏好

### 3. 资料完整度

设计一个完整度提示：

- 基础版已完成
- 助教模块待完善
- 赛事模块待完善
- 前厅 SOP 待完善

例如用户生成助教内容，但门店资料缺少助教信息时，结果区提示：

适合字段多、变化快。

- 开发速度
- 字段灵活性

> MVP 阶段优先使用 JSON profile 字段或 JSON 配置结构，避免大量迁移字段。

但请基于实际项目代码判断。

## 九、Prompt 注入设计

必须设计门店画像如何注入 AI。

注意：

1. 不是所有门店资料都直接注入。
2. 敏感 / 内部信息不应直接外显。
3. 禁用规则优先级应高于风格偏好。
4. 缺失信息必须提示或占位，不得编造。
5. 门店画像应被摘要成短上下文，不要把完整资料全塞进 Prompt。
6. 不同 output_package 可注入不同画像片段。

建议设计：

### 基础画像摘要

- 门店定位
- 主要客户
- 当前经营目标
- 内容风格
- 禁用规则

### 场景画像片段

助教场景注入：

- 是否有助教
- 助教类型
- 助教服务规则
- 助教推广禁用词

赛事场景注入：

- 是否有周赛
- 活动常见规则
- 奖金/报名费是否允许写

前厅场景注入：

- 加微信规则
- 团购转化方式
- 投诉处理边界

### 严禁注入或直接外显

- 内部经营卡点原文
- 员工隐私
- 客户隐私
- 未确认价格
- 未确认助教姓名 / 档期
