# 知识库优化设计 — 对齐"台球行业真实运营逻辑"运营框架

> **日期**: 2026-06-11
> **状态**: 待实现
> **范围**: 知识库 YAML 文件优化 + 角色挂载 + 产品文档同步

---

## 1. 目标

以"球房运营 找台球行业真实运营逻辑"PPT 的运营逻辑为骨架，按 6 个岗位拆分，补齐知识库缺失内容，让 AI 生成的内容从"大方向正确"提升为"执行层面可用"。

### 设计原则

1. **严禁出现第三方品牌名** — 唐希、彬利烎、某门店、某门店等一律不出现，只保留方法论
2. **只提取"怎么做"** — 从源材料中提取操作步骤，去掉"谁做的"和"在哪里做的"
3. **按岗位喂养** — 每个知识文件明确标注服务于哪个角色
4. **知识文件格式统一** — key/name/category/template 四字段，template 用 markdown

```
数据（反馈层）  ──→  老板/店长              ──→  四张表/复盘会/PK机制
```

### 4.3 内容处理规则

所有从源材料提取的内容必须经过以下处理：

1. **去品牌化** — 删除所有"唐希"、"彬利烎"、"某门店"、"某门店"、"开火体育"等品牌名
2. **去人名化** — 删除所有个人姓名、电话号码
3. **去案例化** — 将具体案例转化为通用方法论（如"兰州巨玩店"→"某商业球房"）
4. **保留数据逻辑** — 保留比例、时间段、数量等操作参数，删除具体金额和店名
5. **统一语气** — 使用行业通用的指导性语气，不出现"我们"、"他们"等指向性代词
