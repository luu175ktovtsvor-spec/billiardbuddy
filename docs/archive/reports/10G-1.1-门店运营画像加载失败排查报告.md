## 1. 当前问题现象

- 前端「门店资料」页面正常显示，包含「AI 运营画像」区域
- 页面顶部报错：**「加载门店信息失败」**
- 后端 API `GET /api/v1/stores/me` 返回 500（数据库查询报错）

---

## 2. 根因

**根因 A：migration 未执行。**

10G-1 编码阶段已生成 migration 文件 `003_operation_profile.py`，但报告中明确标注"未在本地执行迁移（仅生成文件）"。

SQLAlchemy model `store.py` 已添加 `operation_profile` mapped_column，应用启动后生成的 SELECT 语句包含该列，但 PostgreSQL `stores` 表实际没有此列，导致：

```
column stores.operation_profile does not exist
```

前端收到非 2xx/404 响应后显示「加载门店信息失败」。

排查过程：
1. 确认 Docker PostgreSQL 在线（`billiards_postgres` 容器运行 32 小时）
2. 确认 Alembic 当前版本为 `0002_generations`，缺少 `0003_operation_profile`
3. 确认数据库 `stores` 表 24 列，无 `operation_profile`
4. 执行 `alembic upgrade head`，成功添加列
5. 验证 API 恢复

---

## 3. 实际修复内容

仅执行了 1 个操作：

```bash
cd server && uv run alembic upgrade head
```

将 migration 从 `0002_generations` 升级到 `0003_operation_profile (head)`。

**未修改任何 .py / .ts / .tsx / .yaml 文件。** 10G-1 的代码本身没有问题，只是缺少数据库迁移执行步骤。
