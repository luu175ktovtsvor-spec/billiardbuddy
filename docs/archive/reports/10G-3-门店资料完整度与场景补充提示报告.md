## 1. 本次任务目标

本轮是门店运营画像完整度评分和场景触发补充提示，不做岗位工作台、不做 10H。

核心实现：
1. 基于 `operation_profile` 计算 9 模块完整度（0-100）
2. 门店资料页顶部展示完整度卡片（进度条 + 已完善/建议补充）
3. 用户生成内容时，根据意图关键词检测缺失画像模块，前端展示补充建议
4. 补充提示不阻塞生成，只在结果区显示轻提示
5. 为后续岗位工作台提供画像可用性基础

## 3. 完整度评分实现

### 3.1 计算逻辑

函数：`calculate_operation_profile_completeness(profile: dict | None) -> dict`

覆盖 9 个模块：

| 模块 | 评分字段 | 满分条件 |
|------|---------|---------|
| basic | positioning, business_district, main_selling_points | 3/3 填充 |
| business_goals | current_goals, monthly_focus | 1+/2 填充 |
| customer_structure | main_customer_types | 非空数组 |
| private_domain_groups | 7 种群类型 enabled | 至少 1 个；会员群+竞技群加分 |
| assistant_system | has_assistant, assistant_types, assistant_booking_rule | has_assistant=true + 类型/规则 |
| events | has_weekly_match, has_light_competition, has_partner_group | 1+/3 |
| commerce_rules | has_groupbuy, has_membership | 1+/2 |
| equipment | table_types, table_type_note | 1+/2 |
| content_style | moments_tone, private_chat_tone, group_notice_tone, forbidden_phrases | 2+/4 |

总分 = 9 个模块分数的平均值。

### 3.2 评分验证

| 配置 | 总分 | 已完成模块 | 建议补充模块 |
|------|------|-----------|-------------|
| 空画像 | 0 | 0 | 9（全部） |
| 完整 MVP 画像 | 74 | 9 | 0 |
| 真实门店数据 | 83 | 8 | events |

### 3.3 前端展示

门店资料页 → AI 运营画像 Section 顶部：

- 完整度百分比（绿/黄/红圆角标签）
- 渐变色进度条
- "已完善"模块名称列表
- "建议补充"模块名称列表（橙色文字）

不阻塞填写、不弹窗、不强制补充。

## 4. 场景触发补充提示实现

### 4.1 支持场景

函数：`detect_profile_suggestions(profile, role, target_customer_type, output_package, user_intent, extra_note) -> list[dict]`

覆盖 7 个触发场景：

| 场景 | 触发关键词 | 检查模块 | 缺失时提示 |
|------|-----------|---------|-----------|
| 助教 | 助教、新助教、点助教、陪玩、陪打、预约助教 | assistant_system | 建议补充助教体系 |
| 会员群 | 会员群、会员通知、会员活动、会员维护 | private_domain_groups.member_group.enabled | 建议勾选会员群 |
| 竞技群 | 竞技群、约局、周赛、月赛、轻竞技、赛后战报、缺一位 | private_domain_groups.competition_group.enabled | 建议勾选竞技群 |
| 桌型 | 乔氏、独牙、斯诺克、台球桌、桌型、设备 | equipment.table_types | 建议补充台球桌类型 |
| 赛事 | 周赛、月赛、赛事、比赛、报名、战报 | events | 建议补充赛事信息 |
| 团购/价格 | 团购、核销、会员、充值、优惠、折扣、价格 | commerce_rules | 建议补充团购/会员规则 |
| 内容风格 | 朋友圈、语气、风格 | content_style | 建议补充内容风格 |

### 4.2 示例提示

```json
{
  "module": "equipment",
  "level": "info",
  "title": "建议补充台球桌类型",
  "message": "你提到了桌型相关内容。补充门店的台球桌类型（普通/独牙/乔氏/斯诺克）后，AI 在生成赛事和约局内容时会更准确。",
  "action_label": "去补充桌型"
}
```

### 4.3 防止过度提示

- 仅当画像字段明确缺失时才触发
- 去重（同一模块仅提示一次）
- 最多返回 3 条建议
- 非阻塞 — 生成正常进行

### 4.4 是否阻塞生成

**否。** 建议仅在 Workbench 生成结果返回后作为 `profile_suggestions` 字段附加，前端在结果区以轻提示卡片展示。生成流程完全不受影响。

## 5. API / Schema 变化

### 5.1 StoreResponse

新增 `operation_profile_completeness` 字段：

```json
{
  "overall_score": 74,
  "modules": {
    "basic": {"score": 100, "completed": true, "missing_fields": []}
  },
  "completed_modules": ["basic", ...],
  "suggested_modules": []
}
```

### 5.2 GenerationResponse

新增 `profile_suggestions` 字段：

```json
{
  "profile_suggestions": [
    {
      "module": "equipment",
      "level": "info",
      "title": "建议补充台球桌类型",
      "message": "...",
      "action_label": "去补充桌型"
    }
  ]
}
```

### 5.3 是否影响旧接口

**否。** `profile_suggestions` 为可选字段（`list[dict] | None = None`）。旧 4 个 Tab 的 GenerationResponse 不包含此字段（默认为 None），前端解析无影响。
