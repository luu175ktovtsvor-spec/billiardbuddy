
**IP 试用方案的限制：**

| 限制 | 说明 |
|------|------|
| 无 HTTPS | 浏览器可能提示“不安全” |
| CORS_ORIGINS | 须配置为 `http://<服务器公网IP>` |
| NEXT_PUBLIC_API_URL | 须配置为 `http://<服务器公网IP>` |
| SSL 证书 | 无法使用（Let's Encrypt 不支持 IP） |
| 适用场景 | ⚠️ 仅适合内部 1-2 人短期试用，不适合对外使用 |

## 五、密钥安全提醒

### 5.1 硬性红线

| 序号 | 规则 | 说明 |
|------|------|------|
| 1 | 不要在本对话中打印真实 DeepSeek Key | 任何 `sk-` 开头的字符串都不应出现在对话中 |
| 2 | 不要在本对话中打印真实 SECRET_KEY | JWT 签名密钥一旦泄露，任何人都可以伪造登录 |
| 3 | 不要在本对话中打印真实数据库密码 | 数据库密码泄露等于数据全部暴露 |
| 4 | 不要将真实 `.env` 提交到 Git | `.gitignore` 已覆盖 `.env` 文件，确认生效 |
| 5 | 不要将服务器密码发到任何聊天工具 | 包括微信、Slack、钉钉等 |
| 6 | 不要在日志中打印密钥 | 后端代码中不 `print(api_key)`、不 `log.info(api_key)` |

### 5.2 服务器安全建议

| 措施 | 操作 |
|------|------|
| server.env 文件权限 | `chmod 600 /opt/billiards-ai/env/server.env`（仅所有者可读写） |
| env 目录权限 | `chmod 700 /opt/billiards-ai/env/`（仅所有者可进入） |
| env 文件不提交 git | `.gitignore` 已确保 `env/` 目录不入库 |
| SSH Key 登录 | 建议禁用密码登录，仅用密钥 |
| 定期更换密钥 | 建议每季度更换 `SECRET_KEY` 和数据库密码 |
| DeepSeek Key 余额 | 在 DeepSeek 控制台设置余额告警阈值 |

### 5.3 如果密钥已经意外泄露

1. 立即在 DeepSeek 控制台重置 API Key
2. 更换 `SECRET_KEY`（会导致所有用户 Token 失效，需要重新登录）
3. 更换数据库密码
4. 检查是否有异常登录或异常 API 调用

## 十、不同资源情况下的部署建议

### 情况 A：已有服务器 + 有域名 ✅

可以直接进入 9E 正式部署执行。完整 15 步流程包括：
购买/配置服务器 → 基础安全配置 → 安装基础环境 → 创建目录结构 → 拉取代码 → 准备环境变量 → 启动 PostgreSQL → 数据库迁移 → 安装后端依赖并启动 → 构建前端 → 配置 systemd → 配置 Nginx → 配置域名解析 → 配置 HTTPS → 配置备份 + 冒烟测试

### 情况 B：已有服务器 + 暂无域名 ⚠️

可以先用 IP 做内部试用部署，但：
- 暂时没有 HTTPS，浏览器会提示不安全
- 只适合 1-2 人内部测试
- 后续绑定域名后需要修改 CORS_ORIGINS、NEXT_PUBLIC_API_URL、Nginx 配置，前端需要重新 `pnpm build`
- 微信浏览器对非 HTTPS 站点限制较多

### 情况 C：没有服务器 ❌

先不要进入 9E。先购买云服务器（阿里云/腾讯云轻量应用服务器，月费约 ¥50-100），配置 2C4G 起步，Ubuntu 22.04 LTS，40 GB+ SSD。购买完成后重新走本清单确认。

### 情况 D：服务器配置太低 ❌

如果低于 2C4G，不建议部署当前版本。PostgreSQL + Next.js + FastAPI + Nginx 四个进程，1C2G 会频繁 OOM。建议升级到至少 2C4G，推荐 2C8G。

### 情况 E：服务器在中国大陆 + 没有备案 ❌

域名必须完成 ICP 备案，备案通常需要 2-4 周。短期可先用香港/海外服务器（无需备案），长期完成备案后迁移到国内。
