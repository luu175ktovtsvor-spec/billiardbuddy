## 1. 本次校准背景

### 为什么在进入 10F 前要先校准产品大脑

10D 阶段完成了 Workbench 核心链路实现和 180 条真实 DeepSeek 调用验证，10E 阶段完成了前端产品化方案设计。在进入 10F（样例库/反例库结构化与 few-shot 接入方案）之前，必须确保产品大脑中的行业认知层是准确的。

用户在 10E 阶段补充了大量台球房助教真实业务逻辑，包括：

- 助教不能只理解为"专业教学陪练"，普通助教的商业价值大量来自服务体验、氛围、情绪价值和预约转化
- "美女助教""点助教"等口语是行业真实语境，系统应该理解但不能直接输出
- 产品需要建立"内部理解层"和"对外表达层"的明确分层
- 前端展示和底层识别也需要分层

如果在产品大脑认知层不准确的情况下直接进入 10F few-shot 接入，会导致样例库和反例库的结构化规则建立在错误的行业理解之上，后续所有 Prompt 都将带着偏差运行。本次校准的目标是在编码前，先把行业规则系统性地沉淀回产品大脑文档中。

## 4. 助教业务规则的核心修正

### 4.1 助教双层分类

在产品大脑中正式建立助教服务的两层分类：

- **技术陪练型 / 高级助教**：有一定球技，客户为提升球技、纠正动作、专业陪练而预约。内容方向侧重技术展示、教学能力、陪练水平。
- **服务体验型 / 普通助教**：客户为综合服务体验而预约（沟通、氛围、情绪价值、陪打体验）。内容方向侧重服务体验、沟通氛围、陪打感受。

此前产品大脑将助教默认为"专业教学陪练"，未能区分大多数普通助教的真实商业场景。本次修正后，Prompt 引擎可根据场景选择不同的内容策略。

### 4.2 普通助教的真实业务价值

在产品大脑中正式确认普通助教对门店的商业价值来自以下维度：

形象吸引力、沟通自然、情绪价值、服务意识、氛围体验、陪打体验、摆球/记分/陪打、一个人来不尴尬、助教预约转化。

**关键原则**：产品理解这些真实需求，但对外表达时专业转译，不低俗、不擦边、不过度颜值营销。

### 4.3 "美女助教"等口语的内部理解与对外表达分层

建立了明确的分层规则：

- **内部理解层**：系统可识别"美女助教""点助教""好看的助教"等口语，映射为"助教到店通知/助教预约转化/助教服务推广"等业务意图。
- **对外表达层**：默认输出"今日助教可约""新助教到店""助教服务体验""想约助教提前说"等专业表达。
- **"美女助教"定位**：不是绝对禁词，允许在用户输入理解层出现，但不作为前端默认卡片标题和系统默认输出词。

### 4.4 新助教的条件允许边界

修正了 10E-2.5 中"新助教"被放入绝对禁止列表的过度限制：

- 用户未提供新助教信息时 → 不得凭空编造"新助教到店"
- 用户明确提供新助教信息时 → 允许专业表达（朋友圈/私聊/群公告/短视频配文）
- 无论何种情况 → 不低俗、不擦边、不编造姓名/价格/照片、不默认免费

### 4.5 不低俗、不擦边、不默认免费

在 Prompt规则库和助教业务规则库中进一步强化：

- 助教服务是付费增值服务，不能默认免费
- 禁止将助教服务作为任何形式的赠品（包括"办卡送助教""送助教课时"）
- 输出内容必须专业转译，禁止直接输出低俗擦边表达
- 前端 UI 不展示"美女助教推广""颜值助教""点她""陪玩""擦边引流"等标签

## 5. 行业术语白名单与风险词转译规则

新增文档 `docs/product-brain/行业术语白名单与风险词转译规则.md` 包含：

- **A 类（白名单）**：5 大类 40+ 条可前端展示的行业专业词（助教场景/客户运营/赛事活动/前厅/门店管理）
- **B 类（识别层）**：8 条底层可识别但不建议前端展示的词（美女助教/好看的助教/漂亮助教/点助教/大哥客户/颜值/情绪价值/陪玩），每条含业务含义、A类转译词、不展示原因
- **C 类（禁止输出层）**：30+ 条高风险禁止词，分低俗擦边类（9条）、虚假承诺类（6条）、违规经营类（9条），每条含风险说明和转译方向
- **20 条完整转译示例表**：用户口语→系统理解→推荐输出的完整对照
- **4 条转译执行原则**：不直接复述、意图保留、降级不明说、前端静默转译
- **Prompt 引擎协作方式**：输入侧、输出侧、前端侧的协作规范
