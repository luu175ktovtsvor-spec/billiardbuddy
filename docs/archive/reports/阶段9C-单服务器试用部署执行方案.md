## 一、推荐服务器配置

### 最低试用配置

| 项目 | 建议 | 说明 |
|------|------|------|
| CPU | 2 核 | AI 调用走外部 DeepSeek API，本机 CPU 压力不大 |
| 内存 | 4 GB | PostgreSQL + Next.js + FastAPI + Nginx 四个进程 |
| 硬盘 | 40 GB SSD | 系统 ~10G + 应用 ~5G + uploads 海报/Logo + 数据库 + 备份 |
| 带宽 | 3 Mbps | 试用期只有 1-2 家门店，QPS 几乎为零 |
| 系统 | Ubuntu 22.04 LTS | 长期支持版，社区资源多，兼容性好 |

### 更稳配置（推荐）

| 项目 | 建议 | 说明 |
|------|------|------|
| CPU | 2 核 | — |
| 内存 | 8 GB | 海报合成（Pillow）耗内存，AI 调用并发时更从容 |
| 硬盘 | 80 GB SSD | 海报每张 ~1-2MB，加上数据库和备份，留足余量 |
| 带宽 | 5 Mbps | 海报下载更流畅 |
| 系统 | Ubuntu 22.04 LTS | — |

### 选型说明

- **2C4G 够用**：试用期只有 1-2 家门店，日均生成量 < 20 次，无并发压力。
- **建议 2C8G**：如果生成海报较多（Pillow 合成 1080×1920 图片耗内存 200-500MB/次），8G 更从容。
- **磁盘不要太小**：海报、Logo、二维码、数据库备份都会占用空间。40G 起步，建议 80G。
- **国内云厂商**：阿里云 ECS / 腾讯云 CVM 轻量应用服务器，月费约 ¥50-100。
- **不建议更低配**：1C2G 跑 PostgreSQL + Next.js + FastAPI 三个进程会频繁 OOM。

## 二、推荐部署架构

### 架构简图

```
┌──────────────────────────────────────────────┐
│              一台云服务器 (2C4G/2C8G)          │
│                                              │
│  外网 ──→ :80/:443 (HTTPS)                    │
│              │                                │
│         ┌────┴─────┐                          │
│         │  Nginx   │  反向代理 + HTTPS 终止     │
│         └────┬─────┘                          │
│              │                                │
│    ┌─────────┼─────────┐                      │
│    │         │         │                      │
│    ▼         ▼         ▼                      │
│  /        /api/    /uploads/                  │
│  │         │         │                        │
│  ▼         ▼         ▼                        │
│ Next.js  FastAPI   Nginx alias                │
│ :3000    :8000     → /opt/billiards-ai/uploads│
│  │         │                                  │
│  │         ├──→ PostgreSQL :5432 (Docker)     │
│  │         └──→ /opt/billiards-ai/uploads/    │
│  │                                            │
│  └──→ 所有进程由 systemd 管理                  │
│                                              │
│  备份：crontab 每日凌晨自动 pg_dump + tar      │
└──────────────────────────────────────────────┘
```

### 架构要点

- **单机全栈**：Nginx + Next.js + FastAPI + PostgreSQL 全部在一台服务器上。
- **反向代理**：Nginx 统一入口，`/` → Next.js，`/api/` → FastAPI，`/uploads/` → 静态文件。
- **进程管理**：systemd 管理前后端进程，崩溃自动重启。
- **数据库**：Docker PostgreSQL，数据卷持久化到宿主机目录。
- **文件存储**：本地目录 `/opt/billiards-ai/uploads/`，环境变量 `UPLOAD_DIR` 指向绝对路径。
- **备份**：crontab 定时任务，每日备份数据库和 uploads。

## 三、服务器目录结构

```
/opt/billiards-ai/
├── app/                       # 项目代码（git clone 到这里）
│   ├── web/                   # Next.js 前端
│   ├── server/                # FastAPI 后端
│   ├── docker-compose.yml     # PostgreSQL 容器
│   └── .env.example           # 环境变量模板（参考用）
├── env/                       # 生产环境变量（不提交 git）
│   ├── server.env             # 后端环境变量，权限 600
│   └── web.env                # 前端构建时环境变量
├── uploads/                   # 持久化上传目录
│   ├── logos/                 # 门店 Logo
│   ├── qrcodes/               # 微信二维码
│   └── posters/               # 合成海报
├── backups/                   # 备份目录
│   ├── db/                    # 数据库备份（.sql.gz）
│   └── uploads/               # uploads 打包备份（.tar.gz）
├── logs/                      # 应用日志（可选，systemd journal 已覆盖）
│   ├── backend/               # 后端日志
│   └── frontend/              # 前端日志
└── scripts/                   # 运维脚本（部署时在服务器上新建）
    ├── backup-db.sh           # 数据库备份脚本
    └── backup-uploads.sh      # uploads 备份脚本
```

### 目录设计原则

- `uploads/` 不放在代码目录 `app/server/` 内，避免 `git pull` 或重新部署时覆盖。
- `env/` 单独存放，不提交 git，权限设为 600。
- `backups/` 单独目录，方便统一管理和异地同步。
- `logs/` 单独目录（如果后续写入文件日志），systemd journal 已覆盖基本需求。
- `scripts/` 运维脚本集中管理。

### 创建目录命令

```bash
sudo mkdir -p /opt/billiards-ai/{app,env,uploads/{logos,qrcodes,posters},backups/{db,uploads},logs/{backend,frontend},scripts}
```

## 四、域名和 URL 规划

### 推荐：同域名反向代理模式

```
https://app.example.com/              → Next.js 前端页面
https://app.example.com/api/v1/...    → FastAPI 后端 API
https://app.example.com/uploads/...   → 静态文件（海报/Logo/二维码）
```

### 前端环境变量

```env
# /opt/billiards-ai/env/web.env
NEXT_PUBLIC_API_URL=https://app.example.com
```

对于同域反向代理模式，也可设为空字符串，前端直接用相对路径 `/api/v1/...`。但设为完整域名更明确，且切换分域名模式时无需改前端代码。

### 后端 CORS

```env
# /opt/billiards-ai/env/server.env
CORS_ORIGINS=https://app.example.com
```

### 优缺点

| 方面 | 同域名 | 分域名 |
|------|--------|--------|
| CORS 复杂度 | 低（同域请求） | 高（需配置 CORS） |
| SSL 证书 | 1 张 | 2 张或通配符 |
| 微信浏览器兼容 | 好 | 跨域可能受限 |
| 扩展性 | 前后端无法独立扩容 | 可独立扩容 |
| 当前阶段 | ✅ 推荐 | 不必要 |

### 域名选购建议

- 主域名：`.com` 或 `.cn`，年费约 ¥60-80
- 应用域名：建议用 `app.` 或 `ai.` 二级域名
- 示例：`app.example-ball.com` / `ai.example-ball.com`

## 五、端口规划

| 端口 | 服务 | 监听地址 | 公网访问 | 说明 |
|------|------|---------|---------|------|
| 80 | Nginx HTTP | 0.0.0.0 | ✅ 开放 | HTTP → HTTPS 重定向 |
| 443 | Nginx HTTPS | 0.0.0.0 | ✅ 开放 | HTTPS 终止 |
| 3000 | Next.js | 127.0.0.1 | ❌ 禁止 | 仅 Nginx 反代访问 |
| 8000 | FastAPI | 127.0.0.1 | ❌ 禁止 | 仅 Nginx 反代访问 |
| 5432 | PostgreSQL | 127.0.0.1 | ❌ 禁止 | 仅本机应用访问 |

### 防火墙规则

```bash
# 开放 80/443
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 确保 3000/8000/5432 不对公网开放（ufw 默认拒绝入站）
sudo ufw enable

# 验证
sudo ufw status verbose
```

> 云服务器安全组也要同步配置——只开放 80/443 入站规则。

## 六、Nginx 反向代理规划

### 配置文件位置

```
/etc/nginx/sites-available/billiards
```

### 伪配置

```nginx
# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name app.example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name app.example.com;

    # SSL 证书（Certbot 自动管理）
    ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # 上传文件大小限制
    client_max_body_size 10m;

    # 静态文件：uploads 直接由 Nginx 服务（绕过 FastAPI，性能更好）
    location /uploads/ {
        alias /opt/billiards-ai/uploads/;
        expires 30d;
        add_header Cache-Control "public, immutable";
        autoindex off;  # 禁止目录列表
    }

    # API 反向代理到 FastAPI
    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 生成可能耗时 10-30s，超时设长
        proxy_read_timeout 300s;
        proxy_connect_timeout 30s;

        # SSE 流式输出需要关闭缓冲（P2 阶段启用）
        proxy_buffering off;
        proxy_cache off;
    }

    # 前端页面反向代理到 Next.js
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 关键配置说明

| 配置 | 说明 |
|------|------|
| `proxy_pass http://127.0.0.1:8000/api/` | 注意尾部 `/api/`，确保路径正确转发 |
| `proxy_read_timeout 300s` | AI 生成最长可能 30s，留足余量 |
| `client_max_body_size 10m` | Logo/二维码上传 < 2MB，海报 ~2MB，10MB 足够 |
| `proxy_buffering off` | 为 SSE 流式输出准备（当前 P0 阶段也可开启） |
| `/uploads/` 用 `alias` | Nginx 直接返回文件，不经过 FastAPI |
| `autoindex off` | 禁止列出目录文件，防止信息泄露 |

### 启用配置

```bash
sudo ln -s /etc/nginx/sites-available/billiards /etc/nginx/sites-enabled/
sudo nginx -t           # 测试配置
sudo systemctl reload nginx
```

### SSL 证书（Let's Encrypt + Certbot）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d app.example.com

# 自动续期测试
sudo certbot renew --dry-run
```

## 七、PostgreSQL Docker 部署规划

### docker-compose.yml（生产版）

项目根目录已有 `docker-compose.yml`，已配置 `127.0.0.1:5432:5432` 端口绑定，可直接使用。

```yaml
version: "3.9"

services:
  postgres:
    image: postgres:16-alpine
    container_name: billiards_postgres
    restart: always
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    ports:
      - "127.0.0.1:${POSTGRES_PORT:-5432}:5432"
    volumes:
      - /opt/billiards-ai/pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

### 改动说明

- `restart: always` — 服务器重启后自动启动
- `volumes` — 使用宿主机绝对路径 `/opt/billiards-ai/pgdata`，方便备份和迁移
- `ports` — 已绑定 `127.0.0.1`，不暴露公网

### 启动命令

```bash
cd /opt/billiards-ai/app
docker compose up -d postgres

# 验证
docker ps | grep billiards_postgres
docker exec billiards_postgres pg_isready -U billiards
```

### 数据库密码

```bash
# 生成强随机密码
openssl rand -base64 24
```

写入 `/opt/billiards-ai/env/server.env` 的 `POSTGRES_PASSWORD` 字段。

### 数据库迁移

```bash
cd /opt/billiards-ai/app/server
uv run alembic upgrade head
```

## 八、后端 FastAPI 生产启动方案

### 启动命令

```bash
cd /opt/billiards-ai/app/server
uv run uvicorn main:app --host 127.0.0.1 --port 8000 --workers 2
```

### 参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `--host` | `127.0.0.1` | 仅监听本机回环，由 Nginx 反代对外暴露。比 `0.0.0.0` 安全 |
| `--port` | `8000` | 与 Nginx `proxy_pass` 配置一致 |
| `--workers` | `2` | 2 个 worker 进程，匹配 2 核 CPU。AI 调用耗时在外部 API，不需要太多 worker |

### 环境变量

从 `/opt/billiards-ai/env/server.env` 读取。`server/config.py` 的 `model_config = {"env_file": ".env"}` 默认读当前目录的 `.env`，systemd 通过 `EnvironmentFile` 注入环境变量，无需依赖 `.env` 文件位置。

### 不要使用的命令

```bash
# ❌ 开发用热重载，不要用于生产
uv run fastapi dev main.py
```

### 依赖安装

```bash
cd /opt/billiards-ai/app/server
uv sync --frozen
```

## 九、前端 Next.js 生产启动方案

### 构建和启动

```bash
cd /opt/billiards-ai/app/web

# 1. 安装依赖
pnpm install --frozen-lockfile

# 2. 构建（环境变量在构建时注入）
#    NEXT_PUBLIC_API_URL 在 build 时写入 .next 产物
NEXT_PUBLIC_API_URL=https://app.example.com pnpm build

# 3. 启动
pnpm start --hostname 127.0.0.1 --port 3000
```

### 重要说明

- **`NEXT_PUBLIC_API_URL` 必须在 build 前设置好**，因为 Next.js 在构建时将其内联到 JS bundle 中。
- `--hostname 127.0.0.1`：仅监听本机，由 Nginx 反代对外暴露。
- Next.js `start` 是生产服务器，非开发热重载服务器。

### 环境变量

从 `/opt/billiards-ai/env/web.env` 读取。但 Next.js 的 `NEXT_PUBLIC_*` 变量在 build 时注入，systemd 的 `EnvironmentFile` 中的变量需要在构建时生效。

**推荐做法**：在构建脚本中显式传入：

```bash
export $(cat /opt/billiards-ai/env/web.env | xargs)
cd /opt/billiards-ai/app/web
pnpm build
```

## 十、systemd 服务规划

### 后端服务

文件：`/etc/systemd/system/billiards-backend.service`

```ini
[Unit]
Description=Billiards AI Backend (FastAPI)
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=billiards
Group=billiards
WorkingDirectory=/opt/billiards-ai/app/server
EnvironmentFile=/opt/billiards-ai/env/server.env
ExecStart=/usr/bin/env uv run uvicorn main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 前端服务

文件：`/etc/systemd/system/billiards-frontend.service`

```ini
[Unit]
Description=Billiards AI Frontend (Next.js)
After=network.target

[Service]
Type=simple
User=billiards
Group=billiards
WorkingDirectory=/opt/billiards-ai/app/web
EnvironmentFile=/opt/billiards-ai/env/web.env
ExecStart=/usr/bin/env pnpm start --hostname 127.0.0.1 --port 3000
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 启动和管理

```bash
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 启用开机自启
sudo systemctl enable billiards-backend billiards-frontend

# 启动服务
sudo systemctl start billiards-backend billiards-frontend

# 查看状态
sudo systemctl status billiards-backend billiards-frontend

# 查看日志
sudo journalctl -u billiards-backend -f
sudo journalctl -u billiards-frontend -f

# 重启
sudo systemctl restart billiards-backend
```

### 注意事项

1. **systemd 的 PATH 可能和 shell 不同**。如果 `uv` 或 `pnpm` 不在 systemd 的 PATH 中，`ExecStart` 需要写全路径：
   ```ini
   ExecStart=/home/billiards/.local/bin/uv run uvicorn main:app --host 127.0.0.1 --port 8000 --workers 2
   ```
   部署时先用 `which uv` 和 `which pnpm` 确认实际路径。

2. **User** 建议创建专用用户 `billiards`，不用 root：
   ```bash
   sudo useradd -r -s /bin/bash -m billiards
   sudo chown -R billiards:billiards /opt/billiards-ai
   ```

3. **EnvironmentFile** 的变量名不能有空格：`KEY=value`，不支持引号包裹 `KEY="value"`（systemd 会把引号当作值的一部分）。

## 十二、uploads 持久化和备份方案

### 存储位置

```
/opt/billiards-ai/uploads/
├── logos/       # 门店 Logo（每个门店 1 张）
├── qrcodes/     # 微信二维码（每个门店 1 张）
└── posters/     # 合成海报 PNG（每次生成 1 张）
```

### 环境变量

```env
UPLOAD_DIR=/opt/billiards-ai/uploads
```

### 访问方式

- Nginx `/uploads/` alias 直接指向此目录，无需经过 FastAPI
- 文件命名使用 UUID，防止猜测遍历
- 禁止目录列表（Nginx `autoindex off`）

### 权限

```bash
sudo chown -R billiards:billiards /opt/billiards-ai/uploads
sudo chmod -R 755 /opt/billiards-ai/uploads
```

确保 Nginx（通常以 `www-data` 用户运行）有读权限：

```bash
# Nginx 用户需要对 uploads 目录有读权限
sudo chmod -R o+r /opt/billiards-ai/uploads
sudo chmod o+x /opt/billiards-ai/uploads /opt/billiards-ai/uploads/logos /opt/billiards-ai/uploads/qrcodes /opt/billiards-ai/uploads/posters
```

### 备份脚本

部署时在服务器上新建 `/opt/billiards-ai/scripts/backup-uploads.sh`：

```bash
#!/bin/bash
# /opt/billiards-ai/scripts/backup-uploads.sh

BACKUP_DIR="/opt/billiards-ai/backups/uploads"
UPLOAD_DIR="/opt/billiards-ai/uploads"
RETENTION_DAYS=30

mkdir -p "$BACKUP_DIR"

tar -czf "$BACKUP_DIR/uploads-$(date +%F).tar.gz" -C /opt/billiards-ai uploads

# 删除超过保留天数的备份
```

## 十三、数据库备份方案

### 备份脚本

部署时在服务器上新建 `/opt/billiards-ai/scripts/backup-db.sh`：

```bash
#!/bin/bash
# /opt/billiards-ai/scripts/backup-db.sh

BACKUP_DIR="/opt/billiards-ai/backups/db"
DB_NAME="billiards_ai"
DB_USER="billiards"
CONTAINER_NAME="billiards_postgres"
RETENTION_DAYS=14

mkdir -p "$BACKUP_DIR"

# Docker 容器内 pg_dump
docker exec "$CONTAINER_NAME" pg_dump -U "$DB_USER" "$DB_NAME" | gzip > "$BACKUP_DIR/db-$(date +%F).sql.gz"

find "$BACKUP_DIR" -name "*.sql.gz" -mtime +$RETENTION_DAYS -delete

echo "[$(date)] database backup completed: db-$(date +%F).sql.gz"
```

### 定时任务

```bash
# 每天凌晨 2 点备份数据库
0 2 * * * /opt/billiards-ai/scripts/backup-db.sh >> /var/log/billiards-backup.log 2>&1
```

| 频率 | 内容 | 保留 | 存储位置 |
|------|------|------|---------|
| 每日凌晨 2 点 | 数据库全量 | 14 天 | `/opt/billiards-ai/backups/db/` |
| 每日凌晨 3 点 | uploads 全量 | 30 天 | `/opt/billiards-ai/backups/uploads/` |

|------|---------|
| 网站打不开 | 1. `systemctl status nginx` 检查 Nginx 是否运行 2. `systemctl status billiards-frontend` 检查前端进程 3. `curl -I http://127.0.0.1:3000` 本地测试前端 |

| AI 生成失败 | 1. `journalctl -u billiards-backend --since "5 min ago" \| grep -i error` 查看错误日志 2. 确认 DeepSeek API Key 正确 3. 检查 DeepSeek 余额是否充足 |

| 磁盘空间不足 | `df -h` 检查；`du -sh /opt/billiards-ai/*` 定位占用；清理旧备份 |

如果上线后出现严重问题需要回滚：

### 代码回滚

**方式一：Git 回滚（有远程仓库或本地有 git 历史时使用）**

```bash
# 1. 停止服务
sudo systemctl stop billiards-backend billiards-frontend

# 2. 回到上一个稳定版本
cd /opt/billiards-ai/app
git log --oneline -5         # 查看最近提交
git checkout <上一个稳定 commit>

# 3. 重新构建前端
cd /opt/billiards-ai/app/web
export $(cat /opt/billiards-ai/env/web.env | xargs)
pnpm install --frozen-lockfile
pnpm build

# 4. 重启服务
sudo systemctl start billiards-backend billiards-frontend

# 5. 验证
curl http://127.0.0.1:8000/api/v1/health
curl -I http://127.0.0.1:3000
```

**方式二：代码压缩包回滚（无 git 仓库、或通过 scp 上传代码包部署时使用）**

部署前应制作一份代码压缩包备份。如果尚未备份但服务器上代码未被覆盖，直接对当前目录打包即可作为快照：

```bash
# === 部署前先备份（部署第 5 步拉取代码后立即执行） ===
cd /opt/billiards-ai
tar -czf /opt/billiards-ai/backups/code-$(date +%F).tar.gz app/
```

回滚步骤：

```bash
# 1. 停止服务
sudo systemctl stop billiards-backend billiards-frontend

# 2. 删除当前代码
rm -rf /opt/billiards-ai/app

# 3. 恢复上一个代码压缩包
tar -xzf /opt/billiards-ai/backups/code-<日期>.tar.gz -C /opt/billiards-ai/

# 4. 重新构建前端
cd /opt/billiards-ai/app/web
export $(cat /opt/billiards-ai/env/web.env | xargs)
pnpm install --frozen-lockfile
pnpm build

# 5. 重新安装后端依赖（以防依赖版本变化）
cd /opt/billiards-ai/app/server
uv sync --frozen

# 6. 重启服务
sudo systemctl start billiards-backend billiards-frontend

# 7. 验证
curl http://127.0.0.1:8000/api/v1/health
curl -I http://127.0.0.1:3000
```

### 数据库回滚

```bash
# 1. 停止后端服务（避免新数据写入）
sudo systemctl stop billiards-backend

# 2. 恢复到备份
gunzip -c /opt/billiards-ai/backups/db/db-<日期>.sql.gz | docker exec -i billiards_postgres psql -U billiards -d billiards_ai

# 3. 重启后端
sudo systemctl start billiards-backend
```

### uploads 回滚

```bash
# 恢复到备份
tar -xzf /opt/billiards-ai/backups/uploads/uploads-<日期>.tar.gz -C /opt/billiards-ai/
```

### 服务回滚

```bash
# 如果 systemd 配置有问题
sudo systemctl stop billiards-backend billiards-frontend
sudo systemctl disable billiards-backend billiards-frontend
# 修复 service 文件后重新启用
sudo systemctl daemon-reload
sudo systemctl enable billiards-backend billiards-frontend
sudo systemctl start billiards-backend billiards-frontend
```

### Nginx 回滚

```bash
# 恢复上一版配置
sudo cp /etc/nginx/sites-available/billiards.bak /etc/nginx/sites-available/billiards
sudo nginx -t
sudo systemctl reload nginx
```

### 回滚检查清单

- [ ] 回滚后服务正常运行
- [ ] 回滚后数据完整性确认
- [ ] 回滚后功能冒烟测试（至少 5 项基础功能）
- [ ] 记录回滚原因和解决方案

## 十八、风险点

### 高风险

| 风险 | 严重性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| DeepSeek API 余额耗尽 | 🔴 高 | AI 生成全部失败 | 部署前检查余额；设置充值提醒；关注用量 |
| 服务器磁盘满 | 🔴 高 | 所有写操作失败（上传、海报、数据库） | 80G SSD；定时清理旧备份；`df -h` 每周检查 |
| SECRET_KEY 泄露 | 🔴 高 | JWT 可被伪造，任意用户可登录 | `server.env` 权限 600；不提��到 git；定期更换 |
| 数据库密码泄露 | 🔴 高 | 数据库可被直接访问 | 强随机密码；仅监听 127.0.0.1；不提交到 git |

### 中风险

| 风险 | 严重性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| AI 生成延迟高 | 🟡 中 | 用户等待时间长 | proxy_read_timeout 300s；前端 loading 状态 |
| 海报合成失败 | 🟡 中 | 无法生成海报 | 字体文件必须部署；日志监控合成错误 |
| systemd PATH 问题 | 🟡 中 | 服务无法启动 | 部署时确认 `uv`/`pnpm` 全路径；手动测试后再配 systemd |
| Nginx uploads 权限 | 🟡 中 | 图片无法访问 | Nginx 用户对 uploads 目录有读权限；部署后测试 |
| SSL 证书过期 | 🟡 中 | HTTPS 失效，浏览器拦截 | Certbot 自动续期已配置；`certbot certificates` 每月检查 |
| Docker 容器未自动启动 | 🟡 中 | 服务器重启后数据库不可用 | `restart: always` 配置；systemd `Requires=docker.service` |

### 低风险

| 风险 | 严重性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| 域名 DNS 未生效 | 🟢 低 | 暂时无法通过域名访问 | 先用 IP + hosts 文件测试；等待 DNS 生效 |
| 微信浏览器兼容 | 🟢 低 | 部分功能在微信中异常 | 手机端测试时重点验证微信浏览器 |
| 备份脚本未执行 | 🟢 低 | 无备份 | 部署后手动执行一次验证；crontab 日志检查 |
| 单点故障 | 🟢 低 | 服务器宕机全部不可用 | 试用期可接受；后续商业化再考虑高可用 |
