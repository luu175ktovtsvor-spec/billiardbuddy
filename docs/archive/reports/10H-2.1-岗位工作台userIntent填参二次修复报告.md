### 3.4 根因：window.location.search 在 Next.js 客户端导航中不可靠

10H-2 修复后的代码使用：

```ts
useEffect(() => {
    const params = new URLSearchParams(window.location.search);
    ...
}, []); // 空依赖数组
```

**根因：在 Next.js App Router 客户端导航（`router.push`）中，`window.location.search` 可能不反映新 URL 的查询参数。**

Next.js 使用 History API 进行客户端导航。当 `router.push('/dashboard/generate?tab=workbench&...')` 执行后，浏览器 URL 立即更新，但 `useEffect(() => {...}, [])` 在组件首次挂载时执行，此时 `window.location.search` 可能仍为空或反映旧 URL。这解释了为什么 role/customer/packages 也不生效（它们也依赖于同一个 URL 读取）——但实际上它们确实生效了。

**细粒度分析**：role/customer/packages "看起来"生效，但实际上它们可能是默认值。`workbenchRole` 默认值是 `"manager"`（与卡片一致），`workbenchTargetCustomer` 默认值是 `"all"`（但卡片设为 `"old"`，用户截图显示为"老客户"——这说明 role/customer 确实是从 URL 读取的）。所以 `window.location.search` 在 effect 触发时可能部分可用。

**最终确认的根因**：在 `useEffect(() => {...}, [])` 中使用 `window.location.search` 读取 URL 参数时，存在时序不确定性。切换到 Next.js 原生的 `useSearchParams()` hook 是标准解决方案——它始终返回当前路由的正确 search params。

## 5. 修复内容

### 修改前（10H-2 版本）

```ts
import { useEffect, useRef, useState } from "react";
import Link from "next/link";
// ...

useEffect(() => {
    const params = new URLSearchParams(window.location.search); // ❌ 不可靠
    // ...
}, []);
```

### 修改后（10H-2.1）

```ts
import { useEffect, useRef, useState } from "react";
import Link from "next/link";
import { useSearchParams } from "next/navigation";  // ✅ Next.js 原生 API
// ...

export default function GeneratePage() {
  // ...
  const searchParams = useSearchParams();  // ✅ 始终返回当前路由的 search params

  useEffect(() => {
    const tabParam = searchParams.get("tab");
    const source = searchParams.get("source");
    // ... 同 10H-2 逻辑
  }, [searchParams]); // ✅ searchParams 变化时重新执行
}
```

### 为什么这个修复可靠

1. `useSearchParams()` 是 Next.js App Router 的标准 API，与路由系统深度集成
2. 在客户端导航（`router.push`）完成后，`useSearchParams()` 立即返回新 URL 的查询参数
3. 不存在 `window.location.search` 的时序问题
4. `[searchParams]` 依赖确保在 URL 参数变化时重新应用预填逻辑
5. `urlParamsAppliedRef` 防止重复应用
