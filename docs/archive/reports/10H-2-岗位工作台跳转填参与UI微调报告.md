## 2. bug 根因分析

### 调用链追溯

1. `workbench/page.tsx` → `handleCardClick()` → `router.push('/dashboard/generate?tab=workbench&intent=...')` ✅
2. URL 中 `intent` 参数正确编码 ✅
3. `generate/page.tsx` → `useEffect` → 读取 `params.get("intent")` ✅
4. **但** `switchTab("workbench")` 在 pre-fill 之前执行，调用了 `setWorkbenchIntent("")` ❌

### 根因

```ts
// 修复前
if (tabParam && TABS.some(t => t.key === tabParam)) {
  switchTab(tabParam as Tab);  // ← 先调用 switchTab，内部 setWorkbenchIntent("")
}

if (tabParam === "workbench" && source === "role_workbench" ...) {
  setWorkbenchIntent(intentParam);  // ← 再尝试设置，但 React 批处理后最终值不确定
}
```

`switchTab("workbench")` 内部执行 `setWorkbenchIntent("")` 将意图清空。虽然在同一个 `useEffect` 同步块中 React 18 会批处理所有状态更新，但两个 `setWorkbenchIntent` 的竞争导致意图未能可靠填入。

### 修复方案

从 `role_workbench` 跳转时，**直接设 tab 不走 `switchTab` 重置逻辑**，并在 pre-fill 完成后 `return`：

```ts
if (tabParam === "workbench" && source === "role_workbench" && !urlParamsAppliedRef.current) {
  urlParamsAppliedRef.current = true;

  setTab("workbench");      // 直接设 tab，不调用 switchTab
  setResult(null);
  setError("");

  // 直接设置所有 pre-fill 值 — 角色、客户类型、输出类型、意图
  ...
  setWorkbenchIntent(intentParam);
  return;  // 阻止后续 switchTab 执行
}

// 普通 URL tab 参数走原逻辑
if (tabParam && TABS.some(t => t.key === tabParam)) {
  switchTab(tabParam as Tab);
}
```
