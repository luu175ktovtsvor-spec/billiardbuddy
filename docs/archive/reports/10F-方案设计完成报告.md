**建议进入 10F-1（样例库 / 反例库结构化），但建议先经 ChatGPT 审查本方案。**

理由：

1. **10F-1 是纯文档工作**：不改代码、不改 YAML、不调 API，风险几乎为零。将 20 条样例和 30 条反例从 Markdown 转为结构化 YAML，建立标签体系。

3. **当前阶段衔接合理**：10F-0 校准了产品大脑，10F-0.5 同步了 YAML 规则，10F 方案设计了架构——现在可以安全地进行 10F-1 数据整理。

## 8. 是否建议 10F-1 只做结构化，不做运行时接入

**是。10F-1 只做结构化，不做运行时接入。**

理由：

1. 10F-1 的产出是静态 YAML 文件——不修改 content_service.py，不修改 free_intent.yaml，不修改 PromptEngine。
2. 结构化后的样例库是"准备好被用"的状态，但实际注入 Prompt 需要在 10F-2 中通过代码实现。
3. 分两步走的好处：如果结构化后的样例库质量不够（标签不全、snippet 太长等），可以在不碰代码的情况下迭代，直到满意再进入 10F-2。

## 9. 最大风险

| 风险 | 等级 | 说明 |
|------|------|------|
| **样例质量不均匀** | 中 | 20 条样例并非全部适合 few-shot。部分样例输出过长（如周赛全套方案）、部分场景太窄（如周五朋友圈）。10F-1 需标注 suitable_for_fewshot 字段，不合格的标记为 false |
| **规则匹配可能选不到样例** | 中 | 边缘场景（如"助教客户 + 赛事活动"组合）可能没有对应样例。触发降级策略时不注入 few-shot，依赖现有规则 |
| **过早引入复杂检索** | 高 | 当前场景空间有限（6×8×10），规则匹配足够。如果过早引入向量检索或 RAG，会大幅增加复杂度而收益极低 |
| **反例注入 Prompt 的风险** | 高 | 如果将反例全文注入 Prompt，模型可能模仿错误输出。方案已明确反例不入运行时 Prompt |
| **过度依赖 few-shot** | 中 | Few-shot 是规则体系之上的辅助层。不应因为加了 few-shot 就放松 baseline_rules 的维护 |
