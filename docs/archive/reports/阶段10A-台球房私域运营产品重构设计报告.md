# 阶段 10A：台球房私域运营产品重构设计报告

---

## 1. 产品重新定位

### 1.1 定位升级

```
旧定位：台球房 AI 文案 / 海报生成器
新定位：台球房私域运营与助教管理工作台
```

旧定位的问题：当前产品本质是"选场景→AI 输出文案/海报"，和把豆包/ChatGPT 包了一层皮没有本质区别。台球房老板试用后会觉得"挺好玩，但不知道每天打开干什么"。

新定位要解决的核心问题：**让球房里的每个人每天打开系统，就知道今天该干什么、该发什么、该联系谁。**

### 1.2 产品一句话定义

> 球房 AI 店长是一个帮助台球房完成"日常运营动作"的工作台——它不管钱，管的是每天该发什么、该联系谁、该推什么、该做什么。

### 1.3 核心价值转变

| 维度 | 旧产品 | 新产品 |
|------|--------|--------|
| 用户打开的理由 | "我想生成一条文案" | "我看看今天该干什么" |
| 核心驱动 | 用户主动想到要生成内容 | 系统主动告诉用户该做哪些运营动作 |
| 内容来源 | 通用 AI 场景 | 围绕球房经营逻辑的具体场景 |
| 用户粘性 | 偶尔用一下 | 每天打开，像打卡工具 |
| 差异化壁垒 | 无（任何 AI 工具都能做） | 台球房经营场景库 + 角色化任务 + 助教管理 |

## 2. 和收银系统 / 通用 AI 的区别

### 2.1 和收银系统的区别

```
收银系统管"钱的流转"：开台、计费、上钟、收银、会员余额、充值、退款、报表
本系统管"人的动作"：每天发什么、联系谁、推什么活动、怎么转化客户、怎么管理助教日常
```

| 收银系统做的事 | 本系统做的事 |
|-------------|-------------|
| 客户到店 → 开台计费 | 客户到店 → 接待话术、加微信话术、推卡话术 |
| 助教上钟 → 计时扣费 | 助教每天 → 发朋友圈、跟进客户、内容推广 |
| 会员充值 → 余额变动 | 老会员唤醒 → 私聊邀约、专属福利、生日关怀 |
| 收银报表 → 营收分析 | 运营日报 → 今天发了什么、联系了谁、转化了几个 |

**本系统不碰收银系统的任何功能**，而是做收银系统管不到的那些"软性运营动作"。

### 2.2 和豆包 / ChatGPT 等通用 AI 的区别

| 通用 AI | 本系统 |
|---------|--------|
| 用户自己想 Prompt | 系统按经营场景直接给任务 |
| "帮我写一条朋友圈" | "今天下午空台，给你生成一条下午促活朋友圈，门店价格已自动带入" |
| 不知道你是台球房 | 知道你几张台、什么价格、有没有助教、最近在推什么活动 |
| 输出通用文案 | 输出带门店名、价格、地址、二维码的可直接发布内容 |
| 没有角色概念 | 老板看全局、店长管运营、助教做推广、前厅搞接待 |
| 没有任务驱动 | 每天登录就有待办事项和运营建议 |

**一句话区分：通用 AI 是空白纸，本系统是填好表格的运营手册。**

## 3. 用户角色设计

### 3.1 老板

| 维度 | 说明 |
|------|------|
| **主要痛点** | 不在店里的时候不知道店长和助教在干什么；不知道运营做得怎么样；团购客户来了就走，不知道有没有转化；助教招不到、留不住 |
| **每天需要做的事** | 看一眼今天店里运营了什么、助教发没发朋友圈、有没有新活动在推、团购客户转化情况 |
| **系统能帮什么** | 今日运营总览（谁做了什么）、助教工作状态一览、活动效果追踪、经营建议 |
| **对应模块** | 今日运营工作台（管理视角）、助教管理概览 |

### 3.2 店长

| 维度 | 说明 |
|------|------|
| **主要痛点** | 每天不知道发什么内容、活动不会策划、团购客户来了不知道怎么转化、助教管不好、群里没人说话、前厅接待不标准 |
| **每天需要做的事** | 发朋友圈、发群公告、跟进重点客户、检查助教工作、安排今日活动、处理客户问题 |
| **系统能帮什么** | 每日运营待办清单、一键生成各场景内容、团购转化话术、助教任务分配和检查、前厅 SOP 提醒 |
| **对应模块** | 今日运营工作台（执行视角）、团购转化助手、助教管理、内容生产中心、前厅 SOP |

### 3.3 助教

| 维度 | 说明 |
|------|------|
| **主要痛点** | 刚入行不知道怎么获客、不会写朋友圈、不知道怎么跟客户聊天、不知道今天该联系谁、店里给的素材少 |
| **每天需要做的事** | 发 1-2 条朋友圈、给老客户发消息邀约、在群里露个脸、跟进意向客户、准备明天的预约 |
| **系统能帮什么** | 每日发圈任务和文案、客户跟进提醒和话术、个人推广海报、人设包装建议、预约邀约话术 |
| **对应模块** | 助教工作台、助教推广内容、助教朋友圈素材 |

### 3.4 教练 / 赛事负责人

| 维度 | 说明 |
|------|------|
| **主要痛点** | 周赛月赛报名人数不够、赛事宣传不会做、学员转化率低、教学课没人报名、竞技氛围搞不起来 |
| **每天需要做的事** | 赛事报名推广、赛制编排、赛前提醒、赛后战报、教学课推广、单人练球客户引导 |
| **系统能帮什么** | 赛事全套内容（方案/报名/海报/提醒/战报）、教学课推广素材、竞技氛围内容 |
| **对应模块** | 教练赛事运营助手、搭子局运营助手 |

### 3.5 前厅

| 维度 | 说明 |
|------|------|
| **主要痛点** | 团购客户核销后不知道说什么、不会推会员卡、客户嫌贵不知道怎么应对、忙时手忙脚乱、各种标准动作记不住 |
| **每天需要做的事** | 接待客户、核销团购、推荐会员卡、加客户微信、处理投诉、开店/闭店检查 |
| **系统能帮什么** | 各场景标准接待话术、推卡话术、加微话术、投诉处理模板、每日检查清单 |
| **对应模块** | 前厅 SOP 助手、员工话术库 |

### 3.6 运营人员

| 维度 | 说明 |
|------|------|
| **主要痛点** | 内容产出量跟不上、不会做海报、抖音/小红书不知道发什么、活动效果评估靠感觉 |
| **每天需要做的事** | 批量产出朋友圈/群公告/海报、规划一周内容日历、各渠道内容分发 |
| **系统能帮什么** | 批量内容生成、多渠道适配（朋友圈/群/抖音/小红书）、内容素材库、活动全套物料一键生成 |
| **对应模块** | 内容素材生产中心 |

## 4. 客户分类与转化路径

### 4.1 客户分类

| 客户类型 | 特征 | 对门店的价值 | 运营重点 |
|---------|------|-------------|---------|
| **团购客户/散客** | 通过美团/抖音团购第一次到店，价格敏感，无忠诚度 | 利润极低，甚至亏损 | 加微信、进群、留下联系方式，转化为私域客户 |
| **新客户** | 第一次或第二次到店，对门店不熟，在观望 | 低，但有潜力 | 良好的第一次体验、二次到店邀约、推荐助教体验课 |
| **老客户** | 来过 3 次以上，有一定习惯，但还没充值 | 中等 | 促进充值、推荐周赛、引导带朋友来、推荐助教 |
| **助教客户** | 预约过助教，愿意为陪练/教学付费 | 高（客单价翻倍以上） | 维护关系、持续预约、推荐更多课时、节日关怀 |
| **竞技/搭子客户** | 喜欢约局、打比赛、社交需求强 | 中高（频次高、带动消费） | 搭子群运营、周赛通知、竞技氛围维护 |
| **轻度台费局客户** | 偶尔和朋友来打一两局，频率低 | 低 | 下午促活引导、搭子群引导、助教体验课推荐 |
| **大客户/充值客户** | 充值会员、高频到店、经常带人来或包场 | 极高 | 专属维护、生日关怀、VIP 活动邀请、防流失 |

### 4.2 转化路径（文字版）

```
路径 1：团购引流 → 私域沉淀 → 复购转化

  团购客户到店
    → 前厅接待 + 加微信 + 进群
    → 成为私域客户
    → 二次到店邀约（优惠券/搭子群/助教体验）
    → 第二次到店
    → 推荐会员卡/充值
    → 成为老客户

路径 2：团购客户 → 助教客户

  团购客户到店
    → 前厅推荐"新人助教体验课"
    → 客户体验助教陪练
    → 助教跟进 + 邀约第二次
    → 客户形成助教预约习惯
    → 客单价从 50 元台费 → 150-300 元（台费+助教费）

路径 3：单人练球 → 搭子局 → 复购

  单人练球客户到店
    → 店长/教练撮合另一位客户
    → 两人凑成搭子局
    → 正常开台收台费
    → 引导进搭子群
    → 形成自约习惯 → 高频复购

路径 4：老客户 → 高价值客户

  老客户
    → 推荐充值（送时长/送球/送助教课时）
    → 邀请参加周赛/月赛
    → 引导预约助教
    → 推荐带朋友来（拼桌/团建）
    → 成为大客户

路径 5：大客户 → 专属维护

  大客户
    → 生日祝福 + 专属福利
    → 充值到期前提醒 + 续费优惠
    → VIP 赛事邀请
    → 包场/团建优先安排
    → 转介绍激励
    → 防流失预警
```

### 4.3 转化关键节点

以下节点是系统必须提供内容和话术支持的地方：

1. **团购核销时** → 加微信话术 + 进群引导
2. **第一次离店时** → 二次到店邀约话术
3. **第二次到店时** → 推卡话术 + 助教体验推荐
4. **加入搭子群后** → 约球接龙 + 竞技局引导
5. **第一次预约助教后** → 助教跟进话术 + 复约邀请
6. **办卡/充值后** → 充值感谢 + 权益说明 + 首次消费引导
7. **30 天未到店时** → 回访话术 + 专属福利
8. **生日/节日时** → 个性化祝福 + 到店优惠

## 5. 核心业务模块规划

### 模块 1：今日运营工作台（升级版）

| 维度 | 说明 |
|------|------|
| **解决什么问题** | 每天打开系统不知道干什么；运营动作碎片化，容易忘 |
| **给谁用** | 店长（主要）、老板（查看）、助教（个人视角） |
| **输入** | 当前日期、星期、节假日、门店配置、近期活动、助教在岗情况 |
| **输出** | 今日运营任务卡片列表，每张卡片可一键跳转到对应功能生成内容 |
| **可生成内容** | 不直接生成，而是引导到各个场景模块 |
| **与旧版区别** | 旧版只是"建议发朋友圈"；新版要按角色给出具体的经营动作，例如"今天下午空台率高，建议发一条下午促活朋友圈+搭子群接龙" |
| **复用 MVP** | ✅ 复用现有 Dashboard 框架，升级规则引擎 |
| **开发难度** | 低（规则引擎扩展 + 卡片 UI 调整） |
| **优先级** | 🔴 高 |

### 模块 2：团购客户转化助手

| 维度 | 说明 |
|------|------|
| **解决什么问题** | 团购客户来了就走，不加微信、不进群、不复购；前厅不知道怎么引导 |
| **给谁用** | 前厅、店长 |
| **输入** | 场景选择（到店接待/加微信/进群/二次邀约/推卡/助教推荐） |
| **输出** | 对应场景的话术 + 朋友圈文案 + 群公告 |
| **可生成内容** | 到店接待话术、加微信话术、进群话术、二次到店邀约话术、团购客户推卡话术、助教体验推荐话术、团购客户专属朋友圈 |
| **复用 MVP** | ✅ 复用现有文案生成和话术生成能力，新增团购转化场景的 Prompt 模板 |
| **开发难度** | 低（主要是新增 Prompt 模板 + 前端场景入口） |
| **优先级** | 🔴 高 |

### 模块 3：助教经营系统

| 维度 | 说明 |
|------|------|
| **解决什么问题** | 助教不会获客、不会发朋友圈、不知道今天该联系谁；店长管不住助教日常工作 |
| **给谁用** | 助教（个人使用）、店长（管理查看） |
| **输入** | 助教个人资料（昵称、风格、擅长、头像）+ 门店信息 |
| **输出** | 助教每日任务清单、个人朋友圈文案、客户邀约话术、个人推广海报 |
| **可生成内容** | 助教朋友圈（日常/技术分享/客户互动/预约引导）、助教客户私聊话术、助教个人海报、助教推荐群公告、助教新客引导话术、助教复约话术 |
| **复用 MVP** | ✅ 文案生成、海报生成、话术生成均可复用，需新增助教资料库和助教维度的 Prompt 模板 |
| **开发难度** | 中（需新增助教资料表 + 助教视角的 Prompt + 助教工作台页面） |
| **优先级** | 🔴 高 |

| **解决什么问题** | 前厅接待不标准、新员工不知道该说什么做什么、每日检查事项靠记忆 |
| **给谁用** | 前厅、店长 |
| **输入** | SOP 场景（开店检查/闭店检查/接待流程/团购核销/投诉处理） |
| **输出** | 标准操作清单 + 对应话术 |
| **可生成内容** | 开店检查清单、闭店检查清单、新客接待 SOP、团购核销 SOP + 话术、客户投诉处理 SOP + 话术、忙时排台 SOP、空台巡场 SOP |
| **复用 MVP** | 部分复用话术生成，SOP 清单需要新的内容形态 |
| **开发难度** | 中（需要设计 SOP 清单展示形态，不只是文案） |
| **优先级** | 🟢 低（可放到后期） |

### 模块 9：内容素材生产中心（升级版）

| 维度 | 说明 |
|------|------|
| **解决什么问题** | 当前内容生成分散在各个入口，缺少统一的素材管理和多渠道适配 |
| **给谁用** | 运营人员、店长 |
| **输入** | 内容主题 + 目标渠道（朋友圈/微信群/抖音/小红书） |
| **输出** | 多渠道适配的内容包 |
| **可生成内容** | 朋友圈文案、微信群公告、抖音标题+文案、小红书笔记文案、视频拍摄脚本建议（纯文字，不生成视频） |
| **复用 MVP** | ✅ 文案生成和历史记录可复用，需扩展渠道适配能力 |
| **开发难度** | 中（多渠道 Prompt 适配 + 内容包展示） |
| **优先级** | 🟢 低（当前单渠道先够用） |

## 6. 当前 MVP 能力复用分析

| 已有能力 | 新产品中的复用方式 | 需要升级的地方 |
|---------|-------------------|--------------|
| **门店资料** | 所有内容生成的基础上下文；助教系统也读门店资料 | 新增助教资料字段（或独立助教资料表） |
| **AI 文案生成** | 团购转化话术、助教朋友圈、搭子局文案、赛事文案——全部复用 TextProvider + PromptEngine | 新增 15-20 个场景的 Prompt YAML 模板；优化文案口吻 |
| **活动方案生成** | 周赛方案、充值活动方案、搭子局活动方案——直接复用 | 新增赛事/助教/搭子局场景的活动模板 |
| **海报生成** | 助教推广海报、赛事海报、招聘海报、搭子群招募海报——Pillow 合成引擎直接复用 | 新增 3-5 个海报模板（助教/赛事/招聘）；视觉升级 |
| **生成历史** | 作为素材库的雏形，所有生成内容都可回查 | 后续加标签/分类筛选 |
| **Dashboard** | 今日运营工作台的框架直接复用 | 升级规则引擎，按角色和经营场景推荐任务 |
| **Prompt Engine** | 所有新场景都通过 YAML 模板扩展，不改引擎代码 | 无需修改引擎，只新增模板文件 |
| **AI Provider** | TextProvider 直接复用 | 无需修改 |

**结论：新产品方向 70% 的工作量是"新增 Prompt 模板 + 新增前端场景入口"，核心引擎和架构不需要重写。**

## 7. 近期开发优先级

### 建议顺序

| 阶段 | 名称 | 核心内容 | 预估工作量 |
|------|------|---------|-----------|
| **10B** | 海报视觉与文案口吻升级 | 海报模板视觉优化、文案 Prompt 口吻调优、去掉"AI 味"、输出更像真实球房运营内容 | 3-4 天 |
| **10C** | 助教资料库 + 助教推广内容 | 新增助教资料表、助教朋友圈文案、助教推广海报、助教邀约话术 | 4-5 天 |
| **10D** | 团购转化 + 搭子局话术 | 团购客户转化场景入口（接待/加微/进群/二次邀约/推卡）、搭子局文案和群公告 | 3-4 天 |
| **10E** | 赛事运营内容 | 周赛/月赛全套内容（方案/报名/海报/战报）、教练课推广 | 3-4 天 |
| **10F** | 前厅 SOP + 店长每日待办 | 前厅标准流程清单、升级 Dashboard 规则引擎、按角色推荐任务 | 4-5 天 |

### 为什么这么排

1. **10B 最先做**：当前海报视觉弱、文案像 AI 生成的，这是用户试用后第一眼感受。提升视觉和口吻是最小投入、最大感知改善的事。

2. **10C 第二做**：助教是台球房提高客单价的核心抓手，也是本系统和通用 AI 最大的差异点。助教经营系统一上线，产品立刻从"文案工具"变成"球房运营工具"。

3. **10D 第三做**：团购转化是球房最痛的场景之一——几乎每家店每天都有团购客户来，但大多数来了就走。这个模块日活最高。

4. **10E 第四做**：赛事是球房常规运营，但不是每天都有。优先级略低于每天都用的团购转化和助教。

5. **10F 最后做**：前厅 SOP 需要设计新的内容形态（清单而非文案），开发量相对大，且不是差异化核心。

## 8. 第一阶段不要做什么

| 暂缓功能 | 原因 |
|---------|------|
| 收银 / 台费计费 | 不是本系统定位，市面上已有成熟收银系统 |
| 助教上钟计费 / 提成 | 属于收银系统职责 |
| 会员余额 / 充值扣费 | 属于收银系统职责 |
| 支付功能 | 不做交易 |
| 复杂 CRM（客户标签/画像/自动分群） | MVP 阶段用户量小，手动管理足够 |
| 复杂排班系统 | 助教排班先用简单的"今日在岗"标记 |
| 复杂绩效考核 | 先跑通基本功能，绩效是运营成熟后的事 |
| AI 视频生成 | 技术不成熟、成本高、球房运营优先靠图文 |
| 一键发布微信/抖音 | 涉及平台 API 对接和合规，短期不现实 |
| 小程序 | H5 先够用，微信浏览器内可打开 |
| OSS 对象存储 | P0 本地存储够用 |
| 多门店连锁管理 | 先做好单店，连锁是后续商业化方向 |

**总原则：本系统只做"软性运营动作"的内容生成和任务管理，不碰"钱"和"交易"。**

## 9. 最小可执行版本设计

### 9.1 版本目标

```
从"能生成内容"升级到"能围绕球房经营场景生成可用内容"
```

用户感知变化：打开系统后不再是"选一个内容类型生成"，而是"我是做团购转化/助教推广/搭子局运营，系统直接给我可用的话术和素材"。

### 9.2 最小版本包含内容

#### A. 海报视觉升级

- 优化现有 5 个海报模板的配色、字体层级、排版比例
- 新增 2 个海报模板：助教推广海报、搭子群招募海报
- 背景图仍用本地静态图，但更换为更高质量的预置图

#### B. 朋友圈 / 群公告 Prompt 口吻升级

- 重写所有现有 Prompt YAML 模板
- 口吻标准：像一个真实的球房店长/助教在发朋友圈，不像 AI 生成的广告
- 去掉过度营销语言（"火爆""超值""不容错过"等）
- 加入台球行业真实用语和场景细节

#### C. Dashboard 今日运营任务升级

- 现有规则引擎升级：增加更多经营场景的推荐规则
- 新增推荐卡片类型：团购转化提醒、助教发圈提醒、搭子群运营提醒
- 卡片点击直接跳转到对应场景入口（带预填参数）

#### D. 新增 3 个经营场景入口

**入口 1：团购转私域**

## 11. 风险点

| 风险 | 严重性 | 规避方案 |
|------|--------|---------|
| **场景做太多，每个都浅** | 🔴 高 | 每个阶段只做 1-2 个场景，做深做透。宁可场景少但好用，不做 20 个场景但都只是换了个 Prompt |
| **Prompt 质量决定产品体验** | 🔴 高 | 每个 Prompt 必须找真实球房场景测试，不能只靠开发者自己觉得"还行"。建议找 1-2 个真实店长试用反馈 |
| **助教模块复杂度膨胀** | 🟡 中 | 第一版助教只做"资料卡+内容生成"，不做排班/绩效/考勤/提成。先验证助教愿不愿意用 |
| **和收银系统边界模糊** | 🟡 中 | 在 CLAUDE.md 和每个任务文档里反复强调"不做钱"。一旦涉及金额、余额、支付，立即停止 |
| **角色系统过早复杂化** | 🟡 中 | MVP 阶段不做权限分离。"老板/店长/助教"先用同一套页面，只是在 Dashboard 推荐任务时做区分。后续再按角色拆分权限 |
| **海报视觉升级依赖设计能力** | 🟡 中 | 如果团队没有设计师，先用更好的预置背景图+调优配色，不追求设计师级别的效果 |
| **新增场景入口导致导航混乱** | 🟢 低 | 侧边栏最多 8-9 个入口。可以用分组：运营（工作台/文案/活动）、转化（团购/助教/搭子）、工具（海报/历史/门店） |

## 12. 是否建议进入 10B 开发

**建议：✅ 进入 10B**

理由：

1. 本报告已明确产品方向、模块规划、复用策略和开发顺序
2. 10B（海报视觉与文案口吻升级）是最小改动、最大感知改善的一步
3. 10B 不涉及新的数据库表、不涉及新的架构变更，只是"让现有功能看起来更专业、输出更自然"
4. 10B 完成后可以立即拿给真实用户试用，收集反馈指导后续 10C/10D 的优先级

**10B 的具体执行范围建议：**

- 重写所有现有 Prompt YAML 模板（口吻升级）
- 优化海报模板的配色和排版
- Dashboard 推荐规则扩展 2-3 条
- 不新增场景入口（那是 10C/10D 的事）
