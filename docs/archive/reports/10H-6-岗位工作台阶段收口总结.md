## 3. 当前产品能力总结

### 3.1 岗位工作台 `/dashboard/workbench`

用户可以按岗位身份进入工作台，看到系统推荐的今日任务。核心流程：

```
选择岗位 → 看到任务卡片 → 点击"去生成"
  → 跳转 AI 工作台，参数自动填入
  → 看到 inputHints 补充引导
  → 用户手动点击"生成运营成品"
  → DeepSeek 生成可直接复制使用的内容
```

### 3.4 inputHints 生成前引导能力

- 用户在 AI 工作台"我想做什么"输入框下方看到浅蓝色提示卡
- 提示内容针对不同任务差异化
- 不阻塞生成，不自动改写意图
- 10H-5 验证：带补充说明的用例输出明显更精准

### 3.5 跳转填参链路

```
/dashboard/workbench
  → 点击任务卡片
  → router.push(/dashboard/generate?tab=workbench&role=...&customer=...&packages=...&intent=...&source=role_workbench&taskId=...)
  → generate/page.tsx useSearchParams() 读取参数
  → 直接 setTab + 填参，不调用 switchTab
  → inputHints 通过 taskId 查找并展示
  → 用户手动点击生成
```

已修复的关键 bug：
- switchTab 重置 intent → role_workbench 分支提前 return
- useSearchParams 二次触发覆盖 → return 移出 ref guard

## 6. 当前已知边界问题

### 6.1 大白话"美式那个"偶发输出"美式台"

| 项目 | 说明 |
|------|------|
| 发现来源 | 10H-3 B9（BASIC_PASS）+ 10H-5 F12（BASIC_PASS） |
| 问题描述 | 当用户以大白话表达"美式那个帮我写点"时，AI 偶尔在输出中直接使用"美式台"，未完全转译为"普通台球桌/店里台子" |
| 当前严重度 | 低 |
| 不是阻塞问题 | AI 不是主动编造门店有美式台，而是随用户口语使用了非标准表达 |
| 当前防护 | Rule 17d+17e 已强化，反例 B037 已沉淀 |
| 后续建议 | 真实试用中继续观察；如果出现频率增加，在 Prompt/反例/测试中继续强化 |

### 6.2 助教管理岗位 inputHints 覆盖率偏低

- 助教管理 8 张卡片中仅 1 张有 inputHints
