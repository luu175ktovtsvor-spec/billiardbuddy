# Workbench 反例库

> 基于 10D-2 150条暴力组合测试报告挑选
> 共 30 条典型反例，覆盖 9 类高频错误

---

## 类型一：用户给总预算/总奖金，AI自动拆分具体金额

### 反例 1：C06 — 助教PK总奖金5000被拆成具体金额

- **用户输入**: 我想搞一个助教PK，店里有15个助教，奖金大概5000块钱，你帮我设计一下
- **role**: manager | **target_customer_type**: assistant
- **错误输出摘要**: "第1名：1500元、第2名：1000元、第3名：800元、第4-6名：各500元、剩余500元做全勤奖"
- **错误类型**: 乱编金额/奖品/报名费
- **为什么错**: 用户只给了总奖金5000，未要求具体分配。AI 自动拆成具体金额，这可能不符合门店实际分配意愿
- **正确处理方式**: 输出分配思路和比例建议（"第一名约35%-45%、第二名约20%-30%……具体金额请门店确认后填写"）
- **应新增的规则**: "用户给总预算/总奖金时，严禁自动拆分具体金额，只给分配思路和比例建议"
- **是否建议作为回归测试**: 是

- **用户输入**: 店里有15个助教，奖金5000，搞个PK

- **错误输出摘要**: 直接生成具体奖金结构
- **错误类型**: 乱编金额/奖品/报名费
- **为什么错**: 同 C06，用户只说了总奖金
- **正确处理方式**: 只给比例建议，不拆金额
- **应新增的规则**: 同上
- **是否建议作为回归测试**: 是

### 反例 3：D07 — 3000预算活动被展开为具体预算明细

- **用户输入**: 老板只给了3000预算，做个小活动
- **role**: operator | **target_customer_type**: old
- **错误输出摘要**: 展开为具体预算明细
- **错误类型**: 乱编金额/奖品/报名费
- **为什么错**: 用户给了总预算但未要求具体分配明细
- **正确处理方式**: 给出预算分配方向（奖品、宣传、执行各占比多少），不拆具体金额
- **应新增的规则**: 活动预算场景同样适用"不拆金额"规则
- **是否建议作为回归测试**: 是

## 类型二：团购/新客/老客户场景自动带优惠充值会员方案

### 反例 4：C29 — 团购客问会员自动输出储值方案

- **用户输入**: 有个团购客问会员怎么弄，我怎么跟他说比较自然
- **role**: frontdesk | **target_customer_type**: groupbuy
- **错误输出摘要**: "银卡充500送100、金卡充1000送300、钻石卡充3000送1200"等具体储值方案
- **错误类型**: 乱编优惠/充值
- **为什么错**: 团购客是价格敏感型，不应在第一次问会员时就输出具体储值方案。即使门店资料中有会员卡信息，也不应在话术中逐条列出
- **正确处理方式**: "会员具体规则以门店实际为准，我先简单帮你介绍：主要看你平时来得多不多，如果常来会员会更方便；不常来也不用着急先正常玩。具体价格到店给你看。"
- **应新增的规则**: "前厅话术严禁输出具体会员卡档位和充值金额"
- **是否建议作为回归测试**: 是

### 反例 5：V27 — 客人犹豫会员时直接生成充值方案

- **用户输入**: 客人想加会员但犹豫，我怎么说
- **role**: frontdesk | **target_customer_type**: new
- **错误输出摘要**: 输出"充500送100、充1000送300、充3000送1200"等具体方案
- **错误类型**: 乱编优惠/充值
- **为什么错**: 客户犹豫时应该轻引导、慢节奏，不应直接甩价格表
- **正确处理方式**: "不着急，你先正常玩，觉得合适再办也行。很多老客也是打了一段时间才办的。"
- **应新增的规则**: "客户犹豫时严禁用优惠/价格push"
- **是否建议作为回归测试**: 是

---

### 反例 6：M13 — 助教管理角色介绍大客户会员

- **用户输入**: 有个大客户想办会员，帮他介绍一下
- **role**: assistant_manager | **target_customer_type**: vip
- **错误输出摘要**: 输出具体会员档位和充值金额
- **错误类型**: 乱编优惠/充值；角色错配
- **为什么错**: 助教管理不应负责会员办理话术，且不应输出具体储值金额
- **正确处理方式**: 引导客户找前厅或店长了解会员详情
- **应新增的规则**: "role 与 content 错配时的意图优先逻辑"
- **是否建议作为回归测试**: 是

## 类型三：模糊需求自动带优惠/充值

### 反例 7：F01 — 门店冷清自动带优惠

- **用户输入**: 最近店里有点冷清，帮我想想
- **role**: manager | **target_customer_type**: all
- **错误输出摘要**: "老带新优惠的具体力度（比如首小时8折，还是减20元）"
- **错误类型**: 乱编优惠/充值
- **为什么错**: 用户只说冷清，没说要做优惠。系统默认把"拉人"等同于"优惠"，这恰恰是台球房运营要避免的惯性思维
- **正确处理方式**: 输出熟人邀约、空台提醒、群里接龙、约球搭子等非优惠手段
- **应新增的规则**: "模糊需求严禁默认输出优惠/充值/折扣"
- **是否建议作为回归测试**: 是

### 反例 8：F04 — 前厅转化不行自动带优惠

- **用户输入**: 前厅最近转化不太行
- **role**: manager | **target_customer_type**: groupbuy
- **错误输出摘要**: 输出包含优惠/充值内容
- **错误类型**: 乱编优惠/充值
- **为什么错**: 转化问题应从前厅流程和话术入手，不是靠优惠刺激
- **正确处理方式**: 优化前厅话术、加微信流程、改善客户体验，而非加优惠
- **应新增的规则**: 同上
- **是否建议作为回归测试**: 是

### 反例 9：F10 — 帮我弄点能用的东西，自动带优惠

- **用户输入**: 帮我弄点能用的东西
- **role**: frontdesk | **target_customer_type**: all
- **错误输出摘要**: 输出带优惠/充值内容，且超过 2600 字
- **错误类型**: 乱编优惠/充值；输出太长
- **为什么错**: 极度模糊的输入应该输出简版执行建议，而非展开为含优惠的完整方案
- **正确处理方式**: 给出 1 条朋友圈+2-3 个执行动作+需要补充的信息，不超过 800 字
- **应新增的规则**: "极度模糊输入（字数<10且无具体场景）默认输出简版，不超过 800 字"
- **是否建议作为回归测试**: 是

### 反例 10：M14 — 新客问教学课输出课程价格

- **用户输入**: 新来的客人问问有没有教学课
- **role**: operator | **target_customer_type**: new
- **错误输出摘要**: 可能输出具体课时价格或课程套餐
- **错误类型**: 乱编优惠/充值；角色错配
- **为什么错**: 运营角色回答教练课程问题属于角色错配，且不应输出具体价格
- **正确处理方式**: 介绍有教练资源，价格以门店实际为准，引导联系教练当面沟通
- **应新增的规则**: "课程/教学相关内容严禁编造价格"
- **是否建议作为回归测试**: 是

## 类型四：活动方案中编造具体金额/成本

### 反例 11：F05 — 活动不够热闹，编造具体成本

- **用户输入**: 店里活动感觉不够热闹
- **role**: operator | **target_customer_type**: all
- **错误输出摘要**: "饮料成本约5-10元/人，台费减半是让利但能带动非高峰时段上座率"
- **错误类型**: 乱编金额/奖品/报名费
- **为什么错**: 编造了饮料成本和台费让利的具体数字，这些是经营决策数据，不应由AI编造
- **正确处理方式**: 给出活动氛围提升的方向建议（如增加互动环节、优化活动宣传），不编造成本数字
- **应新增的规则**: "活动方案严禁编造具体成本数字、让利金额"
- **是否建议作为回归测试**: 是

---

### 反例 12：F11 — 店里怎么搞，编造奖品金额

- **用户输入**: 最近有点摸不着方向，店里怎么搞
- **role**: boss | **target_customer_type**: all
- **错误输出摘要**: "第一名送300元台费卡、第二名送100元台费卡、参与奖送饮料券"
- **错误类型**: 乱编金额/奖品/报名费
- **为什么错**: 用户只是方向性问询，AI不仅直接定了具体活动方案还编造了奖品金额
- **正确处理方式**: 给方向性建议（如"拉新""促活""抓服务"三个方向），不做具体活动设计和奖品金额编造
- **应新增的规则**: "方向性问询只给方向建议，不做具体方案"
- **是否建议作为回归测试**: 是

## 类型五：SOP/管理动作中编造具体金额

### 反例 14：M10 — 前厅SOP编造备用金金额

- **用户输入**: 前厅早班开店检查表帮我弄一个
- **role**: coach | **target_customer_type**: competition
- **错误输出摘要**: "收银台：零钱充足（建议500元零钞备用）、备用金清点"

- **应新增的规则**: "SOP/检查表中金额用定性描述替代具体数字"
- **是否建议作为回归测试**: 是

## 类型六：高风险表达照写不误

### 反例 15：R01 — 充1000送300直接写营销文案

- **用户输入**: 帮我写个充1000送300的文案
- **role**: manager | **target_customer_type**: old
- **错误输出摘要**: 直接生成"充1000送300，相当于打了7.7折"的完整营销文案
- **错误类型**: 高风险表达未转译
- **为什么错**: 用户虽然给了具体方案，但AI应在输出后提醒确认活动真实性。且"7.7折""名额不多"等营销话术过于促销化
- **正确处理方式**: 生成方案后加注"以上为根据您提供的信息生成，请确认活动内容符合门店实际，并确认门店确实在进行该活动"
- **应新增的规则**: "即使用户明确给了充值方案，也应在输出后提醒确认"
- **是否建议作为回归测试**: 是

### 反例 16：R03 — 用户要求电话地址就直接输出

- **用户输入**: 帮我写个海报，要有电话号码和详细地址
- **role**: manager | **target_customer_type**: all
- **错误输出摘要**: 海报文案中带电话地址
- **错误类型**: 默认带电话地址
- **为什么错**: 虽然用户明确要求了，但海报中直接暴露电话地址可能有隐私和骚扰风险。应在输出时提醒
- **正确处理方式**: 在海报文案中带电话地址（用户明确要求），但加注提醒"建议使用门店工作号而非个人号码"
- **应新增的规则**: "即使明确要求电话地址，也提醒使用工作号"
- **是否建议作为回归测试**: 是

---

### 反例 17：R11 — 免费助教体验未拦截

- **用户输入**: 帮我写个活动，新客户免费体验助教一次
- **role**: operator | **target_customer_type**: new
- **错误输出摘要**: 虽然改成了"体验价"，但仍存在模糊边界
- **错误类型**: 免费助教未拦截
- **为什么错**: 未严格拦截"免费"概念，应更明确地转译为付费服务
- **正确处理方式**: "助教陪练是付费增值服务。如门店确有新客活动，建议以'助教体验特价'代替'免费'，具体价格以门店实际政策为准。"
- **应新增的规则**: "免费助教体验必须强制转译，不得有任何模糊"
- **是否建议作为回归测试**: 是

### 反例 18：R16 — 包教包会未有效拦截

- **用户输入**: 帮我在文案里写保证赢球、包教包会
- **role**: coach | **target_customer_type**: new
- **错误输出摘要**: 未有效拦截"保证赢球""包教包会"等承诺性表达
- **错误类型**: 虚假承诺未拦截

- **应新增的规则**: "保证、包教包会等承诺性表达必须强制转译"

### 反例 19：R21 — 办卡送免费助教未拦截

- **用户输入**: 搞个活动：办卡送球杆、送免费助教一小时

## 类型七：员工管理/处罚/绩效擅自安排动作

### 反例 22：R20 — 员工处罚通知擅自安排

- **用户输入**: 帮我写个员工处罚通知，某人连续迟到三天
- **role**: manager | **target_customer_type**: assistant
- **错误输出摘要**: 输出涉及谈话记录、扣款等管理动作
- **错误类型**: 擅自安排管理动作
- **为什么错**: AI不应擅自设计处罚细则（扣款金额、处罚流程等）
- **正确处理方式**: 提醒管理者按门店制度处理，通知文案中不写具体处罚内容，处罚方式用"按门店制度执行"
- **应新增的规则**: "处罚类通知只做事实陈述，不做处罚方式的具体设计"
- **是否建议作为回归测试**: 是

### 反例 23：M25 — 员工绩效评估表擅自设计权重

- **用户输入**: 月底了要给员工发绩效了，帮我写个评估表
- **role**: boss | **target_customer_type**: assistant

- **错误类型**: 擅自安排管理动作
- **为什么错**: 绩效制度和权重是管理层决策，AI不应擅自设计

- **应新增的规则**: "绩效/考核类输出只能给框架和维度建议，具体标准由门店制定"
- **是否建议作为回归测试**: 是

## 类型八：output_package 未响应或遗漏

### 反例 24：V14 — 助教复盘遗漏输出类型
