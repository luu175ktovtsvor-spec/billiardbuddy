# 录音转写整理与回传模板

> 用途：10I 阶段进入真实球房后，录音转写后的标准化整理模板
> 使用方式：每次录音转写后复制一份，按命名规范重命名，存放在 `docs/field-notes/` 目录下

---

## 一、录音转写文件命名规范

### 录音原始文件

```text
YYYY-MM-DD-类型-门店-序号.m4a（或其他录音格式）

示例：
2026-05-13-门店全天观察-测试台球俱乐部-Day1.m4a
2026-05-13-前厅接待转写-测试台球俱乐部-Day1.m4a
2026-05-13-助教管理访谈-测试台球俱乐部-Day1.m4a
```

### 转写后 Markdown 文件

```text
YYYY-MM-DD-类型-门店-DayX.md

示例：
2026-05-13-门店观察-Day1-上午.md
2026-05-13-前厅接待转写-Day1.md
2026-05-13-助教管理访谈-Day1.md
2026-05-13-老板访谈-Day1.md
```

### 类型标签

- `门店观察` — 全天综合观察
- `前厅接待转写` — 前厅客户接待录音
- `助教管理访谈` — 与助教管理的访谈
- `老板访谈` — 与老板/店长的访谈
- `教练访谈` — 与教练/赛事负责人的访谈
- `运营访谈` — 与运营/内容负责人的访谈
- `群消息转录` — 微信群语音消息转写
- `客户对话` — 客户间对话（需特别注明已脱敏）

## 二、脱敏规范

### 必须脱敏的内容

| 类型 | 脱敏方式 | 示例 |
|------|---------|------|
| 客户手机号 | 删除或用 `[手机号]` 替代 | 138xxxx8888 → `[手机号]` |
| 客户真实姓名 | 改为“客户A / 客户B / 助教C” | 王总 → `客户A（男性，约40岁）` |
| 微信号/微信ID | 删除或用 `[微信ID]` 替代 | wxid_abc123 → `[微信ID]` |
| 身份证号 | 完全删除 | — |
| 银行卡号 | 完全删除 | — |
| 具体地址 | 保留到区级，删除门牌号 | XX路XX号 → `XX路附近` |
| 具体营业额 | 改为区间或用 `[营业额区间]` 替代 | 今天做了8000 → `今天做了[中等水平]` |
| 员工工资 | 完全删除 | — |

### 可以保留的内容

- 岗位/角色（店长、助教、前厅、教练）
- 客户类型（团购客、老客户、竞技客户）
- 对话场景和流程
- 行业术语和表达方式
- 运营策略和方法（脱敏后）
- 客户需求和问题（脱敏后）

### 脱敏检查清单

- [ ] 无客户手机号
- [ ] 无真实姓名（已替换为“客户A / 助教B”）
- [ ] 无微信号/微信ID
- [ ] 无身份证/银行卡信息
- [ ] 门店内部敏感经营数据已用区间或描述代替
- [ ] 录音原始文件已标记为“仅本地存档，不外传”

## 四、回传 ChatGPT 的优先级分类

### 必须回传审查

以下类型的内容必须回传给 ChatGPT 审查：

1. **新行业事实** — 任何产品大脑中未记录的行业运作方式、业务流程、岗位职责
2. **新岗位任务** — 当前 44 张任务卡片未覆盖、但高频出现的工作内容
3. **新业务规则** — 助教 PK 规则、会员体系、赛事规则、定价逻辑等新发现
4. **高风险表达** — AI 输出中出现低俗/赌博/追分/乱编优惠/乱编价格的案例
5. **明显不准的 AI 输出** — 用户认为“完全不能用”的生成结果
6. **安全边界突破** — 真实使用中出现当前 Prompt 规则未覆盖的风险表达

### 可回传

以下类型的内容可选择性回传：

1. 普通截图（生成结果截图、页面截图）
2. 普通生成结果样例（用户认为可用或稍改可用的）
3. 用户口头反馈摘要
4. 门店运营流程的一般性观察（不涉及新行业事实）

### 只需存档

以下类型的内容只需本地存档，不回传：

1. 原始录音文件（脱敏后删除）
2. 已脱敏但暂时没有新信息的转写全文
3. 普通环境启动日志
4. 无异常的 tsc/lint/build 日志
5. 门店基础信息（如已记录在门店资料中）

## 五、从转写到全链路同步的标准流程

当转写整理中发现了新行业信息，按以下 10 层链路同步：

| 层 | 同步目标 | 文件/位置 | 何时执行 |
|:---:|---------|----------|---------|
| 1 | 产品大脑 | `docs/product-brain/台球房AI运营工作台-产品大脑.md` | 发现新行业事实后 48 小时内 |
| 2 | 岗位场景库 | `docs/product-brain/台球房岗位场景库.md` | 场景确认通用后 |
| 3 | 门店画像字段 | `docs/product-brain/门店运营画像字段字典.md` | 需要新字段支撑时 |
| 4 | Prompt 规则 | `server/prompts/rules/baseline_rules.yaml` | 发现新安全边界时 |
| 5 | Workbench 场景 | `web/src/lib/workbench-config.ts` | 需要新快捷场景时 |
| 6 | 岗位任务卡片 | `web/src/lib/role-workbench-config.ts` | 发现高频缺失任务时 |
| 7 | 样例库/反例库 | `docs/product-brain/workbench-结构化优质样例库.yaml` / `workbench-结构化反例库.yaml` | 有优质正例或反例时 |
| 8 | 标签字典 | `docs/product-brain/workbench-样例标签字典.yaml` | 需要新标签时 |
| 9 | few-shot 策略 | `docs/product-brain/workbench-fewshot选择策略.md` | 关键词映射需调整时 |
| 10 | 测试用例 | 10H-5 测试用例集 | 新场景需要回归测试时 |

### 同步判断标准

在同步每一层之前，问自己：

- **是否具有行业通用性？** 如果只是单店特有，不进产品大脑，在观察记录中注明“单店特有”
- **是否在 MVP 范围内？** 收银/灯控/会员管理系统功能不进入同步链路
- **是否需要立即同步？** 高频+安全相关的优先同步，低频+锦上添花的先记录再排期
