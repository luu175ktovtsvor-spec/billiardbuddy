## 2. 项目一句话说明

这是一个面向台球房行业的 AI 产品，当前目标是做成：

```text
台球房行业 AI 运营工作台
```

它不是普通聊天机器人，也不是简单朋友圈文案生成器。

它希望服务台球房里的真实岗位：

- 老板
- 店长
- 助教管理
- 前厅
- 运营 / 内容负责人
- 教练 / 赛事负责人

让这些岗位人员在日常工作中，通过填写门店资料、点击岗位任务卡片、输入大白话需求，快速生成可以直接发布或执行的内容。

## 3. 产品最终想解决什么问题？

台球房每天有很多琐碎但高频的运营工作，例如：

- 写朋友圈文案
- 发会员群通知
- 发竞技群约局通知
- 维护老客户
- 推广助教服务
- 招聘助教
- 前厅接待新客 / 团购客
- 回答客户会员、助教、搭子、活动问题
- 发周赛公告
- 发赛前提醒、赛后战报
- 给员工群发通知
- 给老板做经营简报
- 做一周内容规划
- 做开店 / 闭店检查表

这个产品的价值是：

```text
让台球房人员少花时间写、想、整理、通知、跟进，把重复工作交给 AI。
```

## 7. 重要业务规则和行业理解

### 7.1 客户类型

项目目前重点理解这些客户：

- 散客 / 团购客户
- 新客户
- 老客户
- 会员客户
- 助教客户
- 竞技客户
- 约球 / 搭子客户
- 轻竞技 / 周赛客户

团购客户利润低，关键是后续转化：

```text
团购客户 → 老客户 / 助教客户 / 竞技客户 / 私域客户
```

---

### 7.2 私域群

台球房私域群非常重要，当前至少关注：

- 客户群
- 会员群
- 竞技群
- 搭子群
- 助教客户群
- 赛事群
- 员工群

会员群和竞技群是重要场景，不能遗漏。

---

### 7.3 助教业务

助教业务是项目核心之一。

真实逻辑包括：

- 助教服务是付费增值服务，不是免费陪练。
- 助教客户不一定只看球技，也可能看重服务体验、沟通、陪打氛围、情绪价值、到店体验。
- 产品表达必须专业化，不能低俗、擦边、过度颜值化。

推荐产品表达：

- 助教服务
- 助教陪打体验
- 沟通自然
- 服务意识
- 预约转化
- 客户维护
- 到店体验
- 助教服务推广
- 助教管理工具

禁止前端或生成内容直白展示：

- 美女助教
- 陪玩
- 身材好
- 免费助教
- 送助教
- 低俗擦边表达

---

### 7.4 桌型设备规则

当前项目只认 4 类桌型：

- 普通台球桌
- 独牙台球桌
- 乔氏台球桌
- 斯诺克

规则：

```text
除独牙、乔氏以外的中式八球台球桌，都归为普通台球桌。
```

非标准表达：

- 美式台
- 英式台
- 中式八球台
- 比赛台
- 娱乐台

这些可以作为用户原话记录，但不应作为系统标准桌型或门店设备卖点输出。

## 8. 两个 DeepSeek 的区别

本项目里“DeepSeek”有两个不同含义，必须区分。

### 8.1 产品内 DeepSeek API

这是项目后端真正接入的 AI 模型，用来生成内容，例如：

- 朋友圈
- 群公告
- 私聊话术
- 经营简报
- 岗位工作台输出
- 真实调用测试

当报告里写：

```text
是否真实调用 DeepSeek：是
```

通常指的是“产品内 DeepSeek API”。

---

### 8.2 VSCode / Claude Code 接的 DeepSeek 执行模型

这是用户本地开发环境里的执行智能体：

```text
VSCode / Claude Code
↓
背后接 DeepSeek 模型
↓
读取 ChatGPT 写的任务 MD
↓
改代码、跑命令、生成报告
```

此前大多数 10G、10H、10I 执行任务，是由这个“VSCode/Claude Code 接 DeepSeek 执行模型”完成的。

早期第一轮曾用过 Claude Code 官方 Opus 4.6，后面大部分任务是 VSCode / Claude Code 接 DeepSeek 执行模型。

## 9. Codex / CodeLX 的位置

用户已经拥有 Codex / CodeLX 智能体，但当前会员和额度可能还没完全补齐。

未来如果 Codex 成为主要执行人员，它的定位是：

```text
执行劳动力
```

它可以：

- 读项目
- 改文件
- 跑命令
- 启动前后端
- 打开浏览器
- 点击页面
- 截图验证
- 生成报告

但它不应该套娃去控制 VSCode / Claude Code 接 DeepSeek 执行模型。

推荐关系：

```text
ChatGPT：产品大脑 / 任务拆解 / 审查验收
Codex：执行代码、文档、测试、浏览器验证
产品内 DeepSeek API：内容生成和真实调用测试
VSCode / Claude Code 接 DeepSeek：历史执行方式或备用执行方式
```

## 10. 当前实际执行策略

由于 Codex / CodeLX 额度暂时可能不足，用户计划真实球房录音后，优先使用：

```text
VSCode / Claude Code 接 DeepSeek 执行模型
```

处理录音转写资料。

原因：

- 资料可能较长
- 担心 Codex / CodeLX 额度中途断
- DeepSeek 执行链路目前更稳定

建议处理方式：

```text
先用 5-10 分钟小样本跑通流程
↓
确认格式和分析方式正确
↓
再处理完整录音
```

等 Codex / CodeLX 会员和额度补齐后，再尝试切换或对比：

```text
DeepSeek 处理效果 vs Codex / CodeLX 处理效果
```

长期再决定用谁做主要执行层。

## 17. 给执行智能体的通用规则

无论后续使用 Codex，还是 VSCode / Claude Code 接 DeepSeek 执行模型，都必须遵守：

1. 先读任务 MD。
2. 不要假设自己知道项目历史。
3. 不要读取或输出 `.env`、API Key、token、密码。
4. 不要擅自删除数据库。
5. 不要擅自重构大范围代码。
6. 不要未经允许修改 Prompt YAML。
7. 不要根据单条真实录音直接改产品。
8. 不要把单店习惯直接写成行业规则。
9. 不要把风险表达写成可发布文案。
10. 每轮执行后必须生成报告 MD。
11. 报告由用户回传给 ChatGPT 审查。
12. ChatGPT 审查通过后，才能进入下一轮。
