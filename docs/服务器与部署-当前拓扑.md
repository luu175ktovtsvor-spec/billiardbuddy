# 服务器与部署 · 当前拓扑

> 📌 状态:✅现行 · 最后核对 2026-07-14

本文只记录当前服务器、进程、配置边界、发布状态和运维入口。真实密钥只保存在受保护的服务器文件和密码管理器中。

## 1. 服务总览

| 服务 | 机器与端口 | 进程 | 职责 | 敏感配置 |
|---|---|---|---|---|
| `qfgw` | 大陆机 `39.106.214.21`，`127.0.0.1:8799` | systemd `qfgw` | 应用令牌、限流、配额、文本/图片代理与语音转录 | `/opt/qfgw/gw.env`，权限 `600` |
| `qfrelay` | 美国机 `47.77.237.250`，`127.0.0.1:8790` | systemd `qfrelay` | 图片生成与编辑异步任务、美国出口 | relay 环境文件，权限 `600` |
| dataeye receiver | 大陆机 `:9100` | Bun/TS | `/ingest` 批量接收、鉴权和幂等 | receiver token |
| dataeye board | 大陆机 `:9200` | Bun/TS | `/board` 指标展示 | Basic Auth |
| 静态资产 | 大陆机 nginx `/assets/` | nginx | 客户端必须本地执行的 FFmpeg、字体和 manifest | 不包含密钥 |

nginx 对外暴露 `/gw`、`/relay/imgtasks/` 和 `/assets/`，应用进程只监听 loopback。

## 2. 模型网关 `qfgw`

代码入口：`gateway/app.ts`

主要职责：

- 校验客户端 Bearer token。
- 按用户执行令牌桶、在途并发、每日配额和队列背压。
- 在服务器注入模型与供应商密钥。
- 代理文本、图片生成、图片编辑和图片异步任务。
- 通过统一端点执行语音输入与视频口播转录，内部 provider 可替换。
- 记录不包含密钥的用量信息。

主要端点：

```text
POST /v1/chat/completions
POST /v1/images/generations
POST /v1/images/edits
POST /v1/images/tasks
GET  /v1/images/tasks/:id
POST /v1/audio/transcriptions
GET  /healthz
```

应用令牌配置在 `GW_APP_TOKENS`。修改环境文件后重启并检查健康状态：

```bash
ssh root@<大陆机> 'systemctl restart qfgw && systemctl is-active qfgw'
ssh root@<大陆机> 'curl -s --max-time 8 http://127.0.0.1:8799/healthz'
```

## 3. 语音与口播转录

桌面端固定调用 `POST /v1/audio/transcriptions`，上传音频文件、语言和 `json|verbose_json` 输出格式。网关先执行 app token 鉴权、96MiB 文件上限、类型检查、每用户配额、速率限制和单并发，再调用服务器 provider；音频只写入权限为 `700` 的临时目录，任务结束或取消后删除，不记录音频内容和转写文本。

当前大陆机实测资源为 `2 vCPU / 3.4GiB RAM / 40GiB 系统盘 / 2GiB swap`。现行 provider 是服务器端 `whisper.cpp 1.7.6 + ggml-small-q5_1`，权重约 `190MB`，通过 ModelScope 固定提交与 SHA-256 部署。5.12秒合成中文音频公网 smoke 用时约33秒，结果可用但有同音字和繁简偏差，因此只作为当前低频基线，不作为未来高并发规格依据。

配置入口：

```text
GW_TRANSCRIBE_PROVIDER=whisper|upstream
GW_TRANSCRIBE_BIN
GW_TRANSCRIBE_MODEL
GW_TRANSCRIBE_UPSTREAM_URL
GW_TRANSCRIBE_UPSTREAM_TOKEN
GW_TRANSCRIBE_THREADS
GW_TRANSCRIBE_CONC
GW_TRANSCRIBE_RPM
GW_Q_TRANSCRIBE
GW_TRANSCRIBE_MAX_BYTES
GW_TRANSCRIBE_TIMEOUT_MS
```

`whisper` 在 qfgw 主机执行本地二进制；`upstream` 把同一契约转发给受保护的 Qwen3-ASR、云 ASR 或独立 GPU 服务。客户端不感知 provider。视频字幕需要时间戳；若使用 Qwen3-ASR，上游必须同时部署 ForcedAligner 并返回 `segments`。

当前安装命令为 `gateway/deploy-transcription.sh`。脚本固定 whisper.cpp 源码、模型仓库提交和文件 SHA-256，配置 2GiB swap、nginx 100MiB 请求上限、单并发和 systemd 环境。服务端先部署并通过真实音频 smoke，之后才发布远程优先客户端。

## 4. 图片 relay `qfrelay`

代码入口：`relay/app.ts`

relay 在美国服务器完成图片生成或编辑调用，桌面端经 gateway 使用 submit/poll：

```text
POST /images/tasks
  { mode, model, prompt, n, size, response_format?, images?, mask?, input_fidelity? }

GET /images/tasks/:id
  { status, data?, error?, created }
```

`status` 为 `queued`、`running`、`succeeded` 或 `failed`。gateway 将 `/v1/images/tasks` 转发到 relay，客户端只访问 gateway。

运维命令：

```bash
ssh root@<美国机> 'systemctl restart qfrelay && systemctl is-active qfrelay'
```

生图路由、失败边界和质量机制见 `生图-当前能力与设计.md`。

## 5. dataeye

代码入口：`dataeye/receiver/app.ts`、`dataeye/board/app.ts`

桌面 sidecar 在同时配置以下变量时，于应用启动后上传心跳和脱敏崩溃日志：

```text
QF_DATAEYE_URL
QF_DATAEYE_TOKEN
QF_APP_VERSION
```

上传请求使用 gzip JSON、Bearer token 和 `(machine_id, kind, ref_id)` 幂等键。客户端只发送字段白名单，不发送对话内容或门店资料；失败时不影响应用启动。

receiver 写入数据分层，board 读取聚合结果。部署验证以 `dataeye/README.md` 和服务健康检查为准。

## 7. 组件资产托管

资产管理器代码：`ts/src/assets/assetManager.ts`

默认清单地址：

```text
http://39.106.214.21/assets/manifest.json
```

客户端可通过 `QF_ASSET_MANIFEST_URL` 指定清单，通过 `QF_ASSETS_AUTOSTART=0` 关闭启动准备。nginx 资产目录建议使用 `/var/www/qf-assets/`：

```nginx
location /assets/ {
    alias /var/www/qf-assets/;
    autoindex off;
}
```

清单结构：

```json
{
  "version": "2026-07-13-1",
  "assets": [
    {
      "id": "ffmpeg",
      "platform": "darwin-arm64",
      "tier": 1,
      "size": 41234567,
      "sha256": "<64位hex>",
      "url": "http://39.106.214.21/assets/darwin-arm64/ffmpeg",
      "unpack": "none",
      "dest": "ffmpeg"
    }
  ]
}
```

默认客户端资产 ID 为 `ffmpeg`、`ffprobe`、`zh-font` 等必须在客户电脑执行的组件。`whisper-cli`、`whisper-model` 只保留给显式离线模式，不进入默认清单，也不因远程转录失败自动下载。Tier 1 在启动后准备，Tier 2 按功能需要下载；下载支持 Range、断点续传、大小与 SHA-256 校验、失败重试和原子落位。

更新顺序：

1. 计算文件大小和 SHA-256。
2. 上传文件到平台目录。
3. 更新并上传 `manifest.json`。
4. 验证 HTTP 200 和 Range 206。

```bash
shasum -a 256 ffmpeg
stat -f%z ffmpeg
scp ffmpeg root@<大陆机>:/var/www/qf-assets/darwin-arm64/
scp manifest.json root@<大陆机>:/var/www/qf-assets/
curl -s http://39.106.214.21/assets/manifest.json | head
curl -sI -H 'Range: bytes=100-' http://39.106.214.21/assets/darwin-arm64/ffmpeg | head -3
```

客户端资产状态通过 `GET /api/v1/assets/status` 和 WS 进度事件提供。

## 8. 运维检查

- 网关：`systemctl is-active qfgw`，随后访问 `127.0.0.1:8799/healthz`。
- relay：`systemctl is-active qfrelay`，随后经 nginx 验证任务查询。
- dataeye：检查 receiver、board 健康端点和最新心跳。
- nginx：确认 `/gw`、`/relay/imgtasks/`、`/assets/` 路由及证书。
- 资产：确认 manifest 可读、文件支持 Range、校验值匹配。
- 安全：密钥文件权限为 `600`，日志和客户端不包含真实密钥。

## 9. 新服务器规格与迁移

### 9.1 规格选择

| 方案 | 建议机器 | 适用范围 | 结论 |
|---|---|---|---|
| 当前 CPU Whisper | 至少 8 vCPU、16GiB RAM、80GiB SSD | 低并发、成本优先、视频后台任务 | 可用但聊天语音延迟仍需真机压测 |
| GPU Whisper / Qwen3-ASR-0.6B + ForcedAligner | NVIDIA T4 16GB 或同级、8 vCPU、16-32GiB RAM、100GiB SSD | 中等并发、需要时间戳 | 新机最低合理档 |
| Qwen3-ASR-1.7B + ForcedAligner | NVIDIA L4 24GB 或同级、8 vCPU、32GiB RAM、100GiB SSD | 方言、噪声环境、质量和并发优先 | 推荐长期自托管档 |
| Qwen 云 ASR | 当前网关规格即可 | 用量未稳定、希望免 GPU 运维 | 成本随量增长，但迁移最简单 |

ModelScope 当前权重事实：Qwen3-ASR-0.6B约1.88GB，1.7B约4.70GB，ForcedAligner-0.6B约1.84GB。权重大小不等于运行显存；vLLM、音频编码、KV cache、批处理和 ForcedAligner 都需要额外空间，所以不按“模型文件刚好放得下”购买机器。只有聊天短语音且不要时间戳时可降低一档；本产品含视频字幕，按带 ForcedAligner 的组合估算。

### 9.2 迁移顺序

1. 先建立稳定 HTTPS API 域名并把客户端从裸 IP 切到域名。当前 `QF_GATEWAY_URL` 和资产默认地址仍含大陆机 IP，未完成这一步时无法无感换机，旧安装包也不会自动跟随新 IP。
2. 在新机执行 qfgw、转录 provider、nginx、dataeye 和静态资产的可重复部署脚本；模型按固定哈希重新下载，不把模型文件当业务状态搬运。
3. 迁移 `/opt/qfgw/gw.env` 时使用受保护通道并保持 `600`；迁移 `usage.db` 使用 SQLite 在线 backup 或短暂停写后的快照，不直接复制活动 WAL 三件套。
4. `rsync` `/var/www/qf-assets/` 和 dataeye 持久数据，校验文件哈希；在新机用旧 app token 完成健康、鉴权、聊天、图片、语音、时间戳和清理 smoke。
5. 提前降低 DNS TTL，切换域名到新机并观察错误率、延迟、CPU/GPU、内存、磁盘和转录队列。旧机至少保留48小时，不同时写两套用量数据库。
6. 回滚只切回 DNS/反向代理；确认新机稳定后再吊销旧机凭据、停止服务并清理磁盘。密码不写入迁移脚本，服务器长期只允许 SSH key。
