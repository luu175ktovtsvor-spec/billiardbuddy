## 二、网关 qfgw(大陆机 · gateway/app.ts)

- **监听**:`127.0.0.1:8799`,不直接对公网开放;对外统一走 nginx `/gw` 前缀反代(去前缀转发 `http://127.0.0.1:8799/`)。
- **三层阀门**(防单店刷爆 + 藏 key):每家**令牌桶** + **在途并发**上限 + **每日配额** + **队列背压**。
- **藏 key**:真 key/供应商配置只在 `/opt/qfgw/gw.env`(chmod 600、不进 git);客户端只带 `GW_APP_TOKENS` 里发的可吊销 app 令牌;白标——不向客户端暴露底层模型/供应商。
- **主要端点**(客户端经此走):
  - `POST /v1/images/generations`、`POST /v1/images/edits`——生图/改图(同步直连路径)。
  - `POST /v1/images/tasks`、`GET /v1/images/tasks/:id`——GPT 生图**异步**,转发到 relay 的 `/images/tasks`(`config.relayTasksBase`)。见 §三。
  - 文本/对话模型走网关统一出口。
- **发放/改令牌**:编辑 `/opt/qfgw/gw.env` 的 `GW_APP_TOKENS`(JSON,`"<令牌>": "<用户标识,如店铺编号>"`)→ `systemctl restart qfgw`(改 env 必须重启,无热加载)。
- **验证**:
  ```bash
  ssh root@<网关机> 'systemctl restart qfgw && systemctl is-active qfgw'
  ssh root@<网关机> 'curl -s --max-time 8 http://127.0.0.1:8799/healthz'
  ```

## 三、美国 relay qfrelay(美国机 · relay/app.ts)

- **为什么要它**:GPT Image 2 的图在 OpenAI 美国服务器生成,请求必须走美国出口(大陆连不上 OpenAI + 真 OpenAI key 只在这台机);大陆↔美国跨境长连接约 60s 会被掐 → 慢调用不能同步跨境等,挪到 relay 本地跑。
- **契约**(与 gateway `/v1/images/tasks`、ts 客户端 `submitOpenAiImageTask` 对齐):
  - `POST /images/tasks` `{mode:'generate'|'edit', model, prompt, n, size, response_format?, images?, mask?, input_fidelity?}` → 返回 taskId。
  - `GET /images/tasks/:id` → `{status:'queued'|'running'|'succeeded'|'failed', data?, error?, created}`。
- **接线**:relay 监听 `8790`,nginx `/relay/imgtasks/` 转发;真 OpenAI key 只在此机的 relay 环境文件里。
- **进程**:systemd `qfrelay`(Bun 跑),`systemctl restart qfrelay` / `is-active qfrelay` 管理。
- **权威口径**:`生图-当前能力与设计.md`(生图调用链、relay submit/poll、失败边界和验证入口)。

## 六、静态资产托管(资产管理器下载源)

> 对应内核 `ts/src/assets/assetManager.ts`(瘦安装包铁律:安装包只装 app+sidecar+bundled md,
> ffmpeg/ffprobe、转写模型权重、字幕中文字体等大块头**首启后从这里后台静默下载**)。
> 资产是公开静态文件,URL 里**不放任何 token/密钥**;有密钥的东西一律不进 `/assets/`。

### 6.1 nginx 静态路径约定(大陆机)

- 目录:`/var/www/qf-assets/`(建议,首次布 mkdir -p);nginx 加一个静态 location:
  ```nginx
  location /assets/ {
      alias /var/www/qf-assets/;
      autoindex off;
  }
  ```
- 客户端默认清单地址 = `http://39.106.214.21/assets/manifest.json`
  (代码常量 `DEFAULT_ASSET_MANIFEST_URL`,换域名/HTTPS 后改那一处;客户端 env
  `QF_ASSET_MANIFEST_URL` 可覆盖,`QF_ASSETS_AUTOSTART=0` 可关自动下载)。
- **必须保住 Range**:断点续传靠 HTTP 206,nginx 静态文件天然支持;别在这个 location 前面
  套会吃掉 `Range`/`Content-Length` 的代理或动态压缩。验证:
  `curl -sI -H "Range: bytes=10-" http://39.106.214.21/assets/manifest.json | head -3`(应答 `206`)。

### 6.2 manifest.json 格式

```json
{
  "version": "2026-07-10-1",
  "assets": [
    { "id": "ffmpeg",        "platform": "darwin-arm64", "tier": 1, "size": 41234567,
      "sha256": "<64位hex>", "url": "http://39.106.214.21/assets/darwin-arm64/ffmpeg",
      "unpack": "none", "dest": "ffmpeg" },
    { "id": "ffprobe",       "platform": "darwin-arm64", "tier": 1, "size": 40123456,
      "sha256": "<64位hex>", "url": "http://39.106.214.21/assets/darwin-arm64/ffprobe",
      "unpack": "none", "dest": "ffprobe" },
    { "id": "zh-font",       "platform": "all",          "tier": 1, "size": 11223344,
      "sha256": "<64位hex>", "url": "http://39.106.214.21/assets/common/NotoSansSC-Regular.otf",
      "unpack": "none", "dest": "NotoSansSC-Regular.otf" },
    { "id": "whisper-cli",   "platform": "darwin-arm64", "tier": 2, "size": 5566778,
      "sha256": "<64位hex>", "url": "http://39.106.214.21/assets/darwin-arm64/whisper-cli.zip",
      "unpack": "zip", "dest": "whisper-cli" },
    { "id": "whisper-model", "platform": "all",          "tier": 2, "size": 1624555275,
      "sha256": "<64位hex>", "url": "http://39.106.214.21/assets/common/ggml-large-v3-turbo.bin",
      "unpack": "none", "dest": "ggml-large-v3-turbo.bin" }
  ]
}
```

字段口径:
- **id 必须用上面这 5 个规范名**(`ffmpeg`/`ffprobe`/`zh-font`/`whisper-cli`/`whisper-model`),
  内核功能门按这些 id 找资产;Windows 版同名 id 再加一行 `platform: "win32-x64"`(dest 用 `ffmpeg.exe` 等)。
- **tier**:1 = 首启自动串行下(ffmpeg/ffprobe/中文字体);2 = 默认不下、用户第一次用到转写类功能时按需下(whisper)。
- **size/sha256 都是"下载体"的**(zip 就是 zip 的,裸文件就是文件的);sha 变了客户端视为新版本自动重下。
- **unpack:"zip"** 时 `dest` 是包内主文件相对路径;客户端 macOS 用系统 `unzip`、Windows 用系统 `tar` 解包。
- 客户端落位:`~/.billiardbuddy/state/assets/<id>/<dest>`;状态在同目录 `state.json`。

### 6.3 上传/更新资产(owner 运维步骤)

```bash
# 1) 算校验和与大小(macOS 本机)
shasum -a 256 ffmpeg          # → sha256
stat -f%z ffmpeg              # → size(字节)

# 2) 传到大陆机对应目录
ssh root@39.106.214.21 'mkdir -p /var/www/qf-assets/darwin-arm64 /var/www/qf-assets/common'
scp ffmpeg root@39.106.214.21:/var/www/qf-assets/darwin-arm64/

# 3) 更新 manifest.json(改对应条目的 size/sha256/url,version 换个新值)并上传
scp manifest.json root@39.106.214.21:/var/www/qf-assets/

# 4) 验证(200 + 能 Range 206)
curl -s http://39.106.214.21/assets/manifest.json | head -5
curl -sI -H "Range: bytes=100-" http://39.106.214.21/assets/darwin-arm64/ffmpeg | head -3
```

注意:先传文件、后换 manifest(反过来会有一小段"清单指向不存在文件"的窗口,客户端会退避重试,不致命但没必要)。
客户端行为:清单拉不到用本地缓存的上一份;校验不过删掉重下;失败指数退避、绝不弹错,
功能门只显示"正在准备组件 x%"(状态可查 `GET /api/v1/assets/status`)。
