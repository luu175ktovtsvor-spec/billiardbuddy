## 1. 五个最重要的结论(先看这段)

### 1.1 整个行业收敛到 Claude Code 的 harness "约定层",不是"内核层"
要分清两层:
- **内核循环**(ReAct:想→调工具→看结果→再想)是 **2022 年就有的共享研究**,不是 Claude Code 发明。各家内核实现**互不相同**:WorkBuddy 直接**套 OpenAI 官方 `@openai/agents` SDK 的 `Runner`**(CONFIRMED);Codex 是**自研 Rust 四层状态机**(CONFIRMED);Trae 是**自研 Rust `icube_server_rs`**(CONFIRMED);Qoder 是 **Go + LangGraph 风格图执行**(CONFIRMED)。
- **约定/产品层**(`CLAUDE.md`→各家 `AGENTS.md`/`.trae/`/`.qoder/`、skills、hooks、子代理、plan 模式、system-reminder、todo、权限三档、autocompact)才是被 Claude Code 定型、**逐字照抄**的那层。证据最硬:Trae 里"todo 空了别跟用户提"的 system-reminder 与 Claude Code 原文**一字不差**(CONFIRMED)。

> **对我们的意义**:harness 已是行业标配、不是护城河。抄它天经地义(我们 CLAUDE.md 也写了可抄 Claude Code)。差异化只能在**领域/用户/交付形态**上做。

### 1.2 大厂都把"大脑"下沉进原生二进制(Rust/Go),我们还在 Python
Codex/Trae 用 Rust、Qoder 用 Go——为性能、真沙箱、并发、单文件分发。只有 WorkBuddy 用 JS(压缩)、**我们用 Python + FastAPI**。这是与大厂的一个真实代差(不一定要追,但要知道其代价:见 §4)。

### 1.3 五家没有一家上"真混淆"
全部只是标准 minify/strip(短变量名/剥符号),**没有 `javascript-obfuscator` 那种字符串加密/控制流平坦化**(CONFIRMED,`_0x` 全 0)。讽刺的是:**唯一给自家提示词加密(`prompts.enc` Fernet)的是我们自己**。在"保护自家提示词/知识"上,我们比这四个大厂都狠。

### 1.4 商业形态:就我们一家"全本地 + 内置 key + 免登录"
另外四家**全部强制登录 + 云端 + Credits/订阅**:Codex 绑 ChatGPT 账号、Qoder 绑阿里云 Credits、Trae 绑字节账号+计费、WorkBuddy 网关+Credits。我们面向小白的"开箱即用零配置"是这堆开发者工具里的**独一份**(既是短板=工程薄,也是护城河=它们进不来这个场景)。

### 1.5 隐私光谱:我们最私密,Trae 最激进
我们(全本地+静默日志回传自有服务器) → Codex(绑云但 safe/sensitive 脱敏规矩) → WorkBuddy/Qoder(云端一般) → **Trae(最激进:字节全家桶遥测 slardar/TEA/libra + 自研 TTNet 网络栈绕系统 DNS + agent 工具默认自动执行且开关藏起来)**。

## 2. 逐家深拆

### 2.1 WorkBuddy / CodeBuddy(腾讯)——"套壳 OpenAI Agents SDK 的 Claude Code 复刻"

**定性**:VS Code 皮的自研 Electron 壳 + 20MB 压缩 JS CLI 内核(`@tencent-ai/codebuddy-code`)。系统提示、四档权限、hooks、MCP、Task 子代理、记忆四类型全逐字对齐 Claude Code。

**内核循环(CONFIRMED,反压缩+trace)**:它**自己没写内层循环**,100% 委托给 `@openai/agents` 官方 SDK 的 `Runner.run()`。自己的代码只做两件事:
1. 用 SDK 官方扩展点 `callModelInputFilter`(每次发模型请求前触发)挂横切逻辑:死循环检测 → autocompact 检查 → 修复被截断的 tool_call。
2. 外面包一层 **29 级优先级的拦截器链**(`@genie` DI 注入,`Env=2000 … TokenCalculation=500`),做"轮前"准备(注入记忆/系统提醒/图片压缩/沙箱生命周期…),然后才 `runner.run()`。
```
run(agent, input):
  runner = SDK Runner(单例)               # @openai/agents 真实 Runner
  session.abortController.abort()          # 新一轮取消上一轮
  for interceptor in sort(29级拦截器):     # 轮前编排(改 ctx / 置 skipRun)
      interceptor.intercept(ctx)
  runner.run(ctx.agent, ctx.input)         # ★ 工具循环/审批中断全在 SDK 内部
```

**autocompact 真实算法(CONFIRMED,纠正之前"0.8"的说法)**:
- 两条触发通道:`EMERGENCY_AUTO`(轮中,挂在 callModelInputFilter,兜底比例 **0.92**)+ `PRE_MESSAGE_AUTO`(轮前,拦截器 1650 位,兜底 **0.7**)。真实值由产品配置 `tokenUsageThresholds.inputTokens.emergency` 决定,两个字面量只是配置缺失时的兜底。
- 30 秒冷却 + "压完又立刻再压"防抖(`hasMeaningfulNewHistorySinceLastCompact`)+ 连续强压上限 5 次。
- **有未决工具审批时绝不压缩**(防止把等用户确认的卡片压没)。
- 执行走**策略模式**:DI 注入一组 `CompactStrategy`,按优先级找第一个 `canHandle()` 命中的,全不中回退 "Blocking" 兜底。

**审批闸真实逻辑(CONFIRMED)**:不是"某工具静态标 requiresApproval",而是每个工具的 `needsApproval` 统一转发到中心化 `ToolPermissionService` 跑规则引擎:`PreToolUse hook → deny规则 → allow规则(命中直接放行跳过安全检查) → Bash命令风险分类 → ask规则 → 权限模式策略 → 默认ask`。Bash 风险五级(SAFE<LOW<MEDIUM<HIGH<CRITICAL),`rm -rf /`/`git push --force main` 等属 CRITICAL **连"跳过确认"模式都拦不住**。命中"要问"后由 SDK 的 `RunToolApprovalItem` 暂停,经 ACP 协议 `session/resolve_interruption` 回填。HIGH/CRITICAL **永不缓存"记住我的选择"**。

**ToolCallLoopDetector(CONFIRMED,我们没有的东西)**:检测模型工具死循环。阈值**不对称**:白名单常用工具(Read/Grep/Glob/Write/WebFetch/WebSearch/Edit/Skill/Bash)完全相同参数连调 **4 次**判死循环;白名单外(自定义/MCP)容忍到 **40 次**。命中后**不硬熔断**,而是往上下文追加一条 user 消息"STOP calling tools"让模型自己收场。

**@genie DI(CONFIRMED)** = InversifyJS + Spring 风格注解语法糖(`@Component`/`@Autowired`)+ AOP。`@Component` 是**延迟绑定**:装饰时把注册信息塞进全局 Reflect 数组,全部模块加载完再统一组装进容器。全仓 **274 个 DI 服务**(之前逆向已列全)。

**安全**:无混淆;"加密"只是 `conf`/electron-store 配置库自带的 aes-256-cbc 落盘壳(密钥在 app 内,obscurity 非 security);唯一刻意隐藏 = 多模态脚本把腾讯云 API 名 base64(`SubmitAigcVideoJob` 之类,遮品牌,秒解)。

**可借鉴**:① ToolCallLoopDetector(软停止式,4/40 不对称阈值);② autocompact 的"未决审批不压 + 30s冷却 + 防抖"三条护栏;③ 审批规则引擎的"命中 allow 规则跳过安全检查""HIGH/CRITICAL 不缓存"设计。

### 2.2 Codex(OpenAI)——"开源 Rust 内核 + 苹果级客户端信任链"

**定性**:Electron 壳 + 238MB 开源 Rust 内核(codex-rs 0.142)。**本次最大发现:装机二进制 ≈ 公开仓库**——之前以为"realtime语音/multi_agent/attestation 是桌面版私有加的",逐行对照后**证伪**:它们在 `github.com/openai/codex` 里都有完整实现(CONFIRMED,90/120 workspace crate 直接命中,没命中的都是平台专属/proc-macro 包)。真正闭源的只有外面那层 Electron/原生壳。

**crate 结构(CONFIRMED,重建)**:core(主状态机)/ sandboxing(seatbelt+landlock+bwrap)/ execpolicy / app-server(协议)/ ext/{guardian,memories,skills,connectors,goal,image-generation}/ realtime-webrtc / login / model-provider …

**agent 循环(CONFIRMED,自研 Rust 四层状态机,非 OpenAI Agents SDK)**:
```
Task层(RegularTask/ReviewTask/CompactTask):
  loop: last = run_turn(); 若队列无新输入→返回; 否则继续下一轮
Turn层(run_turn,单轮可多次往返模型):
  预采样压缩(context快满提前compact)
  loop:
    取排队的用户插话(steering) → 记历史
    run_sampling_request()
    若模型要求继续 OR 有新输入 → (token快满则auto_compact) continue
    否则 → 跑stop hooks(可拦截强制继续) → 真停则break
Sampling层: 组装工具表 → build_prompt → 流式请求(带重试退避)
```
把"压缩/审批阻塞/用户插话排队"都做成 Turn 循环内可随时插入的分支——**和我们 `loop.py` 三级压缩+tool回灌是同一类设计哲学**,可直接对照。

**真沙箱(CONFIRMED,seatbelt SBPL 逐字读到)**:macOS `sandbox-exec` + 动态生成 `.sbpl`(基础策略抄 Chromium),`workspace-write`/`read-only`/`danger-full-access` 三档本质是"可写根目录列表是否为空"的布尔;路径通过 `-D变量=路径` 传入防 sbpl 语法注入;`/usr/bin/sandbox-exec` 硬编码绝对路径防 PATH 劫持。**纠正**:Linux 侧主力其实是 **bubblewrap(bwrap)+seccomp**,landlock 是 `--use-legacy-landlock` 兼容选项。

**审批+提权(CONFIRMED)**:命令用 **tree-sitter-bash 真语法解析**切成子命令(不是按 `&&` 字符串切),逐段过 execpolicy(allow/prompt/forbidden),**每段都必须单独命中 allow 才算信任**。提权受策略门控(非 OnRequest 模式主动要提权直接拒)。

**Guardian 自动审提权(CONFIRMED,`codex-auto-review` 模型)**:一个 LLM 子代理审 5 类高风险动作(命令/execve/patch/网络/MCP),产出风险等级+用户授权评估,状态机 InProgress→Approved/Denied/TimedOut;协议标 `[UNSTABLE]`,快速迭代中。

**integrity/attestation 真实机制(CONFIRMED,纠正之前认知)**:Rust 内核**自己完全不实现** DeviceCheck/滚动令牌——二进制里搜 `IntegrityState`/`DeviceCheck` **零命中**。它只定义一个 `AttestationProvider` trait,通过 JSON-RPC 反向请求 `attestation/generate` **委托给外面的 Electron 壳**去做;拿回一个不透明 token 塞进 `x-oai-attestation` 头。"只发 OpenAI 域名"不是 URL 白名单,而是靠 `model_provider.supports_attestation()` 布尔位——第三方 BYOK provider 根本不会触发生成(有单测 `non_chatgpt_codex_endpoints_omit_attestation_generation` 佐证)。DeviceCheck 硬件证明的真身在没开源的壳层(需调 Apple `DeviceCheck.framework`,纯 Rust 没这依赖链)。

**app-server 协议(CONFIRMED)**:两代——v1 老式 approval 请求;v2 是 **thread→turn→item** 三层建模,方法名如 `thread/start`、`turn/steer`(运行中插话)、`item/commandExecution/requestApproval`、`item/autoApprovalReview/*`(Guardian)、`attestation/generate`。

**可借鉴**:① 真内核沙箱思路(seatbelt/bwrap,我们目前只有文件沙箱+备份);② tree-sitter 真语法切命令逐段判(比字符串切安全);③ thread/turn/item 协议分层建模;④ "客户端信任链委托"这个架构(把 DeviceCheck 之类原生能力从内核里分离出去,内核只留委托接口)——虽然我们用不上 attestation,但这个**"内核只定接口、原生能力外置"**的解耦值得学。

### 2.3 TRAE SOLO(字节)——"AI 项目承包工:目标进,成品出"

**定性**:VS Code 魔改 + 162MB Rust 常驻内核(`libai_agent.dylib`,工程名 `icube_server_rs`,socket 40005)+ 33MB `agent-tool-host`(工具执行宿主)。骨架是 Claude Code 重度克隆 + Cursor 味工具。

**内部架构(CONFIRMED,从 645 条泄漏 `.rs` 源码路径重建)**:标准 DDD 三层 `handler(API) → domain(业务) → infrastructure(适配)` + workspace 级 `crates/`(llm-client/sandbox/slardar/snapshot 通用能力)。domain 层三根支柱:`plan/simple_service_v2`(turn 编排)+ `ralph_loop`(自主循环)+ `hooks`(Claude Code 式钩子);`toolcall/tools/` 一文件一工具(90+)。

**特权分离(CONFIRMED,罕见地符号未剥离直接读到)**:`agent-tool-host` 是独立子进程,通过字节自研 **Volo/Thrift RPC**(`CommandsService.ExecuteCommand/Initialize/InitMcpServers`)接工具调用。**AI 推理主进程本身不碰文件系统**,危险操作(改文件/跑命令/浏览器)全下放到这个可被沙箱约束的子进程——这是很干净的安全设计。

**Ralph Loop 停止条件(CONFIRMED,`ralph_loop_stop_hook.rs` 读到真正则)**:读 `spec_dir/tasks.md`(退回 `checklist.md`),两条正则数未完成项 `^#{1,6}\s+\[.\]|^- \[.\]` vs 已完成项 `\[[xX]\]`;**全打勾也不立刻停,要连续两次判定完成(consecutive mark_done)才收敛**(防模型刚打勾又反悔);另有 max_round / 用户手停 / 企业策略三条退出。停止后出 `RalphLoopReport`(改动的代码/文档/图片计数 + token 统计)。**Goal 模式与 Ralph Loop 互斥**。

**turn 循环(DEDUCED,日志串拼)**:`tokio::select!` 让"正常路径 vs 用户中断"竞速;单 turn 内工具子循环用 `strict_parallel_tool_executor` 按 read_only/parallel/blocking 三位分批并发,**同批某工具失败传染取消同批其余(sibling_cancel)**;round 级由 Stop hook 决定是否自动续开下一轮。

**记忆(CONFIRMED,`memory/core_memory/strategy/` 读到)**:6 种淘汰策略并存——`exponential_decay/hybrid_half_life/lfu/linear_decay/lru/w_tinylfu`(含 **W-TinyLFU**,工业级缓存淘汰算法)。分层:core_memory(长期,MemGPT 风,带快照)+ shallow_memento(短期便签)。

**压缩(CONFIRMED 枚举 + DEDUCED 差异)**:4 种 `compact_with_separate_model`(独立便宜模型摘要)/`compact_with_chat_model`(复用当前模型)/`compact_with_chat_model_and_chat_prompt`(复用+专用prompt)/`micro_compact_only`(微压缩);另有 `summarized_above`/`truncated_above` 两种历史标记 + 同步/异步(后台)两条压缩线。

**沙箱(CONFIRMED,读到 SBPL 片段)**:macOS `sandbox-exec` + 自定义 profile,并用 `log stream` 监听内核 deny 事件反哺模型;`safe_rm` 别名劫持防护 + `is_dangerous_command.rs` + 文件/TCP/UDP 三维能力位。

**SOLO 独门(DEDUCED+CONFIRMED)**:SOLO Builder 先写 PRD/架构文档存 `.trae/documents/` 再编码(spec 驱动);多种 role agent(solo_coder/solo_builder/voice_*);DeepWiki 代码库文档站;飞书集成、CDP 浏览器、macOS 无障碍电脑操控。

**安全/隐私(最激进)**:无混淆;但字节全家桶遥测(slardar APM + TEA/applog 行为埋点 + libra 远程实验 + 设备指纹)**焊进原生二进制**;自研 TTNet(`libsscronet`)带 HTTPDNS 绕系统 DNS + store-region 数据落地路由(TikTok 同款 `aweme` 机制);**agent 工具默认自动批准执行且开关在 UI 隐藏**;此机为海外版(数据落 trae.ai SG/US + traeapi.us)。

**可借鉴**:① **特权分离**(AI 主进程不碰 FS,工具走独立可沙箱子进程)——安全架构典范;② Ralph Loop 的"tasks.md 打勾驱动 + 连续两次才收敛"的**长任务自主收敛**机制;③ W-TinyLFU 记忆淘汰;④ sibling_cancel(同批工具失败传染取消)。**反面教材**:默认自动执行+藏开关、绕系统 DNS——我们审批闸只卡对外的克制取向反而是对的,别学它。

### 2.4 Qoder(阿里)——"先读懂整个代码库,再动手"

**定性**:VS Code 魔改 + 101MB Go 内核(代号 **Cosy core**,`go1.23`,构建标签 `qoder,ide,prod`)。**是阿里"通义灵码 Lingma"换皮独立品牌**(二进制里 Lingma 配置都在,flag 关掉)。

**内部架构(CONFIRMED,Go 不剥符号→重建 2400+ 包)**:主模块 `cosy/`,顶层按代码量:`chat`(5200符号,LangGraph 风多 Agent 图:coder/deepwiki/atlas/quest/subagent)/ `lang`(多语言解析)/ `atlas`(2368,RepoWiki 引擎)/ `deepwiki`(2344)/ `memory`(2244,mem0 风)/ `core` / `agent`(ACP 协议)/ `indexing`(文本+向量+图三路)/ `quest`(云沙箱)。用了一批**阿里内部 fork**(langchaingo→`lingma-agent-graph`、mcp-go→内部 fork、tree-sitter/goldmark 内部 fork),向量走 **SQLite `sqlite-vec` (vec0)**,全文走 **bleve**。

**RepoWiki/Atlas 流水线(CONFIRMED,最独特,伪代码还原)**:Atlas 是一个**独立于 Qoder 的通用增量知识图谱引擎**(自带 CLI + schema 版本演进),DeepWiki 是它的产品消费方。统一"单步 LLM 阶段"框架(每阶段 `BuildPrompt/Stage/ParseOutput` + `NewExecutor`),8 个阶段复用:
```
冷启动 Generate():
  runPlanFromNode(root)      # ① 模块树规划(复用旧标题/去重/分配文章ID)
  runBudgetAgent()           # ② 复杂度/预算评估(A/B 实验不同预算策略)
  runRelationStage()         # ③ 跨模块关系抽取(LLM 工具调用批量吐关系,去重)
  runSynthStage()            # ④ 叶子→子树自底向上合成;runSynthDirtyClosure只重算"脏"闭包
  runRepoSynthStage()        # ⑤ 仓库级 cross-cutting 知识提取

  # 只对 dirty 子树重跑 ③④⑤,避免全量重算
```

## 4. 对我们项目的映射(→ 详见改进计划)

按"价值 × 可行性(我们是 Python 单窗口小白产品)"筛出真正能落地的:

- **高价值·低成本(强烈建议抄)**:
  - ToolCallLoopDetector(WorkBuddy 式软停止,4/40 不对称)——防我们 agent 卡死烧 token。纯 Python 逻辑,零依赖。
  - autocompact 三护栏(未决审批不压 / 30s冷却 / 无新历史不压)——补我们"压缩可能误伤 + 反复压"的坑。
  - 结构化压缩摘要模板(Primary Request/Files/Errors/Pending/Next Step)——补我们"压缩摘要未结构化"缺口(记忆里早标了)。
- **高价值·中成本(值得规划)**:
  - 记忆类型化 + 抽取子代理 + 召回小模型(WorkBuddy/Qoder 都有,我们店脑记忆可升级)。
  - Qoder RepoWiki 式"知识库增量组织"思路迁移到台球知识库/本机项目理解。
  - 长任务后台化 + Ralph Loop 式"清单打勾收敛"(补我们长任务弱项)。
- **高价值·高成本(记录待议,本轮不做)**:
  - 特权分离(工具走独立可沙箱子进程)——安全架构升级,但要动进程模型,重。
  - 真内核沙箱(seatbelt)——我们文件沙箱+备份目前够用,除非要放开 full-disk。
- **明确不纳入当前产品(反面教材)**:Trae 默认自动执行+藏开关、绕系统 DNS;各家强制登录/绑云——违背我们"全本地+免登录+审批卡对外"的护城河。
