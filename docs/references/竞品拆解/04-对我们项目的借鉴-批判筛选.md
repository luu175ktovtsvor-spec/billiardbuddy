## 0. 批判原则(什么可直接复制/抄/移植/改写,什么只学结论)

**2026-07-07 当前总则**:所有竞品借鉴先服务“强 coding agent 外壳”。CC-Haha 本地源码许可证允许 copy/modify/distribute/publish,所以其底盘能力(文件读写、patch、回滚、压缩、provider failover、trace、子代理、后台任务、检索来源)可直接复制/抄/移植/改写;UI 直接参考 Work Buddy/Codex 式低噪工具流。不要继承不适合我们的开发者产品外壳、云端/登录/Credits 假设、装饰性台球元素、首屏卡片墙。WorkBuddy/Trae/Qoder 等闭源竞品只学分析结论和产品取舍。

**"大厂做了" ≠ "它是对的" ≠ "适合我们"。** CC-Haha 可直接复制/抄/移植/改写其内核能力,产品层仍要确认是否符合我们的用户场景:
1. **对他们对、对我们错**:云端/登录/遥测/Credits(付费开发者工具该有,我们全本地免登录不能有)、RepoWiki(为代码库设计,我们知识库不是代码库)、Hooks(给会改配置的高级用户,我们用户不写 hook)。
2. **本身就过度工程**:274 个 DI 服务、三进程架构、记忆全套子系统——大厂养得起,我们抄进来是包袱。
3. **他们那个选择本身就坏**:Trae 工具默认自动执行 + 开关藏起来(对用户不负责)、给小白静默改写 prompt(用户判断不了)。

下面按这把尺子分档。

## 1. 🟢 闭眼抄(普适的对,且对我们更值)

内核健壮性,无聊但正确;几条对我们**成本模型更重要**(我们用内置 key,烧的是 owner 的钱):
- **工具死循环检测**(学 WorkBuddy):白名单常用工具连调 4 次判死循环、非白名单 40 次(不对称),命中不硬杀而是往上下文塞一条"停"让模型自己收场(软停止)。**对我们比对大厂更值**:BYOK 是用户自己烧,我们是烧 owner 的 key,agent 卡死循环 = 直接烧钱。纯 Python、零依赖。
- **autocompact 三护栏**(学 WorkBuddy):① 有未决审批时绝不压缩(别把等确认的卡片压没);② 30s 冷却;③ 无新历史不压(防"压完又压")。
- **结构化压缩摘要模板**:Primary Request / Files / Errors / Pending Tasks / Next Step,比自由摘要保留更多有用状态。补我们"压缩摘要未结构化"的已知缺口。
- **截断重试**(学 WorkBuddy TRUNCATION_RETRY):tool_call 被 max_tokens 截断就检测→净化→重试。我们**真踩过**写大文件 502 的坑,把补丁升级成正式护栏。
- **慢请求后台化 + 异步压缩 + 完成通知**(四家都有):几分钟的活(生图/视频)点了立即返回、后台跑、完成主动播报;压缩放后台不阻塞对话。直接治我们"生图静默期憋死界面"的老毛病,也对应现状与待办里"发布/剪辑后台异步+完成通知"。

## 2. 🟡 抄思路,做法要换成适合小白用户的版本

- **Prompt 增强器**(WorkBuddy/Qoder 有):后台把用户的大白话扩写成好指令——思路对(帮不会提需求的小白),但**绝不能学"静默改写"**(小白判断不了改歪没)。正确版:改完**给用户看一眼可确认/可编辑**,或只用来**反问澄清**,不替他重写。

## 3. 🟠 砍到小版本(全套是过度工程)

- **记忆系统**:四家的四类型/六维健康度/抽取子代理/每轮召回小模型,是给"开发者跨几百会话"设计的。我们店主需求窄而稳、店脑记忆已在跑。**只取两条纪律**:① 记忆分类;② 用前先核实(它说某文件存在,先 grep 验)。不要那套重机器(每会话多一次子代理、每轮多一次模型调用)。

## 4. 🔵 抄机制,理念按我们产品改

- **长任务**:后台化 + 任务清单跟踪(学 Ralph Loop 的"tasks.md 打勾 + 连续两次才收敛"防抖)= 要;但**"无人值守自主跑到完成"的全自主理念,跟我们"审批闸卡对外、人点确认"的立身之本冲突**——一个自主狂奔的 loop 在店主机器上烧 key、做他没让做的事,正是我们要防的。抄机制,别开自主模式。

### 5.2 ✅ 不碰颜色、conflict-free 的真升级(可上)
和锁定配色**不冲突**、纯质感提升:
- **背景 surface 分层**(纯白拆成 页面底/卡片/次级 2-3 层;深色用抬高的暖灰不用纯黑)

### 5.3 ✅ 文案话术(学 `03`)
- **两套语域**:系统文案硬朗精确(大白话但不卖萌),只有"AI 说话"才第一人称口语("我先帮你查一下…""好了叫你")。
- **报错公式** [发生什么] + [怎么办],别堆"抱歉"。
- **两段式状态文案**"正在准备X → 正在X",比笼统"处理中"更诚实安心。
- **空状态永远带下一步/带鼓励**(别只写"暂无数据")。
- **"确定吗?"只留真高风险**(清空店脑记忆),其余删除用具体问句("删除这张海报?删了找不回")。
- 删除讲清不可逆。

### 5.4 ✅ 交互设计(学 `03`)
- **卡顿分类状态机**(学 Trae):后台分几类(网络/网关排队/模型无响应/工具超时),headline 都说"有点慢",按病因给不同按钮(检查网络/换说法重试/继续等)。对应我们"报错当场认、给下一步"。
- **askQuestion 澄清面板**(学 Qoder):需求含糊时弹选择题(可多选+可自填+可一键推荐),别硬猜、别连问三次。
- **悬浮通知塔**(学 Codex):后台任务(生图/生视频/剪辑排队)做常驻小浮层,可内联追加一句,不用切回主窗口。
- 加载态有"生命感"(呼吸/流光)胜过转圈。

## 6. 工作区模型(新增 · owner 2026-07-05 提出,方向已定,待读码施工)

**问题**:现在是"选文件"——点回形针 📎 在指定文件夹里找单个文件打开(文件级沙箱=内容库+选定文件)。**这是异类**,四家全是"文件夹=工作区"(Qoder"请先打开一个项目"、Codex projects、Trae 空文件夹顶出聊天)。
**方向**:改成**选/新建一个文件夹当工作区 → 打开就进 → 管家在里面自由读写(带改前备份)→ 记住上次工作区**。
**安全边界跟着挪**:沙箱从"文件级"改"工作区文件夹级"——区内可写、出区要审批,**正好等于 Codex 的 `workspace-write` 模型**,不是拆安全是挪边界。
**拿捏度**:我们不是 IDE、用户是小白,**不要**文件树/多工作区/worktree 那套复杂度,做到"选文件夹+打开就进+记住上次"即可。
**施工前置**:必须先读当前 sandbox、tools、workspace 和 renderer 的真实实现，再按仓库改动路由确定主责模块。

## 7. ⚪ 可直接复制/抄/移植/改写前先定边界

- **RepoWiki/知识库增量**(Qoder):为"代码库会变、git 驱动增量"设计,我们台球知识是静态策展 PPT、没有对应触发源。**建议砍**,除非有明确"本机项目理解"场景。
- **情绪检测**(Qoder):LLM 判情绪不准易误报,软化交互靠人设 prompt 就够。**砍**。
- **Hooks 系统**:解决"用户自定义扩展",我们用户没这需求。**砍**。
- **审批粒度五级/tree-sitter 切命令**:安全加固不错,但我们跑命令场面少、攻击面小,**低优先**。
- **特权分离 / 真内核沙箱(seatbelt)**:真·好安全架构,但我们"文件沙箱+备份+审批闸"已覆盖实际风险,且软件装店主自己机器、威胁模型不同。**ROI 低,记待议、本轮不做**。
- **可直接复制/抄/移植/改写但当前先不纳入主产品**:登录/云端/遥测/Credits 订阅、Trae 默认自动执行+藏开关、YOLO 全局跳过确认、IDE 黑话(iCube/YOLO)。这些不是版权问题，而是会影响"全本地+免登录+审批卡对外"的产品定位；后续如 owner 改目标，可按源码/公开行为再搬。

## 8. 施工优先级建议(方向,非承诺)

1. **先做(见效快 + 低风险)**:内核护栏四件套(死循环检测/压缩三护栏/结构化摘要/截断重试)+ 慢请求后台化+完成通知 + 设计 token 质感升级(分层/透明度文字/柔阴影/统一量表)+ 文案公式(两套语域/报错公式/两段式状态/空状态带下一步)。
2. **再做(中等,有产品判断)**:工作区文件夹模型(需先读码)、记忆小升级(分类+核实)、卡顿分类状态机、askQuestion 澄清面板、悬浮通知塔。
3. **待 owner 定**:特权分离、真内核沙箱。(配色已由 走法 B,并在 2026-07-07 桌面 UI/创作工作台批次落地;后续只做一致性维护。)
