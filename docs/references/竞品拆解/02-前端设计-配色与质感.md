## 一、"高级/官方感"的六件套配方(四家一致验证到)

1. **不用纯白纯黑,背景分 2–5 层灰阶**(深色是抬高的暖灰/冷灰,不是 `#000`)。实证:Qoder 深色 `--color-bg-layout:#171716`(暖黑,非 `#000000`);WorkBuddy 深色五级 `#0E0F11→#141518→#1A1B1E→#212327→#2A2C31`。
2. **文字用透明度分级**,一套值适配任何背景色。实证:WorkBuddy `--wb-palette-black-90/-70/-50/-30`(即 `rgba(0,0,0,.9/.7/.5/.3)`),深色侧对应 `rgba(255,255,255,.92/.65/.45/.25)`——同名语义 token(`text-primary/secondary/tertiary/disabled`)左右两套数值互换即可切主题。
3. **只留一个克制强调色,主按钮用中性黑/白,品牌色只点缀链接/角标/焦点**(四家里最关键、最反直觉的一条)。实证:Codex 主按钮背景直接是 `var(--color-text-foreground)`(#1a1c1f 近黑,不是蓝);唯一的蓝 `--blue-300:#339cff` 全篇只用在 1 处——`--color-border-focus`(聚焦环)。WorkBuddy 主按钮 `--wb-button-primary-bg: var(--wb-palette-black-90)`(即 `rgba(0,0,0,.9)`),青绿 `#00C29A` 只出现在链接色、未读角标、选中态描边这几个点缀位。
4. **阴影柔和、多层、低透明度**,不是单层硬阴影。实证:Qoder 四级阴影精确值 `rgba(0,0,0,.02/.035/.055/.075)`;WorkBuddy popover 阴影是两层叠加(`0 4px 12px -4% + 0 3px 6px -8% 4%`)。
5. **圆角/间距/动效统一 token 量表**,圆角集中在 4–8px(不是随手写的数字)。实证:Qoder 全文件 `border-radius:4px` 出现 894 次,是全场最高频值;Trae 主题扩展里 `4px` 出现 374 次同样最高频。
6. **三层 token 架构**:原始尺度(palette/config)→ 语义(text/border/bg/fill/accent)→ 组件别名。实证见下方每家小节的"三层实例"。

## 二、我们项目的病根诊断

现状:白底 + 绿 `#10a37f`(借的 ChatGPT 色)+ 蓝 `#007AFF`(借的 Apple 系统蓝)、跟随系统深色。

对照上面六件套逐条看:①纯白背景基本无 surface 分层(四家都做了 2–5 层灰阶,我们没有);②大概率没有统一的圆角/阴影/动效 token 量表(四家都有,哪怕是 VS Code 白捡来的);③**两个"借来的大厂色"同时高频出现**,这一点和四家"只留一个克制强调色"的共同做法方向相反——四家里离得最近的反例,也只是 WorkBuddy 在**企业登录页**一处硬编码了腾讯 TDesign 品牌蓝 `#0052D9`(`.cb-oauth-callback__btn{background:#0052d9}`),范围极窄(1 个按钮),且这恰好被验证是这四家里**唯一**一处"体系外硬加色"的实锤,证明"到处混用两个不同来源的强调色"确实是少见、显眼的做法。

> ⚠️ **重要说明,别误读**:项目记忆(`chat-window-color-midnight-blue-d.md`,2026-06-28)记录 owner 已经拍板——**当前白底 + 绿 `#10a37f` 主 + 蓝 `#007AFF` 辅这套配色就是定稿**,不再讨论换色,也不要把"绿蓝混用"当反人类点写进验收报告。本节的诊断和第五节的 token 草案**只是竞品分析的客观记录**,供以后如果 owner 主动要重新讨论配色时参考,**不是本文档在建议现在就改颜色**,更不构成变更指令。

## 三、四家真实色板与质感细节(逐家)

### 3.1 Codex(OpenAI)—— 全篇最克制,灰阶 + 单点强调色

| 用途 | 浅色值 | 说明 |
|---|---|---|
| 灰阶 0/50/100/300/500/550/600/700/750/800/900/1000 | `#fff / #f9f9f9 / #ededed / #afafaf / #5d5d5d / #4f4f4f / #414141 / #303030 / #282828 / #212121 / #181818 / #0d0d0d` | 12 级灰阶尺度,`--color-*` 语义层从这批取值 |
| 正文文字色 `--color-text-foreground` | `#1a1c1f` | 不是纯黑,略带蓝紫的深灰 |
| 唯一强调色 `--blue-300` | `#339cff` | 全篇仅用于 `--color-border-focus`(键盘聚焦环),`color-mix(...70%,transparent)` 或写死 `#339cffb3` |
| 边框(以正文色为基准做透明度分级,不是固定 8%) | `--color-border-light` 5% / `--color-border-heavy` 12% / `--color-border-elevation` 12%~20% | `color-mix(in oklab, var(--color-text-foreground) N%, transparent)`,四级都锚定同一个文字色变量 |
| 主按钮 | 背景 `var(--color-text-foreground)`(近黑),文字 `var(--gray-0)`(白) | hover/active/inactive 状态用 `color-mix` 6%/10%/16%/24% 分级,**不引入品牌色** |

- **圆角**:`--radius-2xs-base .125rem`(2px)一路到 `--radius-4xl-base 1.5rem`(24px),且有一个整体倍率开关 `--corner-radius-scale`(默认 1,来自 `--codex-corner-radius-scale`)——圆角是可被一个"设置项"整体缩放的,不是写死数字。
- **字体**:正文走系统字体栈(`ui-sans-serif, system-ui, sans-serif...`),等宽走 `ui-monospace/SFMono-Regular/SF Mono`;品牌字体 "OpenAI Sans" 只在 `.font-openai-sans` 这一个工具类里出现,不是全局字体。
- **判决**:六件套里第 3 条(单一强调色)执行得最彻底——一个蓝色变量、一个用途(聚焦环),其余全部是同一个文字色变量的透明度分级,连边框、阴影、hover 态都锚定它,系统一致性极强但视觉上几乎"看不出"有设计感,靠的是克制而非留白。

### 3.2 WorkBuddy / CodeBuddy(腾讯)—— token 系统化程度四家最深,但登录页有硬伤

| 用途 | 浅色 | 深色 |
|---|---|---|
| 灰阶 1–5 | `#FAFAFA/#F7F7F7/#F2F2F2/#EBEBEB/#E6E6E6` | `#0E0F11/#141518/#1A1B1E/#212327/#2A2C31` |
| bg-primary / secondary / tertiary | gray-3 / gray-2 / gray-4 | 同名映射(层级编号故意错位,不是简单顺序) |
| 文字 primary/secondary/tertiary/disabled | `rgba(0,0,0,.9/.7/.5/.3)` | `rgba(255,255,255,.92/.65/.45/.25)` |
| 品牌强调色 brand-8 | `#00C29A` | `#5FE3C5` |
| 主按钮背景/文字 | `rgba(0,0,0,.9)` / 白 | hover 96%、active 80%、disabled 24% 黑色透明度 —— **不是品牌色** |
| 圆角 xs/sm/md/lg/xl/2xl/full | `2/4/6/8/12/16px / 9999px` | 同 |
| 动效时长 fast/sm/base/slow | `120/150/200/320ms` | 同,缓动 `cubic-bezier(.4,0,.2,1)`(标准)/`cubic-bezier(.2,0,0,1)`(强调) |

- **三层 token 实例(全场最干净的一例)**:原始尺度 `--wb-palette-black-90: rgba(0,0,0,.9)` → 语义层 `--wb-color-text-primary: var(--wb-palette-black-90)` → 组件别名层 `--cb-text-primary: var(--wb-color-text-primary)`。品牌强调色也一样只在链接色、未读角标、选中态描边这几个点上出现,不做大面积背景。
- **字体纠偏**(核实后推翻最初的猜测):body 默认字体走 `--cb-font-family`(系统字体栈 `-apple-system, ... sans-serif`);"Assistant" 这款字体文件虽然打进了包,但实际只在内嵌的 Excalidraw 白板组件里用(Excalidraw 官方默认字体之一,不是 WorkBuddy 自己选的品牌字体);"Montserrat" 更是只用在头像旁边的用户名这一处(`.avatar-container .name`),CJK 兜底 `PingFang SC`。**结论**:body 字体几乎全是系统默认,自定义字体的使用范围比表面看到的"打包了几款字体"要窄得多。
- **一个独有的小巧思**:`@keyframes cb-shining-text-sweep`(背景位置从 200% 扫到 -200%),base/highlight 透明度锚定 `0.26 / 0.55`,专门给"深度思考中"这类 loading 文案做"流光扫字"效果——四家里只有它做了这个细节。
- **唯一实锤的"硬加色"瑕疵**:企业登录 OAuth 回跳按钮 `.cb-oauth-callback__btn { background:#0052d9 }`,这正是腾讯 TDesign 组件库的默认品牌蓝(`--td-brand-color-7:#0052d9`,来自内嵌的 TDesign 组件库 CSS),和主色体系(青绿 + 中性黑)完全不搭调,范围仅限企业登录这一个按钮。
- **判决**:token 系统化程度四家最深(三层架构 + 统一动效曲线 + 独立编译产物),细节巧思也最多;但登录页这个蓝色硬伤,证实了"局部像硬加进去"的直觉是真的——只是范围极窄(1 个按钮),不是主 UI 大范围问题。

### 3.3 Trae SOLO(字节)—— 官方感九成是继承来的,不是自己做的

| 主题 | editor/sideBar bg | activityBar bg | 前景/按钮 | 强调色(progressBar/角标/信息图标) |
|---|---|---|---|---|
| Light(浅色默认) | `#FFF` | `#EDEFF2` | `#31353A` | `#2F74FF` |
| Deep Blue(唯一自己认真调的主题) | `#181D27` | `#232A35` | `#D1D3DB` | `#387BFF` |
| Dark(默认深色) | — | — | — | 主题 JSON `colors` 字段基本是 `null`,即**没有自定义,纯继承 VS Code 官方深色主题** |

- **圆角**:内嵌组件库 CSS 里 `border-radius:4px` 出现 374 次,是全场最高频;`6px`(263 次)、`8px`(125 次)次之,单层扁平阴影为主,没有多层柔和阴影这套讲究。
- **动效**:`easeOutStandard: cubic-bezier(.3, .8, .2, 1)`;`--motion-duration-medium-1: .25s`、`medium-2: .333s`、`long-1: .5s`、`long-2: .75s`。
- **最直接的"抄了没改干净"证据**:自带主题扩展 `theme-icube` 的 `package.json` 里,`"repository":{"type":"git","url":"https://github.com/microsoft/vscode.git"}`——这个字段原封不动指向 VS Code 官方仓库,连改成自己仓库地址都没做。
- **真正自研的部分**:`node_modules/@byted-icube/webcomponents`、`@byted-icube/solo-lite` 才是字节自己的前端组件层(前缀 `icube`),但没有找到成体系的 `icube--` 三层色板 token(全局搜索命中的 `--icube-*` 只有零星 3 个 key,如 `--icube-statusBar-background`),圆角/动效 token 定义在继承来的 `workbench.desktop.main.solo-lite.css` 里而非自建体系。
- **判决**:所谓"官方感"九成继承自 VS Code 本身(连主题包的 repository 字段都没改),字节自己下功夫的地方是配色**数值**本身(尤其 Deep Blue 这套自定义配色),而不是搭了一套自己的 token 架构。

### 3.4 Qoder(阿里)—— 暖灰阶 + 挪用 Ant Design 语义 token 命名,架构最规整

| 用途 | 浅色(`对齐 New Qoder Light`) | 深色(`对齐 New Qoder Dark`) |
|---|---|---|
| `--color-primary`(强调绿) | `#67C96C`(hover `#5BB960` / active `#4CAF50`) | `#2ADB5C`(hover `#3DE06D` / active `#25C653`) |
| `--color-text` / secondary / tertiary / quaternary | `#141414 / #636261 / #838280 / #8E8C8B` | `#D6D6D3 / #95958F / #7B7B75 / #636261` |
| `--color-border` / secondary / tertiary | `#DDDDDD / #BCBBBA / #E6E6E6` | `#2A2926 / #484843 / #2A2926` |
| `--color-fill` / secondary / tertiary / quaternary | `#DFDFDF / #E3E3E3 / #F3F3F3 / #F8F8F8` | `#31312D / #2A2926 / #1D1D1A / #171716` |
| `--color-bg-layout` / `bg-base` / `bg-container` / `bg-elevated` | `#FFFFFF / #FFFFFF / #F3F3F3 / #F3F3F3` | `#171716 / #171716 / #1D1D1A / #171716` |
| 阴影四级 primary/secondary/tertiary/quaternary | `rgba(0,0,0,.02/.035/.055/.075)` | 同(黑色阴影,深浅主题共用同一组透明度) |

- **命名规则实锤**:`--color-primary/-hover/-active/-bg/-border/-text`、`--color-text/-secondary/-tertiary/-quaternary`、`--color-border/-secondary/-tertiary`、`--color-fill/-secondary/-tertiary/-quaternary`、`--color-bg-container/-elevated/-layout/-spotlight` 这套四级递进命名,和 Ant Design Design Token 体系(`colorPrimary/colorText/colorTextSecondary/colorBorder/colorFillTertiary/colorBgContainer/colorBgElevated`)逐字对应,只是把 camelCase 改成了 `--color-` 前缀的 kebab-case,大概率直接挪用了 AntD 的语义色阶命名(是否复用了 AntD 的色阶生成算法本身没法从产物里 100% 证实,但命名规则的对应关系是可验证的)。
- **四层 token 链**(全场最长):配置层 `--config-radius-sm/md/lg/xl/2xl/3xl`(4/6/8/12/16/24px,`--config-motion-duration-fast/base/slow` 150/200/300ms)→ 组件通用层(Tailwind/shadcn 风格命名 `--radius-DEFAULT/sm/md/lg/xl/2xl/3xl`)→ 语义层(`--color-primary/text/border/fill/bg-*`)→ VS Code 集成层(如 `--color-button-primary-bg` 依次 fallback `var(--vscode-aicoding-buttonBackground, var(--vscode-button-background, var(--color-bg-highlight)))`)——最后一层专门留了 VS Code 原生变量兜底,说明这套 token 是"叠"在 VS Code 主题体系之上的,而不是完全推翻重来。
- **圆角有个不完全对齐的小细节**:配置层刻度一路到 24px(`--config-radius-3xl`),但组件实际应用的 `--radius-2xl/-3xl` 都被按到了 `8px`——即真正落地的组件圆角封顶在 8px,全文件 `border-radius:4px` 出现 894 次全场最高。
- **动效**:`cubic-bezier(0.16, 1, 0.3, 1)`(经典 expo-out 曲线,和 Tailwind 默认 `--tw-duration` 用的时长同源)。
- **判决**:暖灰阶(`#171716` 非纯黑)+ AntD 语义命名 + Tailwind 风格组件半径量表叠一起,是四家里 token 架构层数最多、最规整的一个;唯一小瑕疵是配置刻度(到 24px)和实际应用圆角(封顶 8px)没完全对齐,像是拼了 AntD 和 shadcn 两套命名习惯。

## 四、验证的用户直觉

- **"WorkBuddy 偏小白"**:半对。文案外热内专业(见 01 号文档),配色/token 本身系统化程度反而四家最深;"像硬加进去"的直觉**真实存在但范围极窄**——只坐实在企业登录 OAuth 回跳按钮这一处腾讯 TDesign 蓝(`#0052d9`),不是主 UI 大范围问题。
- **"Codex 简洁"**:对,根子是"克制"(一个强调色只用在聚焦环)加"系统化"(边框/hover/圆角全锚定同一批变量做透明度分级),不是靠大留白堆出来的简洁感。
- **Trae / Qoder(用户没深入用过,补充实证)**:都是 VS Code 魔改,"官方感"大部分是**继承**而非**自建**——Trae 连主题扩展的 `repository` 字段都没改;Qoder 虽然架构最规整,但底层也是叠在 VS Code 变量体系上,而非从零重做。

## 五、给我们项目的 token 草案(仅供参考,不是变更指令)

> 见第二节末尾的说明:owner 已拍板当前绿 `#10a37f` + 蓝 `#007AFF` 配色定稿,不改。下面这份 CSS 变量草案只是把四家的共同做法(surface 分层 + 单一强调色 + 双层柔和阴影 + 统一圆角/动效量表)翻译成可执行的 token 形式,留档供以后如果 owner 主动重启配色讨论时直接抄用,现在不落地。

```css
/* 浅色(参照 Qoder 暖灰阶 + Codex 的"单一强调色"做法) */
:root {
  --bg-page: #F3F2EF;         /* 页面底色,不用纯白 */
  --bg-surface: #FFFFFF;      /* 卡片/面板 */
  --bg-surface-2: #ECEAE4;    /* 次级面板(hover/选中态背景) */
  --border: rgba(0, 0, 0, 0.10);
  --text-primary: rgba(0, 0, 0, 0.9);
  --text-secondary: rgba(0, 0, 0, 0.6);
  --text-tertiary: rgba(0, 0, 0, 0.4);
  --accent: #10a37f;                    /* 只保留一个强调色,只点缀链接/角标/焦点环 */
  --btn-primary-bg: rgba(0, 0, 0, 0.9); /* 主按钮走中性黑,不用品牌色 */
  --btn-primary-fg: #FFFFFF;
  --shadow-sm: 0 1px 2px rgba(0,0,0,.04);
  --shadow-md: 0 2px 8px rgba(0,0,0,.08), 0 1px 2px rgba(0,0,0,.04); /* 双层 */
  --radius: 8px;              /* 四家共同的高频圆角 */
  --motion-fast: 150ms;
  --motion-base: 200ms;
  --motion-easing: cubic-bezier(0.4, 0, 0.2, 1);
}

/* 深色:只重写语义层的值,原始尺度/组件层不用动 */
:root[data-theme="dark"] {
  --bg-page: #141310;         /* 暖黑,不是 #000 */
  --bg-surface: #1D1C19;
  --bg-surface-2: #26241F;
  --border: rgba(255, 255, 255, 0.10);
  --text-primary: rgba(255, 255, 255, 0.92);
  --text-secondary: rgba(255, 255, 255, 0.65);
```
