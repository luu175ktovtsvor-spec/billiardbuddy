# 前后端接轨 · 五类连接模式与判据

> 📌 状态:✅现行 · 最后核对 2026-07-12 · 定位:CLAUDE.md「前后端衔接铁律」是四条纪律,本文是它的**工程细分**——前端(照 Codex 的皮)每一个按键/面板,到底走哪条管道接到后端(照 cc 的骨),契约放哪、上下文带什么、错了用户看到什么。配套操作 checklist 见 `.claude/skills/前后端接轨/SKILL.md`。

## 0. 总原则(先背再干)

- **底座分工**:Agent 内部循环的底座参照 cc(ts/src 内核);前端长相/交互参照 Codex(renderer-react)。两者之间**只有契约,没有第三个底座**——所谓"衔接层"不存在,存在的是五类明确的管道。
- **契约以后端为准**:Codex 只回答"长什么样";它的 UI 需要什么数据,就在后端补真实能力或明确降级,**禁止前端 mock 假数据糊界面**。
- **两条线判据**(CLAUDE.md 最高层认知):让 AI 干活的 → A 线模型循环;确定性产品功能(工作台/表单/定时)→ B 线写死代码。两线只用三种廉价方式相接:给模型一个工具 / 塞一条预定义 prompt / 后端直接调。

## 1. 五类连接模式(每个按键先归类,再动手)

### ① A 线对话流(WS 消息族)
- **是什么**:一切"让 AI 干活"的交互——发送、审批卡(允许一次/本次对话都允许/拒绝)、中途插话 steer、打断 interrupt。
- **管道**:renderer chatStore → WS `{type: run|steer|approve|reject|interrupt}` → sidecar → 内核循环;事件流(assistant_text/tool_call/tool_progress/approval_request/done…)回来渲染。
- **契约位置**:`ts/shared/contracts/agent-events.ts` + `agent-websocket.ts` 是 Zod 单一真相源；renderer 类型入口和 sidecar WS 分发共同复用。
- **⚠️ 命门 = 上下文完整性**:这类消息**每一条**都必须带全会话上下文(conversationId / working_dir / permissionMode / enabled_packs)。血案:2026-07-12 真机 E2E 逮到 approve 消息漏带 working_dir → 审批通过的写文件落到默认目录、transcript 劈错分区。修法双保险:前端补字段 + 后端从 session meta 自愈。**新加任何 WS 消息类型,先对照 run 消息把上下文字段抄全。**
- **错误契约**:后端错误经 outputScrub 白标清洗后以事件回流,前端渲染成对话内横幅/气泡,不弹系统框。

### ② B 线产品功能(REST + job 化)
- **是什么**:生图工作台、剪视频工作台、定时任务、门店表单——按钮点了跑确定性代码,不进模型循环。
- **管道**:面板组件 → sidecar REST(`/api/v1/media/*`、`/api/v1/video-edit/projects/*` 等)→ 确定性服务;**慢活一律 job 化**(submit 返回 job id → 轮询/事件回progress → 完成取结果),绝不让 HTTP 挂着等几分钟。
- **契约位置**:各面板的 api 调用 ↔ 对应共享 Schema ↔ server route + services；新增业务不得继续把独立逻辑堆进 `server/index.ts`。
- **⚠️ 命门 = 反逻辑保护**:依赖未就绪(资产没下完/组件在准备)必须显示"正在准备 x%"并就绪后自动继续;失败必须给用户一句能看懂的话。**点了没反应 = 破坏产品的 bug**。

### ③ 本机原生能力(Electron IPC 白名单)
- **是什么**:要动 OS 的按钮——选文件夹/选文件、用默认程序打开、Finder 显示、防休眠。
- **管道**:组件 → `lib/desktopHost.ts`(统一入口,浏览器端优雅降级)→ preload 白名单 → main 进程 `registerIpc()` → Electron shell/dialog。
- **契约位置**:`ts/shared/contracts/desktop-host.ts` 统一 IPC 通道名和 `DesktopHost` 类型；`electron/main.ts`(handler+payload校验)+ `preload.ts`(暴露)+ renderer `desktopHost.ts`(绑定)共同复用；改后重跑 `desktop:build`。
- **⚠️ 命门 = 白名单纪律 + 错误契约显式化**:每个 handler 必须校验 payload(非字符串/超长直接拒);错误语义照系统契约走(例:shell.openPath 返回非空字符串=错误信息,前端拿到就 toast)。浏览器/H5 端没有 desktopHost → 按钮**不渲染**,不是渲染了点不动。
- **零副作用验证技巧**:测链路通不通,用"开一个不存在的文件"→ 必须返回错误串,全链路验证且不真弹任何窗。

### ④ 只读数据面(GET + store 入口归一化)
- **是什么**:工作区文件树、文件预览、会话列表、项目列表、git 状态——展示型数据。
- **管道**:zustand store → GET REST(fs/read、fs/list、workspace-status、sessions、sessions/projects)→ 渲染。
- **⚠️ 命门 = 类型漂移**:Agent WS/事件和 IPC 已迁到共享 Zod Schema；其余旧 REST 仍有手写类型债。**规矩:新跨层契约直接落 `ts/shared/contracts`,前端 API 入口运行时解析；旧 REST 改动时顺手迁移对应契约，不让原始 JSON 直接进组件。** 血案:后端时间是 ISO 字符串、前端类型写 number → 相对时间 NaN；workspace-status 的 tree 形状写错 → 文件树不显示。
- 带工作目录的查询必须带 working_dir 参数(fs 族已封 `wdParam()`,新查询照用)。

### ⑤ 纯前端状态(localStorage,不过后端)
- **是什么**:折叠展开、面板宽度、主题、草稿。
- **判据**:**换台电脑丢了也不心疼的才允许纯本地**。会话绑定工作目录这种业务事实必须后端持久化——前端 localStorage 只做加速缓存,后端 meta 是真相源(openExistingConversation 的 adopt 兜底就是这个模式)。

## 2. 接轨五问(每个新按钮/新面板动手前过一遍)

1. **归哪类?** 上面①~⑤选一个。选不出来 = 需求没想清楚,回去想。
2. **契约在哪个文件?** WS 类型 / REST 路由 / IPC 三层 / store 归一化点,列出两端谁生产谁消费。
3. **上下文带全了吗?** 会话 id、工作目录、权限档、领域包——对照同类现有消息抄全。
4. **错误契约是什么?** 用户点了失败,看到什么话?(禁止静默失败、禁止点了没反应)
5. **测试锁了吗?** `bash scripts/quality_gate.sh` + 共享 Schema 合法/非法/兼容用例 + `/桌面端到端验证`;新连接点没测试盖到就补一条。

## 4. 案例库(真实血案,新会话先读)

- **approve 丢 working_dir**(①类命门):前端漏带上下文 + 后端兜底默认值 = 文件写错文件夹。教训:上下文字段抄全 + 后端自愈双保险。
- **ISO 时间戳 NaN**(④类命门):手写类型骗了自己,运行时静默烂掉。教训:store 入口归一化。
- **openPath 错误契约**(③类样板):按系统契约(非空串=错误)设计返回,前端 toast,零副作用可测。
- **项目分组**(契约先行样板):动手前先发现后端 /sessions/projects 已有,前端只补消费端——**先找契约再写码,经常发现活比想象的小**。
