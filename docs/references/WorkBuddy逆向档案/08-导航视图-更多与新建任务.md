## 0. 侧边栏总体结构（硬编码入口表 · 代码确认）

来源 `connector-CvFT3fv6.js`，源码 `packages/agent-ui/src/modules/iframe-menu/builtin/public-menus.ts`，变量 `sidebarTabMenus`。

**设计原则注释（★值得学的白标机制）**：
> "公共菜单声明。侧边栏主 tab 入口的 key/默认文案/默认图标/排序/gate 声明。点击行为(action)在 conversation-list 消费侧注入，此处只声明展示属性。设计原则：**后端只控展示属性（显隐/文案/图标/排序），跳转行为由客户端按 key 硬编码，不碰功能。**"

即：**后端下发一张"菜单可见性/文案/图标/排序"覆盖表，前端按 key 硬编码跳转**。这是它做灰度/企业定制的核心手法，球房管家可照抄这套"后端控展示、前端控行为"的分层。

## 1. 「更多」菜单 = hover 下拉，聚合"资料库 + 灵感"（代码确认）

### 1.1 触发器按钮
className `conversation-list-tab-button-more`（active 加 ` active`）；内容三段：`<MoreIconV2 16×16>` + `<span>更多</span>` + `<span>`（**红点** moreEntryBadgeVisible + **动态副标签 moreSubLabel**）；`onMouseEnter: handleMoreEntryHover`（hover 预取）。

### 1.2 Dropdown 参数
```
placement: "right-start",   // 向右弹出
triggerMode: "hover",       // 悬停即开，不是点击
offsetDistance: -12,
portalRoot: "body"
```

### 1.3 副标签动态拼
```
if 有资料库项  push "资料库"
if 有灵感项    push "灵感"
moreSubLabel = parts.join("·")   // → "资料库·灵感"
```
即副标签根据实际开启了哪些子项**动态拼**，不是写死。

### 1.4 menu 里有哪些项 + 路由 + gate（代码确认）
三组 concat，组间插分隔线：
- **A 组**（gate `knowledgeBaseEnabled`）：`myFiles`="我的文件" → `/library/my-files`
- **B 组 libraryGroup**（各自 gate）：`tencentDocs`="腾讯文档"→`/library/tencent-docs`、`ima`="ima知识库"→`/library/ima`、`lexiang`="乐享知识库"→`/library/lexiang`
- **C 组**（gate `discoverFeatureEnabled && isInspirationEntryEnabled`）：`inspiration`="灵感" → **`/discover`**（← 灵感 = DiscoverPanel！）

每项 icon 支持后端覆盖（`renderMenuIcon`）。tencentDocs/lexiang 点击前先查 OneID 企业 gate，checking 时弹 toast 拦截。

> **关键结论**：「更多」里**没有**设置、插件、技能、连接器——它只有"资料库四项 + 灵感一项"。设置在别处（§7）。

## 3. DiscoverPanel（/discover）——"灵感"案例起点库

CSS token 前缀 `--dc-*`（自成一套，**单色中性**）：
- 主色 `--dc-primary` **#2C2C2E**（light）/ **#E0E0E2**（dark）
- 背景 #FFFFFF/#101114；卡片 #FFFFFF/#181B20
- 收藏色 `--dc-favorite` **#EF4444**（红心）；按钮渐变 #2C2C2E/#343841
- 布局：`--dc-page-gutter` 20/24px

**文案**：标题"灵感"；副"常见工作流沉淀成可复用的任务起点"；顶部标签 精选/换一换/全部/按场景分类；搜索"搜索灵感"；卡片详情 **"做同款"** / **"立即体验"** / 详细介绍 / 标签类别 / Prompt 预览 / 关联资源 / 产物预览。

**结构**：顶部分类 tab（第一"全部"、第二"精选"，其后后端下发场景）；精选区横滑（换一换）；卡片（cover/title/meta/favorite/badge）；**详情弹层从底部上滑**（`translateY(18px)`→0，radius `18px 18px 0 0`），左右分栏，预览支持 code/docx/pptx/image/markdown/table/iframe，底部"做同款/立即体验"；右侧抽屉（宽 380，"我的收藏"）。

**点击案例卡 → 启动流程**（多阶段）：
1. 可编辑 prompt
2. **资源检查**：技能/专家/MCP 三类，状态 installed/notInstalled/connected/disconnected
3. 缺啥装啥：安装技能→连接 MCP→失败重试
4. 阶段推进：checkingResources → installingSkills → connectingMCPs → **creatingTask** → sendingPrompt → complete
5. 取消保护："启动中，确定取消吗?"

**核心接线（代码确认）**：点"做同款/立即体验"最终 =
```
handleNewTask(true);                     // 开新任务
setConversationListView("tasks");        // 侧栏切回任务列表
adapter.requestInsertContentBlocks({     // 把技能/资源作为 content block 注入输入框
  contentBlocks: [...skillBlocks], clearFirst: true,

```

## 6. 「新建任务」点击流程

### 6.1 点击机制
侧栏第一个 tab（key `new_task`）。点击调 `handleNewTask(true)`——是 useConversations() context 暴露的**注册式 handler**（真正实现由聊天区/claw-workspace 挂载时 register 进来，**混淆读不到函数体**）。效果：清空 currentConversation、切 view 到 tasks、进一屏空白"欢迎页 + 输入框"。上限保护"会话数量已达上限"。

### 6.2 欢迎页 = 新任务落地屏
`WelcomeHeader`：Logo（72px）+ 标题 **"WorkBuddy，我帮你"**（白标换"球房管家，我帮你"）+ 副"一站式产品工作室，助你规划、开发和发布应用。"；标题带装饰（highlightWord/starWord/curveStyle 对某词高亮/星星/曲线下划）。

### 6.3 三种模式选择器（★强机制）
`DEFAULT_MODE_OPTIONS`（模式→prompt 模板映射）：
```
working  日常办公  面向日常工作与知识生产
coding   代码开发  面向代码与工程交付
design   设计创意  面向设计与创意产出
```
> 关键注释：**"renderer 按 `{family}-{welcomeMode}` 组合选择 `.tpl` 模板（workbuddy-craft-design-prompt.tpl 等），因此不再携带 systemPrompt 字段。"** 即选哪个模式，后端就用哪套系统提示词模板。→ 球房管家可照此做"门店运营/内容创作/数据分析"分流。

### 6.4 快捷动作
起草产品规格 / 分析代码缺陷 / 生成文档 / 代码审查 / 重构代码 / 编写单元测试 / 编写文档 / 分析数据 / 起草邮件 / 研究主题 / 总结内容 / 生成报告（点一下把模板 prompt 填进输入框）

### 6.5 工作空间/仓库选择器
新任务可绑定工作目录或代码仓库：选择工作空间 / 新建工作空间 / 打开本地文件夹 / 不使用工作空间；新建工作空间"为工作空间命名，本地将自动创建同名文件夹，命名后不可随意更改"；代码平台三选一 GitHub/工蜂/CNB（选仓库+分支）；"可前往「系统设置」设置默认工作空间存储路径"

### 6.6 空态
无任务时侧栏："暂无任务" / "点击上方按钮开始新任务"

## 8. 给「球房管家」的可复用点（结论）

1. **侧栏"后端控展示、前端控行为"分层**：菜单表下发 显隐/文案/图标/排序，跳转 by key 硬编码——做灰度/门店定制很干净。
2. **"更多"= hover Dropdown 聚合次要入口**，副标签按已开子项动态拼，向右弹、triggerMode hover。
3. **两套配色体系可参考**：资料库/案例库走中性单色（主 #2C2C2E），每日灵感走品牌紫（#6d5ff5）——换成球房品牌色，结构照搬。
4. **"起点/案例 → 新建任务"统一走一个 adapter API**：`requestInsertContentBlocks({contentBlocks, clearFirst, promptText})`——所有"预置 prompt 灌进输入框"都用它，值得我们也抽一个。
5. **模式→prompt 模板映射**：办公/代码/设计三模式各挂一套系统提示词，天然适合我们做"门店运营/内容创作/数据分析"分流。
6. **新任务可选工作空间/本地文件夹/代码仓库**——本地 Agent 桌面版标配。
