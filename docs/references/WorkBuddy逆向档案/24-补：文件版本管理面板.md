# 24-补：文件版本管理（fileVersion 面板）

> **第二轮穷尽补齐**（2026-07-10）。归属：**App 外壳 = WorkBuddy** 侧（复用右侧详情面板"变更"tab）。
> **可信度**：可照抄级别，全从真代码扒出（组件+CSS+i18n+RPC 契约齐全）。
> **一句话**：这是"工作空间文件的 git 式版本历史"面板。**不是独立弹窗/导航项，而是复用右侧产物详情面板（DetailPanel）里的"变更"这个 sidebar tab**——桌面版且开实验开关时，"变更"改名成"文件版本管理"，左栏变 commit 时间线、右主区变该 commit 的文件明细+diff。
> **务实取舍**：见第十一节。

真代码：组件+CSS `detail-panel-wrapper-BYcPBkf-.js` + `detail-panel-wrapper-CeGKbL8Y.css`（源 `packages/agent-ui/src/components/file-version-management/`）；宿主 DetailPanel `src-CA4DIhYw.js`；DiffViewer `src-CMgU1OQk.js`（源 `.../tool-renderer/common/diff-viewer.tsx`）；RPC 契约 `preload/index.js`（源 `workbuddy-server/src/sandbox/contract.ts`）。

## 1. 触发/开启条件（务必先抄）
面板只在 `fileVersionEnabled = isWorkbuddyDesktop && versionControlEnabled` 时出现：
- `isWorkbuddyDesktop = adapter?.isWorkbuddyDesktop === true`（只桌面端）。
- `versionControlEnabled` 来自 `useVersionControlEnabled()`：发 `get-experimental-features-config`，监听 `experimental-features-config-result` 读 `config.versionControl`。**是"实验特性"开关**，每次侧边栏打开重拉。
- **我们可简化：不搞实验开关就直接常开，或挂设置里一个普通开关。**
对宿主 DetailPanel 三处影响：①tab 标签 `changesLabel = fileVersionPanel ? "文件版本管理" : "变更"`（图标仍 ChangesIcon）②左栏 `sidebarView==="changes"` 渲染 `<div class="sidebar-category-file-version">{commit列表}</div>` ③右主区渲染 `fileVersionDetailPanel`（文件明细/diff）④进入该视图把 sidebar 宽度钳到 `FILE_VERSION_SIDEBAR_WIDTH=200`px（只收窄不放宽）。

## 2. 组件树 & 共享状态
```
FileVersionManagementProvider  (Context + reset 确认弹窗)
├─ FileVersionListPanel   → 左栏 sidebar
│   └─ CommitRow × N
└─ FileVersionDetailView  → 右主区
    └─ DetailFileRow × N (可折叠)
        └─ DiffSlotView → DiffViewer
```
Provider state：`commits[]/loading/selectedCommitId/opInflight/resetTarget/resetConfirmLoading` + `versionCacheRef`（Map key=`${path}|${version}`，避免重复 RPC）。左右栏靠同一 FileVersionContext 共享 commits+选中项。

## 3. 左栏：commit 时间线（FileVersionListPanel）
`.file-version-management-panel`（flex 纵向满高）：
- **Header**：标题"文件版本管理"(13/600 省略号) + 刷新按钮(24×24 RefreshIcon 14px 双箭头，title"刷新"，loading disabled)。
- **Body**（纵滚 pad4 0）三态：`loading && commits.length===0`→"加载中..."；`commits.length===0`→"暂无版本记录"；否则 `<ul>` 每项 CommitRow。挂载即 refresh()。
- **CommitRow**（`.file-version-commit-row` 纵向 flex）：
  - `__head`：`__id`(短 commitId `id.slice(0,8)` 等宽，title 全 id) + `__time`(名叫 relative 但实为**绝对 `YYYY-MM-DD HH:MM`**) + `__op`(`operationType` 原样，CSS uppercase 灰底小 tag)
  - `__message`(有才渲染，单行省略 + Tooltip 显全)
  - `__summary`=`fileVersion.filesChanged`="{n} 个文件变更"
  - **动作区**：`isHead`(idx===0)→胶囊徽章"当前版本"(蓝 pill 无按钮)；非 head→两按钮"回滚到此版本"(普通描边，Tooltip revertTip) + "重置到此版本"(`__btn--danger` 红字红边，Tooltip resetTip)，`disabled={opInflight}`，onClick `stopPropagation`。
  - 整行 `role=button tabIndex=0` 点击/Enter/Space 选中；`--selected`(浅蓝底 + 左 2px 蓝 border)。

## 4. 右栏：commit 文件明细（FileVersionDetailView）
- 未选中→"选择左侧任一版本以查看文件明细"。
- 选中后：Header(短 id + 绝对时间 + `__op` 大写 tag + 可选 message + summary)；`<ul.__files>` 每个 DetailFileRow。切换 commit 时 expandedKey 重置（每次进新版本所有文件收起）。
- **DetailFileRow**（`.file-version-detail-file--{kind}`）：
  - 头 `__head`（role=button，Enter/Space 切换）：**变更类型徽章** `__badge--{kind}`（18×18 圆角小方块，白字等宽）：added→"A"绿 #52c41a / modified→"M"琥珀 #faad14 / deleted→"D"红 #ff4d4f / renamed→"R"蓝 #1890ff / unknown→"?"灰 #888（wire 上 `changeType` 数字 0=modified 1=deleted 2=added 3=renamed）。**路径** `__path`（等宽 break-all；renamed 有 oldPath 时"旧路径(删除线灰) → 新路径"）。**chevron** ▾/▸。
  - 展开区 `__diff`（懒加载）：`diffLoading`→"加载 diff..."；`diffError`→"操作失败：{message}"；`diff`→`<DiffSlotView>`（max-height480 可滚 1px 边 radius4）。

## 5. Diff 兜底逻辑（DiffSlotView）— 重点
`loadFileVersionDiff(file)` 拿 before/after 两侧 slot（kind：text 有 content / binary / oversize 带 fileSize / missing 被回收 / absent 该侧无版本号）。DiffSlotView 按优先级出兜底：
1. 任一 binary → "此文件为二进制，不支持 diff 查看"
2. 任一 missing → "原始版本已被回收，无法查看 diff"
3. 任一 oversize → "文件过大（{size}），不展示 diff"（size 走 formatFileSize：<1KB→B，<1MB→KB，否则 MB）
4. 都正常 → `<DiffViewer oldCode newCode fileName>`（absent 侧 content 当空串："" → 新建全绿/删除全红）
**版本物化缓存**：先查 `versionCacheRef`，缺的批量 `queryFileVersionCache({sessionId, relativePath, versions})` 返回 `entries[{version,isBinary,oversize,fileSize,content}]`；没有的 version 标 undefined(=missing)。

## 6. DiffViewer 实现（注意：不是 Monaco！）
注释写"决定渲染 Monaco diff"，**但真实现是自研轻量行 diff**。用 `diff` 库 `diffLines(old,new)` 逐行比 + `highlight.js` 语法高亮（按 `getLanguageByFilename`），渲染成 `<pre>`：
- **裁掉首尾未变化上下文**（只渲染变化区间，中间未变行保留）。
- 每行 `.diff-viewer__item > .diff-viewer__{inserted|removed|unchanged}` = `__gutter`(16px 左侧色条) + `__line-content`(高亮 HTML)。
- 颜色（dark）：新增绿 `rgba(16,185,129,0.2)` 底 + `rgba(16,185,129,0.5)` 左条；删除红 `rgba(239,68,68,0.2)` 底 + `rgba(239,68,68,0.5)` 左条。light 走 `--cb-vscode-diffEditor-*`。12px/18px，滚动条 8px。**没有行号、没有并排——单栏 inline diff。**
- **务实简化：这个自研 DiffViewer 完全可照抄（依赖只 `diff`+`highlight.js`），比接 Monaco 轻得多，建议直接抄它。**

## 7. 回滚 vs 重置（状态流转 + 弹窗）
- **回滚到此版本（revert，保留后续）**：`revertCommit(commit)`→置 opInflight→`adapter.revertFileCommit({sessionId,commitId})`→返回 `{files:[{success,error?}]}`：有失败→toast.error"操作失败：{message}"+refresh；全成功→toast.success**"回滚成功"**+refresh。**不弹确认框，直接执行**（保留其后所有提交，可再回滚）。
- **重置到此版本（reset，丢弃后续 + 确认）**：`requestReset(commit)` 设 resetTarget→触发 ConfirmDialog：title"重置到此版本？"、content"将丢弃该 commit 之后的全部变更，且不可恢复。"、confirmText"确认重置"、cancelText"取消"、`confirmVariant="primary"`（**注意：不是 danger 变体**，尽管危险确认按钮用主色）、confirmLoading。确认→`adapter.resetFileCommit`→成功 toast**"已重置到所选版本"**+清 resetTarget+refresh。
- ConfirmDialog（shell 通用件，createPortal）：遮罩点外/Esc 关闭、confirmLoading 转圈。属 WorkBuddy app-shell 弹层。

## 8. 后端 RPC 契约（sandbox，git 支撑）
preload 4 个通道（源 `workbuddy-server/src/sandbox/contract.ts`）：
- `sandbox:listFileCommits` ← `listFileCommits({sessionId,limit})` → `{commits}`（**新→旧排序**，limit 默认 `DEFAULT_LIMIT=50`）
- `sandbox:revertFileCommit` ← `revertFileCommit({sessionId,commitId})` → `{files:[{success,error?}]}`
- `sandbox:resetFileCommit` ← 同结构
- `sandbox:queryFileVersionCache` ← `queryFileVersionCache({sessionId,relativePath,versions:number[]})` → `{entries:[{version,isBinary,oversize,fileSize,content}]}`
数据结构：`Commit = {commitId, createTimeMs, operationType(大写tag), message?, files:ChangedFile[]}`；`ChangedFile = {relativePath, oldPath?, changeType:0|1|2|3, versionBefore?, versionAfter?}`。
后端实现：CLI 里有 `mapNameStatusCodeToChangeType/parseNameStatus/parseUnifiedDiff/loadCommitMeta`——**底层是真 git**（`git --name-status` 的 A/M/D/R 码）。**我们可选真 git 仓库跟踪工作目录，或自建版本快照表；面板契约照这 4 个方法接即可。**

## 9. 完整文案表（键 `fileVersion.*`）
title 文件版本管理 / empty 暂无版本记录 / detailEmpty 选择左侧任一版本以查看文件明细 / loading 加载中... / refresh 刷新 / headBadge 当前版本 / revert 回滚到此版本 / reset 重置到此版本 / revertTip 把当前文件状态恢复到这个版本，保留此版本之后的所有提交记录（可再次回滚）。 / resetTip 把当前文件状态恢复到这个版本，并丢弃此版本之后的全部提交，不可恢复。 / filesChanged {count} 个文件变更 / resetConfirmTitle 重置到此版本？ / resetConfirmBody 将丢弃该 commit 之后的全部变更，且不可恢复。 / confirmReset 确认重置 / cancel 取消 / revertSuccess 回滚成功 / resetSuccess 已重置到所选版本 / opFailed 操作失败：{message} / unknownError 未知错误 / changeType.modified 修改 / deleted 删除 / created 新建 / renamed 重命名 / binaryNotSupported 此文件为二进制，不支持 diff 查看 / oversize 文件过大（{size}），不展示 diff / versionMissing 原始版本已被回收，无法查看 diff / diffLoading 加载 diff...。（Tab 标题 `detailPanel.fileVersionManagement`=文件版本管理。文案品牌无关，可原样中文。）

## 11. 务实取舍标注（必做 / 可简化 / 暂不做）

**必做（价值高）**：
- 复用右侧详情面板"变更"tab 改名"文件版本管理"（左 commit 时间线 + 右文件明细+diff）。
- **回滚/重置双语义**（回滚=保留后续、重置=丢弃后续+确认弹窗）——这个面板最有价值的交互。确认弹窗用 shell 现成 ConfirmDialog。
- **DiffViewer 直接抄**（自研 diffLines+highlight.js 单栏 inline diff，别上 Monaco）。
- 兜底三态（二进制/超大/已回收）成本低体验好，保留。

**可务实简化**：
- 去掉"实验特性"事件握手，直接常开或设置里一个普通开关。
- `operationType` tag 语义没读到词表，可自己定义（编辑/写入/命令/多文件）或不显示。
- 后端最省事：把工作目录做成真 git 仓库，每次工具改文件后 `git add -A && git commit`；listFileCommits=git log、revert=checkout 到该 commit 生成新提交、reset=`git reset --hard`、diff=读两版本内容。四方法契约照 §8 对齐。

**暂不做**：无（这块整体值得做，是"改文件可回溯/可撤销"的护栏）。
