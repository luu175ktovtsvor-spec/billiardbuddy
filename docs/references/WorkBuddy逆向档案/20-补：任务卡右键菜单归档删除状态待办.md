## 一、任务状态机（7 态，源码 8 字符串归 6 类）
```
WORKING_STATUSES  = {working, planning, running}   // 转圈
COMPLETED_STATUSES= {completed}
PENDING_STATUSES  = {pending}
FAILED_STATUSES   = {failed, error, terminated}
ARCHIVED_STATUSES = {archived}
STATUS_CLASS_MAP = { planning/working/running:"status-success", pending:"status-warning",
  completed:"status-completed", failed/error/terminated/killed:"status-error", archived:"status-secondary" }
```
| status | label | description | 备注 |
|---|---|---|---|
| planning | **规划中** | Agent 正在分析任务并制定执行计划 | 转圈 |
| working | **执行中** | Agent 正在执行计划中的步骤 | 转圈 |
| pending | **等待输入** | 需要你提供更多信息后才能继续 | tag=**待确认** |
| completed | **已完成** | 任务已结束（成功或被终止） | |
| terminated | **异常中断** | 任务异常退出 | error 色 |
| failed/error | **执行失败** | 执行过程中发生错误 | |
| archived | **已归档** | 任务已被归档 | |
派生逻辑：`statusText = lowerCaseStatus==="idle" ? "" : t(taskStatus.{s}.label)`；`getStatusTag` **仅 pending** 返回"待确认"；`canArchive = ["completed","failed","terminated"].includes(status)`；`isArchived` → 不可重命名。team-runtime 兜底（completed 有活跃成员则强显 working）——**我们没协作，可砍**。

## 二、状态徽章图标（lucide 风 24×24 stroke1，currentColor）
working/planning/running→LoaderIcon（转圈 `spin 2s`）/completed→CheckIcon/pending→PendingIcon（问号气泡）/failed/error/terminated→FailedIcon（三角警告）/archived→ArchivedIcon（归档箱）。
**两处样式源不同**：①侧边栏卡片内（属性选择器覆盖）：status-success 图标色 `--wb-accent-unread` 转圈；status-completed svg 隐藏改画 6px 圆点；status-warning **图标 display:none**（只靠"待确认"tag）；status-error svg 隐藏贴 16px 错误 svg 背景。②紧凑列表/task-list-popover 直接显图标。**我们不必搞两套覆盖，一套「图标+颜色+文字」即可。**

## 三、任务卡片本体 AgentCard + hover 交互
卡是通用组件，主壳包 `ConversationCardWithTeamMembers` 传 cardProps（title/time/statusText/statusIcon/tag/titleTag/selected/editable/onTitleChange/onArchiveClick/archiveDisabled/archiveDisabledReason/onDeleteClick(实为置顶pin)/contextMenuItems/section）。
**hover**：动作按钮平时 `display:none`，卡片 hover 变 flex；同时隐藏时间戳。右侧动作区依次：重命名（仅 workspaces 段且 editable 且无右键项，铅笔）/**"更多"⋯ 按钮**（`contextMenuItems.length>=2` 时，点开 ContextMenu）/若 length===1 直接渲染成 icon 按钮/归档按钮（onArchiveClick 存在，disabled 置灰 opacity.35 tooltip 换 disabledReason）/置顶按钮（onDeleteClick，WorkBuddy 绑置顶 pin 不是删除）。

## 四、任务卡右键/"更多"菜单项（按 section 三套）
菜单不是原生右键，是点 ⋯ 弹的 ContextMenu（>=2 项才弹，=1 项直接成 icon 按钮）。
**A. 普通任务（section=tasks）**顺序：
1. `打开文件夹`（`contextMenu.openFolder`，FolderOpenIcon）— cwd 绝对路径且 adapter.openFolder 存在；点前校验目录（不在弹 `conversation.cwdNotExist`）。
2. `重命名`（`contextMenu.rename`，`triggerEdit:true`）— !archived。
3. `保存到工作空间`（`workspace.keep.button`，SaveIcon）— 仅 isPlayground。
4. `分享任务`（`contextMenu.shareTask`）— 分享开关开且非项目子。
5. `删除任务`（`contextMenu.deleteTask`，DeleteIcon）— 非云且 adapter.deleteSession 存在。
**B. 工作空间任务**：重命名/分享任务/删除任务。**C. 云助手子任务**：重命名/删除任务（走 `deleteCloudAgentConversationSession`）。**我们没云助手/项目/协作，B/C 大部分可砍。**
每项带埋点 dtEid（`agent_task_rename/share/delete/archive`）——白标去掉。
**归档不是菜单项**，是卡片右侧独立归档 icon 按钮，tooltip `action.archive.tooltip`="归档"，禁用文案"任务进行中，无法归档"。置顶也是独立按钮（"置顶"/"取消置顶"）。

## 六、归档全流程
1. 触发：归档按钮 → `handleArchiveClick` → `archiveDialogVisible`。
2. **确认弹窗**（ConfirmDialog）：title `archive.dialog.title`="归档任务"，content"确认将该任务归档吗？归档后可在「系统设置-数据管理」中查看已归档任务。"，confirmText"确认归档"，cancelText"取消"，`confirmButtonColor:"#4ecba0"`（青绿非危险），confirmLoading。
3. 确认后：`removeConversation(id)` 乐观移除 → `dispatchEvent("archived-task-changed")` → 成功 toast。
4. **成功 toast**（success，duration4000，Win 加 offset56）：`archive.toast.success`="任务已归档，可前往「系统设置-数据管理」中查看" + 可点链接"已归档任务"（点了 `dispatchEvent("open-settings-archived-tasks")` 跳设置已归档页）；失败"归档失败，请重试"。

## 八、删除全流程（三入口，三实现）
1. **列表删普通任务**：`handleDeleteTaskClick` 用**命令式 Modal.confirm**：title`delete.dialog.title`="删除任务" content"确认后将从列表中删除任务，请确认是否删除？" okText"确认删除" cancelText"取消" `okType:"danger"`。确认→`adapter.deleteSession` 乐观移除→成功"删除成功"/失败"删除失败，请重试"（return false 保留弹窗）。删的是当前任务→`handleNewConversation()`。
2. **删整个工作空间组**（组头 ⋯ "从列表中移除"）：声明式 ConfirmDialog title"移除工作空间" content"确认后将从列表中移除工作空间，请确认是否移除？" confirmText"确认移除" `confirmVariant:"danger"`。确认→该 cwd 下所有会话逐个 deleteSession（全成功才算），toast"移除成功"/"移除失败，请重试"。
3. **已归档页删**：archived-tasks 自带声明式 ConfirmDialog（`delete.dialog.*`，danger，confirmLoading）。

## 十一、待办面板（TodoListViewer）— 出货版是**只读**
- i18n `todoList.*` 完整（taskTitle/taskDescription/newTask/addTask/edit/delete/save/cancel/noTasks/taskCount/status.waiting=等待/inProgress=进行中/completed=已完成/error=错误）。
- **但整个前端 bundle 没有任何 JS 渲染这些"增删改"控件**（只 CSS+i18n）。出货版是详情面板里的**只读** TodoListViewer，展示 agent 计划(TodoWrite) todo，与 `todoStatusStore` 同源。增删改 i18n 键像保留/未启用。
- 只读样式（深色）：`.todo-item`（flex pad12 radius6 bg #1e1e1e border #3e3e42 hover #2d2d30）；20×20 状态图标 16px 色 completed#10b981/in-progress#3b82f6/waiting#858585/error#ef4444；`.todo-index`(序号12灰)+`.todo-text`(14 #cccccc，completed 灰+删除线)+可选 `.todo-description`(12 灰 缩进28)；头 `.todo-count` 13 灰；空 `.todo-empty` 居中。
- 数据模型 `STATUS_WEIGHT = {pending:1, in_progress:10, completed:20, cancelled:21}`（排序用）。
- **归属提醒**：这个 todo 是 agent 生成的计划、渲染在**消息内容区/详情面板**（PlanCreate/PlanTask/PlanUpdate 订阅 `todoStatusStore`），按 owner 边界更偏 cc-haha 侧；WorkBuddy 侧只是给了个只读镜像。

## 十三、务实取舍标注（必做 / 可简化 / 暂不做）

**必做**：普通任务那套菜单（打开文件夹/重命名/分享?/删除任务 + 独立归档按钮）；状态徽章一套「图标+文字+颜色」7 态文字照抄（进行中蓝/转圈、等待输入黄+"待确认"、已完成绿、失败/异常红、已归档灰）；归档完整链路（卡片归档按钮 + 确认弹窗 + 成功 toast 带跳转链接 + 设置里已归档任务整页，`archived-tasks` 组件几乎原样抄）；统一用一个 ConfirmDialog（danger 变体）。

**可务实简化**：状态徽章不必抄"侧边栏属性选择器覆盖成小圆点、pending 隐藏图标"这套复杂覆盖，直接一套图标+文字+颜色；待办面板只做**只读** TodoListViewer（镜像 agent 计划），别投入做用户手动增删改 todo（WorkBuddy 出货版也没启用）。

**暂不做/砍**：云助手/项目子任务/协作 team-runtime 兜底；分享任务/分享文件/转交/云助手删除（无对应后端）；埋点属性（dtEid/dtParams/data-track-*）白标全去掉。
