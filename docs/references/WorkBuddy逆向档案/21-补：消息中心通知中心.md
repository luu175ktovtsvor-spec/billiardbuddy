# 21-补：消息中心/通知中心（msgCenter）

> **第二轮穷尽补齐**（2026-07-10）。归属：**App 外壳 = WorkBuddy** 侧（顶栏铃铛 + 通知面板 + 推送分发器）。
> **可信度**：源码级可读（组件名/JSX/className/i18n key 全明文，用 grep 交叉验证过引用情况）。
> **一句话结论**：实际形态不是档案 02 想象的"带 全部/待处理 两 tab + 全部已读按钮"的独立页，而是**顶栏一颗铃铛 → 点开 320px 宽 Popover 通知面板**（时间分组 + 可展开卡片列表，**无 tab、无"全部已读"按钮**，打开面板即自动全部标已读）。另有一套独立推送分发器（新消息端内 toast，后台改系统通知）。
> **务实取舍**：见第 13 节。

组件文件（`renderer/assets/connector-CvFT3fv6.js`，源码路径见注释）：`MsgCenterBell`（铃铛+面板）、`MessageCard`、`MsgCenterPopupHost`（端内 toast）、`use-msg-center-popup-dispatcher`、`msg-center-popup-utils.ts`、`credits-insufficient-events.ts`、`use-msg-center-facade.ts`。CSS 前缀 `.msg-center-*`/`.notification-*`，token `--nc-*`。

## 1. 挂载点
`MsgCenterBell` 渲染一次，位置**顶栏用户菜单区**（紧挨头像），props `className="user-menu-trigger-msg-center"`。属 WorkBuddy 外壳。我们要照 cc-haha 展示的是点开后的面板内容（消息呈现），铃铛落点归 WorkBuddy 壳。

## 2. 触发器：铃铛 + 未读角标
`<button class="msg-center-bell-btn">`（32×32 radius6 透明，hover bg）内 BellIcon(16×16)。角标三态：`unreadCount>0`→`.msg-center-badge`（数字，>99 显"99+"）；`hasRedDot`→`.msg-center-dot`（纯红点）；否则无。
CSS：badge `top2 right2 min-width14 h14 pad0 3 radius7 bg #f56c6c 白字 font9 transform translate(40%,-30%)`；dot `top4 right4 6×6 bg #f56c6c`。

## 3. 面板容器（Popover）
foundation Popover：`placement="top-end" triggerMode="click"`。DOM：
```
.notification-panel
 ├─ .notification-header → h2.notification-title (只有标题,右侧无按钮)
 └─ .notification-list (onScroll=无限滚动)
      ├─ .notification-empty (loading="加载中..." / 空="暂无消息")
      ├─ .notification-time-group > .notification-time-label
      ├─ <MessageCard> × N
      └─ .notification-empty (加载更多时又显"加载中...")
```
CSS：panel `pad8 12 width320 bg #FFF border0.5px radius16 shadow`；list `max-height70vh overflow-y auto pad0 4 flex column gap8`；滚动条宽3px。

## 4. 列表：时间分组 + 无限滚动
**时间分组**（按天，`getDateKey=YYYY-MM-DD`）：今天→"今天 HH:MM"、昨天→"昨天"、更早→硬编码 `YYYY-MM-DD`（不走 i18n）。
**无限滚动**（`handleScroll`）：距底 <40px 且 hasMore 且不加载中→`loadList(nextCursor)`。**cursor 分页非页码**，`LIST_LIMIT=20`。**没有"加载更多"按钮**。
**过滤**：`isSupportedMessage` = `!DEPRECATED_BIZ_TYPES.includes(biz_type)`，`DEPRECATED_BIZ_TYPES=["teams.invite"]`。

## 5. 消息卡片 MessageCard（核心呈现）
DOM（左中右）：
```
article.notification-card {typeClass}[ is-expanded]  (onClick=展开/收起, onContextMenu=右键)
 ├─ .notification-card-left → 头像
 ├─ .notification-card-center
 │    ├─ p.notification-line (标题, dangerouslySetInnerHTML=msg.title 富文本! 2行截断)
 │    ├─ [收起] .notification-desc-row → p.notification-desc(单行省略) + 展开箭头
 │    └─ [展开] .notification-expanded-content → p(msg.content||summary, pre-wrap) + .notification-expanded-actions
 └─ [仅teams卡] .notification-card-right → 插件 renderActions
```
**头像**：teams 卡→彩色圆 `stableAvatarColor(msg_id)`（从 `["#5AC57A","#607D8B","#3498DB","#8B5CF6","#F59E0B"]` hash 取）+ 首字符；非 teams→当前用户头像 img。24×24 圆。
**卡片类型色**（`--nc-tone` RGB）：teams.project_invite/member→request 橙(234,138,26)；agentmail.→mail 灰；system.→system 绿(22,163,74)；teams.task→task 蓝(37,99,235)；*.mention→mention 紫(124,92,255)；deadline→红；其他→default 灰。
**展开按钮** `.notification-expand-btn`（h32 pad8 12 radius8，第一个 `.is-primary` 黑底白字，其余白底黑字+边框）。文案来自服务端 `action.text`。
**右键删除菜单** `.notification-ctx-menu`（Portal fixed 跟随鼠标）：一项"删除"（`msgCenter.delete`）。点空白/Esc 关。z10000。

## 6. 交互状态流转（照抄重点）
1. **打开面板=自动全部已读**：`useEffect([panelOpen]) → markAllRead().finally(loadList())`。`markAllRead` 调 `facade.markRead({all:true})`，成功后本地 unreadCount=0、messages 全置 is_read。**所以没有"全部已读"按钮**——开面板即读。
2. **单条标已读** `handleMarkRead(msgId)`：`facade.markRead({msg_ids:[msgId]})` 成功→本地置 + `fetchSummary()` 刷角标。
3. **卡片点击**：有插件 actions 只 markRead 不展开；不可展开只 markRead；可展开→切换展开/收起 + 未读则 markRead。`expandedId` 全局单开。
4. **动作按钮** `handleAction`：未读先 markRead；`action.url` http 开头→`window.open`。`visibleActions=msg.actions.filter(a=>!(msg.is_read && a.key==="ack"))`（已读后隐藏 ack）。
5. **删除** `handleDelete`：**乐观删除**——先本地移除，`facade.deleteMessage`；失败塞回 + `message.error(msgCenter.deleteFailed="删除失败，请稍后重试")`。

## 7. 数据模型 + facade API（后端契约）
facade = `createDaemonServiceProxy("msgCenter", daemonClient)`。
**Message 字段**：`msg_id, biz_type, title(可含HTML), summary, content, is_read, created_at(epoch毫秒), actions[{key,text,url?,type?}], notify_displays["in_app"|"system"], ext`。
**方法**：`getSummary()→{total, poll_interval秒, pending_popup}`；`getList(cursor?,limit=20)→{messages[],next_cursor,has_more}`；`markRead({msg_ids}|{all})`；`deleteMessage(msgId)`；`getPendingDisplays({display:["in_app","system"],limit:5})→{items}`；`notifyShown({items:[{msg_id,display}]})`；`executeCallbackAction(url)`。

## 8. 轮询机制
挂载即 `fetchSummary().finally(schedulePoll())`：`DEFAULT_POLL_INTERVAL_MS=30000`（getSummary 的 poll_interval 覆盖）。**前台/后台降频**：`visibilityState!=="visible"` 时间隔 `min(base*4,120000)`（后台×4 封顶 2min，关到托盘仍轮询否则收不到系统通知）。visibilitychange 变可见立刻 fetchSummary。summary 喂给推送分发器。

## 9. 推送分发器：端内 toast + 系统通知（"通知中心"另一半）
`useMsgCenterPopupDispatcher` 返回 `{handleSummary, popupHost}`。与面板**并行**的主动推送：
- `scanPendingDisplays` 拉 `getPendingDisplays(limit:5)` 逐条分流：`ext.position==="chat_input_top"`（积分不足）→走独立事件（输入框上方提示条）；`in_app`+客户端通知开+**前台**→端内 toast 队列；`in_app`+**后台**→系统通知；`system`→系统通知；否则 `notifyShown` 静默 ack。
- **端内 toast 宿主** `MsgCenterPopupHost`（Portal fixed `top:40px right:0 z10000` 竖排）：`MAX_VISIBLE_POPUPS=3` 同时可见，`POPUP_LIMIT=5` 总队列。每条 foundation `Notification`，actions=原 actions 去 ack + 追加 `{key:"ack",text:msgCenter.acknowledge="我知道啦"}`，expandText="查看详情" collapseText="收起"。展开→自动 markRead。
- **系统通知** `sendMsgCenterSystemNotification`：title 去 HTML 兜底"WorkBuddy"；body 去 Markdown >120 截 117+"..."。发送优先级 `window.workbuddyDesktop.notification.sendNotification` → `desktopBridge.invoke("workbuddy:notification:send")` → 浏览器 `Notification`。失败冷却 `SYSTEM_FAILURE_COOLDOWN_MS=300s`。

## 10. 设计 token（`--nc-*`，浅/深）
浅：bg-elevated #fff / surface #f5f5f7 / text-primary rgba(0,0,0,.88) / secondary .62 / tertiary .42 / radius-sm6 md10 full9999。深（`[data-theme=dark]` 等）：bg-elevated rgba(255,255,255,.08) / surface .06 / text 反白；panel bg `--cb-vscode-sideBar-background,#1e1e20`。红点 #1677ff（`.notification-unread-dot` 也未渲染）。

## 13. 务实取舍标注（必做 / 可简化 / 暂不做）

**必做**：铃铛角标 + 320px `top-end` Popover 面板 + 时间分组 + 可展开卡片 + 右键删除 + 乐观删除回滚 + "开面板即全部已读"。这套交互干净可 1:1 抄。数据契约 `getSummary/getList(cursor,limit)/markRead({msg_ids}|{all})/deleteMessage` 直接照搬。轮询 30s + 后台×4 封顶 2min。

**可务实简化**：
- 卡片类型只保留 system(绿)/default(灰) 两三种；头像统一用应用图标/门店 logo，不必彩色首字母 hash。
- 若做桌面通知，推送分发器"前台冒 toast / 后台转系统通知 + 5min 失败冷却 + notifyShown 去重"值得抄（系统通知走 Electron 主进程 IPC）。**若一期不做主动推送，可只留面板。**
- 想补"全部/待处理"tab：WorkBuddy 有 CSS 无实现，自己按 `is_read`/`actions.length>0` 过滤实现（CSS 规格 `.notification-tab` 28px 高、`.is-active` 加边框+浅底可参考）。

**暂不做/砍**：智能体邮箱富卡片、积分不足输入框提示条、teams 加入申请插槽——与球房无关。
