## 4. "记忆更新中"态 —— 统一状态机（两 modal 共用）
- 打开 modal 先 `adapter.checkMemoryUpdating()` 探锁（返回 `{isUpdating,error}`）。
- 进入更新中后 `setInterval` **每 2500ms 轮询** `checkMemoryUpdating`；检测到 true→false → 收尾 + 回调 `onUpdateCompleted("submit"|"import")`。
- 关闭/卸载 → 清 interval、reset state。
- 面板层监听 `adapter.on("memory-update-toast")` → toast，按 source：submit"提交建议更新成功"/import"导入记忆更新成功"/默认"记忆更新成功"。3 秒去重。
- 错误映射 `getLocalizedErrorMessage`：含 "another update in progress"→"已有记忆更新任务在处理中，请稍后再试"；"user not logged in"→"当前未登录，请先登录后重试"；"check memory updating failed"→"检查记忆更新状态失败，请稍后重试"。

## 5. 后端 adapter 接口契约（前端要连的方法）
- `getMemoryProfile()` → `{generateMemoryEnabled, localMemoryEnabled, memoryBlock, updatedAt}`
- `saveMemorySettings({generateMemoryEnabled, localMemoryEnabled})`
- `checkMemoryUpdating()` → `{isUpdating, error?}`
- `submitMemorySuggestion({suggestion, currentMemory})` → `{success, accepted, error?}`
- `importMemoryContent({content})` → `{success, imported, error?}`（`content:""` 复用为清空/重置降级）
- `clearMemory()` → `{success, error?}`（优先用于重置）
- 事件 `adapter.on("memory-update-toast", {source})`
- 这是 cc 记忆机制的产品化包装：面板管开关+预览，后端负责"每晚重生成摘要"+锁+提交建议合并。
