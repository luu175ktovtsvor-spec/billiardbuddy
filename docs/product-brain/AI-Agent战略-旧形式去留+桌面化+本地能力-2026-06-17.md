# AI Agent 战略分析：旧形式去留 + 桌面化 + 本地能力（2026-06-17）

> 基于 6 路调研综合（项目全景①、去留对比②、垂直行业Agent③、桌面GUI④、本地能力⑤ + CC Switch）。回答：转型 AI Agent 后，以前那套（96卡工作台等）留不留、怎么留；怎么让用户在电脑上用 GUI；要不要"长在电脑上"碰文件跑命令。带产品判断力，不照搬 Claude Code。

## 一、旧形式（96 卡工作台）去留 —— 结论：全留，定位重排，不是二选一

**核心事实（①②）**：卡片和 Agent **不是替代关系，是入口层两种范式**，service 层共享同一批业务逻辑（同一批 ~40 个 prompt 模板、同一套 run_generation 管道）。
- 卡片（旧）= "我知道要做啥，给我选模板"——固定意图、可预期、零学习成本
- Agent（新）= "我说一句话，AI 帮我决定调哪个工具"——开放意图、灵活、但依赖模型理解
- Agent 目前只覆盖 ~30%（9 工具 vs 96 卡）；PK方案/SOP清单/绩效/赛制/周赛全流程等**只在卡片有**。

**垂直行业 Agent 调研（③）的铁证**：2025-26 头部垂直 Agent（Fin/Sierra/Harvey/SymphonyAI）**一致的产品逻辑 = "结构化流程为骨架 + 对话为界面，分层叠加，不是非此即彼"**。给非技术用户（小店主/一线员工）的运营 Agent 主流形态是 **"向导 + 审批 + 主动推送"三件套**，不是纯聊天。

**所以去留方案（多维度论证）**：

| 维度 | 卡片工作台 | AI Agent 对话 | 结论 |
|------|------|------|------|
| 用户价值 | 新手发现能力、可预期 | 老手一句话搞定 | 互补，都留 |
| 上手成本 | 零学习（点就行）| 要会描述需求 | 卡片是新手入口 |
| 覆盖度 | 全（96卡/10类输出）| 30%（9工具）| 卡片暂不可替代 |
| 维护成本 | 96卡共用~40模板，可控 | 工具少、好维护 | 砍卡片≠砍模板 |
| 可融合 | promptKey→可包成Agent工具 | 可调同一批prompt | 底层已共享 |

- **不砍卡片**：它是"新手货架"（不知道能干啥→浏览发现）+ "确定性入口"（知道要啥模板→直接点）。覆盖 Agent 没做的 70%。
- **卡片转定位为"快捷入口/技能货架"**，Agent 是"老手通道"，**今日推荐是主动层**。三者并存、互补。
- **怎么"合并"（② 给了零成本的具体做法）**：
  - **94 卡 → 63 个精修 prompt 模板**（PK/SOP/绩效/赛制/投资表/排班/采购等结构化产出，逐场景校准）——这是产品**真护城河资产，100% 保留**。
  - **Agent 30% 覆盖 + 文案质量打折的根因**：`write_operation_content` 调 `generate_workbench` 时**没传 prompt_key**（`tools.py:75-83`），走 free_intent 通用模板，拿不到那 63 个精修模板。
  - **🎯 最高性价比融合动作**：给 `write_operation_content` 加一个**可选 `prompt_key` 入参**，透传到 `generate_workbench` 的 `if prompt_key` 分支（`content_service.py:649`）→ **Agent 一次性复用全部 63 个调好的模板，覆盖度 30%→接近卡片，几乎零迁移**。再喂 Agent 一份"场景名→prompt_key"清单（可从 role-workbench-config.ts 自动生成）让模型按意图选 key。
  - **卡片点击 = 向 Agent 发一条带 prompt_key 的预设消息**（卡片的 userIntentTemplate + promptKey + inputHints 本就是结构化 Agent 指令）→ 前端只维护一份"场景预设表"，不再两套生成入口，消除"砍卡片怕丢功能"顾虑（prompt 还在、入口变预设）。
  - **保留各自形态**：① Agent 独有的 make_platform_content/make_groupbuy（内联校准 prompt 的对外成品）留作工具、不必塞回 YAML；② 卡片的 inputHints 输入引导（手把手提示小白填什么）是 Agent 无等价物的隐藏价值，迁移时变成 Agent 的结构化追问。
  - 合并**不碰合规/配额底线**——两套已共用 run_generation 收口（注入检查/配额/店脑/泄露过滤/计费），且 Agent 多了审批闸（卡片没有）；合并方向是"卡片借用 Agent 的规划+审批"，不反向削弱。
- **进化方向（③借鉴）**：让店主把常用复合操作（如"每周一：拉新裂变+活动预告+日报"）存成**自定义工作流**——这是卡片的进化，沉淀私有经验。

## 二、垂直行业 Agent 能搬进来的（③，按价值排序）

1. **主动推送**（最该补）：当前是"用户来问 AI"。应在今日推荐之上加**主动出现**——淡季信号/节日临近/日报未写/本周流量低 → 主动弹具体行动建议。这就是转型计划的 P4 主动出击。
2. **向导式输入**：把"说一句话填日报"推广到更多场景（活动/周报/促销）——几个选项 + 1 个自由框，AI 扩写，降冷启动焦虑。
3. **know-how 升级为决策护栏**：从"知识库内容"到"什么情况推什么/警告什么"的决策逻辑（如"周末上钟<60%+无活动→推裂变"）。**我们的北极星谓词集 + 诊断决策树已是雏形**，继续强化。
4. **模板库 + 自建工作流双轨**（同①的演进方向）。
5. **结果审批分级**：高风险/高成本（涉价格/全员/大活动）必须确认，低风险（草稿）自动完成，减审批疲劳。
6. **"越用越懂"显性化**：店脑页显示"AI 已学 N 条你的经营习惯、识别到高峰时段/主力客群"，增强留存。

## 三、桌面 GUI —— 两步走，先 PWA 后 Electron 套壳（④）

让台球老板"在电脑上像软件一样用、不碰 CLI"：
- **第一步：PWA**（1-2 天，成本≈0）——现有 Next.js 加 `manifest` + Service Worker，Chrome/Edge 一键"安装到桌面"，自动随网站更新、无签名问题。先验证老板愿不愿装桌面版。**附带最大价值：Web Push 推送通知**（见第四节）。
- **第二步：Electron remote URL 套壳**（3-5 天）——`win.loadURL('https://zzyppz.cn')`，**前端代码零改、仍连云后端**，electron-builder 打 .exe/.dmg。给"买来的软件"信任感（托盘常驻/系统通知/桌面图标）。
- ⚠️ **成本提醒**：Electron 要代码签名（Mac $99/年+公证、Windows OV 证书 ~$200-400/年），不签名会被 SmartScreen/Gatekeeper 拦，老板放弃安装。
- ❌ **不选 Tauri 套壳**：Tauri 加载远程 URL 后 native bridge 失效，白装 Rust 工具链。（注意：CC Switch 用 Tauri 是因为它是**原生桌面应用**，不是套壳现有网页——场景不同。）
- **对标**：腾讯 WorkBuddy=Electron 41、扣子桌面=安装包、Cursor=Electron——国内 ToSMB AI 工具的标准形态就是 Electron GUI。

## 四、本地能力 —— 只做"轻的"，不碰文件不跑命令（⑤，判断力所在）

**技术真相**：所有"AI 碰电脑"系统（Claude Code/Codex/Computer Use/MCP/WorkBuddy）架构一致 = LLM脑 + 执行层 + 权限闸。**但那是给开发者的**（改代码/跑测试/操作 Shell）。

**台球场景判断（不照搬）**：
- ❌ **不搬** Claude Code 那套"改文件/跑命令/操作文件系统"——台球老板没那个心智模型，搬过去只有误操作风险 + 支持负担，不是功能增强。
- ✅ **台球真正要的轻本地能力**（3 件，现有 Web 技术栈就能覆盖）：
  1. **推送通知**（最高价值）："该发朋友圈了""周五建议发约台活动"——PWA Web Push，呼应第三节 PWA。⚠️ 微信 WebView 不支持 Web Push，需引导系统浏览器或走微信服务号模板消息。
  2. **导出到桌面**：日报 Excel（openpyxl 已有）+ File System Access API 让用户选存储位置（体验提升）。
  3. **读本地图片做海报**（已有多图直传）+ 记住上次的 Logo/二维码（后端存，免重传）。
- ❌ Computer Use / 本地 Agent / 读收银 POS 文件——对台球不必要（且 CLAUDE.md 明确"不重做收银系统"）。
- ⚪ **MCP filesystem 可用于后端**（AI 读服务器素材库/模板库），不给用户；自建要防路径穿越。

## 五、BYOK 纯方向落地（结合 CC Switch + 你定的"必须先配才能用"）

- **方向**（你已定）：平台不给门店共享 key，每门店**必须**自带 key，没配则 AI 功能锁住、引导去配。
- **CC Switch 借鉴（含补读的功能 UX agent，2026-06-17 补全）**：
  - ① **厂商预设卡片网格**（最核心 UX）：选厂商从下拉改成卡片网格（logo+名），选中**自动填 base_url，老板只填 API Key**，不用懂 base_url。内置国产主流：DeepSeek/Kimi/通义/智谱GLM/豆包/MiMo/MiniMax/硅基流动。（我们现在只 DeepSeek/MiMo 两个快填，扩成一排卡片）
  - ② **厂商分类 + 差异化提示**：国产官方(只填key) / 聚合服务(只填key) / 自定义(手填)；选后给针对性提示，减少"不知道填啥"卡住。
  - ③ **动态拉模型列表**：配好 key 后「获取模型列表」拉 `/v1/models` 变下拉选——**防老板拼错 model 名**（比现在让用户手填 model 强）。
  - ④ **测试连接 = 延迟测速**：不只成功/失败，显示 ms（我们已实现基础版「连接正常」，可升级为测速 + 自动选最快）。
  - ⑤ **key 密码框 + 眼睛显隐**（门店共用设备防偷看，我已 password 类型 autoComplete=off）。
  - ⑥ **常见坑预设里预填**（很关键）：DeepSeek base_url 是 `/v1`(OpenAI兼容) vs `/anthropic`(Anthropic兼容)、models 接口在根路径单独；豆包超时设 3000s；MiniMax temperature 不能传 0——这些坑在预设里填好，老板不踩。
  - ⑦ Fernet 加密我已做（**比 CC Switch 明文存 SQLite 强**，SaaS 多租户必须加密）；数据结构/SSOT/请求时读最新 key/原子更新——已是；故障转移(主+备 key)可选、暂不急。
- 待改（下一批）：后端没配 key 不回退平台→报错引导；前端 AI 配置从"可选"升为"必要设置" + 多厂商预设；新手引导加"配 key"步骤。

## 六、综合优先级路线（我的建议）

1. **BYOK 纯方向改造**（你已定方向，CC Switch 借鉴在手）—— 让商业模式跑通（平台零 token 成本）
2. **PWA + 推送通知**（1-2天，一箭双雕：桌面感 + 运营提醒，台球最值钱的本地能力）
3. **主动推送（P4）+ 向导式输入**（垂直 Agent 的核心差距，"被动工具→主动助理"）
4. **卡片渐进 Agent 工具化 + 自定义工作流**（旧形式演进，不砍）
5. Electron 套壳（需要"安装包"信任感时）
6. pgvector 语义召回 / Skill 升级（已在 backlog #18/#19）

**一句话**：旧形式全留、定位重排（货架+老手通道+主动层三层）；桌面化走 PWA→Electron；本地能力只做轻的（通知/导出/图片），坚决不碰用户文件系统——这是垂直运营 Agent 的对的形态，不是把开发者工具搬给台球老板。
