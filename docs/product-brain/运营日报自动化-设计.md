## 0. 一句话

把各岗位每天**本来就要交的日报**，从"自己动脑写一段文字"升级成：**填几个数（或说一句话）→ AI 自动写好叙事段落 → 导出排版好的 Excel**。

## 1. 背景与边界（为什么这么做）

- 这些日报模板真实存在（店长 / 助教管理 / 教练 / 前厅，见行业资料）。员工每天重复填，**耗时在"动脑写总结/问题/计划 + 算累计 + 排版"，不在录数字本身**。
- **铁律：不重做收银系统。** 收银系统已实时显示开台数 / 上钟数 / 营业额 / 充值。我们**不做数据看板、不做数据滚动**——那是收银系统的活，做了零差异化。详见项目记忆 `pos-boundary-writing-layer`。
- **本功能定位 = 收银系统下游的「运营文书 / 内容」层**：把数字（加上收银系统采不到的"运营动作数据"）变成**文字、判断、内容**。
- 输入仍来自人（运营动作数据没有任何系统自动记），但：① 输入压到最小（自动带固定信息 / 记累计 / 支持"说一句话"）；② 输入之后的活（写字 / 算 / 排版 / 滚报表）全自动。详见 §4。

## 2. 范围与非目标

### v1 范围
- 岗位日报：**Layer 2**（填表单 + AI 代笔）+ 导出 **.xlsx** + 环比/累计（读上次提交）。
- **配置化引擎**（一表一 YAML），覆盖三种表形态（见 §3.1）。
- **「说一句话」输入（v1 含）**：自然语言 → AI 抽取填表（一个 schema 驱动的**通用**抽取器 + 用户核对/改 → 提交），复用店脑抽取机制。**表单为主、说话为辅**，抽不准用户能改，降级优雅。
- **老板今日交付状态（轻，v1 含）**：老板首页一张"今天 X/N 岗已交日报"状态卡，点进看谁没交→去群里催。**不做**重的"下发任务工作流 / 逐人历史看板"（→ v1.5）。
- **产品内容从厚**：字段照真实模板给全；AI 叙事给足（今日总结/发现问题/明日计划 + 环比诊断 + 花名册业绩播报 + 主/副教练分版）。

### 非目标（明确不做）
- ❌ 实时数据看板 / 数据自动滚动（收银系统已有，零差异化）。
- ❌ 逐笔台账（充值 / 存杆 / 销售登记）、全口径经营数据总表（80 列）→ 那是收银 / 会员 / 库存系统。
- ❌ 排班考勤工资、合同协议（HR 系统；最多"空白模板下载"，不投 AI）。
- ❌ 主动推送通知（web / 微信 WebView 无此能力；到点提醒靠进 App 时今日推荐 + 老板群手动催）。
- 唯一将来可碰 POS 数据的姿势：用户**粘贴 POS 导出 → AI 读了给诊断**（消费，不复制看板）。非 v1。

## 3. 核心设计

### 3.1 三种表形态（一个引擎，三种渲染）

> 数据归属分层决定表形态，不能一套表硬套（PPT「人才管理」章坐实）。

| 岗位 | 数据范围 | 表形态 | 渲染 | Excel | AI 干啥 |
|---|---|---|---|---|---|
| **店长** | 店级总账 | `flat` 平表 | 分节填空 | 单表分节 | 写"发现问题 & 解决方案" |
| **前厅** | 店级（前厅口径） | `flat` 平表 | 分节填空 | 单表分节 | 写"服务问题 / 明日计划" |
| **助教管理** | 团队花名册（N 个助教） | `roster` 多行 | N 行明细 + 汇总 | 明细页 + 排名页 | 写"业绩排名播报" |
| **教练（主/副）** | 个人 | `personal` 个人日报 | 报数 + 今日/累计 | 个人单表 | 写总结 + 对 KPI 提示 |

### 3.2 配置化引擎（一表一 YAML）

一张表 = 一个 YAML，字段 / 形态 / Excel 排版 / AI 提示词全在里头。加第 5 张表 = 写个 YAML，不碰代码：

```yaml
key: report.manager_daily
shape: flat                       # flat 平表 | roster 花名册 | personal 个人
title: "{store_name}·店长日报·{date}"
prefill: [store_name, date, weekday]          # 自动带出，0 输入
groups:
  - name: 今日数据
    fields:
      - {key: revenue,    label: 营业额, source: pos_glance}   # 收银系统有 → 瞄一眼填
      - {key: recharge,   label: 充值,   source: pos_glance}
  - name: 运营动作                                              # ← 收银系统没有，主战场
      - {key: add_wechat, label: 加微信, source: manual}
      - {key: reviews,    label: 好评数, source: manual}
narrative:                        # AI 只写这几段
  prompt_key: report.manager_daily_narrative
  outputs: [今日总结, 发现问题, 明日计划]
  context: [numbers, store_memory, last_submission]    # 喂给 AI 的料
excel: {layout: sectioned}
```

**关键：`source` 字段把"不抢收银系统"焊进配置** —— `pos_glance`（收银系统有，瞄一眼填）/ `manual`（我们的运营动作数据，主战场）/ `profile`（画像自动带）。不靠人记边界。

### 3.3 少输入、多产出 + 输入方式

- **预填**：门店名 / 日期 / 星期 / 台数 / 累计 全自动带出，进来就"已填一半"。
- **累计/环比**：读上次提交（`generations.input_params`），教练的"累计 379"是算的、不是打的。**不建新表。**
- **两种输入**：① 填空表单；② **"说一句话"**——"今天加了 5 个微信、组了 3 局、搞了红牛挑战赛"，AI 抽成结构化数字 + 写成日报（复用店脑抽取 + 自由对话管道）。

```

          │ ①瞄一眼填几个数当上下文     ②[未来]导出粘贴 → AI诊断
          ▼

   平表(店长/前厅) │ 花名册(助教管理) │ 个人日报(教练主/副)

   ┌──── 报表服务 ReportService (编排) ──────────────────────┐

```

## 5. 数据流

1. 打开日报表单 → `prefill` 自动带出固定信息 + 上次累计。
2. 用户填运营动作数（manual）+ 瞄收银屏填几个 POS 数（pos_glance）+ 可选「补充说明」/「说一句话」。
3. POST `/api/v1/reports/{type}` → **ReportService**：
   a. 读上次提交算环比 / 累计；
   b. `run_generation(gen_type="report", sub_type=岗位, input_params=结构化数据, user_input=备注)` → AI 写叙事段落（自动走配额 + 注入检查 + 落库 + 计费）；
   c. openpyxl 按 schema 的 excel.layout 渲染 `.xlsx`。
4. 返回叙事预览 + Excel 下载（微信内走"用浏览器打开"引导）。提交存进 `generations`，下次累计/环比/排名从这查。

## 6. 引导与采纳（发现 → 填写 → 留存）

- **发现**：① 老板/店长**自上而下下发**（B2B 本质，最强；后台"下发 + 谁填了谁没填"看板，催填文案我们生成）；② 今日推荐**到点弹**"今天日报没写"（复用 `dashboard_service` 规则引擎）；③ 岗位工作台默认带（`my_role`）；④ 新手引导加一步。
- **填写**：填空非白纸（字段照模板列死）+ 每格给例 + **"说一句话"消除门槛** + 预填一半 + **首次填完立刻甩成品（aha）** + 一键复用上次。
- **留存**：触发（到点今日推荐 + 老板群催）→ 动作（30 秒报数/说句话）→ 奖励（成品发老板群、老板看得到 = 社交强化）→ 投入（填得越多，排名/趋势/绩效/周月报越全）。

## 9. 风险与依赖

1. **openpyxl 依赖（🔴 必须先办）**：venv 有但未声明。需 `uv add openpyxl` + `uv lock` + 部署后实测。**装包需用户授权**（全局规则）。零风险替代：CSV 导出（WPS/Excel 也能开），但失去样式/多 sheet。
2. **隐私 PII**：助教档案（含"男友/生理期"）、面试表（身份证号）属敏感信息——只做轻字段 / 空白模板，**不替门店存重 PII**（脱敏）。
3. **无主动推送**：到点提醒只能靠进 App 时今日推荐 + 老板群手动催（文案我们生成）。
4. **迁移孤儿旁支**：仓库有 `add_new_tables_and_fields`（revises 012）形成多 head；如确需新表，挂 head=`019`，别碰旁支（复用 generations 表则零迁移、整体绕开）。

## 10. 分期（2026-06-14 拍板：4 张齐头并进，不分期）

- **v1**：引擎 + **三种渲染全做**（`flat` 平表 + `personal` 个人 + `roster` 花名册）→ **店长、前厅、教练（主/副）、助教管理 4 张日报齐头并进**。
  - 代价已知：`roster` 花名册（助教管理，master-detail 多行）是最复杂的渲染器，v1 即含，不后置。
- **v2**：复用同引擎扩 → **周报 / 月报**（从日报滚）、**绩效考核 5 表同构引擎**、**复盘纪要**。
- 边界外永不做：收银数据看板、逐笔台账、HR 工资排班。

## 11. 决策（2026-06-14 全部拍板）

1. **分期** → 4 张齐头并进，v1 三种渲染全做（含 roster 花名册）。见 §10。
2. **Excel 依赖** → **用 openpyxl**（花名册要多 sheet、报表要分节排版，CSV 做不了）。实现时 `uv add openpyxl` + `uv lock` + 部署后实测 `/export`（502 安全姿势）。
3. **「说一句话」输入** → **v1 含**（一个 schema 驱动的通用抽取器，复用店脑抽取；表单为主、说话为辅、抽完用户可核对）。采纳关键友好度、复用现成机制、非每表重写，值得做。
4. **老板看板** → **v1 只做轻状态卡**（今天谁交了）；重的下发工作流 / 逐人历史 → **v1.5**（报表没上线前，全量管理看板是没用的东西）。

> 设计原则（产品负责人 2026-06-14）：用户使用角度自行决断；**产品内容能厚则厚，但不堆没用的东西**——故 NL 输入/老板轻状态/厚内容做进 v1，POS 重做/排班合同/重管理后台不碰。
