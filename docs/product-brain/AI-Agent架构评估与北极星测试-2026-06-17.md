# AI Agent 架构评估 + 北极星对齐测试 — 战略结论（2026-06-17）

> 本文是一次系统评估的结论沉淀：① 我们做的到底算不算 AI Agent、方向对不对；② 一套可常态运行的北极星大规模测试体系；③ 一个关键洞察（瓶颈在哪、下一步往哪走）。
> 配套证据：`docs/references/AI-Agent架构评估-原始调研.md`（12 路并行调查原始）、`docs/test-runs/北极星对齐-*.md`（测试报告）、`server/evals/`（可重复运行的测试体系）。

## 一句话结论

**方向是对的，底子比预期扎实**：项目已经是"真 Agent"（不是套壳 prompt），按 Anthropic 标准处在正确的"工作流主干 + 局部 Agent"混合形态；**内容质量已是第一梯队**（北极星对齐 GREEN 率 97.5%）。**真正的瓶颈不是内容/架构，而是 DeepSeek v4-flash 的指令遵循天花板**——往下提升靠"换更强大脑 / fewshot 反例 / 关键铁律二次校验 / eval 常态化盯防"，而**不是**继续堆 prompt 规则（已 61 条，边际收益递减）。

## 一、我们算不算 AI Agent（架构评估）

算。按 Anthropic《Building Effective Agents》判据逐项核对（均经代码核实）：

| 要素 | 现状 | 证据 |
|------|------|------|
| 真 tool calling | ✅ DeepSeek 真传 `tools`/`tool_choice`，正确处理"content空+tool_calls"边界、流式增量拼接 | `services/ai/providers/deepseek.py:54-58,154-184` |
| 自主 ReAct 循环 | ✅ think→act→observe 多轮，工具结果 `role:tool` 回灌再推理，max_turns 兜底 | `services/agent/loop.py:76-125` |
| 人在环审批闸 | ✅ `requires_approval` 工具不在循环执行，弹确认→`/agent/execute` | `loop.py:108-114`, `tools.py:166-179` |
| 工具复用现有管道 | ✅ 9 个工具走 `generate_workbench`/`run_generation`，自带配额/落库/店脑/合规 | `services/agent/tools.py` |
| 记忆注入 | ✅ 店脑长期记忆 + 门店画像注入 system prompt | `api/v1/agent.py:99-131` |

**但要克制**：Anthropic 明确反对"为了 Agent 而 Agent"（自主性=更高延迟/成本/滚雪球错误）。台球老板要的是**可预期**的文案/活动/日报，所以正确形态是"工作流为主、局部 Agent 点缀"，**不要全 Agent 化**。

### 已知差距（来自调查，按价值排序）
1. **Agent 会话不落库**（刷新即丢历史，`agent.py:14` TODO）——微信 WebView 刚需，最该先补。
2. **记忆全量注入而非 pgvector 语义召回**——越积越慢越不准（转型计划 P2，最大技术债）。
3. **GLM A/B 未实测**——编排大脑稳定性是未知量（配置层已就位，`config.py` 预留 `orchestration_*`）。
4. orchestrator（多岗位协作）是无工具的固定 workflow，与 ReAct loop 两套独立体系。
5. P4 主动出击（合规推送通道）完全未启动——"工具→运营助理"的最后一跃。

## 二、6 个战略问题的答案

1. **方向对不对** → 对，已是真 Agent（6-7 成完成度），保持混合形态，别全 Agent 化。
2. **Skill 能不能做** → 能，且已有雏形。Skill ≠ "查外部资料"（那是 RAG），是"按需注入专业流程的能力包 + 渐进式披露省 context"。项目的 `knowledge YAML + 关键词选择 + PromptEngine` 已是 DeepSeek 版类 Skill。升级方向：给每个 YAML 加 `summary:`（一句话描述，当 Level-1 元数据）+ 关键词命中 0 时 LLM 语义兜底（解决漏选）。
3. **DeepSeek 会自我进化吗** → 不会。API 无状态、权重冻结。"越来越懂"靠：店脑记忆 + 知识库 + **eval 驱动人工迭代**（本文第三节就是这个引擎）。微调太重、体量不够、不划算。
4. **还有啥没做/怎么测/结果定义** → 见第一节差距 + 第三节测试体系；结果定义 = 三级 GREEN/YELLOW/RED 量化。
5. **BYOK（用户自带 Key）** → 现全局单 Key。路径：加密表（Fernet）+ ProviderFactory 按 Key 路由 + 双轨配额（BYOK 不扣 token 成本、仍扣功能次数）。建议做成专业版差异化卖点，分阶段（先生图 Key 后文本 Key）。
6. **北极星可优化点** → 女性客群/企业团建运营空白、中小独立店适配层缺失（现指标是头部连锁特供）、引流合规优先级未排、主题夜/淡季促活套路库不全。

## 三、北极星大规模对齐测试体系（已落地、可重复运行）

**位置**：`server/evals/`。详见 `server/evals/README.md`。

**方法**：3 模拟门店（社区/商业/竞技，含店脑+员工记忆）× 80 场景（7 类）→ 构造 in-memory Store 复刻真实 prompt 拼装 → 真跑 DeepSeek → LLM-as-judge 三级量化。无 DB 依赖、可重复、仅文本零生图。

**结果定义（量化"是否脱离北极星"）**：
- 🟢 GREEN：裁判分≥4（完全对齐，可直接用）
- 🟡 YELLOW：裁判分=3（轻微偏离）
- 🔴 RED：裁判分≤2 或命中硬红线词（脱离北极星）
- 门槛：GREEN 率 ≥85% 才允许合并 main。

**两轮 baseline（eval 工程典型规律：第一版先暴露评分器自身的毛病）**：
| | GREEN 率 | RED | ERROR | NO_JUDGE | 说明 |
|--|--|--|--|--|--|
| v1 | 55% | 9 | 15 | — | 机器关键词误伤（"不赌钱"含"赌钱"、"中八打法"、内部"闭环"）+ 并发限流 |
| v2 | **97.5%** | 0 | 0 | 0 | 改为 LLM 裁判主导（看语境）+ HARD_FORBIDDEN 精选兜底 + 并发降3+双重试 |

**对抗性验真**：裁判没放水——`activity_009` 被判 YELLOW，精准抓到"助教免费指导作赠品违反 NS-PRICE-04 + 优惠钩子偏重价格 NS-SVC-01"；`diagnosis_012` 抓到"过度依赖低价钩子、偏离卖氛围核心"。

## 四、关键洞察：瓶颈在模型，不在内容

`baseline_rules.yaml` 已有 **61 条强制规则**，"助教不能作赠品"写了**整整一段**（第 29 条）、"活动靠巧思不靠打折"也明文在列。**但 AI 仍偶尔违反**（女生场把"助教免费指导"当福利写出来）。

→ 根因是 **DeepSeek v4-flash 的指令遵循天花板**（规则越多、语境越有诱导，越可能漏守某条），不是"缺约束"。这印证调研里 BFCL 数据：DeepSeek V3.2 函数遵循 56 分 vs GLM-4.6 72 分。

→ **结论：不要再往 baseline 堆规则**（过度设计 + 稀释注意力 + 全局高风险）。

**稳定性探针铁证（对偏离场景各重跑 6 次）**：
- `activity_009`（助教赠品疑点）：**6/6 GREEN** → v2 那次 YELLOW 是偶发抖动，约束基本有效。
- `diagnosis_012`（堆优惠）：5 GREEN / 1 YELLOW → 偶发。
- `customer_pricing_001`（充值赠送限台费）：3 GREEN / 2 YELLOW / 1 RED → **唯一稳定的高频弱点**，裁判 6 次里 3 次指出"未明确赠送金额仅限台位费"。
- 而 `recharge_strategy.yaml` 已把"赠送金额仅限台位费"写了**近 10 次**、baseline 第 29 条整段讲助教非赠品——**约束到顶，AI 仍 ~50% 概率漏守，这是模型遵循天花板的铁证，不是内容缺失**。
- 注：HARD_FORBIDDEN 里的充值促销词（充多少送多少/充1送1/充值翻倍/送100%）**后续移除**——4模型探针实测发现它在充值场景误伤（AI 让老板补充"充多少送多少的具体方案"=泛指询问赠送比例，judge 全判 5 分合规，是机器误杀）。大额赠送是否违规改由 judge 看语境判。

## 四点五、4 模型 A/B 实测（2026-06-17，用户提议）—— 推翻了"换模型无效"的中途误判

对 4 个偏离场景各跑 6 次（裁判统一 deepseek-v4-flash），量化"赠送仅限台费"等铁律的严守率（judge≥4 比例）：

| 模型 | cp_001 赠送仅限台费 | 四场景合计 |
|------|------|------|
| `deepseek-v4-flash`（**当前生产**）| **50%** | 83% |
| `deepseek-v4-pro` | **100%** | 96% |
| `mimo-v2.5` | **100%** | 100% |
| `mimo-v2.5-pro` | **100%** | 96% |

**结论（修正第四节"瓶颈是天花板、别堆规则"的下半句）**：
- ✅ 第四节上半句对：约束已说尽，**不该堆规则**。
- ❗ **但"换模型无效"是错的**（中途被 MiMo 单次 full-run 表面数字 + HARD 误伤误导）。严格 6 次探针证明：**唯一守不住的是当前生产的 `deepseek-v4-flash`（最弱最便宜）**，三个更强模型全部 100% 守住。**说明 prompt 机制是有效的、传达到位的，瓶颈是 v4-flash 的能力**。
- 🎯 **换更强模型确实是最直接的解法**。首选 `deepseek-v4-pro`（同家族、改模型名即可、延迟可控）；MiMo 虽稳但慢 3 倍+reasoning延迟+独立付费，不宜当主力。
- 📌 方法论教训：单次跑会被随机性 + 评分器误伤双重误导，**多次探针 + judge 主导信号**才是可靠结论。这正是这套 eval 体系的价值。

## 五、下一步路线（按 ROI 排序）

1. **eval 常态化**（已就绪）：每次改 prompt/知识/换模型前后跑一遍，盯 GREEN 率不回退。这是让"AI 越来越懂台球"真正发生的引擎。
2. **✅ 已做：模型 A/B 实测（见第四点五）。结论=升级模型有效**。落地：**混合路由**——日常/低风险场景（朋友圈/约客/玩法）用 `deepseek-v4-flash`（便宜快）；高风险铁律场景（充值方案/活动策划/客户定价）用 `deepseek-v4-pro`（守得住，cp_001 50%→100%）。`config.py` 的 `orchestration_*` 已预留模型分离，技术上可做。MiMo 不宜当主力（慢3倍+reasoning延迟+独立付费）。
3. **关键铁律 fewshot 反例**：对高危铁律（助教非赠品、卖氛围非优惠）给 AI 看具体反例（项目已有 `workbench-结构化反例库.yaml`），比抽象规则更有效。
4. **Agent 会话落库 + conversation_id**：微信 WebView 刚需（刷新丢历史）。
5. **pgvector 语义召回**：替代记忆/知识的全量注入与关键词选择，修"越积越慢越不准"+"知识选错"。
6. **Skill 化升级**：knowledge YAML 加 `summary:`/`triggers:` + LLM 语义兜底。
7. **✅ BYOK 后端已实现**（门店自带 key、自担成本/并发，解决共用单 key 的并发+成本硬伤；加密+按门店路由+全生成路径接入+API+对抗review，详见 `BYOK-门店自带模型-实现.md`）——前端配置页待做（需设计图）。
8. **北极星内容补全**（女性客群/团建/中小店适配/主题夜）仍待做。
