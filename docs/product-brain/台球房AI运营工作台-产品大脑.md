# 台球房AI运营工作台 - 产品大脑

---

## 1. 产品一句话定义

> 给台球房管理层使用的、围绕真实经营场景的对话式 AI 运营工作台。

它不是普通 AI 工具——用户不需要自己研究 Prompt、自己改内容。
它不是收银系统——不管钱、不计费、不管理会员余额。
它不是固定模板 SaaS——每个球房根据自身门店资料和岗位身份，得到定制化输出。
它不是行业培训系统——不教人怎么运营，而是帮人把运营动作做出来。

**目标是输出能直接发布、能直接执行、能直接交付的成品内容和素材。**

---

## 2. 产品核心价值

让台球房管理层**少想、少写、少设计、少重复沟通**，降低日常运营时间成本。

具体来说：

- **少想**：不用自己想今天该发什么、该联系谁、该推什么活动。系统结合门店资料和经营场景，直接给出可执行的任务和内容。
- **少写**：不用自己写朋友圈文案、群公告、私聊话术、活动方案、日报。说一句话，系统输出成品。
- **少设计**：不用自己设计海报、排版文案、规划活动规则。系统输出完整可用的素材和方案。
- **少重复沟通**：不用反复跟员工说“朋友圈要发什么”“客户怎么跟进”。系统输出可直接下发的执行内容。
- **让门店运营看起来更专业**：统一的内容输出标准和行业调性，让社区球房也能产出商业球房级别的运营素材。

## 3. 目标用户与购买逻辑

### 3.1 老板 — 买单决策者

- **为什么买**：降本增效。不用再靠店长个人能力撑全场，管理层日常运营有系统兜底。减少运营人才招聘和培养的时间成本。
- **看什么**：店长有没有在做事、助教有没有在推广、营业额和利润趋势、团队执行状态。
- **系统帮什么**：今日运营总览、各岗位执行状态一览、经营趋势分析、月度运营汇报。

### 3.2 店长 — 最高频使用者

- **为什么用**：偷懒、省时间、快速交付。每天不用自己从头想活动、写文案、做方案。不会策划活动也能产出可执行的活动方案。新店长上手快，不依赖前任交接。
- **每天做什么**：发朋友圈、发群公告、检查各岗位工作、策划活动、跟进老客户、写日报。
- **系统帮什么**：每日运营待办、一键生成各场景内容、活动方案、日报生成。

### 3.3 助教管理 — 核心使用者

- **为什么用**：管助教是最累的活。招聘文案不会写、培训内容不会做、助教朋友圈没素材、PK方案不会设计。系统把这些全包了。
- **每天做什么**：安排助教今日任务、写助教管理日报、发助教推广内容、跟助教客户沟通、招聘面试。
- **系统帮什么**：助教日任务生成、助教推广文案、招聘文案与话术、PK方案、日报生成。
- **助教业务完整理解**：系统理解的助教业务不仅是"教学陪练"，还包括助教服务体验、助教预约转化、助教内容素材（朋友圈/短视频）、助教个人号运营、助教管理与业绩提升、助教客户维护。助教场景是门店私域运营的核心组成部分。产品理解行业真实需求（包括客户因服务体验、沟通氛围、情绪价值而预约助教），但对外输出时转译为专业、可发布、低风险内容。

### 3.4 教练 / 赛事负责人 — 高频使用者

- **为什么用**：赛事宣传、赛后战报、教学推广这些内容产出太费时间。自己写水平参差不齐。系统统一输出，让赛事运营看起来更专业。
- **每天做什么**：赛事报名推广、赛前提醒、赛后战报、竞技客户维护、搭子局组织、教学课推广。
- **系统帮什么**：赛事全套内容（方案/报名/海报/提醒/战报）、竞技客户维护话术、搭子局运营内容。

### 3.5 前厅主管 — 日常使用者

- **为什么用**：新前厅员工培训成本高，接待话术、推卡话术、投诉处理标准不统一。系统提供标准化 SOP 和话术，让新员工也能快速上手。
- **每天做什么**：接待客户、核销团购、加微信、引导进群、推卡推助教、处理投诉。
- **系统帮什么**：分场景接待话术、推卡话术、加微信话术、投诉处理模板、前厅日报。

### 3.6 运营负责人 — 策略使用者

- **为什么用**：需要持续产出多渠道内容（朋友圈/抖音/小红书/视频号），但内容团队人力有限。系统批量产出、多渠道适配。
- **每天做什么**：规划内容日历、批量产出文案和海报、分析运营数据、调整运营方向。
- **系统帮什么**：批量内容生成、多渠道内容适配（抖音/小红书/视频号/朋友圈）、运营数据分析建议。

## 4. 产品和其他系统的区别

### 4.1 和收银系统的区别

| 收银系统管 | 本系统管 |
|-----------|---------|
| 开台、计费 | 朋友圈文案、群公告 |
| 会员余额、充值 | 客户邀约话术、老客维护 |
| 助教上钟、计时扣费 | 助教推广、助教招聘、助教任务 |
| 收银报表、营收分析 | 运营日报（发了什么、联系了谁、转化了什么） |
| 支付、退款 | 活动方案、赛事内容 |
| 财务对账 | 前厅接待话术、SOP |
| 灯控、电器 | 海报文案、短视频素材 |

**本系统不碰收银系统的任何功能。两套系统互补，不是竞争关系。**

### 4.2 和豆包 / ChatGPT 等通用 AI 的区别

| 通用 AI | 本系统 |
|---------|--------|
| 用户自己想 Prompt | 系统按经营场景直接给任务 |
| “帮我写一条朋友圈” | “今天下午空台，给你生成一条下午促活朋友圈，门店价格已自动带入” |
| 不知道你是台球房 | 知道你几张台、什么价格、有没有助教、最近在推什么活动 |
| 输出通用文案 | 输出带门店名、价格、地址、二维码的可直接发布内容 |
| 没有角色概念 | 老板看全局、店长管运营、助教做推广、前厅搞接待 |
| 没有任务驱动 | 每天登录就有待办事项和运营建议 |
| 输出后用户自己改 | 输出接近成品，微调即可发布 |

| **充值客户** | 已办卡或充值，有一定忠诚度 | 享受会员权益、被重视 | 充值感谢、权益说明、专属活动邀请、防流失 | 充值感谢文案、权益说明、VIP活动邀请 | 不夸大权益、不做无法兑现的承诺 |
| **大客户** | 高频到店、大额充值、经常带人，对球房贡献极大 | 专属服务、被尊重、社交需求 | 专属维护、生日关怀、VIP赛事、转介绍激励 | 生日祝福、专属福利通知、VIP活动邀请、防流失提醒 | 体现专属感但不泄露其他客户信息 |

### 6.2 转化路径

```
路径 1：团购引流 → 私域沉淀 → 复购转化
  团购核销 → 加微信+进群 → 二次到店邀约 → 推荐会员卡/充值 → 老客户

路径 2：团购客户 → 助教客户
  团购到店 → 推荐助教体验课 → 助教跟进+复约 → 客单价翻倍

路径 3：单人练球 → 搭子局 → 高频复购
  单人客户 → 撮合凑局 → 进搭子群 → 自约习惯 → 高频到店

路径 4：老客户 → 高价值客户
  老客户 → 推荐充值 → 邀请周赛 → 预约助教 → 带朋友来 → 大客户

路径 5：大客户 → 专属维护
  生日祝福+专属福利 → 充值续费 → VIP赛事邀请 → 转介绍激励 → 防流失
```

## 8. 核心产品原则

### 8.1 场景模块化

系统覆盖台球房管理层的真实工作场景，不是只提供固定模板。场景来自真实经营需求（不是产品经理臆想），每个场景对应“用户怎么说 → 系统输出什么”的完整闭环。

### 8.2 输入自然语言化

用户像跟 AI 说话一样输入需求，不被迫填写复杂表单。可以说“今天想推一下助教”“帮我写一条老客户邀约”“帮我搞一个世界杯看球活动”，系统理解意图并输出成品。

### 8.3 输出成品化

系统输出尽量接近可直接发布、直接执行、直接交付的成品。不是咨询报告，不是泛泛建议，不是“你可以尝试以下方法”。朋友圈文案可以复制→微调→发布，活动方案可以直接下发执行，日报可以转发到管理群。

### 8.4 岗位化

不同岗位有不同任务、不同场景、不同输出格式。店长要的是数据+总结+待办，助教管理要的是任务分配+激励，前厅要的是话术清单。系统按用户岗位身份匹配场景和输出。

### 8.5 结合门店资料

所有内容生成必须基于门店录入的资料。没有资料就没有精准输出。门店定位、价格体系、助教团队、活动安排等信息是 AI 生成“能直接用的内容”的前提。

### 8.6 不让用户研究 Prompt

用户不需要学习怎么写 Prompt。系统预置了台球房经营场景的 Prompt 模板，用户只需要说“想做什么”，系统自动组装上下文、门店资料、客户类型、岗位身份和场景规则。

### 8.7 不乱编信息

不乱编价格、不乱编优惠、不乱编奖金、不乱编助教姓名和数量、不乱编客户数据、不乱编营业额、不乱编奖品、不乱编门店政策。没有用户输入的信息，用占位符（如 `[请填写：XXX]`）或明确提醒用户补充。

### 8.8 行业现实可以理解，产品输出必须专业、合规、可公开使用

有些行业现实（如平台评分操作、追分赌博、擦边获客等）可以进入内部行业理解库和风险边界库，但不能以原始形式显性产品化。产品输出必须转译为合规、专业、安全的运营表达。

### 8.9 助教服务完整理解，内外表达分层

系统对助教业务的理解不能局限于"教学陪练"。产品大脑必须理解：

- **技术陪练型助教**：客户为提升球技、纠正动作、专业陪练而预约
- **服务体验型助教**：客户为服务体验、沟通氛围、情绪价值、陪打体验而预约（这是大多数普通助教的真实商业场景）

产品不是否认行业真实需求——客户确实会因为助教的形象、沟通、服务体验而预约。产品是理解这些真实需求后，转译成专业、可发布、低风险的内容。

**内部理解层**：系统可识别"美女助教""点助教""好看的助教"等口语背后的业务意图（助教到店通知、助教预约转化、助教服务推广）。

**对外表达层**：默认输出"今日助教可约""新助教到店""助教服务体验""想约助教提前说"等专业表达。不输出低俗、擦边、过度颜值营销内容。

详见 `docs/product-brain/助教业务规则库.md` 和 `docs/product-brain/行业术语白名单与风险词转译规则.md`。

### 8.10 设备桌型分类

台球房设备分类先按以下 4 类处理：

1. 普通台球桌
2. 独牙台球桌
3. 乔氏台球桌
4. 斯诺克

> **核心规则**：除独牙、乔氏以外的中式八球台球桌，统一归为普通台球桌。不要把"中式八球台""美式台""英式台""比赛台""娱乐台"等作为标准枚举。

设备桌型通过 `operation_profile.equipment.table_types` 多选存储（4 个标准枚举值），补充说明通过 `table_type_note` 字段存储。

AI 生成内容时：
- 已提供桌型：可合理参考桌型生成赛事/约局/客户邀约内容
- 未提供桌型：不得编造乔氏、独牙、斯诺克等设备信息
- 未提供新设备/升级信息：不得写新到台球桌、新换台球桌、设备升级
- 桌型未知：使用"店里台子""来打两把"等通用表达

## 9. 风险边界

### 9.1 不能以原始形式显性产品化的内容

| 行业现实 | 为什么不能直接产品化 | 安全转译方式 |
|---------|-------------------|-------------|
| 美团/抖音刷好评操作（关定位、断WiFi、多账号轮换） | 违反平台规则，存在法律和平台处罚风险 | 口碑维护、评价引导、差评安抚、客户体验反馈收集、多样化好评文案生成（供客户自然评价） |
| 追分 / 赌博（控制赌博金额、帮客户谈门） | 涉及违法内容，AI产品绝对不可生成 | 轻竞技、台费局、熟人切磋、饮料局、小奖品挑战、搭子局 |
| 助教招聘规避平台风控（用其他岗位包装） | 误导平台审核，存在合规风险 | 助教招聘合规文案、岗位介绍优化、面试邀约话术、招聘风险提示 |
| 低俗 / 擦边 / 性暗示助教内容 | 违反内容安全底线 | 助教服务专业推广、助教个人号运营、助教短视频内容建议、助教预约转化、助教形象包装 |
| “美女助教””点助教””好看的助教”等口语 | 不能直接作为产品外显词，有低俗擦边风险 | 识别为助教服务推广/到店通知/预约转化意图，转译为”今日助教可约””助教服务体验””想约助教提前说” |
| 交友软件引流（积目/陌陌/soul/探探） | 非正规获客渠道，部分操作可能违规 | 本地客户获客内容建议、个人号内容运营、私域客户沟通建议 |
| 大额充值赠送套路（充5000送2000） | 可能误导消费决策，存在责任风险 | 充值活动风险提醒、一卡通模式介绍、合理优惠建议 |
| 虚假优惠/夸大宣传（全网最低价、绝对最好） | 违反广告法，存在合规风险 | 真实优惠信息展示、门店卖点客观描述 |
| 未经验证的行业数据声称 | 数据来源不明，可能误导产品决策 | 标注为”来源待验证”，不作为绝对事实输出 |

### 9.2 转译原则

1. **理解行业现实**：知道门店在做什么、为什么这么做
2. **识别风险**：判断哪些操作是灰色或违规的
3. **提取需求本质**：门店做这些操作的真正目的是什么（口碑、获客、转化、维护）
4. **转译为合规表达**：用专业、安全、可公开的方式满足同样的需求
5. **必要时加风险提示**：当用户要求的内容接近灰色地带，系统应该提示风险并给出合规替代方案

## 10. 运营方法论

### 10.1 营销本质：识别—创造—传播—交付

营销不是"打折促销"，而是：清晰客户画像 → 了解客户真正需求 → 围绕需求打造优质产品 → 对外传播吸引优质客户消费。没有优质客户，企业无法生存。

球房卖的不是台费，是**氛围**和**人情世故**。氛围靠助教数量（商业球房）或竞技客户基数（竞技球房）；人情世故靠服务体验和社交粘性。

### 10.2 定价规则细化

#### 小比例赠送可以，大额赠送不行

- 充1000送99（约10%赠送比例）→ 合理，风险可控
- 充5000送2000（40%赠送比例）→ 禁止主动建议，会虚增台费、降低利润率
- 产品输出：只建议"小比例赠送"方向，具体比例由门店定

#### 一卡通替代会员卡

- 大额充值赠送会让台费增长困难 → 建议取消会员卡，改一卡通
- 一卡通模式：本金全场消费可用，赠送金额仅限台费
- 示例参考（非定价建议）：充1000送99 / 充3000送399 / 充5000送799 / 充10000送1999
- 产品输出：可以介绍一卡通模式的概念和优势，具体金额用占位

#### 价格尾数 8→9 技巧

- 定价小技巧：价格尾数从"8"调整为"9"（如28→29），微小变化但心理感知不同
- 产品生成定价建议时，如果门店提供的价格尾数是8，可以提示"建议调整为9"
- 不得编造门店没有的价格体系

#### 团购产品设计要点

- 团购品类不超过4-5个，太多不利于爆款单量积累
- 设置明确爆款产品（引流新人9.9/h 等）
- 团购页面要加场馆美图、突出球台品牌

### 10.3 客户标签体系（7维度打标签方法）

教练/助教给客户打微信备注时，应使用统一的标签格式：

**备注格式**：`名字+初次进店时间+客户类型+球技档位`

**描述格式**：`距离+消费频次+分区`

| 维度 | 内容 | 作用 |
|------|------|------|
| 名字 | 客户称呼 | 个性化维护 |
| 初次进店时间 | 如"3月15日" | 判断客户阶段 |
| 客户类型 | 散客/竞技/助教客户/刚上瘾 | 决定维护策略 |
| 球技档位 | A/B/C/D档 | 赛事让条件依据 |
| 距离 | 如"3km内" | 判断到店意愿 |
| 消费频次 | 如"每周2次" | 判断客户价值 |
| 分区 | 引流区/竞技区/贵宾区 | 推荐对应台位 |

**分客户类型维护要点**：
- 娱乐型客户：释放自己 → 引导多来、氛围体验
- 仅限朋友客户：专业体验 → 推荐助教体验或搭子局
- 刚上瘾客户：提升自信 → 推教学课、进圈子
- 竞技客户：竞技氛围 → 推周赛月赛、搭子群

**产品功能方向**：可生成客户标签备注模板、分类型维护话术、客户分类判断指引。

### 10.4 球房氛围打造

| 球房类型 | 氛围核心因素 | 快速打造方法 |
|---------|-------------|-------------|
| 商业球房 | 助教数量 | 引流台+助教休息区+管理层接待+音乐+开台次序+活动 |
| 竞技球房 | 竞技客户基数 | 教练引流+周赛月赛+搭子群+竞技区布局+赛事氛围 |
| 竞技商业球房 | 两者兼顾 | 助教团队+赛事活动双线并行 |

氛围五感：听觉（音乐）、触觉（温度）、视觉（人气）、嗅觉（香氛）。

### 10.5 促销设计原则

促销的本质是"我想让谁干什么"，不是无目的打折。

| 促销目的 | 举例 | 产品可生成 |
|---------|------|-----------|
| 培养客户消费习惯 | 助教免费体验（付费体验课） | 体验课推广文案 |
| 培养客户兴趣 | 充值送器材券 | 充值活动框架 |
| 增加客户沉没成本 | 499元入会送红牛/巧克/皮头 | 会员制度建议框架 |
| 引导单人进店 | 小游戏+奖品 | 小游戏活动文案 |
