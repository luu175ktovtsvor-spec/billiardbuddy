# 视频自动剪辑功能 · 开发 Spec

> 📌 状态:📦历史 · 已被《视频创作工作区-定稿设计-2026-07-01》取代(那份推翻了"对话默认",并补齐双模式/氛围Planner/免费商用选型/工作区) · 可删;仅"引擎16铁律/whisper离线/EDL"等技术细节仍可参考
> **给执行窗口**:本文是「先落 spec → 新窗口照改」工作流的 spec 稿。实现请配合 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 按任务逐个落地,步骤用 `- [ ]` 勾。完工后按本文末「文档处置」标 📦 并同步 `docs/README.md`。

**目标(一句话)**:让用户把自己拍的真实视频素材丢进盒子,AI 自动剪成抖音/小红书那种竖屏成品短视频(自动去废镜+切镜头+挑高光+烧字幕+配乐+响度归一),全本地、不靠 AI 凭空生成画面。

**架构(3 句)**:复用现有 ReAct 循环当编排器(范式 A),把"转录/切镜头/渲染"做成工具挂进去;LLM 只负责出一张 **EDL(剪辑决策表 JSON)** ——选哪段、怎么排、什么调性(审美);渲染器按 EDL 用 ffmpeg 确定性执行,**16 条正确性铁律写死在渲染层**(范式 B 纪律),LLM 怎么发挥都越不过。EDL 是大脑(LLM)和双手(ffmpeg)之间的唯一契约。

**技术栈**:Python(FastAPI 后端) + faster-whisper(本地词级转录) + PySceneDetect(切镜头) + auto-editor(可选·去静音) + ffmpeg(打包二进制,抄 video-use 的 `render.py`) + 现有 `services/agent/loop.py` 编排 + 现有审批闸 + Next.js 前端拖拽入口。

## 调研依据(为什么这么做,执行前先读懂)

- **参考实现**:`browser-use/video-use`(11.6k★ MIT)是本方案主蓝本,它的 `render.py`/`pack_transcripts.py`/`SKILL.md` 可直接抄改(项目允许抄参考码,见 CLAUDE.md「可抄+用库」)。其管线 = `转录→打包→LLM出EDL→渲染→自检`。
- **同源范式**:video-use 本身就是一个"Claude Code 技能"——编排层 = Agent 的 ReAct 循环 + 一份规则手册(SKILL.md)。咱 `loop.py` 是同一个范式,所以**编排层不用新建,只加工具 + 一份剪辑提示词 + 审批闸复用**。
- **为什么剪辑而非生成**:真实素材(尤其有真人脸)走剪辑=真实、可控、本地快、不烧云端钱;AI 生成视频(Seedance)拦真人脸又贵又慢,只适合无素材的概念片。两条互补,本 spec 只做剪辑这条。详见项目记忆 `auto-video-editing-route-research`。
- **真实素材样本**:`~/Desktop/助教素材/成都/` 有 3 段真人竖屏视频(其一 4K 2160×3840·14.86s),`晋江/西安` 是真人照片。竖屏视频正是本功能的输入样本,阶段5 用它真机验收。

## Global Constraints(全局铁律 · 每个任务都隐含遵守)

1. **ffmpeg 用打包二进制,别假设系统有**:系统**没装命令行 ffmpeg**;项目自带 `desktop/node_modules/ffmpeg-static/ffmpeg`。后端(Python)要能解析到一个可用 ffmpeg 路径(优先环境变量 `FFMPEG_BIN`,回退 `imageio-ffmpeg.get_ffmpeg_exe()`)。
2. **必须补 ffprobe**:`ffmpeg-static` **不含 ffprobe**,而探规格/HDR 检测要用它。装 `ffprobe-static`(npm)或用 Python 端方案(见阶段0),路径走 `FFPROBE_BIN`。
3. **16 条正确性铁律不可破**(抄自 video-use SKILL.md,写死在渲染层,LLM 不许碰):
   - 字幕**最后**烧(在所有 overlay 之后),否则被盖=静默失败;
   - **逐段抽取→无损 `-c copy` 拼接**,不用单遍大滤镜图(防二次编码糊画质);
   - 每段接缝 **30ms 音频淡入淡出**(`afade`),防爆音;
   - overlay 用 `setpts=PTS-STARTPTS+T/TB` 对齐第0帧;
   - 字幕时间用**成片时间轴偏移** `out=word.start-seg_start+seg_offset`;
   - **切点卡词边界**,绝不切半个字;
   - 每个切点**留 30–200ms padding**(吸收转录时间戳漂移);
   - 只用**词级逐字转录**,不用 SRT/整句模式;
   - 转录**按源文件缓存**,源没变不重转;
   - 多动画**并行子代理**,不串行;
   - **方案先经人确认再动刀**(=审批闸);
   - 产物只写**专门工作目录**,不污染源素材;
   - **HDR(HLG/PQ)源先 tonemap 转 SDR**(否则上传社媒过曝惨白);
   - 成片**响度归一化** -14 LUFS / -1 dBTP / LRA 11;
   - **竖屏源按高缩放**保方向;
   - **字幕底边距 MarginV≈90**(避开抖音/Reels 底部 UI 安全区)。
4. **对外/花钱动作走审批闸**:出片方案先吐 `approval_request` 卡片,人确认才渲染。做成品给用户看、读写本机文件(带备份)不算对外,直接做。
5. **本地文件沙箱**:视频走**本地路径**直接读,**不走** HTTP 上传(现有 `storage_service.py` 限 2MB,会卡死视频);`..` 越界抛错;产物落 `UPLOAD_DIR`。
6. **SQLite 兼容**:若落库,PG 专属 SQL/类型按方言兜底。
7. **大白话露出**:前端把过程翻成人话("我在听你视频里说了啥/在挑最好的几段/在出片了好了叫你"),别甩 ffmpeg 黑话/job-id。
8. **装依赖先问 owner**:阶段0 列的 pip/npm 依赖需 owner 批准后再装。

## 依赖与下载清单(★必读 · 不下载跑不起来)

剪辑这条链路全本地,要搞两类东西:① Python 库(pip,从 PyPI 下) ② **模型权重/二进制(单独下,光装库不够)**。
> 云端视频模型(通义万相/PixVerse/Vidu/可灵)是**百炼上开通、不用下载**,不在此列。要下载的只有剪辑这条本地链路。

### A. Python 库(pip,装进 server 的 .venv · 需 owner 批)
```bash
cd server
uv add faster-whisper          # 本地词级转录(自带 CTranslate2 推理引擎)
uv add "scenedetect[opencv]"   # 切镜头(纯像素分析,无模型权重)
uv add imageio-ffmpeg          # 提供可用 ffmpeg 二进制兜底
# 可选,先不装看够不够:
uv add auto-editor             # 去静音/口水(也可纯用 whisper 词间隙实现,先不装)
```
> scenedetect 靠 OpenCV 像素分析,**没有模型权重要下**,pip 装完即用;auto-editor 同理无模型。**唯一要单独下权重的是 whisper(见 C)。**

### B. ffmpeg / ffprobe 二进制
- **ffmpeg = 已有**,用 `desktop/node_modules/ffmpeg-static/ffmpeg`(或 imageio-ffmpeg 自带的)。
- **ffprobe = 要补**(ffmpeg-static 不含)。二选一:
  ```bash
  # 方案1(推荐):desktop 侧装 npm 包
  cd desktop && npm i ffprobe-static
  # 路径:desktop/node_modules/ffprobe-static/bin/<platform>/<arch>/ffprobe
  ```
  方案2:后端用 imageio-ffmpeg 的 `ffmpeg -f null` 自己解析规格替代 ffprobe(省一个依赖,但 HDR/规格探测代码要自写)。

### C. Whisper 模型权重(★核心下载 · 不下转录跑不起来)
faster-whisper 调 `WhisperModel("small")` 时**自动从 HuggingFace 下载** CTranslate2 权重到 `~/.cache/huggingface`。模型仓库与大小(已核实 2026-06-29 · HF API):

| 模型 | HF 仓库 | 大小 | 选用 |
|---|---|---|---|
| tiny | `Systran/faster-whisper-tiny` | 75 MB | 太糙,不用 |
| base | `Systran/faster-whisper-base` | 141 MB | 凑合 |
| small | `Systran/faster-whisper-small` | 464 MB | 质量一般,只有 CPU 很慢的机器才退到这 |
| **medium** | `Systran/faster-whisper-medium` | 1.46 GB | **推荐默认**(质量好、速度可接受) |
| **large-v3** | `Systran/faster-whisper-large-v3` | 2.95 GB | **质量最好**(球房环境嘈杂/要最准选它,CPU 慢一些) |

**owner 拍板「体积大无所谓、运行得好优先」→ 默认直接上 `medium`(1.46GB);要最高转录质量(尤其球房现场嘈杂)就上 `large-v3`(2.95GB)。体积不是约束,真正要权衡的是本地 CPU 转录速度——模型越大越准但越慢。**

**预下载(★只在你/CI 构建时做一次 → 打进包;终端用户运行时绝不下载)**:
```bash
# 注:huggingface-cli 已废弃,用 hf(huggingface_hub 自带)。构建机直连 HF 即可(本机实测 huggingface.co 可达)
hf download Systran/faster-whisper-medium --local-dir server/ml_models/faster-whisper-medium
#   若构建机被墙连不上 HF:翻墙下好再拷过来即可(hf-mirror.com 现在是 308 跳回 huggingface.co,未必能当镜像,以实测为准)
# 代码里离线加载(运行时绝不联网,硬要求):
#   WhisperModel("server/ml_models/faster-whisper-medium", device="cpu",
#                compute_type="int8", local_files_only=True)
```
> ⚠️ **关键(连着「国内运行」那节)**:下模型是**构建期一次性**动作。模型打进 DMG/EXE 后,**终端用户运行时是本地离线加载、根本不碰 HF**——所以国内用户没外网也能用。`local_files_only=True` 是硬要求,防它运行时偷偷连 HF 把整条链路拖死。

### 体积说明(owner 拍板:体积非约束)
- **owner 决定:体积大无所谓,运行得好优先。** 模型按**质量**选(默认 medium,可上 large-v3),不为省体积牺牲质量。
- 参考净增:medium ≈ +1.5GB / large-v3 ≈ +3GB,加 ffprobe(几十 MB) + python 库(约一两百 MB)。**装机包大几个 G 可接受。**
- 真正要盯的不是体积,是**本地 CPU 转录耗时**(见下「待办/风险」)——这才是影响"运行得好"的实际约束。

## 封装内置(★分发给终端用户 · 零配置 · 必读)

> **owner 拍板**:产品要打包发给台球房老板用,**上面这些东西全部内置进安装包**——用户装完开箱即用、**不联网、不 pip install、不下模型**。这是咱"全本地+全内置"产品形态的硬要求,不是装在开发机就行。

**要内置进包的四样**:
1. **Python 后端 + 库**(faster_whisper / ctranslate2 / scenedetect / opencv / av) → PyInstaller 打进去。
2. **ffmpeg 二进制** → 用 `imageio_ffmpeg` 自带的那个(在 `.venv/.../imageio_ffmpeg/binaries/`,PyInstaller 会跟着收),或 ffmpeg-static。
3. **ffprobe 二进制** → `ffprobe-static`(electron 侧已装,`desktop/node_modules/ffprobe-static/bin/<plat>/<arch>/ffprobe`),后端经 env 路径调到。
4. **whisper 模型权重 1.46G**(`server/ml_models/faster-whisper-medium/`) → 作为 PyInstaller **data 文件**打进包,运行时 `local_files_only=True` 离线加载(绝不让它联网现下)。
5. **字幕字体**(`server/assets/fonts/`,如得意黑 SmileySans OFL) → 打进包。**★坑(已实测)**:ffmpeg-static 和 imageio_ffmpeg 的 ffmpeg **都没带 fontconfig**(只 `--enable-libass`),mac 上靠 CoreText 只认**已安装**的系统字体,**自定义目录里的字体按 FontName 找不到会回退**。系统自带字体(苹方/黑体/宋体)能直接换;但要用打包的自定义字体(得意黑等),**别指望 `fontsdir` 生效**。两条出路:① **把字体嵌进 ASS 字幕文件**(`[Fonts]` 段·UU 编码·libass 原生支持·字体随字幕走、任何用户机都生效、无需安装)——**推荐**;② 或换一个带 fontconfig 的 ffmpeg 构建。当前代码 `subtitle_font` 参数可换字体,系统字体即时生效,自定义字体待按①补 ASS 嵌入。

**PyInstaller 打包要点(C 扩展 + 大模型有坑,别踩)**:
- ctranslate2 / av / opencv 带 C 扩展和动态库 → `.spec` 里 `--collect-all ctranslate2`、`--collect-dynamic-libs`(av/cv2),漏了打包后 import 崩。
- whisper 模型用 `--add-data "server/ml_models/faster-whisper-medium:models/faster-whisper-medium"` 打进去;运行时路径用 `sys._MEIPASS` 解析(dev 用相对路径)。
- **`av` 和 `opencv` 都带 `libavdevice`** → 重复动态库(本地已见 objc 警告,运行时无害但打包冗余/可能冲突):评估 faster-whisper 是否真需要 `av`,不需要就 exclude 掉省事。
- ctranslate2 各平台 wheel 不同 → **必须在对应平台构建**(Win 包在 Win 上打,Mac 在 Mac 上打)。

**二进制路径解析(`ffbin.py` 要同时认 dev 和打包后)**:
- dev:`imageio_ffmpeg.get_ffmpeg_exe()` + `ffprobe-static` 路径;
- packaged:解析到 app 资源目录(`sys._MEIPASS` 下 / electron `process.resourcesPath`);
- **统一走 env `FFMPEG_BIN`/`FFPROBE_BIN`**:electron 启动后端时注入正确的打包路径,后端只读 env,dev/打包同一套代码。

**模型不进 git,CI 构建时拉取再打包**:
- `server/ml_models/` 已 gitignore(1.46G 不进库);
- CI 流程:`hf download`(走 hf-mirror) → PyInstaller `--add-data` 模型 → electron-builder 出 dmg/nsis;
- 现有 `desktop-build-win.yml`(Win)要加这步;Mac 侧同理补一条。

**跨平台**:ffmpeg/ffprobe(imageio_ffmpeg / ffprobe-static 都多平台,选对 arch)、ctranslate2 wheel、whisper 模型(跨平台通用,一份即可)。

**包体预估**:净增几个 G(模型 1.46G + ctranslate2/opencv 几百 M + 二进制几十 M)——owner 已拍板**体积无所谓、运行得好优先**,大几个 G 可接受。

## 国内运行(★终端用户在国内网络能不能跑 · 必读)

> **核心结论**:能跑——前提是把"需要外网的事"全压到**构建期**,**运行期只剩"国内可达的 LLM 调用"**,其余全本地。

**分清两个时刻**:
- **构建期(你/CI 的机器)**:下 whisper 模型、装 pip/npm 包——可翻墙/直连 HF,下完打进包。**终端用户不经历这步。**
- **运行期(台球房老板的机器·国内·无外网)**:只跑打进包的本地组件 + 必要的国内 API。

**运行期逐组件过(国内能不能通)**:

| 组件 | 运行期要不要网 | 国内能不能跑 |
|---|---|---|
| whisper 转录 | ❌ 不要(本地 + 离线加载) | ✅ 纯本地 |
| 场景检测 / ffmpeg / ffprobe | ❌ 不要(本地二进制) | ✅ 纯本地 |
| LLM 挑高光(选片决策) | ✅ 要(调文字模型) | ⚠️ **必须走国内可达端点**(MiMo / 网关),不碰 OpenAI 等被墙外网 |
| 图生视频(另一条线) | ✅ 要 | ✅ 走百炼(阿里·国内) |

**"国内能跑"的两条硬要求**:
1. **所有本地组件打进包 + 离线加载**(whisper `local_files_only=True`、ffmpeg/ffprobe 走包内二进制)→ 运行期零外网。即上面「封装内置」。
2. **运行期唯一的联网点(挑高光的 LLM)走国内可达的模型/网关**——项目已有 `gateway/app.py`(国内 CN 机)+ MiMo 国内端点,沿用即可,**别让这步直连任何被墙外网模型**。

**必须验证 / 别假设**:
- **别假设 HF 在国内通**:本机这次能连 huggingface.co 可能因开发者有代理;**终端用户大概率连不上** → 模型必须 bundle,绝不让 app 运行时去 HF 下。
- **确认挑高光的文字模型是国内端点**(MiMo/网关),不是被墙外网模型。
- **真机验(上线前必过)**:拿一台**纯国内网络(无代理)**的机器装打包版、断开外网,跑一条剪辑,确认全程不卡在某个外网请求上。

**EDL 契约(`edl.py`,中央数据结构,抄 video-use 的 EDL 格式)**:
```python
from pydantic import BaseModel

class EdlRange(BaseModel):
    source: str          # 源文件 key
    start: float         # 卡词边界(铁律6)
    end: float
    beat: str = ""       # HOOK/PROBLEM/SOLUTION... 镜头作用
    quote: str = ""
    reason: str = ""     # LLM 为什么选这段

class EdlOverlay(BaseModel):
    file: str
    start_in_output: float
    duration: float

class Edl(BaseModel):
    version: int = 1
    sources: dict[str, str]          # {"C0103": "/abs/path.mp4"}
    ranges: list[EdlRange]
    grade: str | None = None         # 预设名 / 原始ffmpeg滤镜 / "auto" / None
    overlays: list[EdlOverlay] = []
    subtitles: str | None = None     # master.srt 路径,最后烧
    total_duration_s: float | None = None
```

**`render.py` — 直接抄 video-use 的 `helpers/render.py`,改这几处**(原文见 https://raw.githubusercontent.com/browser-use/video-use/main/helpers/render.py):

2. 渲染顺序严格保留(铁律 2/3/13/14):逐段抽取(grade+30ms淡入淡出+HDR tonemap+竖屏按高缩放)→无损concat→overlay(PTS shift)→字幕最后烧→loudnorm;
3. 字幕 `SUB_FORCE_STYLE` 的 `MarginV=90`(铁律16)保留;
4. 暴露 `render_edl(edl: Edl, out_path: str, preview: bool=False, build_subtitles: bool=False) -> str`。

## 待办 / 风险 / 待验清单

- **whisper 模型预下载/打包**:打包(PyInstaller)要把 medium/large-v3 权重预置进包或首用引导,否则装机版离线跑不起来。(体积非约束,owner 已拍板,大几 G 可接受)**[需验]**
- **本地 CPU 转录耗时(已实测·M2 够快)**:实测 medium/int8 在 **M2** 上转 14.86s 片用 **6.0s(=2.5x 实时,比实时还快)**,模型离线加载 2.6s。**M2 这类机器性能没问题**,转录不是瓶颈。剩余未知 = **弱机(终端用户的旧 Windows 本)**:可能掉到 ~1x 或更慢,短片仍可接受但要在弱机上真验一条;large-v3 更准更慢,按机器权衡。**[弱机需验]**
- **★素材"没人说话"的片子(空镜/摆拍)要走另一条剪法**:实测成都那段 4K 几乎无语音(只识别出 4 个杂词)——它是摆拍/B-roll,没口播。**转录驱动的挑高光对这种片子没料**,得退到「场景检测 + 视觉 + 卡音乐点」来剪。所以编排要**分两路**:① 有口播 → audio-first 按说话内容选片(video-use 那套);② 空镜/摆拍 → scene-first 蒙太奇(按镜头切+节奏排)。助教素材是「说话类」+「摆拍类」混合,**两路都要支持**(阶段3 的提示词要带这个判断)。**[设计·影响阶段2/3]**
- **ffprobe 方案二选一**:npm `ffprobe-static`(desktop 侧暴露路径给后端) vs 纯 Python 探规格。阶段0 定一个。**[决策]**
- **auto-editor 要不要装**:去静音也可纯用 whisper 词间隙实现,先不装 auto-editor 看够不够。**[决策]**
- **横竖屏重构图(auto-reframe)不在本期**:本期只做竖屏源直接剪;横转竖跟随主体开源弱,留后续。**[范围外]**
- **卡点配乐/版权音乐留后续**:本期字幕+基础配乐,beat 卡点不做。**[范围外]**
- **生成视频是另一条线**:本 spec 只做剪真实素材;图生视频(通义万相/PixVerse/Vidu 换型)见记忆 `video-model-selection-real-person`,不在本文。
