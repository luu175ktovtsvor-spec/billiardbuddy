## 🔴 头号发现(致命·挡打包):bundled 三层能力打包后静默蒸发

**现象(铁证)**:把编译好的出货二进制**从 repo 外目录跑**(模拟打包后 cwd=userData),结果:
- 命令数 = **0**(从 repo 里跑有 commit/model/help 等)
- 技能数 = **0**(/commit /debug /review /security-review /verify 等 10 个 bundled 技能全没)
- 子代理同理 = **0** → agent_task 工具静默不注册

**根因**:`defaultAgentsRoot / defaultCommandsRoot / bundledSkillsRoot` 三个函数全靠两类路径定位 bundled `.md`:
1. `import.meta.dir` —— 编译二进制里是虚拟 `/$bunfs`,里面没有 .md(.md 是运行时 readdir 读的、不是静态 import,`bun --compile` 不嵌入);
2. `process.cwd()` —— 打包后 electron 把 sidecar cwd 锚到 userData,不是 repo。

两条都失效,且:build-sidecar 不嵌入 .md、electron-builder 不发这些目录、没有 `process.resourcesPath` 兜底、没有 env 覆盖。代码注释里写着"cc 把内置 agent/技能编进二进制"——**但这个嵌入从没为编译二进制做过**(只给 vanilla 前端做了 embeddedFrontend)。

**后果**:子代理、bundled 技能(/commit 等)、bundled 斜杠命令三层能力,**开发里完美、过 1644 测试,打包后凭空消失**。app 不崩(优雅空列表),但功能没了——最坏的门面:看着是地基,运行时定位断了。

**修复方向(本轮做,纯后端+打包配置,不碰前端)**:按**二进制自身位置**(`process.execPath`)定位随包资源 + electron-builder 把三个 bundled 目录发到 `Resources/bundled/` 下(与 `Resources/binaries/<sidecar>` 同级)+ 三个 root 函数加 execPath 相对候选。验收 = 重编译后从 repo 外跑,命令/技能/子代理数恢复非零。
