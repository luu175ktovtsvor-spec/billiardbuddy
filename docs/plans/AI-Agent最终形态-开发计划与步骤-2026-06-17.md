## P0+ · 地基补丁（建议立即做，1-2 天）

### 目标
让对话管家 Agent 一次性复用全部 63 个精修 prompt 模板，覆盖度从 ~30%（9 工具）跳到接近 96 卡——**几乎零迁移、不碰合规/配额底线**。这是性价比碾压一切其它增项的一步。

### 范围与步骤
1. 给 `write_operation_content` 工具加**可选 `prompt_key` 入参**（`server/services/agent/tools.py:75-83` 附近）。
2. 透传到 `generate_workbench` 的 `if prompt_key` 分支（`server/services/content_service.py:649`）——该分支已存在，工具此前没传，才退化成 free_intent 通用模板。
3. 从 `web/src/lib/role-workbench-config.ts` **自动生成一份「场景名→prompt_key」清单**，喂给 Agent 大脑（作为工具 description 或单独的技能目录），让模型按用户意图选对 key。
4. `make_platform_content`/`make_groupbuy_content` 保持内联校准 prompt 不动（它们是对外成品、不必塞回 YAML）。

### 关键改动文件
`server/services/agent/tools.py`、`server/services/content_service.py`、（生成清单脚本）`web/src/lib/role-workbench-config.ts`。

### 验收
- 北极星 eval（`server/evals/`）跑 Agent 路径，验证带 `prompt_key` 时质量对齐卡片路径（GREEN 率不回退）。
- 真实 DeepSeek 冒烟：对话里说「帮我写个周末抢一大战的群公告」，Agent 选对 `prompt_key`、产出质量≈卡片。

### 依赖
P0 已完成（ReAct 循环、function calling、工具注册表都在）。无新依赖。

## P1 · 对话管家 MVP + 大脑（原计划 + 两项新增）

### 目标
老板能在对话里说「帮我搞定这周末活动」，Agent 规划并连续调用文案/海报/群公告/约客等工具，交付整套；过程可见。

### 范围与步骤
1. **（原）对话管家前端页**：`/dashboard/chat` 与 `workbench/[cardId]` 加「过程展示」面板（思考 + 工具调用 timeline + 多步进度）。前端 `web/src/lib/api.ts` 的 `_consumeSSEStream` 按事件类型路由（thinking/tool_call_start/tool_result/step/approval_request/done）。
2. ★ **Agent 会话落库 + conversation_id**：用现成 `Conversation`/`ConversationMessage` 表（`agent.py:14` 的 TODO），微信 WebView 刷新不丢历史——移动端刚需。
3. ★ **混合模型路由**：高风险铁律场景（充值方案/活动策划/客户定价）路由 `deepseek-v4-pro`，日常低风险（朋友圈/约客/玩法）走 `v4-flash`。`config.py` 的 `orchestration_*` 已预留模型分离。
4. **（原）大脑稳定性实测**：用真实运营任务做小样本 A/B，实测 DeepSeek 规划稳定性；不达标一键切 GLM-4.6。

### 关键改动文件
`web/src/lib/api.ts`、`web/src/app/dashboard/chat/page.tsx`、`server/api/v1/agent.py`、`server/services/agent/loop.py`、`server/config.py`、`server/services/ai/factory.py`。

### 验收
- Playwright 真实点通核心路径（说一句话→看到思考/工具/进度→交付整套）。
- 刷新页面历史不丢。
- 混合路由实测：`cp_001`「赠送仅限台费」在路由 pro 后守住率 50%→100%（探针 6 次）。
- 大脑规划稳定性有实测结论（继续 DeepSeek 还是切 GLM）。

### 依赖
P0+。

## P1.5 ★ · 体验地基（移动/桌面 + 一线日活 + BYOK + handoff）

> 本阶段是「让产品真正被用起来」的一批低风险高确定性改动，多数纯前端/轻后端，可与 P1 并行推进。

### 1.5a　门店画像「客群/业态标签」（补全新客群/新业态的钥匙）
- **范围**：`server/models/store.py` 的 `operation_profile` 加**业态标签**（普通店/24h 无人自助店）+ **客群标签**。客群标签按《台球行业真实运营逻辑 PPT》真实四类客户（散客/竞技/助教/追分）为根，叠加**门店主打客群**维度（女性友好/青少年亲子培训）——**删掉原误加的"团建/企业"**（企业订包厢本质=个人娱乐，不是独立客群）。门店设置前端加选择（用 CardSelect）。生成时注入 prompt，让现有 96 卡管道吐「无人店版/招生版/女生版」差异化内容。无人店标识同时在前端**屏蔽前厅/助教类卡**。
- **改动**：`server/models/store.py`、（迁移）`server/db/migrations/versions/`、`web/src/app/dashboard/store-settings/page.tsx`、`web/src/types/store.ts`、prompt 注入处（`prompt_engine` / `content_service`）。
- **验收**：标了「无人店」的门店，前厅/助教卡隐藏；标了「青少年」的门店，招生类内容自动差异化；北极星 eval 加 2-3 个新客群场景，GREEN 不回退。
- **反过度设计守则**：优先用标签驱动差异化，只对真正缺骨架的场景（青少年招生、团建包场）新建少量卡，不为每个客群堆几十张卡。

### 1.5b　一线员工极轻固定入口（破解「只有老板用」；助教=挣钱引擎）
- **范围**：给助教（今日约客话术/朋友圈推广文案/服务 SOP 速查）、前厅（FAQ 一键回复库/排班通知模板/台呢维护提醒）一组**卡片货架轻入口**——一线不学对话、点卡片就行。
- **助教内容的"度"**（贴 `助教业务规则库.md` §5/§6 + 终局蓝图 §〇）：**对内/私域**（一对一邀约话术、客户维护、管理带教）贴真实运营逻辑、可更直接（情绪价值/形象/陪伴/到店可约）；**对外公开发布**（公开抖音/小红书/招聘平台）校准到"有吸引力但不把号搞封/不惹事"。不再"一刀切死守纯专业陪练"。唯一不碰=营销成实际性交易（组织/容留卖淫罪，老板坐牢线）。
- **改动**：`web/src/lib/role-workbench-config.ts`（已有助教/前厅卡，整理出「一线速用」分组）、前端工作台按 `my_role` 默认进对应货架。
- **开放问题（待用户拍板）**：一线是给**独立轻账号**还是继续「管理岗代写」？建议先给只读卡片货架轻入口验证日活，不开独立写权限。
- **验收**：助教/前厅角色登录默认落在自己的速用货架；点卡片零学习出内容。

### 1.5c　PWA + Web Push（桌面感 + 本机运营提醒）
- **范围**：Next.js 加 `manifest` + Service Worker，可「安装到桌面」（成本≈0、随网站更新、无签名）。Web Push **仅系统浏览器/桌面 PWA 场景**启用（该发朋友圈了/周五约台）。**微信内明确告知拿不到推送、引导用浏览器打开**——不承诺「微信里也提醒你」。
- **改动**：`web/` 加 manifest/SW/推送订阅；后端加推送下发端点（VAPID）。
- **验收**：Chrome/Edge 能装到桌面；系统浏览器收到一条本机提醒；微信内有「用浏览器打开开通提醒」引导。
- ⚠️ 推送定位收敛为「本机/桌面提醒为主、微信内合规补充」（微信内强价值节点走服务号一次性订阅，见 P4）。

### 1.5d　BYOK 前端配置页（商业模式跑通的临门一脚）
- **范围**：后端已实现（Fernet 加密 + 按门店路由 + 全生成路径 + API）。前端做 **CC Switch 式厂商卡片网格**：选厂商**自动填 base_url、老板只填 API Key**；内置 DeepSeek/Kimi/通义/智谱 GLM/豆包/MiMo/MiniMax/硅基流动；配好 key「获取模型列表」拉 `/v1/models` 变下拉（防拼错 model 名）；测试连接显示延迟 ms；key 密码框 + 眼睛显隐；常见坑（base_url 是 `/v1` vs `/anthropic`、豆包超时、MiniMax 不能传 temperature=0）预填进预设。AI 配置从「可选」升为「必要设置」，没配则锁 AI 功能、引导去配。
- **改动**：`web/src/app/dashboard/store-settings/`（新增 AI 配置页）、新手引导加「配 key」步骤。
- **验收**：非技术老板能选厂商、填 key、拉模型列表、测速、保存并跑通一次生成。
- 详见 `docs/product-brain/BYOK-门店自带模型-实现.md` + 战略文档第五节。

### 1.5e　handoff 发布清单 + 配图打包 + 复制校验（把「最后那一下」做顺）
- **范围**：备好内容后给老板一张**发布清单**：「去哪发→粘哪里→配几张图→话题标签→发完打钩」。复制文案时把 `make_poster` 产出的图打包成「内容包」，微信内走「长按保存图」引导。复制必校验真实结果（`lib/wechat.ts` 已有基础），失败降级长按/execCommand。
- **改动**：`web/src/lib/wechat.ts`、对外内容展示组件、`make_platform_content`/`make_groupbuy_content` 结果渲染。
- **验收**：微信 WebView 内复制校验通过/失败有降级；内容+配图一起给；老板照清单能把内容发出去。

### 1.5f　店脑「越用越懂」显性化
- **范围**：`/dashboard/store-brain` 页展示「AI 已学 N 条经营习惯 / 识别到高峰时段 / 主力客群」；生成时标注「已套用你上次的 XX」。把迁移壁垒可视化。
- **改动**：`web/src/app/dashboard/store-brain/`、`server/services/memory_service.py`（暴露统计）。
- **验收**：店脑页能看到已学条数与识别标签；生成结果有「已套用」标注。

### 1.5g　向导式输入推广
- **范围**：把「说一句话填日报」范式扩到活动/周报/促销——几个选项 + 1 个自由框，AI 扩写。
- **改动**：复用日报的自然语言抽取范式（`reports` extract），扩到更多场景前端表单。
- **验收**：活动/促销场景能「选几项+说一句」→ AI 扩写成完整内容。

### P1.5 验收门
前端 tsc 干净 + `bash scripts/test.sh` 全绿；Playwright 过一遍移动端核心路径；北极星 eval 不回退。

## P2 · 记忆与技能 + 内容补全

### 目标
记忆按需召回、记得「上次给你出过什么」；补齐行业标配（智能客服/问数据）与高确定性内容缺口（新客群/赛事/差评/分层）。

### 范围与步骤
1. **（原·最高）pgvector 语义召回**：`store_memories` 加 `embedding` 列 + HNSW 索引，注入前召回 top-k（8~12 条）而非全量。新增 `EmbeddingProvider`（DeepSeek 无 embedding 接口——走 OpenAI `text-embedding-3-small` 或自托管中文 embedding，**编排前定来源**）。可借鉴 OpenClaw 记忆工程参数（分块 ~400 token、近期常驻、旧记忆语义召回），但放云端 DB + 人在环可看可改。
2. **（原）情景记忆**：复用 `generations`/`usage_events` 加 embedding，记「哪天给这家店出过什么/效果如何」。
3. **（原）对话滚动总结**：最近 5 轮之上把更早对话压成摘要。
4. **（原）审批闸完善**：审批态走 DB（跨 worker）；proposal 模式（已部分落地）。
5. **（原）Skill 规范化**：knowledge YAML 加 `summary:`/`triggers:` + LLM 语义兜底（修关键词漏选）。
6. ★ **智能客服 FAQ 话术库**：台球房常见问题（营业时间/团购怎么用/助教怎么约/能否拼台）一键回复内容——**只做「内容+复制」，不碰自动接管应答**（避微信红线）。给前厅高频日活入口。
7. ★ **对话式问数据/诊断**：把日报+诊断做成对话问答（「这周比上周咋样」「淡季哪天最差」）——**只读 POS 数字写判断**，不碰收银。
8. ★ **赛事全流程 + 衔接官方大赛**：看球活动卡内置台球官方赛事（世运会 Heyball/中式八球超级赛/大师赛）主题 + 「门店赛季制衔接官方赛事」内容角度。
9. ★ **客户分层维护决策卡**：基于已有 ABCD 分级 + 6 类标签 SOP，产出「给客户打标签 + 分层维护节奏」建议（不存个人身份信息）。
10. ★ **差评/投诉回应话术卡**（自带查漏补充）：差评危机公关/客诉安抚话术，纯内容层。
11. ★ **真实客群内容补全**（取代 v1 误加的"团建/企业包场"）：
    - **博弈客群运营**（竞技/追分）：竞技客户（小赌怡情爱好者，球技交流为主）+ 追分客户（气氛热烈·赌钱）的**氛围营造 + 客户维护话术 + 会员赛/约局组织**——基准 §1.6 真实客群，球房"必须有"。**对内运营内容贴真实**；守"控金额/守底线"，**不生成赌场抽水组局放贷这类经营/组织级内容**（开设赌场罪，老板坐牢线）。
    - **助教层"度"校准**（见 1.5b）：把助教推广/邀约/维护的"内部贴真实、对外校准"落进 prompt 与转译词库（`助教业务规则库.md` §5/§6 思路，对内/私域放宽）。
    - **青少年/亲子招生卡组**：暑期招生/家长话术「放下手机练专注力」/考级体验（中式八球青少年报名翻倍）。
    - **女性友好内容**：用 1.5a 客群标签驱动差异化（环境+服务卖点，基准 §1.1 女性看重环境与服务）。
    - 优先用 1.5a 客群标签驱动，只对缺骨架的新建少量卡。

### 关键改动文件
`server/models/`（store_memories embedding 迁移）、`server/services/memory_service.py`、`server/services/ai/`（EmbeddingProvider）、`server/prompts/knowledge/*.yaml`（summary/triggers + 新增内容）、`server/prompts/operation/*.yaml`（新场景）、`web/src/lib/role-workbench-config.ts`（新增少量卡）。

### 验收
- 记忆召回相关性 + token 成本下降有数据；审批闸拦住所有 side-effecting 动作。
- 北极星 eval 加入新客群/赛事/差评/客服场景，GREEN 率 ≥85% 才允许合并。
- FAQ/问数据真实跑通，且守住「只备内容不自动应答」「只读不控收银」边界。

### 依赖
P1/P1.5；EmbeddingProvider 来源先定。

## P3 · 对外动作深化 + 轻管理工具（全部经审批闸）

### 目标
把「AI 备内容 → 人去发」的 handoff 做到操盘级；补店长真实日常的轻管理工具。**真发需平台资质/原生壳的部分只引导、不替发**。

### 范围与步骤
1. ★ **平台团购操盘深度**：在 `make_groupbuy_content` 之上补「选品策略（引流款 9.9-19.9/时 + 高毛利附加）+ 探店达人对接话术 + 短视频脚本矩阵 + 团购客转私域复购 SOP」——加盟商 69.9% 最想要的营销推广策略。
2. ★ **排班/对账/采购/设备维护轻工具**：排班通知模板、耗材采购清单、月度对账复盘话术、设备/台呢维护提醒、消防自查/夜班交接清单（自带查漏补充）。**数字归 POS，只做模板/话术/提醒**，不做库存/排班/安防系统。

## P4 · 主动出击（被动工具 → 主动助理）

### 目标
在对的时机主动推对的动作给老板/店长——北极星标准「④对的时机推对的动作」唯一未达标项的落地。

### 范围与步骤
1. **（原）排程引擎**：定时任务（沿用现有 cron 模式或轻调度）。
2. **（原）门店状态监测**：基于行为信号/今日推荐规则（淡季信号/节日临近/日报未写/本周流量低）。
3. **（原·关键）合规推送通道**：
   - **主渠道** = PWA/桌面本机通知 + 站内今日推荐升级（P1.5c 已铺）。
   - **微信内强价值节点**（到期/重要）= 服务号**一次性订阅消息**（每次推送需用户先点授权、同 scene 不累积、需认证服务号 ¥300/年 + 备案域名）——只用于强价值节点，不堆日常提醒。
   - **短信**（关键提醒）= 唯一无平台资质捆绑的主动通道，但有签名报备/按条计费门槛（⚠️ 本条**未官方查证**，落地前核实）。
4. ★ **客户分层维护提醒**：「某客户 7 天没来→提醒约台话术」——客户分级知识库已有，只做提醒+话术，不做 CRM 系统，数据从日报/POS 只读取。
5. ★ **预生成**：如「明天会员日，已备好 3 版文案」，到点主动呈现。

### 关键改动文件
新增调度模块、`server/services/dashboard_service.py`（监测规则）、`server/services/behavior_service.py`、推送下发端点。

### 验收
- 能在合适时机主动推一条有用提醒，且推送通道合规（微信内不做日常主动群发）。
- 客户沉默提醒真实触发，且只读不控、不碰个人微信。

### 依赖
P1.5c（PWA 推送载体）、P2（店脑/行为信号）。

## 可选 Track ★ · 一键发布（小豆芽式 RPA，用户 2026-06-17 已决定可做）

> v1 原把此项列"永久红线·坚决不做"，**v2 据用户决定撤销红线、改为可选能力**——决策只看 ROI/维护成本/责任归属，不看"灰不灰产"。本 Track 与主线 P0-P4 解耦，可在 P3 之后按需启动。

### 目标
在「AI 备好平台定制内容」之上，给愿意用的门店提供「**单店自有号 + 半自动 + 人确认**」的一键发布——人扫码登录自己的号 → AI 备内容 → 人点确认 → 到点模拟发布到抖音/小红书等。

### 范围与步骤（建议默认范围）
1. **平台优先级**：先抖音 + 小红书（台球房最重要两个内容平台）；快手/视频号次之。
2. **技术路径**：Playwright/patchright 浏览器自动化 + 指纹/多开浏览器 + 扫码/Cookie 登录 + 定时调度（与小豆芽同款底层）。跑在**服务端带图形界面的浏览器**或门店本地。
3. **强制半自动 + 走审批闸**：内容生成→`approval_request`→人确认→才发；不做静默全自动。复用现有 proposal 模式审批闸。
4. **限定单店自有号**：人扫码登录门店**自己的**账号；**不做"替很多门店批量矩阵代发"**（矩阵号批量=高危靶心 + 支持负担大）。

### 风险梯度（写清，便于你做范围决策）
- 单店自有号·原创·低频·半自动 → 灰产但相对低危（但平台改版/风控升级随时可能挂，需持续维护）。
- 矩阵号批量同质 → 高危（小红书 2024 一月清退 125 万号即此类[二手]）→ **不做**。
- 个人微信自动群发/一键转发 → 最高危（腾讯打击最狠、永久封号[官方]）→ **单列、需你单独拍板**，默认暂缓。

### 责任归属护栏
号是门店的、封了会怪我们 → **半自动 + 人确认**让"出事有人背锅"，且与审批闸一致；上线前给门店**明确风险告知**（自有号自担风险）。

### 验收
- 单店扫码登录→备内容→人确认→真实发布到抖音/小红书各走通一次；全程有审批闸；无静默自动发。
- 维护成本评估：平台改版导致脚本失效的检测与告警机制。
