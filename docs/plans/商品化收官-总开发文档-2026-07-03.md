## 1. 方向定论（产品最终形态）

**一句话定位（对内对外都用它）**：豆包是「会聊天的百科」，我们是**「住在你电脑里、看得到你家生意、能直接把活干完、越用越懂你这家店的店员」**。

这不是口号，是三根被业界验证过的柱子（Shopify Sidekick / Square AI / 美团商家 AI / MIT NANDA 调研三方互证）：

1. **连着这家店的真实数据**——报表、门店画像、历史作品、店脑记忆。豆包永远没有。
2. **就地把活干完**——不是给一段话让老板复制粘贴，是直接改好文件、出好图、出好视频、发起任务。ChatGPT 桌面版连本机文件都碰不了（它的 agent 在云端虚拟机）——**本机执行是我们的领先项，不是补课项**。
3. **越用越懂这家店**——MIT 对几千家企业的调研点名：AI 工具被弃用的分水岭不是智能，是「记不记得我、学不学我的反馈」。店脑记忆方向正确，要让记忆在对话里主动露脸。

**「简约大气」的操作性定义**（Codex/Claude/Dia/Warp 等 14 款产品共性）：不是功能少，是**控件按需出现**——默认界面只剩输入框和内容，其余用到才浮现；模型不选、插件成目录、技能全自动、过程一行大白话可展开。

**两条一票否决**（从商家真实吐槽反推，蓝鲸调研）：
- 内容生成千篇一律 = 立刻被归为鸡肋。文案/回评必须带进店名、具体活动、顾客细节，宁可多问一句不出通稿。
- 执行必须「预览 + 确认 + 后台跑完叫你」。审批闸方向已对，别退回「直接改」或「只会说不会做」两个极端。

**壳子体检总判**（2026-07-03，对照当前 main 代码亲读）：主循环/压缩/跨轮历史/店脑/缓存**没有一个机制是设计错的**，官方「产品必备五件套」（循环+权限、压缩、记忆、技能、子代理）全有且在「好/够用」档。owner 曾疑虑的两点已澄清：压缩阈值已是 `max(窗口−48k, 0.7窗口)`≈952k（比 Claude Code 更能撑，不用改）；跨轮历史已是完整轨迹 JSONL 整段回放（不是「只回放 5 轮」）。真缺口只有「没做完」的几件事，都编进批次 F。

## 批次 B · Windows 观感与图标（四个根子一次修完）

**目标**：Windows 版观感对齐微软 Copilot 官方规范档次；图标任务栏不糊不白板；Mac 不回退。
**根子诊断**（全部有官方来源，2026-07-03 调研）：① 无中文字体栈→落微软雅黑且雅黑无中间字重（UI 层级全塌）；② Electron 33 没吃到 Chromium 132 的文字发灰官方修复；③ Windows 是原生默认标题栏；④ electron-builder 拿 icon.png 自动转出**单帧 256 ico**（源码实锤 app-builder icon-converter.go 只编码一帧），任务栏小图标硬缩必糊。

### B1 🟠 内置中文字体（工作量：中）
- 选型：**HarmonyOS Sans SC**（授权白纸黑字允许 embed/bundle/redistribute，B 站客户端先例）或 MiSans（字重最全但要署名）。打**官方原始 TTF 别子集化**（两家都禁改编），带 Regular/Medium/Bold 三字重 ≈24MB（owner 拍板体积无所谓）。安装包带协议文件 + 「关于」页署名一句（硬性要求）。
- 落点：TTF 进 `web/public/fonts/`；`globals.css` 加三条 `@font-face`；`web/tailwind.config.ts` 加 `fontFamily.sans` 栈：
  `-apple-system, BlinkMacSystemFont, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Segoe UI", Arial, sans-serif`
  （Mac 上前两项先命中保原生观感；Windows 命中内置字体）。
- 字重纪律（抄微软官方规范）：全 app 只用 400/600 两档，禁 700 禁斜体；字号 4-5 档（正文 14/20、小字 12/16 下限、区块标题 20/28、页标题 28/36）。
- ⚠️ 验收硬条件：在一台 **1080p/100% 缩放**的低价 Windows 真机上肉眼对比内置字体 vs 雅黑的小字清晰度（Firefox/Chromium 官方都有过「无 hinting 新字体低分屏更糊」的回退先例），过了才定稿。

3. **发人之前平台侧设硬上限**（已提进 owner 行动项⓪）：网关配额是软闸，模型平台后台的消费上限才是「key 被扒也赔不了大钱」的硬兜底。
