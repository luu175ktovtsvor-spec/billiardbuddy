> **给新窗口：** 本项目当前在推进的事 = 把"球房 AI 运营助手"接入**微信小程序**。本文是**权威计划**。
> 铁律：① 代码在 `feat/miniprogram` 分支做，**`main` = 美国生产，勿动**；② 外部规则（微信/备案/OpenAI）**先爬证再做、别凭记忆**；③ 备案域名**长期指向大陆服务器、绝不能迁走**（迁走会掉备案 → 小程序挂）。
> 详细约束见 memory「小程序接入约束」；本文 = 架构 + 代码管理 + 任务拆解 + 现状。

更新：2026-06-15。

## 1. 目标
把现有 web 应用接入微信小程序，**前端正常显示、后端正常用**。先 web-view 复用现有 web+后端（快、稳、改动小），通了再评估原生重写。

## 2. 已核实的硬约束（2026-06，爬微信/阿里云官方 + 阿里云售后印证）
- **ICP 备案**：通过**阿里云(接入商)**办，微信只校验。**美国服务器无法备案**（海外节点，阿里云不受理海外服务器备案）。
- **web-view**：仅**企业认证**小程序可用（个人主体不行）；加载的**业务域名须 ICP 备案 + HTTPS**。
- **wx.request 服务器域名**：国内主体**须备案** + HTTPS + 不能用 IP/端口。
- ⚠️ **备案后把域名迁去美国/换接入商 → 会掉备案**（管局/接入商核查注销）→ 小程序前后端全挂。**所以备案的那个（子）域名必须长期解析到大陆服务器。**
- **一个域名可拆子域名**（A/CNAME）指向多台服务器；备案只需验证一台大陆服务器，备案后可自由配多台。→ **不用新买域名**，现有 `zzyppz.cn` 拆子域名即可。

## 3. 选定架构（大陆备案网关 → 美国后端，保 OpenAI 直连）

```
微信小程序 (web-view)
      │  打 备案子域名 (HTTPS)
      ▼
大陆服务器 39.106.214.21（北京·Nginx 网关）
   · serve 前端页面（业务域名，备案）
   · /api 反向代理 ──────────────►  美国服务器 47.77.237.250
                                      · FastAPI 后端
                                      · OpenAI gpt-image-2 直连(~80ms)
                                      · DeepSeek
```
- **域名**：`zzyppz.cn` 拆子域名——一个**备案子域名(指大陆)**给小程序用（业务域名 + request 域名都用它）；大陆网关把 /api 反代到美国后端。美国后端**继续直连 OpenAI**（不挂代理）。
- **为什么这样**：备案合规（备案域名常驻大陆）+ OpenAI 直连这套费劲调通的不动。代价=大陆→美国一跳跨境延迟（生图本就慢，可接受）。
- **前端怎么 serve（Phase 1 再定）**：大陆 2核2G 内存吃紧、不适合在上面跑 `next build`。倾向：构建产物在别处生成后同步到大陆、大陆只 serve + 反代；或大陆 Nginx 直接反代前端到美国（页面首屏跨境略慢，webview 会缓存）。Phase 1 实测取舍。

## 5. 代码版本管理（重要，新窗口照此办）
- **单仓库(monorepo)**，**不另起新仓库、不复制桌面文件夹**。
- 分支：`main`=美国生产(勿动) / `dev`=日常 web / **`feat/miniprogram`=小程序+大陆网关的所有工作**（从 dev 拉，已建）。
- 新增目录（只加不动现有主体）：`miniprogram/`(小程序壳)、`deploy/mainland/`(Nginx 反代配置 + 部署脚本)。
- 共享主体少动：`server/`(顶多加 CORS)、`web/`(顶多加"在小程序 webview 里"的小适配)。
- 流程：在 `feat/miniprogram` 上做 → 本地/大陆联调验证 → 合 `dev` → 合 `main` 上线。黄了直接删分支，**生产不受影响**。
- 想同时开两个文件夹：用 `git worktree`（同仓库、不复制）。

### ⚠️ 版本与服务器隔离铁律（防止第二版本"串掉"美国生产）
1. **分支隔离**：`main` = 美国生产的唯一来源（`deploy_us.sh` 只 `git pull origin main` 部署到美国）。小程序的活全在 `feat/miniprogram`，**未完成绝不合进 `main`**——一合就会随下次部署上到美国生产。
2. **服务器隔离**：美国机 `47.77.237.250` 只跑 `main`；大陆机 `39.106.214.21` 只跑小程序网关（独立部署，配置在 `deploy/mainland/`）。**两台机的部署脚本不许交叉**——别在大陆机跑 `deploy_us.sh`，别用美国那套去碰大陆。
3. **唯一共享点 = 美国后端**：小程序经大陆网关反代到美国后端，所以若需后端配合（如给大陆网关域名加 CORS），这类**后端改动会进 `main` → 上美国生产**。原则：只做**最小、向后兼容**的共享改动（如 CORS 多允许一个域名），走常规测试+部署，**别夹带小程序专属逻辑**。
4. **部署后两台分别冒烟自检**（`systemctl active` 会骗人，必须实测真实 API/静态）。
5. **新窗口铁律**：要做小程序 → `git checkout feat/miniprogram`；**绝不**因"顺手"把 `feat/miniprogram` 合进 `main` 或部署到美国机。

## 6. 任务拆解（分阶段）
**Phase 0 —— 你(用户)来，长周期·卡脖子（只有你能办）**
1. 大陆 ECS **续费**到剩余 ≥3 个月（否则备案服务号办不了）。
2. 阿里云提交 **ICP 备案**（域名/子域名绑大陆服务器；3–22 工作日）。
3. **小程序企业认证**（¥300/年，web-view 必须）。
4. 域名解析拆子域名（备案子域名 → 大陆 39.106.214.21）。
→ 细化步骤见 `docs/miniprogram/备案与认证清单.md`（待写）。

**Phase 1 —— 我(AI)来，不等备案即可先做**
1. 大陆服务器装 Nginx + 写反代配置（serve 前端 + /api→美国），放 `deploy/mainland/`。
2. web-view 小程序壳工程（一个 web-view 指向备案前端域名），放 `miniprogram/`。
3. web 端小适配（检测在 webview 里、相应隐藏/调整）。

**Phase 2 —— 备案过后**
填小程序后台「业务域名 / 服务器域名」=备案子域名 → 联调 → 上线。

**Phase B —— 可选，以后定**
原生 / Taro 重写（届时 `miniprogram/` 变成原生工程，调同一后端）。
