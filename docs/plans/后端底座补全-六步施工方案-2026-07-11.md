1. **规格来源分两类,绝不混**:
   - **内核(A 线)= 全参照 cc-haha 源码**(`~/Desktop/cc-haha-ref/src`)。cc 有什么样就做成什么样,不自造概念、不留"我们特有的状态"(例如不存在"具名子代理休眠"这种事——cc 自带子代理常驻可用,我们照做,现网 `ts/src/agents/bundled/` 已有 explore/general-purpose/plan 三个)。

2. **文档不当规格**:CLAUDE.md/总览/迁移矩阵是开发导航,可能过时说错(本轮已抓到一例:总览说"具名子代理休眠",实际代码已激活)。本方案每一条都**先到真代码核实过现状**才写;实施时每条再**打开 cc 对应源码确认行为**后动手,不凭文档记忆写码。
3. **干法**:主窗口直接干、不派子代理;每步改完跑全量 `bun test` + `bun run typecheck`,绿了才进下一步;复杂逻辑先写行为对齐测试再实现(ts/CLAUDE.md 铁律 1)。

## 第 1 步 · 堵两个产品层安全洞(规格 = owner 铁律,非 cc)

### 1a. 通用安全红线无条件注入
- **现状(已核实)**:`ts/src/harness/systemPrompt.ts` 的 `buildSystemPrompt` 里没有任何红线章节;红线只存在于台球包 `SAFETY_FLOORS`,不挂包 = 裸奔。违反 CLAUDE.md 铁律 #1"安全红线永远注入"。
- **改法**:`harness/prompts.ts` 新增红线常量(五条:不营销实际性交易 / 不帮开赌场坐庄抽水 / 未成年保护 / 法律文书提示专业把关 / 不照搬绝对化广告词),`buildSystemPrompt` 无条件拼入(位置放 `BASE_IDENTITY` 之后)。台球包 `SAFETY_FLOORS` 保留(领域细化版,与通用版并存不冲突)。
- **验收**:测试断言挂包/不挂包两种装配下系统提示都含红线;白标守卫测试不回归。

### 1b. 审批防伪密钥不再默认空串
- **现状(已核实)**:`ts/src/permissions/approval.ts:11` `process.env.SECRET_KEY ?? ''` ——没设 env 时用空串当 HMAC 密钥,审批 token 可被伪造。
- **改法**:没设 `SECRET_KEY` 时,进程启动后首次取密钥时用 `crypto.randomBytes(32)` 生成一次、模块级缓存。sidecar 重启后旧 token 自然失效→审批卡重新弹一次(安全的失败方向,不落盘、不新增密钥文件)。
- **验收**:未设 env 时密钥非空;签名/验证往返通过;错 token / 空 token / 长度不符全拒。

## 第 3 步 · hooks 27 事件 + 命令/技能统一契约(规格 = cc 源码)

### 3a. hooks 事件补全
- **规格(已亲读)**:cc `src/entrypoints/sdk/coreTypes.ts:25-53` `HOOK_EVENTS` 共 27 个。
- **现状(已核实)**:`ts/src/hooks/hooks.ts` 只 13 个;缺的 14 个(PermissionRequest / PermissionDenied / Setup / TeammateIdle / TaskCreated / TaskCompleted / Elicitation / ElicitationResult / ConfigChange / WorktreeCreate / WorktreeRemove / InstructionsLoaded / CwdChanged / FileChanged)配置了也被静默吞。
- **改法**:①事件名全集进类型与白名单,配置可声明、不再静默吞;②按 cc 的派发点逐个接线:PermissionRequest/PermissionDenied 进权限闸,TaskCreated/TaskCompleted 进任务服务,Elicitation 对进 MCP elicitation,WorktreeCreate/Remove 进 worktree 工具,其余(Setup/CwdChanged/FileChanged 等)照 cc 派发位置搬;我们运行时真没有对应物的,登记清楚"可声明、暂无派发点",不装死。
- **验收**:每个新接事件一条派发断言;未知事件名报警不吞。

### 3b. 命令/技能动态注入 + 统一执行契约
- **规格(已核实存在)**:cc `src/skills/loadSkillsDir.ts:375` `executeShellCommandsInPrompt`(命令正文内嵌 `` !`…` `` 现场执行回填,MCP 来源禁执行)+ `${CLAUDE_SKILL_DIR}`/`${CLAUDE_SESSION_ID}` 变量替换;cc 用单一 Skill 工具统一承担发现+执行(`SkillTool.ts`)。
- **现状(已核实)**:我们两个 loader(`commands/commandLoader.ts`、`skills/skillLoader.ts`)的 getPrompt 都无内嵌 shell、无变量替换;命令走 read_command 是"只读展开",不落 allowedTools/hooks/fork,与技能待遇不对称。
- **改法**:①照抄 `executeShellCommandsInPrompt` + 变量替换接进两处 getPrompt(保留 MCP 来源禁执行门,我们 loadedFrom 需补 'mcp' 标记);②命令补执行语义(复用 executeSkill 的 allowSkillTools/registerSkillHooks/fork 管线),消除"用户敲 /命令落权限、模型调不落权限"的不一致。
- **验收**:行为对齐测试含 `` !`…` ``、嵌套引号、MCP 来源跳过;命令/技能同一输入同一权限判定。
