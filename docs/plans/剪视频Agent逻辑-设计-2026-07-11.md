# 剪视频 Agent 逻辑 · 设计(用户对话里要求剪视频,Agent 怎么剪)

> 📌 owner 问:用户在对话窗口要求剪视频,Agent 应该如何去剪?两条线(运行设置好的程序 vs 让 Agent 循环)选哪条?owner 说"这个问题你比较专业,认真思考"。⚠️ owner 有个 GitHub 剪视频仓库(给 Claude Code/codex 用的)要装成 Skill,细节等 repo;本文先定架构骨架,repo 到了往里填。

## 一、结论:B 线引擎 + A 线粗粒度编排(和生图同构)

**剪视频 = B 线确定性引擎(帧级活儿)+ A 线 Agent 只做"意图→计划"的粗粒度编排。** 完全对齐生图的模式(Agent 调 generate_image/edit_image,媒体管线干活),也对齐 owner 的"两条线"铁律。

**为什么不是纯 A 线让 Agent 循环剪**:帧级剪辑(切镜头/卡点/字幕/转场/渲染)是确定性像素/时间轴操作,塞进模型 ReAct 循环既慢又不可控(模型不该逐帧算)。这活儿归 B 线引擎(我们已有:`videoEditProjects` 时间轴唯一真相源 + 10 种原子操作 + 事务回滚 + ffmpeg 渲染 + VAD 分流 + B-roll 五步)。

**为什么不是纯 B 线跑死程序**:用户的话是自然语言意图("剪成 30 秒抖音、去掉开头空镜、配点节奏")——需要模型把意图翻成引擎能执行的计划。这层归 A 线。

## 二、Agent 怎么剪(三步,对话里)

```
① 用户对话:"把我拍的这段球房视频剪成 30 秒抖音,去掉开头空镜,配点节奏感"
② Agent(A 线)判断这是剪视频意图 → 调粗粒度工具 edit_video/plan_video:
   - 入参 = 高层意图 + 素材引用(用户导入的视频路径/上传 id)+ 目标(时长/比例/风格)
   - 不传帧级参数(那是引擎的事)
③ 工具内部(B 线引擎)干活:
   - 探测素材(时长/音轨/场景)→ auto_plan 生成时间轴草稿(切镜头/卡点/字幕)→ ffmpeg 渲染出草稿
   - 返回:草稿视频 + 时间轴摘要(让 Agent 能向用户复述"我这么剪的")
④ Agent 向用户汇报草稿 + 关键决策;用户要调 → 进可视化看板微调(⚠️看板属"基于此调整",owner 暂挂等 Codex 逆向)
```

**Agent 的职责边界**:翻译意图 → 调引擎 → 复述草稿决策 → 接住用户反馈再调引擎。**不逐帧剪**。

## 三、Skill 集成(owner 的 GitHub 剪视频仓库)

owner 收藏的剪视频仓库(给 Claude Code/codex 用)装成 Skill 的正确姿势(照"插件军规"):
- **仓库若是"一套 ffmpeg 操作脚本/CLI"** → 装成 **Skill**(SKILL.md 教 Agent 何时用 + 怎么调),Agent 在对话里 use_skill 加载,skill 正文用内嵌 shell(我刚做的 `!\`…\``)驱动那套脚本。这条路子最轻,直接复用主 Agent 的 coding 能力跑仓库的程序。
- **仓库若是"一个更好的剪辑引擎"** → 作为 B 线引擎的替代/增强,包成 `edit_video` 工具(粗粒度意图入口),内部调它。
- 两种都遵守:①本体确定性(引擎/脚本)②Agent 只给粗粒度意图入口 ③人握方向盘(草稿→看板微调)④资产(ffmpeg/依赖)走静默下载 ⑤登记审批类别(出片=本地文件,不算对外,直接做)。
- **等 repo 链接**:owner 给了仓库地址后,我读它判是"脚本 vs 引擎",按上面对应姿势装。
