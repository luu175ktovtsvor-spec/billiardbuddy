# 生图与人像优化——流程、质量标准与风险边界

> 📌 状态:✅现行 · 最后核对 2026-07-09

本文档回应阶段目标 `docs/plans/强-coding-agent-桌面外壳-阶段目标.md` §13(生图与人像优化)与 §17.9(生图/人像优化要有明确流程、质量标准和风险边界)。它是**设计规格文档**,不是实现记录:给出可据以后续实现的流程、质量验收清单与风险边界,并明确标注哪些环节卡在 owner 决策。**本文只写文档,不改代码。**

---

## 一、结论先行(大白话)

1. **这是插件式延伸能力,不是产品主壳。** 本项目第一性目标是强 coding agent 桌面外壳(§1),生图/人像优化只是通用 Agent 工作台上可挂载的一项能力,不能反客为主。
2. **现状已有一条能跑的「文本→图 / 参考图→图」链路,但没有针对「人像优化」这个场景做专门的质检和风险闸。** 现有代码:agent 工具 `make_poster` / `generate_image`(`ts/src/media/mediaTools.ts`)→ 后台任务 `startStudioGenerate` / `startStudioEdit`(`ts/src/media/mediaJobs.ts`)→ 模型路由 `routeImageModel`(Seedream/豆包 vs gpt-image-2 双通道)→ 落盘作品库。改图链路 `startStudioEdit` 只在 HTTP 路由 `/api/v1/studio/edit`(`ts/src/server/index.ts`)暴露,**没有作为 agent 工具暴露**。
3. **本文档把 §13 的重点(输入图质检、肖像授权、人物一致性、真实感、手脸肢体错误、过度美化、商业可用、失败兜底、批量并发、成本控制、结果质检、对比预览、版本/重生成/回滚)拆成:端到端流程(第二节)+ 可验收质量标准(第三节)+ 硬性风险边界(第四节)+ 模型路由策略(第五节)。**
4. **最大差距:输入图质检、肖像授权确认闸、人像结果质检(手脸肢体/过度美化/一致性)、生图的花钱审批闸、新前端(ts-desktop)的对比预览/版本回滚 —— 现状代码里基本没有,需要补(见第六节现状差距表)。**
5. **卡 owner 的关键三项:①模型选型 + key + 各平台消费上限;②是否上「人像质检模型」(人脸/手部/肢体缺陷检测、过度美化判定、人物一致性比对都要视觉/CV 模型,选型+成本 owner 拍板);③海外出口通道(gpt-image-2 大陆调不了,需国外中转)。见第七节。**

## 二、核心场景与端到端流程

### 2.1 目标场景(§13)

用户上传一张门店助教照片(可能光线差、构图差、表情不理想),系统帮他生成更适合门店宣传的人像 / 形象照 / 商业宣传图。**输入是真人照片,输出用于商业投放** —— 这决定了它比普通生海报多两道闸:肖像授权、真人结果质检。

### 2.2 端到端流程图(设计目标)

```
[1 导入]           用户上传/指定本机照片(拖入或选文件)
   │                产出:trusted 本机路径(进 _trusted_image_paths 白名单)
   ▼
[2 输入图质检]     判定:分辨率/清晰度/是否单人主体/光线/遮挡/是否真人
   │  ├─ 不合格 → 明确告诉用户"哪不行、要不要换一张",不硬生成
   │  └─ 合格   → 继续
   ▼
[3 肖像授权确认]   硬闸:真人照片必须用户确认"我拥有这张照片的使用授权、被拍者同意用于宣传"
   │  └─ 未确认 → 停,不进模型
   ▼
[4 模型路由]       按能力路由:人像重塑走高保真通道(gpt-image-2),
   │                中文文字/贴文案走 Seedream/豆包;海外通道不可用则降级+提示
   ▼
[5 生成]           后台任务链路(startStudioGenerate/startStudioEdit),
   │                批量≤4张、并发受任务系统约束、失败自动兜底重试
   ▼
[6 结果质检]       判定:手/脸/肢体无明显错误、人物与原图一致、真实感、
   │                无过度美化、分辨率/构图达标、无违规文字/水印
   │  ├─ 命中风险 → 标风险提示,建议重生成或人工确认后再用
   │  └─ 通过     → 进对比预览
   ▼
[7 对比预览]       原图 vs 生成图并排;标注质检结论与风险提示
   ▼
[8 版本选择/重生成/回滚]  用户选定/要求重生成/回退到上一版;所有版本可追溯
```

### 2.3 每步输入输出与判定点

| 步 | 输入 | 输出 | 判定点 / 现状锚点 |
|---|---|---|---|
| 1 导入 | 本机图片路径 / data URI / `/uploads/*` | 受信路径集合 | 现状:`resolveLocalImagePath` 只放行 `/uploads/*` 或 `_trusted_image_paths` 白名单内绝对路径;`collectImageReferences` 最多 14 张参考图。**已有沙箱护栏** |
| 2 输入图质检 | 原始照片字节 | 合格/不合格 + 原因 | 现状:仅有 `imageDimensions`(读宽高)和印刷二维码源图质检 `inspectPrintQrAsset`,**没有针对人像的分辨率/清晰度/主体/光线质检**。差距,需补 |
| 3 肖像授权 | 用户确认动作 | 授权布尔 + 时间戳 | 现状:**代码中无任何 consent/授权字段**。差距,需补硬闸 |
| 4 模型路由 | prompt + body(image_model/ratio/mode/poster_text) | 选定 provider+model+route reason | 现状:`routeImageModel` 已实现完整规则(见第五节),`COMPLEX_CREATIVE_KEYWORDS` 含「写实人像/电影感人像/肖像重塑」→ 走 gpt-image-2。**已有** |
| 5 生成 | 归一化 body | 落盘图 + generation_id | 现状:`startStudioGenerate`/`startStudioEdit` → 后端代理 `/api/v1/studio/{generate,edit}` 或本地 `directOrLocalImageFallback`;`clampCount` 限 1-4;`submitSeedreamImageJsonWithRetry` 对 429/5xx 重试;`seedreamFallbackAfterOpenAiFailure` OpenAI 失败自动切 Seedream。**已有生成+兜底** |
| 6 结果质检 | 生成图 | 质检结论 + 风险标记 | 现状:仅 `inspectHardTextRequirement` 出 `text_quality_status: pending_ocr`(硬文字待人工核对,**OCR 本身未实现**)。**没有手脸肢体/过度美化/一致性质检**。差距 |
| 7 对比预览 | 原图 + 生成图 | 前端并排视图 | 现状:老 `web/src/app/dashboard/studio/page.tsx` 有 studio 页(退役线);新 `ts/desktop/renderer` 是最小壳,**无对比预览**。差距 |
| 8 版本/重生成/回滚 | 用户选择 | 选定版本 / 新任务 / 回退 | 现状:每次生成有独立 `generation_id` 且落盘可回查(`posterUploadForGenerationId`),但**无前端版本管理/回滚交互**。差距 |

## 三、质量标准(可验收清单)

下面每条尽量给出「怎么判」。判据分三档:**A=可自动检测**(纯代码/尺寸/哈希)、**B=可半自动**(需视觉/CV 模型给分,人工兜底)、**C=需人工确认**(闸放在用户侧)。

### 3.1 输入图质检(生成前)

| 项 | 标准 | 判据档 | 备注 |
|---|---|---|---|
| 分辨率 | 主体清晰,短边建议 ≥ 768px(印刷用途更高) | A | 复用 `imageDimensions` 已能读宽高 |
| 单人主体 | 优化人像时应能识别到清晰的单一人脸主体 | B | 需人脸检测模型 |
| 清晰度/模糊 | 非严重失焦/运动模糊 | B | 拉普拉斯方差等,或视觉模型打分 |
| 光线 | 非严重欠曝/过曝/大逆光 | B | 直方图统计(A 可粗判)+ 视觉模型 |
| 遮挡 | 脸部关键区域无严重遮挡 | B | 人脸关键点 |
| 真人判定 | 输入应为真人照片(卡通/AI 图另作说明) | B/C | 关系到风险边界第四节 |
| 不合格处理 | 不硬生成,用大白话说清「哪不行、建议怎么办」 | A | 对齐 §9「失败时有可理解原因和下一步」 |

### 3.2 生成结果质检(生成后)

| 项 | 标准 | 判据档 | 备注 |
|---|---|---|---|
| 真实感 | 不塑料感、不 AI 味失真;皮肤/材质自然 | B | 视觉模型评审 |
| 人物一致性 | 生成人物与原图为「同一个人」,五官/脸型/肤色不漂移 | B | 需人脸相似度(embedding 比对),阈值待定 |
| 手部无错 | 无多指/少指/畸形手 | B | 人像高发缺陷,单列 |
| 脸部无错 | 无双瞳/歪脸/不对称错乱/牙齿糊 | B | |
| 肢体无错 | 无多肢/断肢/关节反向 | B | |
| 不过度美化 | 保留可辨识度,不磨成「换了个人」;瘦脸/磨皮有度 | B/C | 与「人物一致性」互为约束;超阈值给风险提示 |
| 分辨率/构图 | 输出尺寸符合所选比例,主体构图达投放标准 | A | `imageSizeForProvider` 已按 provider 规整尺寸 |
| 无违规叠加 | 未经用户显式要求,不出现中文文字/价格/Logo/二维码 | A | 对齐 CLAUDE.md 铁律(见第四节) |
| 硬文字核对 | 若用户显式要文字,投放前提示人工核对 | A(提示)/C(核对) | 现状 `text_quality_status: pending_ocr` 已出提示,OCR 未落地 |
| 无水印 | 商业投放默认关水印 | A | Seedream 通道 `watermark` 现状默认 false |

### 3.3 商业可用性门(投放前总闸)

必须同时满足才标「可商用」:授权已确认(3.3.C)+ 结果质检无未处理的高风险项 + 无未经授权的违规叠加。任一不满足 → 标「需人工确认」,不标可商用。

> ⚠️ 实现说明:3.1/3.2 里 B 档全部依赖「人像质检模型」,现状代码没有。是否上、上哪个、成本上限 = **owner 决策**(第七节)。在模型到位前,B 档判据降级为「生成时把风险清单原样提示给用户,由用户人工把关」——即用 C 档兜底,绝不假装已自动质检通过。

## 四、风险边界与合规(硬规则)

把 §13 合规口径与 `CLAUDE.md`/`ts/CLAUDE.md` 安全红线落成不可协商的硬规则。**这些不因用户偏好、不因「听着能提高转化」而松动。**

### 4.1 肖像与身份(§13 合规口径)

- **R1 授权前置(硬闸)**:对真人照片做优化/重塑,生成前必须让用户显式确认「拥有该照片使用授权、被拍者同意用于门店宣传」。未确认不进模型。
- **R2 不做未授权身份冒充**:不生成「让 A 变成特定真实人物 B」「冒充某名人/某真人」的结果。
- **R3 不把换脸/深度伪造当卖点**:产品文案、工具描述、前端引导里不出现「换脸/深伪/AI 换头」作为能力卖点。功能定位是「把用户自己的、已授权的照片优化得更适合宣传」,不是身份替换。
- **R4 真人结果风险提示 + 质检门**:真人相关生成结果一律带风险提示,并经第三节结果质检;质检没过不标「可直接商用」。
- **R5 未成年保护**:对齐 `_SAFETY_REDLINE`——涉及未成年人的人像生成/优化直接拒绝。

### 4.2 生图内容红线(对齐 CLAUDE.md 铁律)

- **R6 不主动塞元素**:生图 prompt 不主动塞中文文字 / 价格 / Logo / 二维码,**除非用户显式填**(CLAUDE.md 关键约束 §7 + 台球挂载铁律)。现状 `make_poster`/`generate_image` 工具描述已写明「不要默认把上传图当 Logo」,印刷叠加(logo/二维码)仅在 `print_mode===true` 且用户显式给路径时触发。
- **R7 不营销实际性交易、未成年保护、不照搬绝对化广告词**:`_SAFETY_REDLINE` 永远注入,与挂不挂台球包无关。生图文案/画面同受约束。
- **R8 白标不暴露底层模型**(`ts/CLAUDE.md` 铁律 7):对用户不暴露 gpt-image-2 / Seedream / 豆包等底层模型名与 provider;错误信息里模型/密钥要脱敏(现状 `sanitizeMediaError` 已抹掉 `Bearer`/`api_key`)。

### 4.3 安全与成本红线(对齐第 2/6 节权限体系)

- **R9 花钱动作走审批闸**:生图属 `spend`(成本)类动作(CLAUDE.md 核心架构原则 §5)。**现状差距:`make_poster`/`generate_image` 工具未设 `requiresApproval`/`approvalClass:'spend'`**(`ts/src/media/mediaTools.ts` 里两个工具只有 `isReadOnly:false`)。权限框架本身已支持 `ApprovalClass = 'file'|'spend'|'outreach'|'destructive'`(`ts/src/permissions/types.ts`),只是没接上。补齐时应把生图归 `spend`,让高成本/批量动作进审批。
- **R10 内置 key 设消费上限**:内置 owner 的模型 key 必须在各平台后台设消费上限防盗刷(CLAUDE.md 铁律 2 + §13)。这是 owner 侧配置,代码侧现只有 `clampCount`(单次≤4)作量的兜底。
- **R11 本机文件护栏**:参考图/底图只读受信路径(`resolveLocalImagePath` 沙箱),不越界扫用户磁盘;落盘只写 `uploads/posters` 等既定目录。**已有**。
- **R12 不做 AI 生成视频**:本能力不延伸到任何「让图片动起来 / 图生视频」——该整条链路已按 §11 删除,不复活、不建议。

### 4.4 失败兜底边界

- **R13 不假装成功**:后端/通道不可用时给占位预览必须标 `local_preview:true` 并明说「这是占位、不是模型生成图」(现状 `localImageFallback` 已如此)。质检模型缺位时,结果质检结论必须如实标「未自动质检、请人工把关」,不得默认通过。

## 五、模型路由策略(前端统一对话框,后端按能力路由)

对齐 §13「模型策略暂不写死」:前端是一个统一对话框,后端按**能力**路由到不同模型;**不把纯文本模型当图片理解入口**。

### 5.1 能力分层(不写死具体模型)

| 能力 | 路由目标 | 现状锚点 |
|---|---|---|
| 图片**理解**(读输入图、质检、一致性比对) | 视觉/多模态模型(**待选型**,owner) | 现状无独立图片理解入口。差距 |
| coding agent(主循环) | 文本主模型(provider 体系,与生图分开) | 已有 `createModelFromRuntimeProviders` |
| 图像**生成** | 生图模型(高保真人像 / 中文文案两类) | `routeImageModel` 已实现 |
| 图像**改图/局部重绘** | 生图模型 edit 通道 | `startStudioEdit` → `/images/edits` |
| 剪辑编排 | 另有链路(真实素材剪辑,不在本文范围) | `videoEditProjects` |

### 5.2 现状生图路由规则(`routeImageModel`,`ts/src/media/mediaJobs.ts`)

按优先级(先命中先定):

1. `explicit_model` —— 用户/上游显式给 `image_model` → 用它。
2. `explicit_provider_seedream` / `explicit_provider_openai` —— 显式 `image_provider`。
3. 改图模式(`_image_mode==='edit'` 或有 `source_generation_id`):文字修复类关键词 → Seedream(`edit_text_fix_seedream`),否则内容改写 → OpenAI(`edit_content_openai`)。
4. `hard_text_seedream` —— 有硬性中文文字需求(`poster_text` 或 prompt 含「写上/写着…」)→ Seedream(中文排版更稳)。
5. `complex_creative_openai` —— prompt 含 `COMPLEX_CREATIVE_KEYWORDS`(**写实人像/高保真/photorealistic/电影感人像/肖像重塑** 等)→ gpt-image-2(高保真人像)。
6. `western_dominant_openai` —— 英文为主 → gpt-image-2。
7. `default_seedream` —— 默认走 Seedream/豆包。
8. `seedream_only_ratio` —— 比例 `2:5`/`5:2` 强制 Seedream。

默认模型名:Seedream = `doubao-seedream-4-5-251128`,OpenAI = `gpt-image-2`(可被 env `IMAGE_MODEL_NAME`/`SEEDREAM_IMAGE_MODEL_NAME`/`OPENAI_IMAGE_MODEL_NAME` 覆盖)。

> **人像优化落点**:门店助教「写实人像/形象照」正好命中规则 5 → 高保真通道(gpt-image-2)。这也正是海外出口约束最强的一条(见 5.3)。

### 5.3 provider 适配与国内/海外出口约束

- **Seedream/豆包通道**(`seedreamImageConfig`):走国内网关 `QF_GATEWAY_URL` + `QF_GATEWAY_TOKEN`(或 `ARK_API_KEY`),端点 `/ark/images/generations`,`provider:'seedream-gateway'`。国内直连,无出口问题。
- **OpenAI 兼容通道**(`openAiImageConfig`):`OPENAI_BASE_URL`(或 `QF_GATEWAY_URL`)+ `OPENAI_API_KEY`,端点 `/images/generations`(生成)/`/images/edits`(带底图改图)。**gpt-image-2 大陆调不了**(CLAUDE.md),需国外出口/中转(如已有的美国 relay `zzyppz.cn`,测试专用路由 `/relay/openai-test/`)。
- **降级**:OpenAI 通道失败且非显式指定时,`seedreamFallbackAfterOpenAiFailure` 自动切 Seedream 并给脱敏 warning。海外出口不可用时,人像高保真需求应降级到国内模型 + 明确提示「本轮用国内模型,写实度可能略降」,不能静默失败。
- **BYOK 校验**:`validateImageModelPayload` + `imageProviderGuess`(`ts/src/server/index.ts`)能对用户自填的生图 base_url/model 做「供应商-模型名是否对得上」的宽松校验。

## 七、卡 owner 的决策项

| # | 决策项 | 缺什么 | 影响什么 |
|---|---|---|---|
| O1 | **生图模型选型 + key + 消费上限** | 定用哪些生图模型(国内 Seedream/豆包 + 海外 gpt-image-2 的确切型号)、提供内置 key 与各平台 base_url、并在各平台后台设消费上限 | 没 key 整条链路只能出占位图(`local_preview`);没消费上限 = 内置 key 被盗刷风险(R10) |
| O2 | **是否上「人像质检模型」** | 第三节 B 档判据(人脸/手部/肢体缺陷检测、过度美化判定、人物一致性 embedding 比对、真实感评审)全依赖视觉/CV 模型;要不要上、上哪个、跑本地还是云端、成本上限 | 决定结果质检是「自动+人工」还是「纯人工兜底」。不上则质检降级为把风险清单提示给用户人工把关(R13),不能声称已自动质检通过 |
| O3 | **海外出口通道** | gpt-image-2 大陆调不了,需要稳定的国外中转(现有 `zzyppz.cn` relay 是测试专用,生产化/带宽/稳定性/成本要 owner 定) | 决定「写实人像高保真」这条最强路由能否在国内用户机上真正跑通;不通则人像需求只能降级到国内模型 |
| O4 | **图片理解入口模型** | 输入图质检、一致性比对需要一个多模态「看图」模型(与文本主模型、生图模型可不同) | 无它则输入图质检(第 3.1 节 B 档)与结果一致性判定无法自动化 |

> 说明:O1/O3/O4 本质都是「模型+key+出口+预算」,是 owner 的商业与合规决策,不是内核实现能自行拍板的。本文档的流程与质量标准在这些决策落地前即可先实现「结构与闸」(授权闸、输入/结果质检的挂点、风险提示、对比预览、版本回滚),质检的「自动判分」部分待 O2/O4 到位后填充。
