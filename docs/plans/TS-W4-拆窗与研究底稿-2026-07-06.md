## 1. W4b · 定向脚手架(plan / todo / system-reminder / steering)

**Goal:** 让 agent 会「先规划后动手(plan)」「用清单跟进度(todo)」「每轮吃到系统提醒(reminder)」「跑一半能被插话纠偏(steering)」。

**红线/关键(照 Python 语义,借 cc-haha 结构):**
- **plan 模式两层**:① 权限判定(W4a 已做:plan 档非只读→跳过);② **W4b 补**:enter/exit 工具、plan 文件是唯一可写路径(cc-haha `isSessionPlanFile`:`normalize` 后 `startsWith(plansDir/slug) && endsWith('.md')`)、plan 指令作 system-reminder 注入。我们 Python 更简(纯按 `read_only` 判,无 plan 文件专属)——**W4b 至少做到 Python 级;plan 文件专属可写是 cc-haha 加成、可选**。
- **todo**:数据结构照 **Python `{task, status}`**(status ∈ `pending|in_progress|done`,`done` 非 cc-haha 的 `completed`;无 `activeForm`),渲染 `☐/◐/☑`。两条更新路:`todo_write` 工具 + 内联 `task_progress` 参数(Cline Focus-Chain,任何工具调用可带 markdown 清单,`_pop_task_progress` 剥离)。每次更新吐 `todo_update` 事件。

## 2. W4c · 上下文韧性(压缩 / 轨迹 JSONL / 打转)

**Goal:** 长对话不撑爆(压缩)、跨轮不失忆(完整轨迹回放)、不原地打转(两层检测)。

**红线/关键:**
- **压缩三级** `snip → microcompact → autocompact`(照 Python;cc-haha 更深多 `contextCollapse`,不必抄):
  - **触发** `threshold = max(window − 48k, window·0.7)`;度量 `effective = max(字符估算, last_prompt_tokens)`;**`window` 为 `undefined` ⇒ 关闭 autocompact**;连续失败 3 次熔断。
  - **microcompact**:把旧只读工具结果的 content 换占位、留最后 4 条,**原地改、不重建前缀**(prompt-cache)。
  - **autocompact**:`system` 前缀永不摘要;末 `keep=12` 逐字留;切点不落在 tool-call/result 配对中间;旧段 ≥6 条才摘要;重建 = `前缀 + [此前对话摘要]summary + 保留段`,**全循环唯一允许重建前缀的点**。摘要调用 = 同主模型、`max_tokens=1024`、**thinking 关**(MiMo 否则吃光额度)、成功后 `last_prompt_tokens=0`+`just_autocompacted=true`(吐一次 `context_note` 大白话)。**可选升级**:采 cc-haha 的 9 段结构化摘要 prompt(尤其"§6 all user messages" + "§9 next step 逐字")替我们的一段式,保真更高。
  - **反应式溢出兜底(红线)**:`context_overflow.py` 纯分类 `looksLikeContextOverflow(err)`(结构码 `context_length_exceeded` + 关键词表);provider 400 命中 → 强制一次 autocompact(无视阈值)+ 重试一次。估算会漏掉保留窗内单条超大 tool_result,这层是必需网。
- **完整轨迹 JSONL(红线 = 跨轮记忆底座)**:每行 = **原始 OpenAI 兼容 message dict、逐字**(去掉开头 system)。路径 `{upload_dir}/transcripts/{cid}.jsonl`,`cid` 须匹配 `^[A-Za-z0-9_-]{1,128}$`(路径穿越护栏)。**整轮覆盖写**(非 append,因返回的 messages 已含输入历史)、原子 tmp+rename、全故障安全。**F-10 竞态修**:turn 开始记 baseline 行数,turn 结束把 baseline 之后被外部(媒体任务 mid-turn append)追加的尾巴重新接上(`captureBaselineLen`/`savePreservingExternalTail`)。回放 = 读行→`Message[]`→喂进 initMessages 的 history,无变换,坏行跳过。
- **打转两层(cc-haha 两者都无,我们从 Gemini CLI + OpenHands 移植)**:
  - **层1 硬拦**(executeTool 内):完全相同 `tool|args` **连续** 5 次(`MAX_SAME_CALL`,任何不同调用重置)→ 拒执行、回灌"别重复了"。
  - **层2 软推**(`stuck_detector`,纯函数,扫末 20 条、只看最后一条真人 user 之后):4 模式 `action_observation=4 / action_error=3 / monologue=3 / alternating=6`。命中 = 软推(不 abort)、每 episode 一次、吐 `context_note`(非 steering,免渲成用户气泡)。
  - **新增(腾讯 4/40 里的"40")**:`stuck_detector` 只看重复模式、看不见"40 个**不同**调用都在空转"。**加一个 per-task `toolCallsTotal` 累计计数,越过 ~40 未收敛 → 注入同款软推(或升级 force-final)**。("4"已被 action_observation=4 + 硬拦=5 覆盖,不必再加。)

**建议 TS 形状:** `ts/src/context/compaction.ts`(常量 48k/0.7/12/6/3/4;`shouldCompress`/`splitForAutocompact`/`microcompact`/`autocompact`(返重建或 null)/`compactPipeline`/`looksLikeContextOverflow`/`forceRecompact`)· `ts/src/memory/transcript.ts`(`class Transcript`:`path/save/append/load/captureBaselineLen/savePreservingExternalTail`,record=原始 `Message`)· `ts/src/harness/stuckDetector.ts`(`detectStuck(messages)` 纯函数 + 常量 + `MAX_TOTAL_TOOL_CALLS_NO_PROGRESS=40`)。循环每轮**顶部** `messages = await compactPipeline(...)`、`model.step` 包 try 接溢出兜底、batch 后 `maybeFlagStuck`、收敛处 `finalMessages=trajectoryWithFinal(...)`,端点用 `savePreservingExternalTail` 落盘。

**载重 file:line:** 压缩(Py)`loop.py:1719-1744`(pipeline)/`:1663-1716`(auto)/`:1620-1641`(split)/`:1545-1573`(micro)/`:1688-1695`(摘要调用)/常量`:192,232,233,244,250`/触发`:1727-1737`;溢出`context_overflow.py:99-111`+`loop.py:554-561,594,633`;压缩(cc)`services/compact/autoCompact.ts:30-72,160,260-265`+prompt`prompt.ts:61-129`;轨迹`transcript.py`(全)+`context.py:145-167`+`loop.py:514-529,1188,1810,1900`;打转层1`loop.py:1456-1485`+常量`:199`、层2`stuck_detector.py`(全,常量`:36-42`)+反应`loop.py:832-855`+call sites`:1268,1406,1910,2079`。**注入接口(给 W7)**:`getUserContext()→{claudeMd?,currentDate}` memoized(cc `context.ts:155-189`)、`findRelevantMemories(...)`(cc `findRelevantMemories.ts:39`,便宜侧模型选 ≤5)、`transcript.load()`。**任务量:~7–8 任务。**

## 4. W4e · 扩展·钩子与子代理(hooks / goal-hook / subagents)

**Goal:** 事件钩子(观测/拦截/续跑)+ 目标自检 + 子代理(递归嵌套循环)。**接 loop 与 model,建议 W4 最后做。**

**红线/关键:**
- **hooks 两层**:① **进程内注册表**(`hooks.py`,纯回调 list,**全故障安全**——吞异常不崩循环):`PreToolHook(name,args,ctx)→{deny?}`(首个 deny 胜、拦执行)、`PostToolHook`(观测)、`StopHook(messages,ctx)→{continue?}`(首个 continue 胜、逼续跑、`stop_blocked` 每 finalize 一次)、事件钩子(UserPromptSubmit/SessionStart→`{block?,context?}`)。② **配置 shell 钩子**(`hooks_config.py`,读 `.claude/settings.json` 的 Claude Code 格式、`bash -c` + JSON stdin、exit 2 或 `{"decision":"block"}` 拦、`DESKTOP_CONFIG_HOOKS` 门控)——**可整体延后**(env 门控、独立)。cc-haha 有 ~16 事件的大机器,**只跟我们 Python:Pre/Post/Stop + 两事件**。
- **loop 接线(hooks 是块9 唯一进 loop 的)**:`runPre` 在 executeTool 前(deny→回灌 `[已被拦截]`)、`runPost` 在结果 capping 后、`runStop` 在 finalize 前(continue→append user 消息 + continue,once-per-finalize)。**这是 W4e 的载重接线。**
- **goal-hook**:最小子系统(常驻一个 Stop 钩子读 `ctx.goal`,非空→`{continue: 目标自检}`,空则 no-op)。依赖 hooks 的 Stop 机制 + `ctx.goal`。是 hook 系统端到端跑通的活样板。
- **subagents**:`run_subagent`(在 `web_tools.py:592-663`,**不是 background_tools.py**)= **递归进同一循环**。schema:`task`(必)/`focus`/`subagent_type ∈ {general-purpose, explore, plan}`,`read_only=True` 但**永不 `concurrent_safe`**(共享 db session)。构建:按 `billiards_mode` 选 registry → 滤到**只读工具 + todo_write、排除 run_subagent 自身**(防递归)→ **`_SAFETY_REDLINE` 前置进子代理 prompt(载重红线、保留)**→ 新 `AgentContext` 共享 db/store/model、重置每轮态 → `run_agent_loop(..., max_turns=5)` → 结果 `【子代理已完成子任务】\n{final}`。**无** frontmatter 代理文件/worktree/后台/模型覆盖(那些是 cc-haha 加成,以后想加照 `loadAgentsDir.ts` 字段扩)。
