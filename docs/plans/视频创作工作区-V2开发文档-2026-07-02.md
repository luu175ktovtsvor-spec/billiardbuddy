## 1. 一句话 + 定位

**给台球房店主一个"独立的视频创作工作区整页":选本机素材 → AI 自动剪成有包装的竖屏成片(V2 自研模板渲染器)→ 秒级预览 → 用大白话对话让它改文案/重做 → 出片。** 主打「氛围模式」(摆拍/颜值/空镜的卡点集锦),口播模式后续接。

**为什么是"这一版"**:经 4 种渲染方案真机对比(见 §3),`V2 自研模板渲染器`(浏览器渲 HTML 模板)成品感最强、可对话改文案,选定它。

## 2. 效果基线(已真机验证 · 不是设想)

2026-07-02 拿真实球房素材(`~/Desktop/助教素材/球房素材/IMG_*.MP4` 18 条)端到端真跑通,成品在 `~/Desktop/球房-方案对比/`:

1. **重剪(Round 1)**:V2 全流程真出片 —— 13 镜头 / 14.8s / 1080×1920,带分段标题条 + 品牌开场卡 + 青色斜切转场 + 水印 + 卡点程序化 BGM + 响度归一化。豆包导演自动配的文案偏**竞技风**(飒爽击球/精准发力/专注瞄准…)。
2. **对话改文案(Round 2)**:模拟店主一句话「这是美女助教氛围片,别整竞技风」→ LLM 带上下文把 13 条文案整体重写成**氛围颜值风**(浅笑倚球台/慵懒拨发梢/眼眸含星光/心动这一瞬…)→ 只换文案层重渲、素材不动 → 重出一版。

**验证结论**:① V2 渲染流程能出"像能直接发"的成片;② "文案"与"素材/镜头"是解耦两层,所以**一个带上下文的 LLM 能按店主一句话把文案重做**——这就是产品要的"可对话重做"。

## 3. 四方案对比结论(为什么选 V2)

| 方案 | 特征 | 取舍 |
|---|---|---|
| v4 ffmpeg 基线 | 纯硬切、无文字 | 太朴素,≈现有 `render.py`,只当底层 |
| v1 GL 转场 | 炫 shader 转场、无文字 | 只解决转场、没包装 |
| v3 MoviePy 合成 | 简单底部字幕 | 字幕朴素、不够成品感 |
| **v2 自研模板渲染器** | **分段标题条 + 品牌卡 + 转场 + 水印 + 卡点BGM** | **✅ 选定**:成品感最强、文案层可对话重做 |

**V2 = 用网页技术做视频**:HTML/CSS/JS 写模板(`template.html`)→ 浏览器逐帧渲染截图 → ffmpeg 编码。思想同业界 Remotion,但自研精简版(不引 Remotion 框架)。

## 4. 全景架构(数据流)

```
                          ┌──────────── 独立工作区整页(前端)────────────┐
                          │ 预览播放器(客户端秒级) · 时间轴/镜头 · 控制台 │
                          │            └── 内置对话框:改文案/重做 ──┘     │
                          └───────────────┬───────────────┬─────────────┘
                        选素材/参数         │ SSE 进度       │ 大白话指令
                                           ▼               ▼
  素材 ──①理解&挑高光(氛围Planner)──→ ②AI导演排镜+配文案 ──→ ③时间轴文档(真相源)
        PySceneDetect切窗 + VLM打分         豆包 LLM             稳定ID·分轨·caption层独立
                                           │                        │
                          ④对话改文案(LLM带上下文重写caption)◄──────┘
                                           │
                                           ▼
                      ⑤V2 模板渲染器(浏览器逐帧渲 template.html)──→ ⑥ffmpeg编码+BGM+响度 ──→ 成片mp4
```

**三段解耦不变**(沿用现有):① 前端/AI/圈点都只对**时间轴文档**发原子操作;② 渲染器消费文档确定性出片;③ **caption 是文档里独立的一轨**,所以改文案 = 只改 caption 轨 + 重渲染染层,素材/镜头零改动 = 秒级、可反复对话。

### 5.3 ★通用兜底 + 台球加持(内容检测分支)+ 特效/音乐不重样

**架构原则**(镜像整个产品:通用 Agent 默认 + 领域知识可挂载):视频编排**默认通用、识别到台球才加持**。豆包本就在看画面(打分那趟),顺手判"是不是台球+哪类场景",几乎零成本。

- **检测**(`vlm.classify_content`):看几帧代表画面 → `{is_billiards, scene}`;scene ∈ 门店环境/助教展示/人气氛围/口播讲解/通用。失败降级"通用",不崩。
- **台球知识包**(`billiards_video_kb.py`,**提炼自 PPT 原文**,中性无来源名·守两条红线):
  - 内容两型(P79):获客型=产品卖点(口播) / 流量型=擦边(氛围);
  - 氛围展示三型(P90):门店环境B-roll / 助教展示(美女展示) / 人气氛围(场景展示);
  - 助教人设四型(P188):性感/可爱/飒爽/潮酷 —— 文案+风格跟人设走;
  - 每场景给 文案/风格/音乐 三份指引。
- **分支**(`assemble.auto_plan_v2`):`is_billiards` → 把场景的 caption/style/music 指引注入 `caption_shots(domain_ctx)`/`plan_style(domain_ctx)`;否则通用(`domain_ctx=None`,自由发挥)。对话编辑(`edit_agent`)、改文案(`recaption_v2`)都带同一份领域指引,保持一致。
- **特效不重样**:`director.plan_style` 让 LLM **按内容/情绪给每段编排** transition/motion/caption样式/主题色,还能写 `customCss` 随意发挥;`template.html` 是**数据驱动的通用引擎**(不是死模板)。
- **音乐不重样**:`plan_style` 出 `{mood,key}`;台球场景 mood 从场景建议(门店chill/人气hype/助教按人设);**key 再叠一个"内容指纹派生 key"**(`hashlib` 按片段/时长)→ 不同素材必不同调,`bgm.py` 按 key 移调。

**两条业务线(干净分裂,只在出方案分叉,下面文档/预览共享)**:
- **氛围线**(`planners/ambient.py` → V2 模板 `/auto_plan_v2`+`/render_v2`):VLM挑高光→导演配文案+编排特效→浏览器渲花哨成片+BGM。**卡点**:段时长吸附整数拍(`bgm.beat_for_mood`),切点落鼓点。
- **口播线**(`planners/speech.py` → `/auto_plan?mode=speech`+`/render`):whisper转录→按说的话挑讲话段→自动配字幕(说的话)→`render_timeline` **保原声+烧字幕**(不走花哨模板,口播要清楚)。**真机验通**(1.mp4:挑出"月均77万→90万"8段口播+15条字幕+原声)。
- 两线都过内容检测:台球口播/台球氛围各按 KB 处理;非台球自由发挥。前端 mode 切换待补(薄适配)。

## 6. ★核心能力:对话改文案(带上下文的 LLM)

**这是产品差异点,单独拎出来说清。**

- **数据模型**:镜头清单 manifest 里每个 shot 有 `{dir(帧目录), caption}`;文案与素材帧分离。
- **首次出片**:导演 LLM 按镜头内容生成文案(可能不合调性)。
- **对话重做**:店主在工作区对话框说大白话(如「文案改成美女助教风,别用击球/瞄准这些词」)→ `recaption.py` 把【原文案 + 店主指令 + 镜头语境】喂 LLM → LLM 输出新文案数组 → 替换 manifest 的 caption + brand → **只重跑渲染层**(帧目录复用,不重新抽帧/不重新导演)→ 秒级出新版。
- **⚠️"秒级"只在客户端预览,不在最终导出**(实测修正):
  - **预览端秒级**:改文案时,前端预览用 DOM 文字浮层即时刷新,店主立刻看到新文案(这就是 §9"预览走客户端"的意义)。
  - **导出端不秒级**:最终成片要走浏览器逐帧截图渲染,实测 280 帧 ≈ 2 分钟(Playwright 每帧截图 ~0.4s 是瓶颈)。所以"改文案→看效果"秒级,"确认导出成片"要等 1–2 分钟(只在最后点一次)。
  - **Phase 2 优化方向**:① Electron 离屏渲染可能比 Playwright 截图快;② 或把"文字层"从逐帧截图里拆出来、用 ffmpeg drawtext/ASS 合成(改文案只重合成文字层,真秒级),仅动画效果退一档。二选一在 Phase 2 拍。
- **上下文承载**:LLM 每次带着「上一版文案 + 累计的店主偏好」,支持多轮微调(改完还能再改)。正式版把这段对话历史挂进工作区会话,实现"越聊越懂这条片子的调性"。**已实测**:改后帧复用(不重抽),文案确实按指令改对(星杆美学→甜系助教)。

### 6.5 ★通用化 + 特效引擎(大模型随意发挥)· 2026-07-02 重构

**编排层领域无关,适配任意视频**(owner:用户可能剪自己的旅游/美食/宠物/产品视频,不止台球):
- VLM/导演/编辑 提示词**全去台球化、内容驱动**(VLM 识别真实主体 → 文案/风格跟着画面走,不套台球模板)。`subject` 改成开放式("人物特写/美食/风景/宠物/产品…")。

**特效不再是死模板,是大模型驱动的引擎**(owner:特效转场要让大模型"随意发挥"):
- `template.html` 重写成**通用引擎**,读 manifest 里数据:每段 `style`(transition 转场 `fade/wipe/slide/zoom/glitch/flash/none` + motion 镜头运动 + caption 字幕 `pos/anim/color`)+ 全局 `theme.accent` 主题色 + **`customCss`(大模型自己写的 CSS 特效·随意发挥逃生口)**。
- `director.plan_style(shots, mood)`:LLM 按内容/情绪**自己编排整条片的视觉风格**(每段可不同、有节奏)。**已实测**:一句"炫酷快切科技冷调"→ 主题色 #0FC6F1、段2 glitch+居中pop字幕、段3 flash+顶部打字机、还自动写了 customCss。
- `edit_agent` 加风格反馈:`restyle`(整体重编排)/`set_caption_pos`/`set_accent`,所以"转场炫点/字幕放上面/换冷色调"都能对话改。
- **为什么这个方式对**:V2 选浏览器渲染的真正威力就在这——CSS/JS 几乎能做任何视觉效果,大模型能直接生成它;换 ffmpeg 就没这个自由度。

## 8. ★V2 渲染器的打包关键决策(浏览器从哪来)

V2 靠浏览器逐帧渲 HTML。原型用 Playwright 自带 Chromium。**打包分发时怎么办**(全内置铁律:客户装完开箱即用):

- **方案 A(推荐)复用 Electron 自带 Chromium**:桌面壳本就是 Electron(内含 Chromium)。用**隐藏的离屏 `BrowserWindow`** 加载 `template.html`、逐帧 `capturePage()` 截图。**不额外打第二个 Chromium**(省 ~150–300MB、避免两个 Chromium 冲突)。渲染逻辑从 Node 侧(Electron 主进程)驱动。
- **方案 B 打包 playwright-core + 内置 chromium**:实现最像原型、最省改动,但 DMG/EXE 多背一个 Chromium。owner 说过"体积不是约束",可接受,但 A 更干净。
- **决策**:优先 A(离屏 BrowserWindow);A 若遇字体/时序坑难缠,退 B。**这条必须在阶段2真机验打包后拍死**(dev 能跑≠装机包能跑)。

> 其余进包物料(沿用现有铁律,全打进 DMG/EXE):whisper medium 权重(离线)、ffmpeg/ffprobe 二进制、得意黑字体(`server/assets/fonts/SmileySans-Oblique.ttf`)、Python ML 依赖(faster-whisper/scenedetect/opencv/pillow/numpy)。

## 10. 铁律 & 已知坑(实测踩过)

1. **VLM 图片 base64 直传**,别喂外网 URL(智谱 1210)。
2. **whisper 幻觉**:摆拍/音乐片会被 whisper 幻觉出"啊啊啊/by bwd6"并**误报有口播**(实测)。氛围模式**不依赖转录**;但要加"幻觉过滤"(VAD + 词数/置信度阈值),别让误判口播污染字幕。
3. **HDR→SDR tonemap**:手机 HDR 片不转会过曝惨白(`render.py` 已有链)。
4. **竖拍旋转**:手机竖拍常横存+旋转标记,`probe_video` 已转正,别再误判 16:9。
5. **字幕安全区**:MarginV≈90 避开抖音底部 UI(`render.py` 已有)。
6. **响度 -14 LUFS**:社媒标准,出片必做。
7. **VLM 限流降级**:免费档 429 → 退避重试 → 仍失败走启发式,**管线不崩**(`vlm.py`/`ambient.py` 已有)。
8. **打分缓存**:帧打分按 `帧文件` 缓存(`.score.json`),重剪/改文案不重复调 VLM 不重复扣费。
