# 前端文案与交互规范 · 改造清单

> 📌 状态:🚧进行中 · 任务〈前端文案与交互官方化改造〉· 2026-07-02 落稿 · **✅ owner 2026-07-05 已拍板全部决策（见 §6），可开工**

## 0. 一句话目标

把前端从"每个窗口随手写文案"收敛成"一套规范 + 一个声音"，解决 owner 指出的三个观感问题：**不官方、随便、啰嗦**。骨架不动（执行过程折叠/审批卡/终端块这些学 CC 的结构保留），只改"说话方式"和四个交互硬伤。

**本次分析结论（2026-07-02 全量扫描 web/src/components/desktop/ + lib/ + hooks/，约 1000 处中文文案）：**
1. 对话流里混了三种"声音"：真 AI 回答、伪装成 AI 的系统通知（33 处 `pushAssistantMessage`）、原文显示的工程化 prompt 大气泡 —— 啰嗦感主因。
2. 回答底部最多同时出现 10 个带文字按钮 —— 大厂全是 2~4 个纯图标。
3. 文案语体无标准：自称三套混用（管家 22 处 / AI 10 处 / 我）、网络口语（啥/干活/折腾/捣鼓）、时态标点 emoji 随手写 —— 随便感主因。

## 1. 文案规范（改完后所有新文案照此写，验收可判定）

### 1.1 自称与人称（✅ owner 2026-07-05 拍板：对话「我」+ 说明「管家」）

| 场景 | 规则 | 例 |
|---|---|---|
| 对话流里 AI 说的话 | 一律第一人称「我」 | "我来判断要不要读文件" |
| 界面骨架（按钮/标签/菜单/状态） | 不用人称，纯动宾 | "选择工作文件夹"（不写"让 AI 在这里干活"） |
| 说明性文字（欢迎页副标题/设置项描述/tooltip） | 统一用「管家」，禁止"AI/AI 助手/它"混用 | "门店名会用进管家写的文案里" |

判据：同一屏幕内不得出现两种自称。

### 1.2 语体基线 + 禁用词表

大白话 = **中性白话**（微信/支付宝式），不是网络口语。禁用词与替换：

| 禁用 | 改为 |
|---|---|
| 啥（"发啥/干啥"） | 什么 / 具体化（"要发的内容"） |
| 干活 | 处理 / 工作 / 具体动词 |
| 折腾、会折腾的人 | 进阶用户 / 需要自定义时 |
| 捣鼓、鼓捣、合计、落子 | （删，见 §2 spinner） |
| 好了叫你 | 完成后会提醒你 |
| 没加成、没拿到 | 未能添加 / 获取失败 |

### 1.3 状态词与标点

- 进行中一律「正在 + 动宾…」；完成一律「已 + 动宾」；失败一律「××失败」+ **一件**用户能做的事（不堆两三个建议）。
- 句号：只有完整句子才带；按钮、标签、状态 chip、菜单项一律不带（现状 "已确认执行。" / "已取消。" 违例）。
- 省略号统一半个字符宽的「…」一个；禁止「……」六点、禁止动词截半（现状 "正在备……"）。
- 中文文案内一律全角标点，禁半角逗号混排（现状 video-studio-drawer "在出片了,好了叫你…"）。

### 1.4 Emoji 与图标

界面骨架禁 emoji（🤔/🎯/✅/⤢ 全部换 lucide 图标——项目本来就在用）。AI 生成内容里的 emoji 不管。

### 1.5 黑话翻译（露出给用户前必须过这层）

| 内部词 | 用户看到 |
|---|---|
| run_subagent 等工具名原文 | 只出现大白话标签（agent-tools.ts 已有机制，命令回复里漏了） |
| "esc 中断" | "按 Esc 停止"（或只留「停止」按钮） |
| 终端块里的 exit 0 / stdout | 保留（终端语境本身是等宽黑底，用户预期如此） |

### 1.6 工具标签统一格式

一律**现在式动宾、2~5 字**。现状混了完成时和口语长句，对照见 §2。

## 3. 交互改造项（4 个工单，按性价比排序）

### 3.1 【C1】系统通知退出对话流（33 处 `pushAssistantMessage` 分流）

**问题**：应用状态通知伪装成 AI 气泡，还落进对话历史。大厂铁律：系统的话走 toast/横幅，AI 的话才进对话流。

**做法**：
1. 新建 `web/src/components/desktop/toast.tsx`（macOS 风格：顶部居中浮出、2.5s 自动消失、成功/失败两种；样式对齐现有设计语言 #10a37f/#ff3b30）。项目现无 toast 组件，preview-panel 内部有局部 flash 实现可参考但不共用。
2. 33 处调用逐一分流（`grep -n 'pushAssistantMessage(' web/src/components/desktop/*.tsx web/src/hooks/*.ts`）：

| 类型 | 去向 | 典型（chat-shell.tsx 行号） |
|---|---|---|
| 操作结果通知（已保存/已删除/已导出/导出失败/已恢复） | toast | 359, 361, 593, 595, 622, 626, 631, 883, 885 |
| UI 限制解释（任务在跑别切会话/别删除） | 删除，改禁用态（§3.4） | 308, 385；use-agent-chat.ts:469 |
| 命令查询结果（/help /agents /mcp /skills /plugins /context /cost） | 保留在对话流（内容是"给用户读的资料"），但按 §1.5 去黑话 | 840-873 |
| 真 AI 内容（每日草稿正文、种子演示回答） | 保留 | 176, 406 |
| 目标设定确认（/goal） | toast | 539, 540, 813 |

3. 验收：干完后全仓 `pushAssistantMessage` 只剩"对话内容"类调用；toast 不进对话历史。

### 3.2 【C2】快捷按钮 prompt 隐藏化（显示文案与实际载荷分离）

**问题**：`use-agent-chat.ts:384` 把 `send(msg)` 的整段工程化 prompt 作为用户气泡显示。点"转成任务"会冒出一段 4000 字的"用户发言"。大厂 suggested replies 只显示短句，模板藏在请求里。

**做法**：
1. `send(msg, opts?: { displayText?: string })`；`ChatMessage` 加 `displayContent?: string`；chat-thread 渲染用户气泡时 `m.displayContent ?? m.content`。
2. 涉及的发送点全部补 `displayText`（chat-shell.tsx）：追问 chips（chat-thread `buildFollowUp` 的 prompt，displayText=按钮标签）、转成任务(575)、重做一版(637)、确认采用/重做(662-665)、基于此调整(654)、做成视频(563-568)、换素材再试(642)。
3. **跨模块影响（⚠️ 改前读 `docs/耦合地图与改动检查清单.md`）**：后端把用户消息原文落库、历史回放时会把长 prompt 又显示出来。需要 `POST /api/v1/agent` 请求体加 `display_text` 透传、消息落库时一并存、拉历史接口返回。涉及 `server/api/v1/agent.py` + 消息存储模型 + `web/src/lib/api.ts`。改完跑 `python3 scripts/build_coupling_map.py --write`。
4. 折中方案（如果不想动后端）：只做前端 displayContent，接受"重新打开历史会话时看到原 prompt"。**建议做全套**，半套等于没修。

### 3.3 【C3】回答动作栏收敛（10 个 → 3 个 + 溢出菜单）

**现状**（chat-thread.tsx:856-921）：复制到微信 / 好评 / 右侧打开 / 重做一版 / 保存成品 / 导出到电脑 / 转成任务 + 最多 3 个台球追问 chips；成品卡再加"这条不太合适"。

**改为**：
- 常驻 3 个（图标化，hover 出文字 tooltip）：**复制、好评、重做一版**。
- 收进「…」溢出菜单：右侧打开、保存成品、导出到电脑、转成任务。
- 台球追问 chips 最多 2 个（`billiardsFollowUpActions` 里 `actions.length < 3` 改 `< 2`）。
- 成品卡的"这条不太合适"也收进「…」菜单。
