# 生图模块重构 · 编排（第一期）

> **For agentic workers:** 本文是"编排"阶段产物（实现路径 + 任务拆解 + 回退设计），供评审与后续 executing-plans 使用。**未经用户确认实现路径前，不要进开发。** 第一期 = 海报生图引擎 + 自由描述前端 + all-GPT 渲染（含回退预留）；第二期（助教出片）见 §9。

**一句话目标：** 把"用户一句大白话 → 一张能用的台球房海报"这条路打通——核心是补上一层 **DeepSeek 提示词扩写引擎**，前端砍掉场景卡片只留"一个描述框 + 看示例"，第一期**文字/Logo/二维码全部交给 gpt-image-2 渲染**，并把数据结构留成"随时能回退到 Pillow 合成"的样子。

---

## 1. 背景与问题（现状）

- 现状管线：用户输入的原始 prompt **直接喂** gpt-image-2（`poster_service.py:build_poster_prompt` 只做结构拼接，无语义扩写）。
- **病根（已验证）**：标准 Image API（`images.generate`/`images.edit`）**不像 DALL·E 3 / Responses API 那样自动扩写提示词**。所以"周五抢一大战海报"这几个字就是模型收到的全部——浪费了模型实力，出图平庸。
- 现状前端：对话式 + 14 个零碎场景标签 + 8 个风格预设硬编码在 `posters/[conversationId]/page.tsx`。用户判定"场景碎、卡片复杂且丑"，要砍。

## 2. 调研结论与关键事实（已联网验证，决定架构）

> 来源以 OpenAI 官方 cookbook/docs 为主，辅以 2026 年实测。完整链接见本节末。

| 能力 | gpt-image-2 实测结论 | 对设计的影响 |
|------|----------------------|--------------|
| 提示词扩写 | 标准 Image API **不自动扩写** | **必须自建扩写层**（DeepSeek） |
| 中文文字 | 常用字 ~98%，但**单次仍 5–10% 错字**，高清下错字更扎眼；价格/电话错一位即废 | v1 交给 GPT 渲染，**关键信息靠"出多张+体验"兜底**，留回退 |
| Logo 融入 | 能自然摆放带光影，但**会重画真 Logo**、细节走样（非像素级保真） | v1 让 GPT 渲染上传的 Logo，**接受不够精确**，留回退 |
| 二维码 | **API 渲染 100% 扫不出**（ChatGPT 网页能扫是其隐藏后处理，API 不给） | ⚠️ 最大风险点；v1 仍按用户决策交给 GPT，**体验后大概率要回退到 Pillow 叠码** |
| 人脸保真 | gpt-image-2 较强（官方列为核心能力），但需 prompt 显式"锁脸" | 用于第二期"助教出片" |
| 出图随机性 | 每次构图随机，固定坐标盲贴会压内容 | 印证 v1 不做固定坐标叠加；回退方案需用"留白+小底卡+高容错"而非盲贴 |

**用户拍板的 v1 取舍（2026-06-14）：** 文字/Logo/二维码**全部交给 GPT 渲染**，先做最简单的版本去真机体验；**不行就回退**。本编排据此把回退设计成"加一道后处理 stage 即可"，不推倒重来。

来源：OpenAI Cookbook《GPT Image Models Prompting Guide》(gpt-image-2)、`platform.openai.com/docs/guides/image-generation`、Apiyi 二维码实测、火山/图叮中文实测。

## 3. 核心设计决策（locked，含理由）

| # | 决策 | 理由 |
|---|------|------|
| D1 | **两条线**：海报（第一期）/ 助教出片（第二期，先验证） | 目标不同：营销物料 vs 个人朋友圈出片，管道/UI 分开 |
| D2 | **砍掉场景卡片**，只留"一个描述框 + 看示例" | 用户判定卡片复杂且丑、不符人性；引擎够强就不需要模板菜单 |
| D3 | **场景智能搬进引擎**（隐形）：扩写时识别意图、检测缺失的"观众必须看到的信息" | 既不堆 UI，又保证招聘缺联系方式这种会被提醒补 |
| D4 | **高频复用靠生成历史/收藏/续修**，不靠模板 | 周赛每周做——复用上次那张改日期，比我们猜模板更准（功能已存在） |
| D5 | **引擎为主**：DeepSeek 把大白话/字段扩写成结构化提示词，**可见·可改·可关** | 补上"标准 API 不自动扩写"的缺口；对齐 Ideogram/Firefly 透明可编辑范式 |
| D6 | **背景两来源**：① AI 生成场景 ② 上传门店照优化（`images.edit`，店照放第一张） | "我的店"比"通用 AI 店"可信；门店照进 AI 当底图优化 |
| D7 | **v1 文字/Logo/二维码全交给 GPT**，Logo/二维码**手动上传**才带 | 用户决策；最简版本先体验 |
| D8 | **数据结构化保存** poster_text / logo / qr / 背景模式 | 让"回退到 Pillow 合成"只需加一道 stage（D7 的安全网） |
| D9 | **出多张选一张** | 成本非约束（客户付费）；对冲 gpt-image-2 随机性与中文错字 |
| D10 | 守住：`gpt-image-2` 写死、配额、租户隔离、合规、扩写不计配额 | 项目铁律 |

## 5. 后端怎么做

### 5.1 扩写引擎 `server/services/poster_prompt_engine.py`（新增，单例风格仿 prompt_engine）

职责：把"用户输入 + 门店语境"扩写成可直接喂 gpt-image-2 的提示词，并检测缺失的观众必看信息。

- **调用 DeepSeek**：复用 `services/ai/providers/deepseek.py`。**不走 `run_generation`、不计配额**（对齐店脑后台学习"不计配额"的先例）。
- **System prompt 要点**（按 OpenAI 七段式 + 研究结论）：
  - 角色：台球房海报提示词专家；输出**英文**场景描述（英文出图更稳），但**要在图上出现的中文文案原样保留、用引号标注"render this exact Chinese text, do not translate"**。
  - 结构：`用途 → 场景 → 主体 → 关键细节 → 构图/排版 → 光线/色彩/情绪 → 风格 → 约束`。
  - 注入：台球房行业语境（中式八球/斯诺克/球房环境）、门店画像/店脑（品牌调性）。
  - 文字渲染指令（v1 all-GPT）：把"要写的字"按"标题大、信息中、联系方式小"布局；要求文字清晰、排版对齐（借用实测有效的"网格系统布局规范"一句）。
  - 约束：不擦边、不编造未提供的价格/时间/奖金、台球器材品牌按白名单豁免、无第三方机构名。
  - 输出 **JSON**：`{"image_prompt": "...", "needs": ["..."]}`（仿 Open WebUI 的 JSON 契约，解析稳）。
- **needs 检测（D3 场景智能）**：根据识别到的意图判断关键信息是否齐（如招聘→联系方式/待遇；赛事→时间/报名方式）。缺则回填 `needs`，前端横幅提示补（复用既有 `lib/placeholders` 思路）。

### 5.2 数据结构（D8 回退预留）—— 复用 `generations` 表，零迁移优先

`ImageGenerateRequest` 与落库 `input_params` 里**分字段保存**（不要只存合并后的 prompt）：
```
description       # 用户大白话
poster_text       # 结构化: {title, lines[], contact}  ← 观众看的中文，单独存
background_mode    # "ai_generate" | "store_photo"
store_photo_path   # 背景模式=store_photo 时
logo_path, qr_path # 手动上传，可空
ratio, count
expanded_prompt    # 引擎产出（落库便于复盘/复用）
```
> 回退时：新增一个 Pillow 合成 stage，读 `poster_text/logo_path/qr_path` 精确叠到 AI 背景上——**无需改数据模型**。

### 5.3 gpt-image-2 调用（`openai_image.py` / `poster_service.py`，小改）

- 维持写死 `model="gpt-image-2"`。
- 输入图顺序：**要保真的放第一张**（门店照 / 之后阶段的人像）；Logo/二维码随后（API 上限 16 张，已有逻辑）。
- **出多张**：`count` 放开到 2–4（现 `generate_images` 已按 count 循环，前端当前锁 1，需放开）。
- 比例尺寸沿用已修正的 `SIZE_MAP`（3:4=1152×1536 等）。

### 5.4 API（`server/api/v1/posters.py`）

- `POST /posters/expand`（新）：`{description, poster_text, background_mode, ratio}` → `{image_prompt, needs}`。供前端"可见·可改"。
- `POST /posters/generate`（改）：接收（可能被用户编辑过的）`image_prompt` + 结构化字段 + 图片 + `count` → 出多张。
- `GET /posters/showcase`（新）：返回灵感示例 `[{image_url, idea_text}]`；点击用 `idea_text` 填描述框。

### 5.5 复用（不重造）

配额 `check_poster_quota`/`increment_poster_usage`、注入校验 `check_input_injection`、租户隔离（contextvars 自动过滤）、`is_deleted==False`、微信下载长按保存。**扩写调用不计配额。**

## 6. 前端怎么做

> **原则：引导式，不是模板目录。** 前端核心是"教用户怎么用"——主体永远是那个描述框，旁边只用三样轻引导：①会教人的占位示范（如"例：周五抢一大战，图上写'报名费10元、赢家拿奖金'，要热血电竞风"）；②一句话用法提示（"大白话说清：做什么+图上写什么字+想要什么感觉"）；③少量示例做"示范"（非目录），点"参考思路"帮起头、可改。**主界面不常驻一堆说明、更不堆模板；"能做什么 / 怎么用 / 示例"统一搬进 §6.2 的新手引导界面，主界面只留工具本身。**

- 重做 `web/src/app/dashboard/posters/[conversationId]/page.tsx` + 列表页；删除硬编码的 14 标签/8 风格。
- 新界面（手机第一）：
  1. **描述框**（主入口）
  2. **背景来源**切换（CardSelect：AI 生成 / 上传门店照）
  3. **要写的字**（标题/信息/联系方式，结构化输入；`needs` 缺失项横幅提示）
  4. **比例**（CardSelect）
  5. **手动上传 Logo/二维码**（默认折叠，要才传）
  6. **扩写预览**：展示"AI 优化后的描述"，可改、可切回原话、可关（默认开、收在"高级"里）
  7. 角落 **"怎么用 / ?" 入口**：随时打开 §6.2 的新手引导/功能介绍界面（示例与教学都收在那，主界面不再挂示例区）
  8. **出图**：出多张 → 选一张 → 落库 → 下载/转发；复用历史/收藏/续修
- 设计系统对齐 CLAUDE.md：iOS 蓝、`rounded-2xl/xl`、底部 sheet、吸底主按钮、触控≥44px、WebView 复制/下载适配。

### 6.2 新手引导 / 功能介绍界面（落地页风格，第一期就上）

把"能做什么、怎么用"从主界面挪到这里——一个**落地页风格的功能介绍屏**，主界面因此保持干净。

- **形态：落地页风格**——全屏、视觉化、可滚动看示例与说明，**不是**逐步点点的 tooltip 向导。**样式**可借现有 `/landing-preview`（CLAUDE.md：内部调样式用的落地页代码）；**"首登自动弹 / 记已看过 / 可重开"的触发机制**借 `components/onboarding-guide.tsx`。两边各取一块，不从零造。
- **触发**：首次进入生图**自动弹一次**（落地"已看过"标记，之后不再自动弹）；主界面"怎么用/?"入口**随时可重开**——想看才看，不看不打扰。
- **内容**：
  - **能做成什么样**：几张示例成品图（替代原先挂在主界面的示例区）；
  - **怎么用**：大白话说清"做什么 + 图上写什么字 + 想要什么感觉"，剩下交给 AI；可上传门店照当底图；可出多张挑；
  - 几条"怎么写效果好"的小贴士；
  - 示例可"参考这张思路"→ 关引导、把描述填进主界面（可改）。
- **可跳过、不强制**——老用户不被打扰。

## 8. 验证 / 体验 / 回退

- **体验什么**：用户真机生成几类海报（赛事/充值/招聘 + 门店照优化各跑几张），重点看：
  1. 中文标题/价格/时间**有没有错字**；
  2. 上传的 **Logo 像不像**；
  3. **二维码扫不扫得出**（手机实扫）。
- **回退判据（量化）**：二维码实扫失败 > 偶发 / 关键中文错字明显 → 启用 §5.2 预留的 **Pillow 合成 stage**（二维码必回退；Logo/文字按体验决定）。
- **回退成本**：仅"加一道后处理 stage 读结构化字段"，数据模型与前端不动。

## 9. 第二期边界（助教出片，先验证再做）

- 定位：助教发**朋友圈的漂亮场景照**（≠ 海报）。**锁脸**（提示词显式"保持本人五官/脸型/肤色不变，只改背景/光线/氛围"）+ 场景化美照；磨皮交给她自己的 app。
- 修图：抠背景/换底/重打光等"不重画脸"的操作。
- **必须先用真助教照片小验证**（女孩子对自己照片极挑剔，是唯一"挑剔翻车"风险点），过了再正式做。
- 复用同一台扩写引擎 + 同一套生图调用（仅加锁脸提示词），不另起炉灶。

## 10. 铁律对齐 & 不做的事

- **守**：`gpt-image-2` 写死；配额/租户/合规复用；扩写不计配额；`is_deleted==False`；prompt/YAML 禁第三方机构名（器材品牌按白名单豁免）；微信下载长按保存；dev 期不跑 `next build`。
- **并发硬限制（已实现）**：生图**每用户单次单张、禁批量**（schema `count` 锁 `le=1` + 端点强制 `count=1` + 前端撤掉"出几张"）；**同一时刻每用户只允许一张在跑**（`posters.py` 的 `_GENERATING_USERS` 进程内集合拦截，重复发 429）——防并发刷量、护住 OpenAI 每分钟出图限额（Tier1=5张/分）。⚠️ 进程内集合仅单 worker 有效，多 worker 需换 DB/Redis。**完整并发方案**（全局队列限速 + DeepSeek/OpenAI 余额预算告警 + 429/503 退避重试）尚待编排。
