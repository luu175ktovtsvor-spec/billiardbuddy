## 二、逐板块详解(每块三段:① WorkBuddy 是什么 → ② 我们填什么 → ③ 落 React 哪 + 优先级)

### 板块 1 · 项目新手指引(Onboarding)

**① WorkBuddy 是什么**(来源 05-项目 §五,可信度:JSX/i18n/常量【读到】,demo 由谁在何时建【后端盲区】)
- **不是引导浮层/tour,而是首次进项目自动创建的一个"demo 任务"**,靠一份 `welcome.md` 驱动,分两半:
  1. **输入框预填**:当 `selectedTask.isDemo===true` 且项目网盘 ready,从网盘搜真实 `welcome.md`,作为**文件引用块**塞进输入框,并预填文字:「根据 [welcome.md 文件块] 教我如何快速上手 项目 功能」。按 `onboarding-demo:{userId}:{projectId}:{taskId}` **只填一次**(localStorage 去重)。
  2. **右侧预览注入 welcome 概览**:同 demo session 注入一个 `type:"overview"` artifact(name `welcome.md`,title「欢迎使用 WorkBuddy 项目」)。优先 fetch 网盘真实内容;失败/为空降级到**内置兜底 markdown**(可直接照搬改写):开场"你好,新朋友 👋",把"和 AI 协作完成工作"拆成入口讲、一张"主要模块"表逐行讲、"推荐上手姿势"5 步、收尾。

**② 我们球房管家填什么**(软件经验 + 台球场景延伸)
- 台球老板首次打开 → 自动建一个"**教我上手**"demo 会话,右侧弹一份**欢迎概览**,输入框预填一句"教我如何快速上手球房管家"。
- **概览内容(替换 welcome.md)** 讲清球房管家能干的三条主线,每条给一句"你现在就能试":
  - **挂"台球运营专家"** → "输入框选台球运营专家,我就懂你门店的运营打法(助教/营销/会员/淡季)"。
  - **出第一张活动海报 / 内容** → "说'帮我出一张周末双人优惠海报',直接给图"。
  - **跑一次经营诊断** → "把上月营业额报表拖进来,我帮你看哪儿漏钱、怎么补"。
  - 顺带点到:定时日报、排班表、对账、点评回复。
- **分两版 welcome**:默认**通用版**(球房管家=通用电脑助手);用户选了"台球运营专家"领域包 → 换**台球版** welcome(直接讲门店场景)。对应领域包"默认不挂"的产品定位。
- **首次三步引导**(可选,做成概览里的三个可点卡):① 挂台球专家 → ② 出第一张海报 → ③ 跑经营诊断。点一下就把对应 prompt 灌进输入框(走复用机制 §三.2 的 `requestInsertContentBlocks`)。

**③ 落 React + 优先级**
- 视图:`pages/EmptySession`(新建任务空欢迎屏)承载首启检测;右侧 **workbench 注入一个 `OnboardingWelcome` overview artifact**(🔵自建,复用 Block E 右侧预览的 artifact 渲染)。
- 状态:首启检测走 `settingsStore`/`sessionStore` + localStorage 去重键(照 WorkBuddy 的 `onboarding-demo:*` 思路,单机改成 `onboarding-demo:{deviceId}`)。
- 预填走 §三.2 统一 adapter。
- **优先级 P0**:第一印象屏,成本低价值高,应在地基"最小聊天屏"跑通后紧接着做。

### 板块 2 · 任务(侧栏任务列表 + 点开)

**① WorkBuddy 是什么**(来源 03-布局 §2、09-交互 §10、05-项目 §4.2)
- 侧栏结构自上而下:品牌区 → 新建任务按钮 → 图标导航 → **任务搜索框 → 任务列表(带相对时间)** → 底部用户区。
- **任务 = 一次 AI 协作会话(conversation)**。任务项 = 复用型 `.cb-sidebar-nav__item`(图标+标题+badge+hover 才显的行内 action)。相对时间:刚刚 / {h}h 前 / 昨天 / {d}d 前。
- **点开** = 进入该会话:恢复完整对话历史 + 右侧产物。任务 hover 更多菜单:重命名/归档/删除/退出协作(按权限)。新建中占位标题="新建任务中"。项目里的任务还有 scope 切换(全部/协同/个人)、来源(手动/自动化)、隐私提示"你的任务是私密的,除非你共享它们"。

**② 我们球房管家填什么**
- **任务 = 一件具体的活**:一次经营诊断 / 一条内容创作(海报/文案/短视频)/ 一次排班 / 一次对账 / 一张活动方案。侧栏"任务(N)"就是老板干过的活的历史,按时间倒排、可搜。
- **点开** = 回到那次会话:看当时的对话、AI 给的结论、产出的图/表/文档(右侧产物)。
- **AI 自动起名**:新建时占位"新建任务中",AI 根据首条消息自动起个好认的名(如"周末双人优惠海报"、"6 月营业额诊断"),对不懂技术的老板友好。
- 单机单用户 → **去掉协同/隐私那套**(scope 切换、"除非共享"提示)不需要;归档/删除/重命名保留。

**③ 落 React + 优先级**
- 视图:`layout/Sidebar` 的任务列表(富内容,**Block D**)+ 点开进 `pages/ActiveSession`(主聊天屏)+ `chat/SessionTaskBar`。
- 数据:`/sessions`(列表)、`/tasks?conversationId=`;侧栏项复用 cc 的 `SidebarNav`(图标+标题+副标+badge+行内 action,见 09-交互 §10)。
- **优先级 P0**:这是产品核心闭环(新建→干活→回看),地基阶段就要跑通,本来就在 React 迁移的 Block D + 地基里。

### 板块 3 · 更多·资料库·灵感

**① WorkBuddy 是什么**(来源 08-更多 §1~5,可信度:入口表/路由/CSS/文案【读到】,后端场景分类【盲区】)
- **"更多" = hover 下拉**(不是点击):`triggerMode:"hover"`、`placement:"right-start"`、向右弹。触发器 = 图标+"更多"+**红点+动态副标签**;副标签按实际开了哪些子项**动态拼**("资料库·灵感")。
- menu 里三组(组间分隔线),**只有资料库四项 + 灵感一项,没有设置/技能/连接器**:
  - A 组 `myFiles`"我的文件"→`/library/my-files`;B 组 `tencentDocs/ima/lexiang`(第三方知识库);C 组 `inspiration`"灵感"→**`/discover`**。
- **两个"灵感"辨析(易踩坑)**:
  - 更多菜单点"灵感"→ `/discover` → **DiscoverPanel**(案例/工作流**起点库**,单色中性 `#2C2C2E`,shell-main 占满主区):顶部分类 tab(全部/精选/后端下发场景)+精选横滑(换一换)+卡片,详情弹层从底部上滑,底部"做同款/立即体验"。**点案例卡 → 多阶段启动流**(检查技能/专家/MCP → 缺啥装啥 → 建任务 → 灌 prompt)。
  - `/inspiration` → **InspirationPanel**(每日个性化灵感 **feed**,紫色 `#6d5ff5`,shell-panel 侧滑):每日卡片 feed + 兴趣标签 onboarding(16 标签)。**这条路由不在更多菜单里**(WorkBuddy 自己也没露出入口)。
- **资料库四子项**各是独立面板:我的文件(任务成果+云端网盘)、腾讯文档(最重,webview 选择器)、ima/乐享知识库。
- **设置不在"更多"里** → 在**底部账号头像菜单**(账户/系统设置/个性化/外观/数据管理/帮助/已归档/检查更新…)。

**② 我们球房管家填什么**
- **资料库 → 门店资料库**:
  - **我的文件**保留(任务成果 + 本地文件夹):AI 生成的海报/文案/短视频/排班表/对账表都归这;门店画像、导出的经营报表、PPT 底本、活动素材也在这。
  - 腾讯文档/ima/乐享 → **第三方知识库连接器,起步占位**(通用能力,排后);未来可接门店自己的云盘/知识库。
- **灵感(discover 案例库)→ 运营灵感与模板库**:把台球运营常见打法沉淀成"**可复用的任务起点**"卡:
  - "给会员发节日活动" / "淡季拉客方案" / "新店开业造势" / "助教人设打造" / "周末满台冲刺" / "差评危机公关回复" / "赛事引流" / "会员充值促销"。
  - 点"做同款" → 走 §三.2 adapter 把该场景的预置 prompt(+需要挂的技能/专家)灌进输入框、开新任务。**多阶段启动流照搬**(检查/安装技能 → 挂专家 → 建任务 → 灌 prompt)。
  - 配色走中性单色(换我们品牌中性色),与"每日灵感"的品牌色区分。
- **灵感(inspiration 每日)→ 每日运营灵感**(P3 后置):每天推台球行业动态/运营小技巧卡(如"这周同城这三家在搞什么活动""淡季这么发朋友圈"),兴趣标签换成门店关注点(营销/会员/助教/赛事/器材/装修)。
- **设置照搬"在头像菜单不在更多里"**:球房管家的设置(外观/数据/领域包/模型/检查更新)放底部用户菜单。

**③ 落 React + 优先级**
- 更多下拉 = `layout/Sidebar` 里的 more dropdown(**Block D**,复用 floating-ui Dropdown,hover 触发、副标签动态拼)。
- 资料库面板 = 复用"我的文件"面板(可接 workbench);案例库 = **新 `pages/DiscoverPanel`**(shell-main);每日灵感 = **新 `pages/InspirationPanel`**(shell-panel)。
- 案例卡启动流复用 §三.2 adapter + 技能/专家安装闭环(依赖板块 5)。
- **优先级**:资料库(我的文件)**P1**、案例/模板库 **P1**(直接提升"老板不会写 prompt"的可用性)、每日灵感 **P3**、第三方知识库连接器 **P2 占位**。

### 板块 4 · 自动化

**① WorkBuddy 是什么**(来源 07-自动化,可信度:CSS/i18n/数据模型/12 模板【读到】,调度引擎【后端盲区】,datasource【WorkBuddy 自己标 mock】)
- **定时任务/无人值守 Agent 调度器**。**环境门槛:仅本地可用**(非本地直接挡:"请在本地 IDE 中使用")——依赖桌面常驻进程跑调度,天然适配我们桌面版。
- 两 Tab:**定时任务 / 运行记录**;工具条 搜索/批量管理/从模版添加/+添加自动化。
- 任务列表行:状态点 + 频率文案 + 下次执行时间(十几种状态文案:已暂停/运行中/正在创建会话/已错过将补跑一次/排队中…);hover 出测试运行/归档/删除;更多菜单 编辑/暂停/恢复/立即运行/删除;按状态分组(已安排/执行中/已完成/已归档)。
- **创建/编辑 = 整页替换编辑视图**(不是小弹窗)。字段:名称 → 工作空间 → **提示词(内嵌完整 ChatInput,带模型/技能/专家/连接器选择器)** → **执行频率(调度编辑器)** → 推送渠道开关 → 连接器授权 → **执行权限(免确认执行 / 需逐次确认)**。
- **调度编辑器 = 标准 RRULE 数据模型**:三档 周期/按间隔/单次;`schedule = { freq, byday[], bymonthday[], bymonth[], byhour, byminute, interval, intervalHours }` + 生效日期区间。**这套很成熟,可 1:1 照搬。**
- **权限风险确认弹层**(选"免确认执行"时弹):标题"这条自动化任务将以完全访问权限运行"+三条风险 + 必勾 checkbox"我已了解风险…"。
- **12 内置模板**(每日 AI 新闻/每周周报/体检提醒…),含完整 prompt + 调度配置,结构可全量照抄。

**② 我们球房管家填什么**
- **自动化 = 无人值守定时 Agent**,是单店老板的**高频刚需 + 差异化卖点**。台球场景 12 模板(换掉 WorkBuddy 那 12 个):
  | 模板 | 调度 | 干什么 |
  |---|---|---|
  | 每日经营日报 | 每天 09:00 | 汇总昨日营业额/台时/助教业绩,一句话点评 |
  | 每周排班提醒 | 每周日 18:00 | 生成下周排班草稿 + 缺口提醒 |
  | 每月对账 | 每月 1 号 10:00 | 拉上月报表对账,列异常 |
  | 淡季营销文案 | 每周三 14:00 | 生成本周朋友圈/点评营销文案 |
  | 节假日活动预案 | 单次/按节日 | 节前 3 天出活动方案 + 海报 |
  | 点评巡检提醒 | 每天 20:00 | 提醒回复大众点评/抖音新评论(不自动回,给草稿) |
  | 赛事/包场巡检 | 每周 | 检查本周赛事/包场排期冲突 |
  | 会员到期提醒 | 每天 | 列本周到期会员,给召回话术 |
- **调度模型 1:1 照搬 RRULE**(周期/间隔/单次 + 生效区间)。
- **权限档照搬**(免确认执行 vs 逐次确认)+ 风险弹层——无人值守 Agent 标配。**但产品红线卡死**:自动化产物只到**本地/预览**,**不自动群发/私信/发布**(点评回复只给草稿);"免确认执行"仍不能越过对外触达红线(对齐 CLAUDE.md 审批闸只卡对外/不可逆/花钱)。
- 推送渠道文案里的"WorkBuddy 微信小程序"换成我们自己的渠道(或起步只落本地通知)。

**③ 落 React + 优先级**

## 三、可复用的跨板块机制(★标出我们该复用哪些)

这些是 WorkBuddy 反复用、跨多个板块的"底层机制",**我们抽出来一次,多处复用**——这是"后期怎么改省事"的关键。

### 3.1 后端控展示 + 前端 by-key 硬编码跳转(分层)【来源 08 §0】
- WorkBuddy 原则:"**后端只控展示属性(显隐/文案/图标/排序),跳转行为由客户端按 key 硬编码,不碰功能**"。菜单表下发一张可见性/文案/图标/排序覆盖表,前端按 key 跳转。三 Tab 也用 `useVisibleMarketTabs` 按配置裁。
- **我们复用**:侧栏主 tab、三 Tab、更多菜单都走这套。**领域包(billiards)可按开关裁 Tab/菜单**——挂台球专家时露出"经营诊断/排班"入口,通用模式时收起。做门店定制/灰度很干净。

### 3.2 requestInsertContentBlocks adapter(所有"预置 prompt 灌输入框"统一走一个 API)【来源 08 §3、§4】
- WorkBuddy:案例卡"做同款"、每日灵感卡、快捷动作、模板 —— **所有把 prompt/技能块塞进输入框的动作都调同一个** `adapter.requestInsertContentBlocks({ contentBlocks, clearFirst, promptText })`。
- **我们复用(强烈建议抽一个)**:板块 1 新手三步、板块 3 案例/模板卡、板块 8 快捷动作、板块 4 自动化模板、板块 5 技能推荐 —— 全走这一个 adapter。抽在 `chatStore`/composer 层,后期加任何"一键起任务"入口都免重复接线。

### 3.3 mode → `{family}-{welcomeMode}.tpl` 模板映射(选模式挂对应系统提示词)【来源 08 §6.3】
- WorkBuddy:选 working/coding/design,后端就用对应 `.tpl` 系统提示词模板,前端不携带 systemPrompt。
- **我们复用**:板块 8 三模式(门店运营/内容创作/数据分析)各挂一套模板;天然对齐我们"领域包挂载 + 斜杠技能底座"——把领域包/模式做成"选哪个,SessionStart 就注入哪套提示词/知识/工具"。

### 3.4 信任闸 + 安全检测(第三方产物统一过一道)【来源 06 §1.6/§2.5/§4】
- WorkBuddy:技能包/专家包/MCP 安装前都过安全扫描(safe/low/medium/high,病毒/恶意意图),高风险手动确认;MCP 首次连接"信任/拒绝",判定恶意"已拦截";全局急停"禁用全部技能/MCP/插件"。
- **我们复用**:板块 5 技能/专家/连接器/MCP 统一走这道闸。我们内置 key 免登录、第三方少,但**用户导入的技能包/MCP/专家包必须过检测**(红线不松);全局急停照搬。

### 3.5 弹层技术底座(floating-ui + 复用组件)【来源 09 §0】
- WorkBuddy:所有点击弹出的东西走 `floating-ui/react`(useFloating/FloatingPortal/useHover/useDismiss/offset/flip/shift…)+ 一套复用组件(Popover/Dropdown/ConfirmDialog/HoverSubMenu/Tooltip/ContextMenu/Toast);统一 Esc 关闭、Tooltip 默认 delay 300ms。

### 3.6 welcome.md demo 任务机制(首次进 X 自动建 demo + 概览 artifact + 输入框预填)【来源 05 §五】

## 四、建议实现顺序(全搬前提下的先后 · 不是砍)

> owner 口径:**8 板块都要建**。下面是"先建哪个更快让单店台球老板用上、更快形成闭环"的**建议顺序**,不是取舍。

### 第一梯队(P0 · 核心闭环,地基阶段就要有)
1. **板块 8 新建任务** + **板块 2 任务列表**:入口 + 干活 + 回看,这是产品最小闭环,本来就在 React 地基(Block D + 最小聊天屏)里。
2. **板块 1 项目新手指引**:成本低、第一印象价值高,跑通最小聊天屏后紧接着做。

### 第二梯队(P1 · 台球差异化价值,核心卖点)
3. **板块 5 技能 + 专家**:出海报/剪视频/排班/对账 + 挂台球领域包/角色——这是"球房管家能干活"的核心体现,后端底座(skills + `packs/billiards` + `agents`)已就位,前端补市场/详情/召唤即可。
4. **板块 4 自动化**:日报/排班/对账是单店老板最高频刚需、差异化强;需后端调度引擎先就位。
5. **板块 3 资料库(我的文件)+ 案例/模板库**:让"不会写 prompt 的老板"点一下就起任务,直接提升可用性。

### 第三梯队(P2 · 通用能力占位,先搬骨架,内容/启用排后)
6. **板块 5 连接器 + MCP**:门店系统集成(美团/POS/会员)依赖外部对接;MCP 是通用能力;先建骨架 + 安全闸,内容随对接推进。
7. **板块 6 项目**:单店可用"工作空间组织 + 门店档案挂载"(右侧配置面板最值钱,可提前抽出复用);多店/连锁上量才刚需;协同占位不启用。
8. **板块 7 助理**:总控 + @协作先用后端子代理跑通(不必等 Dashboard);完整助理网格/创建向导/浮窗排后。

### 第四梯队(P3 · 锦上添花)
9. **板块 3 每日灵感(inspiration)**:每日行业动态/运营技巧 feed,内容运营成本高,靠后。

**为什么这么排(软件经验)**:先立"入口→干活→回看"闭环(P0),再上"能干台球的活"(P1:技能/专家/自动化/模板——直接对应产品卖点与老板刚需),再补"通用能力骨架"(P2:连接器/项目/助理——全搬但内容/启用可迭代),最后锦上添花(P3)。**所有 P2/P3 都是"先占位不删",骨架照 WorkBuddy 搬全,内容与启用随迭代填。**
