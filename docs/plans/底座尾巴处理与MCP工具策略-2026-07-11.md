## 二、MCP 工具策略(核心结论:内置工具已覆盖日常,MCP 按三层补"外部服务")

### 0. 先分清:哪些能力**不需要** MCP(内置工具已自带)

内核自带 40+ 工具已覆盖:读写改文件/跑命令/联网查抓(WebFetch/WebSearch)/生图海报/Excel·Notebook 编辑/任务清单/子代理/团队协作/记忆/门店资料检索/代码工具族(git/LSP/大纲/诊断)。**社区常见的 filesystem/fetch/git 类 MCP 一律不需要**——装了反而重复+吃上下文。MCP 的定位 = 接"我们没有、也不该自建"的**外部服务**(A 线工具池扩展,不是产品功能)。

### 1. 第一层 · 出厂内置(零配置,走网关藏 key)——先做这一个

**高德地图 MCP**(官方,`https://mcp.amap.com/sse?key=...`,SSE/streamable-http 远程接入):
- **为什么是它**:①店主真用得上——12 个接口(周边搜索=查竞对球房/餐饮配套、天气=活动安排、路线规划、地理编码),贴门店经营场景;②**远程 HTTP 接入,用户机器零依赖**(不需要 node);③key 挂 URL → 完美套用我们"网关藏 key"架构:**网关加一条 `/mcp/amap` 反代注真 key**(gw.env 存 key,客户端配置只指向网关带 app 令牌)——网关本来就有 `/v1/amap/**` 通路,顺水推舟;④高德个人配额免费(对齐"能免费就免费")。
- **落地清单**:网关反代路(小活)→ 内置 .mcp.json 模板指向网关 → 白标口径:界面叫"地图查询(高德)"(高德是行业真实服务名,照台球包"真实平台名保留"口径,不脱敏;藏的是 key 不是名字)。

### 2. 第二层 · 精选可挂载(设置里一键开,按需)

| MCP | 给谁用 | 依赖/闸门 |
|---|---|---|
| **Playwright 浏览器自动化**(微软官方) | 店主"帮我上网页后台操作/截图"类活 | 本地 stdio,`npx` 跑 → **需要 node 运行时** → 挂进资产管理器静默下载清单(对齐瘦安装包铁律);属对外触达,走审批闸 |
| **Context7**(官方,查最新库文档) | 用我们盒子写代码的用户 | 远程/免费档;coding 场景装 |

**❌支付宝 MCP 已否决(owner 2026-07-11 指出,核实成立)**:该 MCP 面向"自己接开放平台收款"的商家(需商户私钥,只能看到经该 API 创建的交易);球房老板的钱走**各家收银机厂商**的通道,支付宝 MCP 看不到这些流水,店主也基本没有开放平台商户账号——接了是空管子。**算账/对账的真实归属 = 既有"POS 只读"产品口径**:老板从收银系统导出报表 → 内置工具(读文件/edit_excel)直接分析,厂商无关、零依赖。台球收银厂商无官方 MCP/统一接口,不逆向对接;哪天有官方接口再评估。

### 3. 第三层 · 用户自带(机制已就绪)

`.mcp.json` / 设置添加任意 server——信任闸(未受信工作区不连)、外部工具恒审批、隐形 Unicode 净化、断线重连,本轮全部就位。

### 4. 要补的机制(按优先序)

1. **网关 MCP 反代路**(藏高德 key)——小活,先做;
2. **node 运行时进资产清单**——没有它第二层 stdio 类(Playwright)跑不起来;挂在资产下载器 task(铁律 #3 既有待办);
3. **MCP 精选清单 UI**(设置里一键开关,像领域包选择器)——前端期做;
4. **MCP 工具渐进披露**——外接 server 一多,工具规格吃上下文,照技能清单的"列清单→按需展开"处理(登记,量大了再做)。

### 5. 明确不做的

微信/小红书/抖音等**无官方 MCP** 的平台不接第三方逆向实现(封号/法律风险,违背"给店主稳定可用"定位);数据库/K8s/云厂商运维类 MCP 与用户画像无关,不进精选。
