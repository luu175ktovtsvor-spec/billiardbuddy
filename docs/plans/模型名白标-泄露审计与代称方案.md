# 模型名白标 · 泄露审计与代称方案

> 📌 状态:🚧进行中 · 任务〈task#38 真实模型名泄露审计 + 代称方案〉· 出稿 2026-07-10
> owner 口径:**前端页面绝对不能暴露真实大模型名称/供应商**,把模型具体名改成"能力档"代称;以后自建数据看板(dataeye)重接上报时,载荷同样禁带真实模型名/PII。
> 本轮只做 **审计 + 方案**,**不改任何代码**(改动留给后续实现波,避免撞正在跑的前端 React 地基)。

---

## 0. 一句话结论(大白话)

现在的软件在好几个地方会把"底层到底用的哪家哪个模型"漏给用户看——文字模型漏得最狠:**只要哪个模型出口连不上、进入冷却,前端就会弹一条灰字系统提示,里面直接写着真实模型名和供应商的原始报错**;还有一个 `/model` 状态接口会把真实模型名 + 供应商网址(baseUrl)一起吐给前端(这是"设置抽屉查看当前模型"要接的口)。生图那边则是失败/兜底的提示语里明晃晃写着 "Seedream""OpenAI 图片通道"。

治理思路:**别在出口处显示模型名,一律换成"能力档"代称**(写实生图 / 创意生图 / 标准 / 增强),供应商网址一律不吐。落地方式是在**后端 API 出口 + 媒体结果出口**加一层"脱敏映射",前端只认代称。本轮先把清单和改法写清,不动代码。

## 3. 代称映射表(真实模型 → 用户可见代称)

> 口径 = **能力档**,不是换个假模型名。绝不露供应商与模型名。

### 3.1 生图模型
| 真实(后端路由用,不外露) | 用户可见代称 | 何时用/能力定位 |
|---|---|---|
| `doubao-seedream-4-*`(火山方舟 Seedream) | **写实生图** | 照片级写实、**硬中文字准**(海报文字、二维码重排);默认档 |
| `gpt-image-2`(OpenAI GPT Image 2) | **创意生图**(亦可叫"增强生图") | 复杂创意、西文主导、内容编辑 |
| 路由原因(default_seedream / complex_creative_openai …) | **不外露**;必须给一句就用中性 `已按内容自动选择生图引擎` | 反正用户不需要知道选了哪家 |
| 兜底/切换文案(a-e) | **不点名**:统一 `生图引擎繁忙,已自动切换备用引擎重试`(去掉 Seedream/OpenAI) | 失败/兜底 |
| 校验接口 `known_models` | **不返回真实名**:改为返回代称档位或直接省略该字段 | BYOK 面板 |

### 3.2 文字模型
| 真实(claude-*/deepseek/MiMo/GLM… 由 env 决定) | 用户可见代称 | 说明 |
|---|---|---|
| 主出口(内置 key 走网关) | **默认不显示模型名**;如需标就 `球房管家大脑` 或能力档 `标准` / `增强(深度思考)` | 能力档按 reasoningEffort/是否思考区分,不按厂商 |
| 备用出口(fallback provider) | **备用通道**(不带名、不带 baseUrl) | 冷却/故障时只说"正在切换备用通道",不报真实名与原始错误 |
| `baseUrl`(供应商 endpoint) | **一律删,永不外露** | 比模型名更敏感 |
| 原始报错 `lastError` | **不透传**;归一成中性 `当前通道暂时不可用,已自动切备用` | |

> **前端展示统一规则**:下拉/标签/报错/系统旁白/进度,凡对用户可见处,一律走代称;需要"当前用的是哪档"时显示能力档(写实生图/创意生图/标准/增强),绝不出现 `seedream`/`doubao`/`gpt-image`/`openai`/`anthropic`/`claude`/`火山`/`方舟`/`volc`/`ark`/供应商域名。

## 5. 上报(dataeye)脱敏注意点(留给 task#16 上报重接)

> 现状:仓库里**没有活跃的 dataeye/telemetry 上报代码**(全仓 grep 无遥测发送逻辑;`report*` 命中的都是后台任务进度/桥接,非外发遥测)。所以这是**设计时约束**,写清防止重接时踩坑:

1. **载荷禁带真实模型名/供应商/endpoint**:凡上报里涉及"这轮用了哪个模型/哪家/哪个 baseUrl",一律换能力档代称或直接不报;复用第 3 节映射 + `scrubProviderIdentifiers`。
2. **禁带 PII**:门店真实名/地址/店主手机/客户资料/图片原图/工作区绝对路径/`.env` 值一律脱敏或不报(对齐全局规则第 2 节 + CLAUDE.md 台球红线)。路径只报相对形态或哈希。
3. **原始错误先清洗再报**:上报错误统一过 `scrubProviderIdentifiers`(去供应商/模型/endpoint)+ 去 Bearer/key,再截断长度。
4. **prompt/生成内容默认不外发**:用户 prompt、图片 prompt、生成图 base64 属敏感,默认不进上报;要统计只报计数/耗时/成败/代称档位这类非内容指标。
5. **上报出口单点**:所有上报走一个 `reportEvent()` 封装,在封装内强制跑脱敏白名单(只允许列出的非敏感字段),避免各处随手塞字段漏 PII/模型名。
6. **与白标一致性**:上报脱敏用的代称映射与前端展示**同一张表**(第 3 节),别两套口径漂移。

## 6. cc-haha 是怎么做模型白标/展示的(参考)

查了 `~/Desktop/cc-haha-ref`:
- cc **不直接把内部模型 ID 摆给用户**,而是过一层 `getPublicModelDisplayName(model)`(`src/utils/model/model.ts:377`)映射成"公开展示名",**未知模型返回 `null`**(即不认识就不硬展示原始 ID)。
- 状态栏/`/model` 走 `getModelDisplayLabel()`(`src/utils/status.tsx:366-372`):默认档显示 `Default <description>`(能力/档位描述),而非裸模型串。
- `src/server/api/models.ts:121` 对前端返回的是 `name: model.label`(展示名/标签),不是原始 ID。
- cost/attribution 用 `getCanonicalName` / `getPublicModelDisplayName` 收敛命名。

**对我们的启示**:cc 那套"内部 ID→公开展示名,未知则不展示"的模式正好可抄。差别是——cc 是 Anthropic 自家,公开名仍是 Sonnet/Opus;**我们白标更进一步:公开名不带任何厂商/模型线索,只给能力档(写实生图/创意生图/标准/增强),供应商与 baseUrl 一律不出。** 实现上照 cc 的"集中一个映射函数 + 出口统一调用"结构落地(即第 4 节的 `publicModelNames.ts` + `publicProviderSummary`)。
