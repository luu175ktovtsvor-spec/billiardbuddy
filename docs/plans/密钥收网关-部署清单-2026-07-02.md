## 2. 服务器 `gw.env` 要加哪些变量(只写变量名,值部署时手填)

需要确认/新增的是**限流参数**(有默认值,不改也能跑,量大再调):

```bash
# /opt/qfgw/gw.env 追加(可选,不填则用代码里的默认值)
GW_ARK_CHAT_RPM=30          # 火山豆包视觉/文本 令牌桶(每分钟请求数),默认 30
GW_ARK_IMG_IPM=20           # 火山 Seedream 生图 令牌桶(每分钟张数),默认 20
GW_ARK_IMG_CONC=6           # 火山 Seedream 生图 在途并发,默认 6
GW_Q_ARK_CHAT=500           # 每用户每日「视觉打分+导演配文案」调用次数上限,默认 500
GW_Q_ARK_IMG=20             # 每用户每日 Seedream 生图张数上限,默认 20
```

确认 `gw.env` 里已有:
```bash
GW_ARK_KEY=<火山方舟真 key,方舟控制台申请>
GW_ARK_BASE=https://ark.cn-beijing.volces.com/api/v3   # 默认值,一般不用改
```

## 3. nginx 怎么暴露(如果之前没配过 `/gw` 前缀转发,这次一并给)

网关只监听 `127.0.0.1:8799`(不直接对公网开放),对外统一走 nginx 的 `/gw` 前缀反代、去掉前缀转发给本地端口:

```nginx
# /etc/nginx/conf.d/qfgw.conf(示例,server_name/证书按实际域名或裸IP配置)
location /gw/ {
    proxy_pass http://127.0.0.1:8799/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";      # 长连接/流式响应必须关 Connection: close,否则 SSE 会被截断
    proxy_buffering off;                 # MiMo 流式对话必须关缓冲,否则 SSE 变成一次性吐完、前端看不到打字机效果
    proxy_read_timeout 1800s;            # 视频轮询/生图慢请求要给够,别让 nginx 先超时断了连接
    client_max_body_size 20m;            # 图生图/VLM 多帧网格图走 base64,请求体可能到几 MB,给够余量
}
```
```bash
nginx -t && systemctl reload nginx
```

验证 nginx 转发生效(裸 IP,别用域名,防本机代理劫持域名 DNS):
```bash
curl -s http://<网关IP>/gw/healthz
```

## 4. 怎么发 / 吊销 app 令牌

令牌就是 `gw.env` 里 `GW_APP_TOKENS` 这个 JSON 字典:`{"令牌字符串": "用户标识"}`。

**发新令牌(给一台新客户机器)**:
1. 生成一个随机字符串当令牌(如 `openssl rand -hex 24`,别用真实姓名/店名当令牌本身)
2. 编辑服务器 `/opt/qfgw/gw.env`,往 `GW_APP_TOKENS` 的 JSON 里加一条 `"<新令牌>": "<用户标识,如店铺编号>"`
3. `systemctl restart qfgw`(改 env 必须重启进程才生效,内存里没有热加载)
4. 把这个令牌填进对应客户机器的 `desktop/bundled.env` 四个 `<app令牌>` 位置,重打 DMG/EXE 或（如果支持热更新配置）直接替换文件

**吊销令牌(机器丢失/客户退款/怀疑扒包)**:
1. 编辑 `gw.env`,把 `GW_APP_TOKENS` 里对应的键值对删掉
2. `systemctl restart qfgw`
3. 该客户端后续所有请求立即变成 401(`app 令牌无效`),不用管客户端本身、不用远程操作对方电脑

**看谁在用、用了多少**:
```bash
curl -s "http://<网关IP>/gw/admin/usage?token=<GW_ADMIN_TOKEN>&n=50"
```

## 5. 每个通道的验证 curl(占位符替换成真值再跑;不计费的用免费端点,计费的量小)

```bash
GW=http://<网关IP>/gw          # 网关对外地址
TOKEN=<发给这台机器的 app 令牌>  # 替换成真令牌,别用真令牌以外的字符串测(会 401,属预期)

# 0) 健康检查(不鉴权、不计费)
curl -s "$GW/healthz"

# 1) MiMo 对话(流式,非计费也很小)
curl -sN -X POST "$GW/v1/chat/completions" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"mimo-v2.5","messages":[{"role":"user","content":"你好,一句话自我介绍"}],"stream":true}'
# 预期:SSE 逐块吐出 data: {...}，不是等全部生成完才一次性返回

# 2) GPT 生图(计费,先用最小尺寸/最短 prompt 测通路即可)
curl -s -X POST "$GW/v1/images/generations" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","prompt":"a red apple on white background","size":"1024x1024"}'

# 3)【新】火山豆包视觉/文本(非流式,量小,几厘一次)
curl -s -X POST "$GW/v1/ark/chat/completions" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"doubao-seed-1-6-250615","messages":[{"role":"user","content":"只回复:测试成功"}],"max_tokens":50}'
# 预期:200 + choices[0].message.content 里有内容；缺 GW_ARK_KEY 时应返回 503「视觉/文案功能未配置」

# 4)【新】火山 Seedream 生图(计费,预留通道——poster_service.py 客户端暂未接,只验网关自身通不通)
curl -s -X POST "$GW/v1/ark/images/generations" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"doubao-seedream-4-5-251128","prompt":"a red apple on white background","size":"2048x2048","watermark":false,"response_format":"url"}'
```

**401 验证**(令牌错/缺,应该被拦,不应该打到上游):
```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST "$GW/v1/ark/chat/completions" \
  -H "Authorization: Bearer 明显是错的令牌" -H "Content-Type: application/json" -d '{}'
```

## 6. 客户端 `bundled.env` 最终形态

打包前把 `desktop/bundled.env.example` 复制成 `desktop/bundled.env`(该文件已 gitignore,不进仓库),
按注释把 `<网关IP>` 和 `<app令牌>` 替换成真值(多处 `<app令牌>` 可以填**同一个**令牌,网关按令牌认机器不认通道):

```bash
DESKTOP_LOCAL=1
DEEPSEEK_BASE_URL=http://<网关IP>/gw/v1
DEEPSEEK_API_KEY=<app令牌>
TEXT_MODEL_NAME=mimo-v2.5
OPENAI_BASE_URL=http://<网关IP>/gw/v1
OPENAI_API_KEY=<app令牌>
IMAGE_MODEL_NAME=gpt-image-2
QF_GATEWAY_URL=http://<网关IP>/gw/v1
QF_GATEWAY_TOKEN=<app令牌>
BUNDLED_MODEL_LABEL=MiMo V2.5
BUNDLED_IMAGE_LABEL=GPT Image-2
```

**没有任何一行是真平台 key**——全是网关地址(公开信息)和 app 令牌(可吊销的通行证)。就算这个文件被人从
安装包里扒出来,拿到的也只是一张可以被服务器随时作废的"卡",不是能直接去 MiMo/OpenAI/火山官网用的真钥匙。

### dev-only 开发机后门(不要用于打包给客户的机器)
`server/services/video_edit/vlm.py` 和 `director.py` 在 `QF_GATEWAY_URL`/`QF_GATEWAY_TOKEN` 没配置时,
会退到 `ARK_API_KEY`/`VLM_API_KEY`/`VIDEO_LLM_API_KEY` 等 env 直连火山方舟——这是给开发机联调用的后门
(不用等网关部署好就能跑通视频剪辑台),**绝不能出现在发给客户的 `bundled.env` 里**。

## 7. 遗留风险清单(全部用变量名/占位符表述,不含真值)

1. **Seedream 生图客户端未接网关**:`server/services/poster_service.py`(第 236 行附近)目前桌面盒子内置的
   Seedream 生图分支仍然 `image_base_url = "https://ark.cn-beijing.volces.com/api/v3"` **直连火山方舟**,
   用的是 `settings.ark_api_key`(即客户端 `.env.bundled.local` / `bundled.env` 里的 `ARK_API_KEY` 真值)。
   本次已经在网关建好 `/v1/ark/images/generations` 通道,但**客户端接入是后续待办**(不在本次改动范围内,
   因为 poster_service.py / factory.py 归其他并行任务负责)。在客户端切过来之前,Seedream 生图这条链路
   的真 key 实际上还是打包在客户端的,不算完全收编。
2. **PG 密码轮换**:git 历史里如果出现过明文 PostgreSQL 密码(旧提交),需要找出对应仓库/commit 并轮换
   数据库密码——这是老仓库遗留问题,不在本次网关收编范围,单独跟进。
3. **老仓库明文密钥轮换**:据项目记忆(`bundled-models-gateway-direction`),老仓库（云端 `billiards-ai-ops`）
   历史提交里有明文密钥,需要排查具体是哪些 key(MiMo/OpenAI/其他)并逐个在对应平台后台重新生成、作废旧的。
4. **relay 令牌现状**:美国出口服务器(`zzyppz.cn`)的生产 `/relay/openai/` 通道令牌(`GW_RELAY_TOKEN`)
   和测试专用 `/relay/openai-test/` 通道令牌是两套隔离的令牌,值都只存在各自服务器的 env 文件里
   (`server/.env.usrelay.local`,本地 gitignored)。本次未改动 relay 侧,仅提醒:美国机的令牌轮换周期
   / 谁持有,建议单独建一份密钥轮换台账(不进代码仓库)。
5. **网关本身的单点风险**:目前 `qfgw` 是单台大陆服务器、SQLite 本地记账、无高可用——服务器挂了所有客户
   同时不可用。规模上来后需要评估 Redis 共享限流 + 多机部署(网关 README 已有此待办,非本次范围)。
6. **Seedream 生图未真机验证**:`seedream_image.py` 顶部注释自己写了"按官方文档写,但未真机验证"——
   即便后续客户端接入了 `/v1/ark/images/generations`,上线前仍需真账号跑一次校准(size 取值范围、
   base64 大图是否被接受)。
