# 工作目录 + 任意文件上传 + 入口更明显 · 设计 spec

> 2026-06-25。改底部输入框(composer)的文件处理,对齐 Claude Code 的"工作目录"主流做法。
> 本文是写给执行会话的设计依据:每块都给确切改哪个文件/函数,不留 TBD。
> **已定方案 = 选项一(忠实对标 Claude Code)**:工作目录是"默认上下文 + 低摩擦区",**不是牢笼**;全盘可达靠权限弹卡把关。

## 〇、为什么是选项一(对标 CC 的事实依据)

已核实 Claude Code 真实行为(出处:[permissions.md](https://code.claude.com/docs/en/permissions.md) / [how-claude-code-works.md](https://code.claude.com/docs/en/how-claude-code-works.md))。用 folder2 启动、没 `/add-dir`、默认权限档:

| 对工作目录外(folder1)的操作 | CC 实际行为 |
|---|---|
| 读文件 | 直接读、不弹卡(读类不拦) |
| 改文件 | 弹卡 → 同意就改 |
| 跑命令(读类/写类) | 读类直跑、写类弹卡 |
| 整机别处 | OS 能碰的都能碰,唯一把关 = 权限弹卡 |

→ **工作目录 = 默认/低摩擦区(窝里顺、出界问),不是硬墙。** 想真关墙得自配 deny 规则 / 给 Bash 开 OS 沙箱(默认都关)。
→ 故选项二(出界硬拒绝)比 CC 还严、是过度收紧,**弃用**。选项一忠实对标 CC。

## 一、目标(大白话)

1. **工作目录**:每个会话能"新建或选一个文件夹"当工作区,AI **默认在那建/写文件**,会话顶部显示当前工作目录;不同会话各自独立。像 Claude Code 选一个项目文件夹。
2. **可达范围不收(对标 CC)**:设了工作目录,AI **照样能访问电脑别处的文件**,靠权限弹卡把关。工作目录只是默认上下文,不是牢笼。
3. **自动接受编辑只在工作区内(CC 甜区)**:"自动接受编辑"档只在【工作目录 + 选定文件/文件夹 + 内容库】内免确认;**出了这范围的修改永远弹卡**(正是 CC 的 acceptEdits 行为)。
4. **粘贴任意文件**:从访达复制任何文件(PDF/Excel/任意类型)→ 输入框 Cmd+V 直接变附件。不再只认图片。
5. **入口更明显**:回形针讲清"加文件·图片·视频·文件夹都行";工作目录单列一项、可新建。

## 三、详细设计(逐块 + 确切改点)

### 3.1 `AgentContext` 加字段 — `server/services/agent/context.py`
```python
# 本会话工作目录(用户选/新建的文件夹绝对路径):相对路径默认落这 + 自动接受编辑的主范围。
# 空 = 无工作目录(行为同今天:相对路径落内容库)。可达范围不受它影响(对标 CC,全盘可达靠权限档把关)。
working_dir: str | None = None
```

### 3.2 `_resolve` 把工作目录当相对路径基准 + 允许根 — `local_tools.py:47`
- 相对路径基准改成工作目录优先:
  ```python
  base = (Path(ctx.working_dir).resolve() if getattr(ctx, "working_dir", None) else _library_root().resolve())
  path = (p if p.is_absolute() else base / p).resolve()
  ```
  (有工作目录 → 相对名落工作目录;否则维持内容库。绝对路径不受影响。)
- `full_disk_access=True`(默认)→ 维持现状直接放行(第 55 行不变)→ **全盘可达保留**。
- 允许根新增工作目录:沙箱校验段(fd False 时才走到)把"`path` 在 `ctx.working_dir` 内"也算放行,与内容库同级。

### 3.3 工作区判定 helper(给审批门控用)— `local_tools.py` 新增、导出
```python
def path_in_workspace(raw_path: str, ctx) -> bool:
    """目标路径是否在工作区内 = 内容库 ∪ 工作目录 ∪ 选定文件/目录 ∪ tool-results。
    相对路径按 (ctx.working_dir or 内容库) 解析。用于 auto_files 判"改这文件要不要免确认"。
    不抛、故障安全(判不了→False=更安全的弹卡)。**与 full_disk_access 无关**(它管免不免确认、不管能不能碰)。"""
```

### 3.4 自动接受编辑收口(CC 甜区)— `_auto_approve`(`loop.py:247`)
- 签名加 `args`:`_auto_approve(tool, args, ctx)`(`loop.py:518` 调用处补传 args)。
- auto_files 分支(`loop.py:259-260`)改:
  ```python
  if mode == "auto_files":
      if kind != "file":
          return False
      path = (args or {}).get("path")
      return path_in_workspace(path, ctx) if path else True   # 工作区内免确认;区外→弹卡
  ```
- `force_confirm` / `ask` / `full` / `plan` 全不动。→ 净效果:auto_files 从"全盘免确认"收成"工作区内免确认、出界弹卡",**对标 CC acceptEdits**。

### 3.5 run_command 默认 cwd 落工作目录(小增强,不动门控)— `local_tools.py:372`
```python
cwd = (args.get("cwd") or "").strip() or (getattr(ctx, "working_dir", None) or None)
```
- 门控(`:358` 要 full_disk_access)**不动**:fd 恒 True、命令照常能跑。只是没显式传 cwd 时默认在工作目录下跑(让"在这建文件/跑脚本"符合直觉,对标 CC 在 cwd 跑 bash)。

### 3.6 接口威胁线程(不动 `_resolve_permission`)
- **`AgentChatRequest`**(`agent.py:559` 附近)加 `working_dir: str | None = None`。
- **ExecuteRequest**(`agent.py:978` 附近)加 `working_dir: str | None = None`。
- **chat 构造 ctx**(`agent.py:856`)传 `working_dir=body.working_dir`。
- **execute 构造 ctx**(`agent.py:1026/1029`)同样传 `working_dir`,审批执行用同一工作目录解析路径(否则相对名解析不一致)。审批 token 绑模型原始 args、解析在执行时做 → 只需 working_dir 进 execute ctx,**不动签名逻辑**。
- ⚠️ **`_resolve_permission` 不改**(选项一不碰 fd 默认逻辑)。

### 3.7 注入模型(让 AI 知道默认在哪干活)— `agent.py:333` 附近(动态尾段)
有 `working_dir` 时加一行(措辞对标 CC、不说"牢笼"):
`当前工作目录:{working_dir}。新建/保存文件、跑命令默认在这里;你仍可访问电脑别处的文件,但改工作目录外的文件会先弹卡请用户确认。`
- 放动态尾段(非静态前缀),不破坏前缀缓存铁律。

### 3.8 前端 — 工作目录状态/入口/显示
- **状态**:`workingDir: string | null`,**新建的 per-conversation 持久化**(现有权限档/知识库偏好是全局存的,无 per-conv 先例):按 `conversation_id` 存 localStorage;切/重开会话恢复;新会话=null。⚠️ 新会话首条消息发出前还没 `conversation_id` → 先放 React state,等 `chat.conversationId` 回来再落 localStorage(套 `chat-shell.tsx` 现有"拿到新 conversationId 就刷新"时机)。随每条消息透传 `working_dir`(`use-agent-chat.ts` payload + `api.ts` streamAgent 加该字段,挨着 `selected_files`)。
- **设置入口**:回形针(📎)从"直接选文件"改成**小菜单**两项:
  - 「加文件 / 文件夹」→ 现有 `onPickFiles`(`files.pick({filesAndFolders:true})`)。
  - 「设为工作目录…」→ `files.pick({directory:true, createDirectory:true})`(见 3.10)。
- **显示**:composer 上方一条 chip「📁 工作目录:{basename} ✕」,套 `/goal` 目标条同位置(`chat-shell.tsx:304`)。点 ✕ 清空;hover/点名显示全路径。chip 旁小字(对标 CC、不暗示牢笼):`AI 默认在这建文件;碰别处文件会先问你`。

### 3.9 前端 — 粘贴任意文件(`handlePaste`,`desktop-composer.tsx:170`)
```
改判定:遍历 e.clipboardData.files / items(kind==="file")
  - 有真实路径的文件(f.path,访达复制来的)→ 直接拿 path 加附件(走与拖拽同一条路,免 saveTemp)
  - 只有字节没路径的图片(截图工具)→ 维持现有 saveTemp(保留扩展名)
```
- ⚠️ **真机需验**:Electron 渲染进程粘贴"访达复制的文件"是否给 `.path`。验不通则退回"saveTemp 任意类型字节"兜底。**实现时先验证再定走法,不凭记忆下结论。**

### 3.10 壳层 — 入口更明显 + 新建文件夹(`main.js:112`)
- `files:pick` 支持 `opts.createDirectory`:选目录时 `properties` 加 `"createDirectory"`(macOS 原生弹窗即带"新建文件夹"按钮)。
- 回形针 tooltip / 菜单文案讲清"加文件·图片·视频·文件夹都行"。

## 四、数据流(一句话串起)
```
用户点回形针→「设为工作目录」→ 系统弹窗(带新建文件夹)选/建一个文件夹
  → 前端存 workingDir(按 conversation_id)+ 顶部 chip「📁 + 默认在这建文件、碰别处会问你」
  → 每条消息 payload 带 working_dir → 后端进 ctx.working_dir(可达范围不变、全盘可达靠权限档)
  → ① 相对路径/新建文件默认落工作目录(_resolve)② run_command 默认 cwd=工作目录
     ③ 系统提示告诉模型默认在哪、出界改文件会弹卡
     ④ auto_files 档:工作区内编辑免确认、出界弹卡(_auto_approve + path_in_workspace)
  → 审批执行 /agent/execute 也带 working_dir,解析一致
```

## 五、不做(YAGNI)
- **不动 `full_disk_access` 默认 / `_resolve_permission`**:可达范围保持全盘(对标 CC),不收紧、无 run_command 连带。
- 不加"信任这个文件夹"独立开关(工作目录天然就是自动接受范围,CC 亦如此)。
- 不动数据库 schema(工作目录前端按会话持久化,后端每请求无状态收 working_dir)。
- 不动审批签名 / denial_tracker / 内容库默认可写。
- 不做"多工作目录"(主目录 + 选定文件已覆盖 CC 的"主 + add-dir")。
- 不做 deny 规则 / Bash OS 沙箱(CC 也默认关;真要更严后续单独做)。
