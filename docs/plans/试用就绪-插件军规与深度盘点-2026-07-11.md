## 一、生图/剪辑:你的直觉是对的,而且它就是你自己定的架构

**判词:"AI 在循环里直接操纵生图模型效果不如人工控制"——对,这正是项目里已经写死的"两条线"思想**(CLAUDE.md 核心原则总纲):生图/剪辑本体 = B 线确定性代码(路由/尺寸/质检/回滚全是写死的规则),循环只拿到"一个动词"级的工具入口;精细控制归工作台(人握方向盘),对话只当加速层。这也是"创作引擎 v2"当年四路验证的定论:默认=面板/预览保下限,质量=确定性检查+用户一眼挑,**不靠 AI 自评**。所以"加进循环"不是不合理——是"只把粗粒度入口加进循环、把方向盘留给人"才合理,现状架构正是这么长的。

**现状体检(以代码/文档为准,不粉饰):**

| 块 | 现状 | 缺什么 |
|---|---|---|
| 生图 | ✅健康:Seedream+GPT 双模型走网关、自动路由、跨引擎兜底、印刷模式、QC 骨架;已作为循环工具(make_poster/generate_image)真机验过 | ①人像授权闸/质检收口(task#11,助教照片是试用真场景)②**GPT 异步开关 QF_GPT_IMAGE_ASYNC 两台服务器已部署但未激活**——不开的话跨境长连接掐断问题还在,试用前必须置 1(纯配置)③React 生图工作台缺(task#39,vanilla 有) |
| 剪辑 | 🟡骨架健康:时间轴唯一真相源+原子操作+事务回滚+VAD 分流+B-roll 五步引擎,HTTP 路由能跑 | ①**循环里根本没有剪辑工具**(createMediaTools 只暴露生图;AI 想帮店主剪片都碰不到,task#37/#40)②**whisper 二进制+权重没随包**(task#41,用户机器上转写=占位字幕)③智能文案重写是本地占位(老媒体后端死链)④React 剪辑工作台缺 |

**剪辑接进循环的正确姿势**(等做 task#37 时照此):循环只给一个"用这批素材出一版草稿/按这句话调整草稿"的工具,产出的是**工作台里的可改草稿**,人看了才导出成片——绝不做"AI 一条龙出成品"。

## 二、MCP:纠一个认知,其余你理解的方向没错

**"大模型具备 Playwright 的 MCP 接口"——不对,MCP 接口长在我们的壳上,不长在大模型上。** 真实链路:我们的后端连上 Playwright MCP server → 拿到一串工具说明书(名字/描述/参数)→ **塞进每次发给模型的工具清单** → 模型看到"browser_navigate:打开网页…"这类描述,像挑内置工具一样挑它。所以"AI 能不能主动意识到"取决于三件事,全在我们手里:①连接成功(server 起得来)②工具描述写得清楚(何时该用)③工具清单没把模型淹死(40+ 内置 + MCP 一堆,弱模型会挑花眼)。

**试用版对 Playwright 的建议:二期再放,试用先不放。** 三个理由:①要给用户机器下载 node 运行时+浏览器(几百 MB,资产下载器还没建);②MCP 工具恒审批,浏览器自动化每一步点一次确认卡=没法用,得先设计"本会话允许浏览器操作"的记忆放行 UX;③国产模型驱动几十个细粒度浏览器工具的可靠性未经评测。试用版内置高德地图 MCP 就够(零依赖、走网关藏 key)。

## 三、插件建造军规(从你的两条线思想推导,以后每个"外造插件"照此验收)

1. **本体是确定性代码**:业务逻辑写死在 B 线服务里,绝不织进循环;循环只经三种廉价接口碰它(给模型一个工具 / 塞一条预定义 prompt / 后端直调)。
2. **只暴露"一个动词"**:给循环的工具要粗粒度、意图级("出一版海报草稿"),不暴露一堆细旋钮(旋钮是工作台的事);入参 schema 严格、结果可验收、失败可回滚。
3. **人握方向盘**:生成类插件产出草稿/多版本,人一眼挑;AI 不自评质量;质检是确定性检查,不可用就明说"未质检",绝不假装通过。
4. **降级要诚实**:插件依赖(模型权重/二进制/网络)没就绪,界面显示"正在准备组件 x%"并就绪后自动继续,绝不点了没反应(铁律 #3)。
5. **进出有账**:每个插件登记三样——资产清单(要下载什么,进资产管理器)/审批类别(碰不碰 对外·不可逆·花钱)/白标口径(对用户叫什么)。

## 五、替你想到的问题(你没提、我认为有分量的)

1. **模型单点风险**:整个产品体验绑在国产模型的"挑工具"能力上。行为对齐测试锁的是"壳判得对",没有东西锁"模型用得好"。→ 建一套**店主任务评测集**(20~30 个真实任务:改价目表/出海报/查周边/分析报表),换模型/升级前跑一遍,分数掉了不上线。这是"工程不出问题"里最容易被漏的一半。
2. **工具清单膨胀**:40+ 内置 + MCP + 领域包工具,对弱模型是认知负担 → 按场景瘦身(不挂台球包时不注册台球工具已做到;MCP 渐进披露已登记;后续可考虑"场景工具集")。
3. **弱机资源打架**:店里电脑跑 ffmpeg 出片 + 生图轮询 + 对话并发,CPU 可能顶死 → 媒体 job 加并发上限(小活,登记)。
4. **版本升级不丢数据**:transcript 这轮改了存储格式,migrations 机制已有;试用期每次推更新前,**旧数据升级路径必须进回归**(把"拿真旧 state 目录升级"写进验收脚本)。
5. **完全断网的表现**:店里网络抽风时,应用得说人话("网络不通,已保存你的输入")而不是转圈——降级文案过一遍(小活)。
6. **多窗口并行你说"没大问题"——基本属实**:多会话/后台任务/子代理机制都在;真正的坑在上一条(弱机资源)而不在机制。
