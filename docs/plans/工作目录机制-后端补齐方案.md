# 工作目录机制 · 后端补齐方案

## 0. 这份文档要解决什么（大白话）

owner 的核心洞察：模型上下文有限、每开一个新窗口就是一次全新对话，靠 cc-haha 那套「项目记忆常驻注入 + memdir 自动记 + 会话持久化 + **工作目录锚定**」机制，AI 才不会失忆、不显笨。这四环里，**工作目录锚定是总开关**——因为几乎所有「按项目分区」的东西（项目记忆、自攒记忆、历史会话、权限规则、命令技能）都是拿「工作目录的路径」当钥匙去分区的。**换工作目录 = 换一整套记忆和会话空间。**

owner 具体问的四点，本文逐条给答案：
1. 不选文件夹时，**默认工作目录在哪**（后端必须提前设好）。
2. 「新建文件夹」vs「使用现有文件夹」的逻辑。
3. 选文件夹涉及**访问电脑权限**（弹「允许访问其他数据」）。
4. 用户选了目录，模型就**直接在该目录工作**；不选，模型在**一个全局工作目录**工作。

调研范围：cc-haha 参考实现（`~/Desktop/cc-haha-ref`）、我们现状（`ts/src` + electron 壳）、WorkBuddy 的 UX 与后端契约。

## 1. cc 工作目录机制全貌

先建立一张总图，后面所有补齐都对着它。

### 1.1 一句话本质
cc 桌面端架构 = **Electron 壳 + 前端 React + 后端 server sidecar + 每会话 spawn 一个 CLI 子进程**。工作目录这条链贯穿四层：前端选目录 → 后端把它当 workDir → spawn CLI 子进程时 `cwd = workDir` → 子进程内部把 `originalCwd / projectRoot / cwd` 三个状态全指向 workDir → 所有工具（读/写/glob/grep/bash）解析相对路径都走这个 cwd → 于是「模型只在选定目录里干活」。

### 1.2 默认 cwd（没选文件夹落哪）
- 纯 CLI：落在你敲命令时的终端目录（`process.cwd()`）。
- 桌面/后端会话（我们要抄的这条）：**前端没传 workDir 时，后端兜底成 `os.homedir()`（用户主目录 ~）**。
  - 关键点：`sessionService.ts:2566-2567` `const resolvedWorkDir = workDir || os.homedir()`。
  - server 配置里另留了一个显式默认位 `ServerConfig.workspace`（注释：给没指定 cwd 的会话用的默认工作目录）——**这就是「后端提前设好默认工作目录」的官方挂点**。

### 1.3 选/切文件夹
- 前端选择器 `DirectoryPicker.tsx`，三种来源：最近项目（从 `~/.claude/projects/*` 历史反解）、**原生系统文件夹对话框**（Electron `showOpenDialog` + `openDirectory`）、Web 兜底目录树。
- 切目录 = `onChange(path)` 改选择器的值 → store 用新 workDir 建新会话。

### 1.4 「新建」vs「使用现有」——cc 里没有两条路
- **代码里没有单独的「新建文件夹」分支**。macOS/Windows 的原生文件夹对话框自带「新建文件夹」按钮，用户在系统弹窗里当场新建再选，回来的都是一个绝对路径。「新建」和「用现有」是**同一个 `showOpenDialog` 出口**。
- 注意：`createSession` 里的 `fs.mkdir(..., {recursive:true})` 建的是**元数据目录** `~/.claude/projects/<sanitized>/`，**不是 workDir 本身**——workDir 必须已存在，否则 `startSession` 校验直接抛 `WORKDIR_INVALID`。

### 1.5 权限——三层，别混
1. **OS 系统级文件访问（就是「允许访问其他数据」弹窗）**：macOS TCC 权限由**原生 `showOpenDialog` 触发**——用系统选择器选中文件夹，就是 app 拿到该位置读写权的方式。选完后端 `registerFilesystemAccessRoot(absWorkDir)` 把该根加进白名单，预览/浏览 API 才肯读它。默认只放行 `~` 和 `/tmp`。
2. **App 级信任门（trust dialog）**：`config.projects[path].hasTrustDialogAccepted` 按项目存。会从 cwd 沿父目录 + git root 往上找有没有被接受过的标记。信任门管 hooks 是否执行、部分 auth。
3. **每工具的工作区围栏（真正「模型只能在选定目录里干活」的执行点）**：`allWorkingDirectories = originalCwd ∪ additionalWorkingDirectories`；**在工作目录内的读写自动放行**；在工作目录外 → `behavior:'ask'` + 建议「Always allow / add-dir」，用户点了才把外部目录加进围栏。
   - 一句话：**选中的 workDir = originalCwd = 自动放行区；区外要么弹「允许」要么被 ask 拦。**

### 1.6 全局 vs 项目——三态 cwd，别搞混
| 概念 | 语义 | 谁改它 |
|---|---|---|
| `originalCwd` | **文件操作基准**：工具解析相对路径、transcript/CLAUDE.md 锚定 | 会话中途 worktree、resume 会改 |
| `projectRoot` | **稳定的项目身份**：history/skills/cron/memdir 都认它，会话期保持稳定 | 只在启动定 |
| `cwd`（当前） | 当前所在，可被 AsyncLocalStorage 按异步上下文覆盖，让并发子代理各看各的 | setCwd / override |

- cc 内核里**没有单一的「全局工作目录」变量**，「全局」实际指配置/记忆家目录 `~/.claude`（settings、projects/、全局 CLAUDE.md 都在这）。owner 说的「不选文件夹时的全局工作目录」= 后端兜底的那个 workDir（cc 里是 `os.homedir()`）。
- owner 要的「选了目录模型直接在该目录、不选则在一个全局工作目录」正好对上：选目录 = 把 workDir 设成该目录（既是 projectRoot 又是 cwd）；不选 = 用固定全局目录做 workDir。

### 1.7 记忆/会话怎么按目录锚定（不失忆的机理）
**核心思想一句话**：几乎所有持久化都用「工作目录路径」当 key，把路径 `sanitize`（非字母数字→`-`）后当文件夹名，存进 `~/.claude/projects/<sanitized>/`。换工作目录 = 换 key = 换一整套记忆/会话；同一个 git 仓库的多个 worktree 被 `findCanonicalGitRoot` 归一到同一套记忆。

| 东西 | 锚在哪个目录变量 | 落点 |
|---|---|---|
| 会话 transcript（`<id>.jsonl`） | **originalCwd** | `~/.claude/projects/<sanitize(originalCwd)>/<id>.jsonl` |
| memdir 自动记忆（MEMORY.md + logs） | **projectRoot 的 canonical git root** | `<memBase>/projects/<sanitize(gitRoot)>/memory/` |
| 项目记忆（CLAUDE.md 家族） | **originalCwd 的目录链**（从 cwd 往上到根逐层读，再加 ~/.claude 用户级） | 各层 CLAUDE.md + .claude/rules |
| skills/commands/agents | cwd → gitRoot 链，每层 `.claude/<subdir>` | — |

- **换目录 = 换记忆吗？→ 是。** transcript 按 sanitize(originalCwd) 分文件夹、memdir 按 sanitize(gitRoot) 分文件夹、CLAUDE.md 按目录链读。换 workDir，三样 key 全变 = 加载另一套记忆/会话。这正是「打开哪个文件夹 = 进入哪个项目的记忆空间」。
- **git root 归一**：同一仓库主 checkout 和所有 worktree 归一到同一 memory 目录，避免每个 worktree 一套记忆。

### 1.8 新对话怎么把该目录的记忆加载回来（不失忆的落点）
**核心不变量**：sessionId 和它的 projectDir **原子绑定**（`switchSession(sessionId, projectDir)` 一起改，绝不漂移）。三条加载回来的路径：
1. **CLI resume/切目录**：恢复会话时 `setOriginalCwd(session.workDir); setCwdState(session.workDir)`——从 session-meta 里记的 workDir 把 cwd 重新指回去，CLAUDE.md/skills/transcript 全部按老 workDir 重新锚定。
2. **桌面 resume**：workDir 在建会话时就写进 transcript 的 `session-meta`；恢复时读出来 → 带 `--resume sessionId` + `CALLER_DIR=workDir` 重新 spawn，子进程 chdir 回该目录。
3. **打开一个老文件夹开新对话（同目录不同会话）**：因为记忆按目录锚定，只要 workDir 一样，`getMemoryFiles` 就重新加载同一份 CLAUDE.md（常驻注入系统 prompt），memdir 的 MEMORY.md 通过检索回来，历史会话可见可续。**→ 同一文件夹再打开，CLAUDE.md + MEMORY.md + 过往 transcript 自动回来，这就是「不失忆」的落点。**
- 换目录时要**清缓存**（`clearMemoryFileCaches()`）否则读到旧目录记忆；`getAutoMemPath` 以 projectRoot 为 memoize key，projectRoot 变则自动重算。

### 1.9 ⚠️ cc-haha 的专门补丁（Bug#5，必抄）
光在 spawn 时设 `cwd:workDir` **不够**。子进程 preload 顶层会执行 `if (process.env.CALLER_DIR) process.chdir(process.env.CALLER_DIR)`。打包桌面里 server sidecar 被从 `cwd=/` 启动，CALLER_DIR 继承成 `/`，于是即便 spawn 传了 `cwd:workDir`，preload 又把它 `chdir('/')` 打回根目录 → AI 感知的工作目录废掉、记忆/会话锚定全废。
**修法**：childEnv 里显式覆盖 `CALLER_DIR: workDir` 和 `PWD: workDir`。**这条我们打包后一定会踩，必抄。**

## 2. 默认工作目录该设哪（不选文件夹时的全局工作区）

### 2.1 我们现状（问题所在）
- 不选文件夹时 = `workspaceFromBody()` 兜底 `process.cwd()`（`ts/src/server/index.ts:662`）。
- 这个 `process.cwd()` = sidecar 启动 cwd = Electron `app.getPath('userData')`（`main.ts:65`，macOS ≈ `~/Library/Application Support/球房管家`）。
- **三个问题**：
  1. 它是个**用户在 Finder 里根本找不到的隐藏 App 支持目录**——模型生成的生图/报表/剪辑产物会写进这里，用户找不到。
  2. 它跟 stateRoot（`~/.billiardbuddy/state`）、library（`~/.billiardbuddy/library`）是**三个不同的隐藏目录**，各管各的，没有一个显式命名的「全局工作区」常量。
  3. ⚠️ **风险点**：`workspaceFromBody`/`touch`/run 端点全都 `?? process.cwd()` 兜底。如果哪条路径 sidecar 不是从 userData 起（或未来改动），打包后从 Finder 启动 cwd 会是 `/`，不选文件夹 = 模型在 `/` 干活 = 写不下/乱写。

### 2.2 建议（后端提前设好一个显式全局工作区）
**不要裸落 `~`，也不要继续隐式复用 sidecar 的 cwd。** 设一个固定、命名清楚、用户可发现的全局工作目录常量。两个候选，二选一由 owner 拍：
- **A. 用户可见路径**：`~/Documents/球房管家/`（或 `~/Documents/BilliardBuddy/`）。优点：用户在 Finder 找得到生成物，体验好；缺点：落在 Documents，macOS 会触发一次 TCC「允许访问文稿」授权。
- **B. App 私有路径**：`~/.billiardbuddy/workspace/`。优点：不触发 TCC、稳定可写、跟其他 `.billiardbuddy` 目录同族；缺点：隐藏，用户默认找不到生成物。

**落地要点（无论选哪个）**：
1. 后端起 server 时把它写进一个显式常量（对齐 cc 的 `ServerConfig.workspace`），所有 `?? process.cwd()` 兜底改成 `?? DEFAULT_WORKSPACE`。
2. **启动时 `mkdir -p` 确保存在**——否则 Workspace 构造/校验会失败。
3. 存进配置、允许在设置里「更改」（对齐 WorkBuddy「默认工作空间存储路径」那一行：只读 input 显示当前值 + 「更改」按钮调原生选择器）。

> 白标铁律：命名一律中性 `BilliardBuddy`/`.billiardbuddy`，绝不出现 `Claude`/`.claude`。

## 3. 「新建」vs「使用现有」+ 权限的后端逻辑

### 3.1 新建 vs 现有——我们已就位，无需两套分支
- `ts/desktop/electron/main.ts:303` `desktop:pickWorkspace` 已用 `properties: ['openDirectory','createDirectory']` 调原生选择器。`createDirectory` 让 macOS 对话框右下角自带「新建文件夹」按钮——**选现有=直接选，新建=对话框里现建再选，后端一视同仁拿最终路径**。这块契约后端已就位，和 cc/WorkBuddy 一致。
- **决策点（可选延伸）**：若产品想区分「新建时初始化项目」（新建目录时自动写 `.billiardbuddy/`、放一份欢迎版 `BILLIARDBUDDY.md`、登记为新项目），目前没有这层，需专门做。

### 3.2 权限——三层，对应到我们
1. **逻辑围栏（我们自己的，已有）**：`Workspace.resolve()`（`ts/src/workspace/workspace.ts:33-48`）路径必须在 `root` 内 / 命中 `allowedPaths` / `fullDiskAccess===true`，否则抛 `WorkspaceBoundaryError`，叠 symlink 逃逸检查。
   - `allowedPaths` ← body 的 `selected_files`；`fullDiskAccess` ← body 的 `full_disk_access`（对应前端「允许完全访问」盾牌开关）。
   - 运行时可扩：`additionalWorkingDirectories`（= cc 的 `/add-dir`）+ `withAllowedPaths()`。
2. **OS 写围栏（已有）**：`ts/src/sandbox/sandbox.ts` 把命令包进 OS 沙箱（macOS seatbelt / Linux bwrap），`writablePaths=[workspace.root]`，默认开，缺依赖优雅降级。
3. **macOS TCC 隐私授权（就是「允许访问其他数据」弹窗）——⚠️ 完全没做**：
   - 全仓无 `systemPreferences` / `getMediaAccessStatus` / Full Disk Access 任何调用。现状全靠 macOS 自己弹，App 不主动请求、不检测授权状态、被拒后只回 EPERM 报错文本、无引导用户去系统设置的兜底。
   - **两条「权限」别混**：应用内「允许完全访问」= 沙箱围栏松紧档（`fullDiskAccess`）；macOS「完全磁盘访问」= 系统给不给整个 app 读盘的权，是 TCC。选文件夹时若选了 Documents/Desktop/Downloads，Electron 原生框本身也会触发 TCC。
   - **补齐参照 WorkBuddy 的三个工程细节**（设置→系统授权页，仅 macOS）：① 懒检查（只对用户点过「去授权」的项检查，避免首装就弹 osascript 框吓人）；② window focus 回刷（macOS 授权后无回调，靠 focus 重查）；③ 去授权深链 `x-apple.systempreferences:` 先 `execFile('/usr/bin/open',[url])`、失败再退 `shell.openExternal`（否则 Sonoma 点了没反应）。三项权限：完全磁盘访问 / 辅助功能 / 自动化。

### 3.3 信任门——选新文件夹的安全闸（地基已有，UX 没接）
- 选了个新文件夹 = 一个**未受信工作区**。未受信时该目录的 `.billiardbuddy/settings.json` 里的 allow 规则不生效、`.mcp.json` 不自动 spawn、工作区来源的 hook 不执行（`ts/src/server/index.ts:967-976`，信任源都是 `McpTrustStore.isTrusted(workspaceRoot)`）。防恶意文件夹一选中就绕过审批闸。
- 地基（task #28）已建；缺的是**选新目录时触发一次「信任这个文件夹吗」授予**（入口 `POST /agent/mcp/trust` 或 startServer `trustedWorkspaceRoots`），选文件夹 UX 还没接上信任提示。

## 5. 我们现状 vs cc 差距 + 后端补齐清单
