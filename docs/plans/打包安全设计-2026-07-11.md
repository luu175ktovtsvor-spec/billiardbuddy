# 打包安全设计:防解压读取代码/敏感信息

> 📌 owner 要:安装包被解压/被读取软件扫时,代码 + 敏感信息怎么保护。"打包前必须想清楚"(实现打包前才做,本文是设计)。已核实真实威胁面。

## 一、威胁模型(核实过,非猜)

| 攻击场景 | 能读到什么 | 核实 |
|---|---|---|
| 解压安装包 + 逆向 sidecar 二进制 | bun --compile 二进制**内嵌 JS bundle 明文**:全部后端代码 + 台球知识 + 守卫 + 白标逻辑 | ✅`strings 二进制` 搜到 21 处 billiards/台球/sessionStartContext |

| 抓取随包配置 | 若打包塞了 app 令牌 → 可盗用网关 | 见下"功能缺口" |

## 二、皇冠珠宝**已被保护**(最重要的结论)

**真 provider key(OpenAI/Ark/MiMo,值钱的)只在网关服务器 `/opt/qfgw/gw.env`(chmod 600),客户端从来没有。** 已核实:网关藏 key、客户端只带**可吊销 + 限流 + 限配额**的 app 令牌。→ **就算整个客户端被解压逆向,偷不到贵的 provider key**(最坏是盗用令牌,而令牌可吊销+限流+限配额+可绑机器)。这条架构决策把最灾难的风险堵死了。

## 三、真实缺口 + 设计(功能与安全一体)

### 🔴 缺口:打包后 app 拿不到网关令牌(功能 + 安全一体)
核实:`bundled.env` **不在 electron-builder 的 files/extraResources**(dev 才用)→ 打包后 `applyEnvFiles` 找不到 → **无网关配置 → 连不上模型**。这既是功能缺口,也决定"令牌怎么进客户端"这个安全命门。

**正确设计 = 首启设备激活(一石二鸟)**:
1. 安装包**只带网关 URL**(非机密)+ 激活机制,**不带任何令牌**(包里没令牌可偷)。
2. 首启:门店输入 **激活码**(owner 每家试用店发一个)→ app 拿激活码去网关 `/activate` 换一个**绑定本机 machine_id 的专属令牌** → 令牌经 **safeStorage(复用 credentialKey 的 Keychain/DPAPI + AES-256-GCM)加密存本地**,绝不明文落盘。
3. 网关侧:`/activate`(激活码→机器绑定令牌)+ 令牌校验加 **machine_id 绑定**(令牌首次使用记录 machine_id,之后从别的机器用→拒)。
**收益**:①包里无令牌(解压无所获);②每店专属令牌(泄露只牵连一店,吊销即断);③令牌被从本地扒走→换台机器用无效(machine_id 不符);④顺带解决"打包后连不上模型"的功能缺口。
**要建**:网关 `/activate` 端点 + machine_id 绑定校验(我有网关权限);客户端首启激活流 + 令牌 safeStorage 存取(复用 credentialKey)。**打包前做**。

### 🟡 台球知识"护城河"(分阶段)
二进制明文可读 = 台球知识/守卫/白标逻辑可被扒。
- **试用期(10~20 家信任店)**:接受二进制可读,真实风险低,不额外做。
- **广泛分发**:核心台球知识**加密放后端**(task#23:prompts.enc 式,运行时从网关取解密,或知识直接由网关下发不入包)→ 包里没有明文知识。**打包/分发前做**。

### 🟡 本地数据加密
- providers.json:✅已 AES-256-GCM(credentialKey DEK)。
- transcript(可能含门店 PII):当前明文。建议**复用同一把 DEK 加密 transcript 落盘**(读取软件扫 userData 也拿不到明文对话)。**试用前可做,中等优先**。

### ⚪ 二进制混淆:不投入
bun --compile 二进制本质可逆(任何本地二进制都可逆),混淆是弱防御、ROI 低。**正确姿势 = 假设客户端全可读,保证里面没有灾难级机密(真 key)——已做到**。不为"看起来安全"投混淆。

## 四、优先级(对齐上线)
| 项 | 何时 | 为什么 |
|---|---|---|
| **设备激活 + machine_id 绑定**(网关 /activate + 客户端首启激活 + safeStorage 存令牌) | **打包前必做** | 既补"打包后连不上模型"功能缺口,又堵令牌提取风险 |
| transcript 落盘加密(复用 DEK) | 试用前(中优先) | 门店 PII 防本地扫读 |
| 台球知识加密/后端化(task#23) | 广泛分发前 | 护城河;试用期可缓 |
| 二进制混淆 | 不做 | 弱防御、ROI 低;皇冠珠宝已不在客户端 |

## 五、一句话给 owner
最值钱的东西(真 provider key)**已经不在客户端、在网关服务器**——解压逆向偷不走。剩下要做的是**首启设备激活**(包里不塞令牌、每店专属、绑机器、加密存),它同时补上"打包后拿不到令牌连不上模型"的功能缺口——这是打包前的头号必做项;台球知识护城河与本地 PII 加密按分发阶段跟进;二进制混淆不值得做。
