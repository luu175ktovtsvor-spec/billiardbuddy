## 0. 为什么这么做(对齐预期 · 防鸡肋)

**一句话**:给台球房店主一个"懂台球、剪他自己拍的素材、出能发抖音/小红书短视频"的 AI 创作工作区——剪真素材是主力,生成/数字人补缺口,模板保底,用户一眼挑/微调兜质量。

**主选 = 剪店主自己拍的素材**(不是凭空生成),理由:① 店主天天在拍(口播促销/店面/助教活动),有料;② 口播是他们最好的内容、也是这套的甜区(已验证);③ 剪辑是他们的真痛点;④ 跟产品同物种(本地 + LLM + 工具)。

**替代路权衡(都掂过,没有更优的单选)**:
- 纯生成(描述→全 AI 视频):本地门店营销靠"真店面/真助教/真老板"转化更好,AI 凭空生成 stock 味重、贵、慢、真人脸有红线 → 不如剪真素材。当"没素材"时的补充。
- 纯模板库(CapCut 式):拼数量必输 CapCut,不是我们的牌。模板当"保底层"用,不当主体。
- 数字人(照片+脚本生口播):给"不想出镜"的店主当补充,不是主选。
- → 最优 = **统一创作台:剪真素材当主力 + 模板保底 + 生成/数字人补缺口**(产品已在往这走:图片台 i2v 跳转视频台、统一归创作工作室)。

**★防鸡肋三铁律(违反必鸡肋)**:
1. **主打口播**(强项打头,别一上来秀氛围);
2. **氛围走「edit + 模板保底 + 用户挑/微调」,别纯自动甩**;
3. **老实框预期**——卖"省 90% 功夫、出能发的初剪、再点几下成好",**别卖"全自动出爆款"**。

**成片预期(诚实定档)**:
- **口播 → 直接能发、效果好**(已用 1.mp4 真机验证:77万→90万营业额口播 剪成 26 秒竖屏 钩子→数字→CTA + 真字幕)。
- **氛围/无口播 → "能看的初剪",约 CapCut 一键成片七八成**(卡点蒙太奇 + 挑较好看的镜头 + 跟主体竖屏 + 配乐),用户挑/微调后到"好"。诚实短板:卡点差一点点、美学分挑得"安全平淡"(漏名场面)、多人偶尔跳/跟错主角。
- **上限取决于素材**:garbage in, garbage out;AI 救不了烂素材。

## 2. 核心架构:时间轴文档当唯一真相源 · 三段解耦

```
① 编辑视图(前端)  ←→  ② 时间轴文档(JSON·真相源)  ←→  ③ 渲染器
   人挑/圈点 + AI 改        稳定ID映射·分轨道·校验           FFmpeg 确定性出片
```
- **②时间轴文档** = 谁在第几秒、哪段接哪段、字幕/音乐在哪轨。AI/手动/圈点 三种编辑**全归一成"对它发原子操作"**,在此层统一校验 + 撤销/重做。
- **AI = 改文档的操作**,不出黑箱片(EditDuet/LAVE 范式)。
- 数据模型用**稳定 ID 映射(不用数组下标)**防 AI 改下标错位;时间用浮点秒。

## 3. 双模式 + 后台双 Planner「干净分裂」

**口播模式 / 氛围模式 都做成【可选】**(用户显式选剪法;自动判断可当默认建议、但用户能改):

```
口播Planner(转录→挑话+插B-roll) ─┐
                                  ├→ 都输出同一份【时间轴文档】→ 同一套预览/导出
氛围Planner(切镜头+节拍+视觉挑镜+reframe→卡点) ─┘
```
**只在"出方案(Planner)"这层分裂,下面的文档/原子操作/预览/渲染全共享**(像 loop.py 同步/流式共享状态机、只在分叉处分)。这就是"两条管线干净分开、不揉成一坨"。

- **口播 Planner**:whisper 转录(已有)→ 按内容挑段 → 自动字幕(已有)→(可选)在停顿处插环境 B-roll(需视觉理解判"哪段是环境")。
- **氛围 Planner**:PySceneDetect 切镜头(已有)→ 节拍检测 → 视觉挑镜(美学/质量分)→ auto-reframe 跟主体 → 卡点排布 → 配乐。

## 4. 创作工作区(独立形态)+ 客户端预览/服务端导出

**从"slash 窄抽屉"升级成独立创作工作区**(slash 保留当快捷入口):
```
┌─ 视频创作工作区 ───────────────────────────────┐
│  ┌───预览播放器(边播边圈·秒级)──┐  ┌─右:控制台─┐ │
│  │                            │  │ 模式口播/氛围│ │
│  └────────────────────────────┘  │ 大白话输入   │ │
│  ┌─下:时间轴(可圈点)──────────┐  │ AI 剪辑方案  │ │
│  │ [段1][段2] 字幕轨 音轨 框选改 │  │ 参数(比例…) │ │
│  └────────────────────────────┘  └───────────┘ │
└────────────────────────────────────────────────┘
```

**★关键架构:预览走客户端、导出才走服务端**(同一份时间轴文档喂两端)——这是"好用/响应快"的命门:
- **预览端(浏览器·秒级)**:`<video>` 按文档播源片的选定段 + DOM 字幕浮层 + audio 配乐,改一刀立刻看到,不等 FFmpeg。
- **导出端(服务端·慢但只跑一次)**:FFmpeg 按同一份文档确定性出最终成片。
- (现状是连预览都 FFmpeg 重渲=55秒,卡;必须改成客户端预览。)

**可圈可点 = 两个维度**(类比生图的 mask,视频多个时间维度):
- **时间上圈点**:时间轴框选某段/某剪辑点 → 针对性改(换素材/裁短/卡一刀/改字幕)。
- **空间上圈点**:某帧上圈一块 → 裁切/重构图/放大跟主体(也解决横转竖跟人)。
- 本质 = 选中时间轴文档的某部分 → 只对它发一个原子操作,**现有架构原生支持**。

**输出比例可选**:竖 9:16 / 方 1:1 / 横 16:9 / 保持原片(现写死 9:16,要做成选项)。

## 5. 全免费商用选型(每块 + 许可 + 本地/云)· ★避雷

> 判据:permissive(MIT/Apache/BSD/ISC/CC-BY)=能免费商用;copyleft(GPL/AGPL)和 非商用(CC-NC/S-Lab/研究许可)=不行。**代码许可与模型权重许可分开看(已一手 LICENSE 核实)。**

| 块 | 免费商用选型 | 许可 | 备注 |
|---|---|---|---|
| 切镜头 | PySceneDetect | BSD ✅ 已有 | |
| 转录 | faster-whisper | MIT ✅ 已有 | |
| **节拍卡点** | **librosa.beat** 默认;要更准上 **beat_this**(CPJKU·ISMIR2024·含权重) | ISC / MIT | librosa 卡规整鼓点够;偏晚 0.02-0.06s 补 offset |
| **挑好看的镜头** | **OpenCV 启发式**(废片闸门)**+ LAION 美学预测器**(排序)结合 | Apache / Apache+MIT | 标准做法:先毙废片再排美学 |
| **auto-reframe 跟主体** | 单人 **MediaPipe**;多人 **YOLOX+ByteTrack**;自加 One-Euro 平滑 | Apache / Apache+MIT | 单人≈Smart Reframe 七八成 |
| **VLM 看懂内容** | ✅ 已定走**云端 API·智谱 GLM-4.6V-Flash**(免费·见 §6);本地方案(Qwen2.5-VL-7B 等)已取消(店主机扛不住) | 云 API | 只在"懂语义"才上,别拿它算清晰度;分层(启发式→CLIP→VLM) |

**★必须避开的雷**:
- **Ultralytics YOLOv11 = AGPL**(传染copyleft,闭源商用要开源全app或买授权)→ 换 YOLOX/RT-DETR原版/MediaPipe。
- **DOVER 美学评分 = S-Lab 非商用** → 换 LAION 美学 + OpenCV。
- **madmom 模型权重 = CC-BY-NC** + **aubio=GPL** + **Essentia=AGPL** + **BeatNet 拖 madmom** → 节拍用 librosa/beat_this。
- **InsightFace 模型 = 非商用 → pyautoflip 别用**;**Qwen2.5-VL-3B=研究版、InternVL3 继承Qwen底座、LLaVA 带 Llama 限制** → VLM 用 7B 或 Moondream2/SmolVLM。

**结论:全免费商用能凑齐、不用花钱。**

## 6. VLM「看懂内容」放哪跑(✅ owner 已拍板 2026-07-01)

**铁律:VLM 一律走云端 API,不做本地部署。** 理由 = 店主电脑配置普遍偏低(办公本/集显),本地 7B 需 Apple Silicon 16G+ 或独显 8G+ VRAM,**大多跑不动、电脑扛不住**;凡吃硬件的重模型都推到云上、不占店主算力,任何破机器都能用。**「本地打包 Qwen2.5-VL-7B / Moondream2」方案取消,不再考虑。**

**主用 = 智谱 GLM-4.6V-Flash(云 · 免费)**:
- 免费、且比老款 GLM-4V-Flash 强一大截(9B,通用看图 VQA 反超 Qwen2-VL-72B);key 由 owner 提供,已真机验通(文字 + base64 看图均 200)。
- ⚠️**模型名用 `glm-4.6v-flash`,别用 `glm-4v-flash`**(后者是最弱的老款)。
- ⚠️**图片必须 base64 直传,别喂外网 URL**——智谱服务器在国内拉不动海外图床(实测报 `1210 图片解析错误`);咱们抽的是本地视频帧,天然适合 base64。

**阿里百炼 Qwen-VL:已取消**(owner 2026-07-01),不作为 VLM 方案。

**机制**:云端模型在供应商服务器跑;网关(`gateway/app.py` 已部署 CN 机)只**藏 key + 转发**,真 key 在服务器 `gw.env`,**店主 app 只带令牌、永远不碰 key**(与现有生图/生视频内置 key 同套路)。

**保险**:智谱免费档官方未承诺永久(GLM-4.5-Flash 有下线先例、有速率限制),所以**网关上游做成可换**——真要切,项目已握**硅基流动(生图)/火山方舟(Seedance)** 两把现成 key,都有强视觉模型可顶上,不必赌死智谱一家。
