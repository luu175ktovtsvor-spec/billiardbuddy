### ⚠️ 协作页（多 Agent）与 worker 数的已知问题

后端跑 **2 个 uvicorn worker**，而多 Agent 协作页（`/dashboard/workbench/collaborate`）的任务状态存在**进程内存**里（`orchestrator._tasks`，未落库）。发起任务的 worker 与前端轮询命中的 worker 可能不同 → 约 50% 概率返回"任务不存在"。

**处置（部署前决定其一）：**
- 短期：若主推协作页，把 backend 改 `--workers 1`（牺牲部分并发，但协作页稳定）；
- 长期：协作任务落库（见 `docs/遗留工作清单.md` 协作页补强项），之后可恢复多 worker。
- 工作台主链路（非协作页）不受影响——它用数据库存生成记录，与 worker 数无关。

### AI 图片生成架构

| Provider | API | 状态 | 原因 |
|----------|-----|------|------|
| `OpenAIImageProvider` | `images.generate` + `images.edit` | ✅ 在用 | 标准 Image API，无需组织验证 |
| `OpenAIResponseImageProvider` | Responses API（gpt-4o） | ❌ 未注册（死代码） | 需要 Organization Verification，无法通过 |

**为什么用标准 Image API：** Responses API 需完成 Organization Verification，账号无法通过，故用标准 Image API。

**"多轮对话"如何实现：** 标准 Image API 不支持 `previous_response_id`，通过 `images.edit` 把上一张图作为底图（`refine_from`）传入实现"基于此调整"；参考图（用户上传）与底图可同时传入，prompt 内声明各自角色。

**OpenAI 接口地址：** 生产直连 `https://api.openai.com/v1`（美国节点实测 ~80ms 正常）。Cloudflare Worker 代理仅为国内本地开发的备选（直连不通时用）。出口 IP 为阿里云美国（AS45102），如遇 OpenAI 对机房 IP 风控再考虑切代理。

## 七、常见问题

### 后端启动失败
```bash
journalctl -u billiards-backend -n 50 --no-pager
# 常见：.env 配置错误、数据库连接失败、端口占用、语法错误
```

### 前端白屏（日常部署已自动构建，仅异常时手动）
```bash
ls /var/www/billiards-ai/web/.next/standalone/.next/static/
# 若缺失则手动构建
cd /var/www/billiards-ai/web && npx next build --no-lint
cp -r .next/static .next/standalone/.next/static
systemctl restart billiards-frontend
```

### 协作页报"任务不存在"
见 §一 的 worker 警告——2 worker 下内存任务跨进程不可见，改单 worker 或等落库改造。

### 生图失败
- 检查 OPENAI_API_KEY 是否有效、账户是否欠费
- 直连 `api.openai.com` 测试：`curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://api.openai.com/v1/models`（返回 401 即网络正常，只是没带 key）

### API 502
```bash
systemctl status billiards-backend && nginx -t
```

### SSL 证书过期
```bash
certbot renew && systemctl reload nginx
```
