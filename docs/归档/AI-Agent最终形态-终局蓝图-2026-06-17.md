## 〇、产品立场（最高纲领，先立这条）

> **这是给台球行业内部人用的运营工具**——不上架应用商店、不对公众开放。**内容必须贴合真实运营逻辑（台球行业真实运营逻辑/`球房运营逻辑基准.md`），不为"政治正确"过度消毒。** 一定不违背每个岗位的运营逻辑与岗位职责。

**真实运营逻辑（必须吃透、不得违背）**：
- 球房**主要靠助教挣钱**。助教是商业球房**核心岗位 + 氛围引擎**（"商业球房氛围最主要因素=助教数量"），带"形象/情绪价值/陪伴"性质——**该擦的现实进内部理解，该擦必须擦**。**助教管理岗核心职责 = 招助教、带助教、让助教挣到钱**。
- 客群是**四类个人客户**（基准 §1.6 根模型）：散客（线下社交）、竞技（技术交流·小赌怡情爱好者）、助教（情绪价值）、追分（输赢刺激·气氛热烈·确实在赌钱）。**球房必须有博弈类客户**。消费主体是个人/亲朋好友/家庭/朋友局；**企业本质=个人娱乐**（最多订包厢），不是独立客群。
- 教练价值 = 增加竞技客户基数；店长/助教管理/教练核心都是**营销 + 让人赚到钱**，不是单纯陪打/管人。

**度的把控原则（2026-06-17 用户最终拍板，取代早先"对内/对外校准"的折中）：全真实、不消毒、没有"度"。** 这是给行业内部人用的工具，内容全部往真实行业靠——消毒过头就不是这行的内容、就是乱编。以下真实内容/词汇照常出现，**不再转译、不再禁**：
- 助教情绪价值/颜值/形象/陪打/陪伴/暧昧感、"美女助教""点助教""大哥客户"等真实口语；
- 助教推广/抖音引流可走**颜值/形象/暧昧感的"擦边"营销路线**；
- 助教**刷交友软件**（探探/陌陌/Soul）获客（真实渠道，可建议可写话术）；
- **追分/博弈客群**（追分/约局/台费局/赢一把/小赌怡情/热闹围观）照实写氛围。

**只守两条底线 —— 这是"真实"本身、不是消毒**：
1. **不编造**：助教姓名/年龄/身高/价格/照片、客户历史、门店变化/新设备、竞对信息——未知用占位符（编了＝乱编＝违背真实）。
2. **助教是台球陪练 + 门店不碰刑事线**：颜值/暧昧感可作营销氛围但落点始终是台球陪打；不营销**实际性交易**（客人越界→保护助教、拉回打球，见 `assistant_difficult_situations`）；博弈客群可服务，但**门店本身不亲自抽水/组局/定盘口/放贷**（开设赌场罪）。另保留商业真实：助教付费不写免费/不作赠品、不打包赢包教保票、不写全城最低价（虚假宣传/广告法）。

## 一、先正面回答你的三个问题（带证据）

### 问题 1：小豆芽这类「一键转发抖音/小红书」——官方接口资质，还是自研？

**事实答案：绝大多数是「自研」（浏览器自动化/RPA/指纹多开/模拟登录），不是平台官方授权。**

- 小豆芽靠**多开浏览器 + 指纹浏览器**为每个账号造独立指纹环境（模拟不同设备/系统/内核/IP），规避平台"同一设备批量操作"风控——典型反检测 RPA，不是 API。[二手]
- 易媒助手要用户**交账号密码/扫码绑定**，模拟发布。官方 API 用 OAuth、从不要账号密码。[二手]
- 开源同款（social-auto-upload 等）坐实技术栈 = **Playwright/patchright 浏览器自动化 + 扫码/Cookie 登录**，README 明写"零 API 依赖、模拟真人操作"。[官方/GitHub]
- 平台官方代发 API 确有（抖音 `create_video`、快手 `photo/publish`），但要企业资质 + 公函 + 代发权限审批 + 逐号 OAuth + 数量上限——轻量工具基本不办。[官方] 小红书根本无"发笔记到账号"官方 API。[二手]

**→ 产品决定（用户 2026-06-17 拍板）：可做，列为「可选能力」。** 你已定"技术能实现就做、灰产无所谓"。我把它从原"永久红线"改为**可选能力**，决策只看 ROI 与维护成本，不看"灰不灰产"。落地要点（给你做范围决策的真实风险梯度）：
- **风险不是铁板一块**：单店**自有号、原创内容、低频**发布 ≠ 矩阵号批量同质内容。小红书 2024 一月清退 125 万号[二手]，靶心是**矩阵号批量二创/跨账号引流**——单店自有号原创低频发，风险**显著低于**矩阵场景（但仍是灰产、平台改版/风控升级随时可能挂）。
- **技术路径**：与小豆芽同款 = Playwright/patchright + 指纹/多开浏览器 + 扫码/Cookie 登录 + 定时调度。最现实是**门店自己的号、半自动**（人扫码登录→AI 备内容→到点模拟发布）。
- **责任归属（你做范围决策时权衡）**：号是门店的，封了门店会怪到我们头上——所以建议**默认半自动（人确认）+ 单店自有号**，不做"替很多门店批量矩阵代发"（那才是真高危且支持负担大）。
- **个人微信自动群发/一键转发是单独一档**：腾讯打击最狠（《微信个人帐号使用规范》明令、永久封号）[官方]，比抖音/小红书 RPA 风险高一个量级。技术上同样能做，但**单列出来让你单独决定**，别和小豆芽式多平台发布混为一谈。
- 详见第四节「对外动作」与开发计划「一键发布可选track」。

### 问题 2(a)：GUI 怎么实现？是「能直接修改电脑软件」的类型吗？

**答：不是，也不该是。我们的桌面版 = 把网站装进一个桌面窗口（PWA→Electron 套壳连云后端），不是 AI 去点你电脑上的软件。**

「让 AI 直接操作桌面软件」（点后台、改文件、跑命令）对台球老板是**负资产**：① OSWorld 基准上通用电脑操作成功率仅 38%~72%[二手]，1/4~1/2 任务会失败，误操作=真金白银亏钱；② 门槛与支持负担爆炸（要配 server/命令行/API key）；③ 不可控。

> 注意：这条和「一键发布」不矛盾。一键发布是**固定流程的内容分发自动化**（半自动、人确认、单店号），可控性远高于"AI 自主操作整台电脑"。我们做前者、不做后者。

### 问题 2(b)：OpenClow（小龙虾）能直接改软件 + 有记忆系统，参考它？

**答：你记的是 OpenClaw（昵称小龙虾，差一字母），真实存在（开源、GitHub 24 万+ star）。操作路线不学，记忆工程可借鉴。**

- OpenClaw 是「个人电脑操作层」Agent——自主写脚本/读写文件操作电脑[二手]，属问题 2(a) 否决的那条路（23 万实例暴露、有文件被窃/¥499 代装[二手]）。
- 它的「记忆」**不是模型真记住**：本地 .md 日记 → 分块（~400 token、80 重叠）→ 嵌入 → SQLite 向量库 → 今昨常驻、更早按需语义召回。[二手]

**→ 含义**：**操作路线坚决不学，记忆工程可借鉴**——其分块/检索策略与我们 **P2 的 pgvector 店脑高度同构**（分块 ~400 token、近期常驻、旧记忆语义召回），但我们放云端 DB、人在环可看可改，更适合多端 SaaS。

| 客服·常见问题 | ❌ 未成型 | FAQ 话术库+一键回复（只备内容不自动应答）|

### 3.4 自带查漏补充（5 维分析没显式覆盖的真实场景）
- **多店连锁/加盟**：暂用"门店切换+各店独立店脑"，连锁报表归 POS，不做复杂多租户层（后续看连锁客户）。
- **投诉/差评公关**：补"差评/投诉回应话术卡"（P2，纯内容层）。
- **消防/安全/夜班巡店**：前厅已有"巡店安全卡"，补消防自查/夜班交接清单轻补丁（P3）。

**矩阵结论**：补全主要靠**两个画像字段**（业态 `无人店` + 客群 `女性/青少年/亲子`）让 96 卡管道自动吐差异化内容；助教层是**调度"度"而非堆卡**；只对真缺骨架的少数场景（青少年招生、团购操盘、FAQ、差评、追分客群运营）新建少量卡。

## 五、风险、边界与待你拍板的开放问题

### 5.1 两条永久硬边界（任何功能不得越）
1. **POS 只读不控**：开台/计费/灯控/收银/一卡通余额/上钟计时/库存全归 POS，我们只"读数字写判断"。
2. **不帮经营/组织级犯罪**：服务助教/追分/竞技客群的运营/话术/氛围/维护照做；但不生成赌场抽水组局放贷、组织/容留性交易这类把老板送进去的操作。守这条=保护老板。

### 5.2 一键发布（可选能力）的风险，由你做范围决策
- **风险梯度**：单店自有号·原创·低频·半自动（人确认）→ 灰产但相对低危；矩阵号批量同质 → 高危（小红书 2024 清退 125 万即此类[二手]）；个人微信自动群发 → 最高危（腾讯打击最狠[官方]）。
- **建议默认范围**：单店自有号 + 半自动（人扫码登录、AI 备内容、人确认后到点发）；不做"替很多门店批量矩阵代发"（高危+支持负担）；个人微信单列、单独决定。
- **责任归属**：号是门店的，封了会怪我们——半自动+人确认是"出事有人背锅"的护栏，也复用现有审批闸。

### 5.3 诚实标注的不确定项（落地前官方查证）
OSWorld 成功率、Electron 签名报价、小红书清退 125 万、微盟 58 场景——均**二手**；短信触达门槛**未查证**；智谱 AutoGLM 桌面细节**未查到**；各平台"真发"资质以 `docs/references/P3对外平台-官方文档与资质清单.md` 为准、落地前重核。

### 5.4 待你拍板的开放问题
1. **一键发布范围**：是否就按"单店自有号 + 半自动 + 人确认"做？平台范围（抖音/小红书/快手/视频号）？个人微信要不要纳入？（建议：先做抖音+小红书半自动，个人微信暂缓）
2. **助教对外公开内容的"度"**：对外公开发布的擦边尺度你定一条线（比如"可颜值/亲和/陪伴、不露骨不性暗示"），我据此校准转译词库——还是对内对外都放开、由门店自己把关？
3. **一线员工日活**：助教/前厅给独立轻账号入口，还是继续"管理岗代写"？（建议：先给只读卡片货架轻入口验证日活）
4. **桌面 Electron 套壳**：等老板明确要"装机版"再做？（建议：PWA 先上、Electron 看信号）
