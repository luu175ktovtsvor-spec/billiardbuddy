## 5. 工作法(照已完成 4 单的成功模式·就是 superpowers 的 `subagent-driven-development` skill)
1. 拆单前先 grep/读真码把落点定死(侦察给了 file:line 但行号可能已漂,让实现子代理**验证而非照抄**)。
2. 每单派**全新 Sonnet 子代理**实现(owner 指定 Sonnet·覆盖 skill "最省模型"默认):施工单写 `.superpowers/sdd/e-batch/e-briefs/`、报告写 `e-reports/`,**走文件 handoff 不塞主窗口上下文**。TDD、`uv run pytest tests/ -q` 全绿、改接口跑 `python3 scripts/build_coupling_map.py --write`。commit message 末尾**不加 Co-Authored-By**(项目无此惯例)。
3. 实现完 → `scripts/review-package BASE HEAD`(BASE=派实现前记的 commit·**别用 HEAD~1**·交错历史用精确哈希)生成 diff 包 → 派 **Sonnet 审查子代理**(spec 符合度 + 代码质量两结论)。脚本在 `/Users/swl/.claude/plugins/cache/claude-plugins-official/superpowers/6.1.1/skills/subagent-driven-development/scripts/review-package`,审查模板同目录 `task-reviewer-prompt.md`,输出写 `.superpowers/sdd/`。
4. Critical/Important → 派**一个**修复子代理(带全部 findings·只重跑覆盖测试)→复核。小修复(删死码/补日志/去重)主窗口可读修复 diff 自查代替重型复审。Minor 记台账留全分支复审裁。
5. **流水线**:一个 writer(实现/修复)+ N 个 reader(审查)可并发;**绝不两个 writer 同分支**(git 撞车)。Track A 与 Track B 文件不重叠,可"上一单只读审查 ‖ 下一单实现"交错。每单 commit 哈希即时记台账。
6. 每单审干净 → SDD ledger 追加一行 `单N: complete (commits base7..head7, review clean)`。
