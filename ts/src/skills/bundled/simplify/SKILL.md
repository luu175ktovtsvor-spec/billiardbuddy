# 代码复查与清理

把所有改动过的文件过一遍——复用、质量、效率——发现问题就地修掉。

## 阶段一:找出改了什么

运行 `git diff`(有暂存改动就 `git diff HEAD`)看改动。若没有 git 改动,就复查本次会话里你刚编辑过、或用户提到的最近改动文件。

## 阶段二:复查三个维度

改动较大且 `Task` 可用时并发派三个复查子任务；改动较小时直接按同样三个维度检查。先读取模块公共入口，避免把跨域重复误抽成无归属的共享代码。

### 子代理 1 · 复用复查

逐处改动:
1. **搜既有工具 / 助手函数**看能不能替掉新写的代码(常在 utils 目录、共享模块、被改文件的相邻文件里)。
2. **标出任何和既有功能重复的新函数**,指出该用哪个现成函数。
3. **标出本可以用现成工具的内联逻辑**——手搓的字符串处理、手动路径拼接、自定义环境判断、临时类型守卫等,都是常见候选。

### 子代理 2 · 质量复查

同一批改动,查这些糙写法:
1. **冗余状态**:重复已有状态、本可推导的缓存值、本可直接调用的 observer/effect
2. **参数膨胀**:给函数不停加新参数,而不是重构 / 泛化已有参数
3. **带小改动的复制粘贴**:近乎重复的代码块,该抽成共享抽象
4. **抽象泄漏**:暴露本该封装的内部细节、破坏既有抽象边界
5. **字符串硬编码**:在已有常量 / 枚举(字符串联合)/ 品牌类型的地方用裸字符串
6. **无谓嵌套**:不带布局价值的包裹元素
7. **无谓注释**:解释「代码在干啥」的注释删掉(好命名已说明),只留非显然的「为什么」(隐藏约束 / 微妙不变量 / workaround)

### 子代理 3 · 效率复查

同一批改动,查效率:
1. **无谓的重复工作**:重复计算、重复读文件、重复网络 / API 调用、N+1
2. **错失的并发**:互相独立的操作却串行跑
3. **热路径变胖**:给启动 / 每请求 / 每渲染的热路径新加阻塞工作
4. **反复的空更新**:轮询 / 定时器 / 事件回调里无条件触发的 state/store 更新——加变更检测守卫,没变就别通知下游
5. **无谓的存在性预检**:操作前先查文件 / 资源是否存在(TOCTOU 反模式)——直接操作、处理错误就好
6. **内存**:无界数据结构、缺清理、监听器泄漏
7. **过宽操作**:只需一部分却读整个文件、只筛一个却加载全部

## 阶段三:修

汇总发现后逐条就地修。若某项会改变外部契约、用户行为或扩大主责模块，跳过并单独报告，不混进清理批次。
