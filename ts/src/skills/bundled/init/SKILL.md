# 初始化项目记忆:生成 BILLIARDBUDDY.md

用户的额外要求(如有):$ARGUMENTS

你要为当前代码库生成一份 **`BILLIARDBUDDY.md`**(文件名就叫这个,写到工作区根目录;别用别的文件名)。它是「以后打开这个项目先读的说明」,让助手快速上手。

## 第 1 步:摸清这个仓库

真去读、别猜:
- 读 `README`、`package.json` / `pyproject.toml` / `Cargo.toml` 等清单文件,拿到常用脚本(构建 / 测试 / 跑起来 / lint)。
- 从仓库根到当前目录读取适用的 `AGENTS.md` 和同类项目指令；记录优先级，不复制互相冲突的旧口径。
- 用 `LS` / `Glob` / `Grep` 摸清目录结构、主要模块、技术栈。
- 找出代码风格与约定:格式化配置、命名习惯、测试怎么组织、有没有既有的贡献指南 / cursor 规则等,把有用的并进来。

## 第 2 步:若已存在就改、别覆盖

- 若工作区已有 `BILLIARDBUDDY.md`,读它,在此基础上**增补 / 更新**,保留仍然正确的内容,别整篇推倒重来。

## 第 3 步:写 BILLIARDBUDDY.md

内容精炼、可执行,建议含这几块:
- **常用命令**:构建、测试(含跑单个测试)、lint、启动 / 运行的确切命令
- **架构速览**:主要模块 / 目录各干什么、数据大致怎么流、关键边界
- **改动路由**:若仓库已有模块地图或工程 Skill，记录改动前应如何判定主责模块和验证范围
- **代码约定**:风格、命名、测试组织方式、其他"新人容易踩"的约定
- **注意事项**:该项目特有的坑、非显然的约束

只写你**真在仓库里核实过**的东西,别塞泛泛的"最佳实践"空话。写完告诉用户文件存在哪、记了哪几块,可直接编辑微调。
