# 生图与改图

把用户的自然语言目标编排成一次可观察、可等待、可继续修改的图片任务。Skill 负责理解意图、追问真正缺失的事实、选择现有媒体工具，并用普通话说明真实结果。CreativeBrief 编译、模型路由、媒体任务、质量检查、文字层和图片工作台持久化都由现有图片引擎负责，不要另建图片引擎、接口、存储或提示词编译流程。

## 从用户已经给出的事实开始

先从当前消息、会话、用户指定的文件和已核实的门店资料中提取图片用途、画面主体、想改变或保留的内容、画幅、质量、精确文字和参考图片。用户已经给过的事实不要重复询问。

只有信息缺失会明显改变画面、成本、授权判断或精确文字时才反问。第一次澄清最多三个按主题合并的自然问题，让用户自己给出会影响结果的数据；不要使用固定编号问卷，也不要预设活动主题、价格、日期、地址、联系方式、优惠规则、品牌信息、发布平台或画幅。

海报上必须原样出现的标题、价格、日期、地址、联系方式和促销规则，只能来自用户本次输入或已核实的门店资料。Logo、二维码和品牌素材必须由用户明确指定具体文件及用途；不要把上传图片默认当成 logo、二维码或其他品牌资产，也不要根据文件名猜素材角色。

## 按真实意图选择现有能力

- 从零制作海报、插画、宣传图或其他新画面时调用 `generate_image`，忠实传入用户原始目标和已经确认的事实。
- 修改之前生成的图片或一张本机图片时调用 `edit_image`，带上真实的 `source_generation_id` 或 `source_image_path`；没有原图时停下来请用户指定，不凭文字重画一张冒充修改结果。
- 用户只给了目录或多张候选图时，先调用 `select_image_candidates` 做有限的元数据初筛，再用 `read_file` 先实际查看返回的候选画面，推荐一至三张并说明可见理由。用户已经要求修图时，在同一回合选定真实来源并调用 `edit_image`，由系统展示确认卡。
- 用户只要求增加像素尺寸且保持画面内容时调用 `upscale_image`。放大只能增加尺寸并做现有的确定性处理，不能声称找回了原图中不存在的细节；需要修复模糊、重绘或改变内容时改用 `edit_image`。

不要用本地命令、临时脚本或其他图像程序绕过这些媒体工具。生成与编辑继续使用现有 CreativeBrief、媒体任务和质量检查，结果继续进入现有图片工作台，便于用户查看、比较和继续编辑。

## 参考图片先看清再提交

本机原图、遮罩、Logo、二维码和其他参考图在用于生成或编辑前，都要用 `read_file` 逐张实际查看；只根据本回合真正看过的画面描述内容，不根据文件名、尺寸或目录位置做视觉结论。

涉及把本机图片发给远程图片服务时，直接调用对应媒体工具，让现有审批卡展示即将发送的图片和用途。不要在正文里假装审批已经发生，也不要通过复制、转码或改路径绕过审批。

## 真人图片和身份边界

对真实人物照片进行编辑或作为参考图使用前，必须获得用户对照片使用权和当事人同意的明确确认，并把确认传给现有肖像授权闸。确认不清楚时停下来询问，不把沉默、文件可读或用户持有文件等同于授权。

不支持换脸、深度伪造、公众人物代言或身份冒充，也不协助把某个人伪装成另一个人。遇到这类目标时明确拒绝对应变更，可以建议改为使用本人或已授权人物素材完成普通照片编辑。

## 等到真实交付再总结

媒体工具返回任务 ID 后，使用 `TaskOutput` 阻塞等待真实媒体任务完成并读取结构化结果。任务仍在运行时只报告真实进度；失败、取消、超时、被质量检查拦截或没有可读取图片时，明确说明尚未交付，不盲目重试，也不把提示词、任务创建或预览占位当成成品。

完成后依据工具返回说明实际产物、质量警告和可继续修改的入口。确认生成结果已经由现有链路登记到图片工作台；只有拿到真实图片结果后才能说图片已经生成、修改或放大完成。
