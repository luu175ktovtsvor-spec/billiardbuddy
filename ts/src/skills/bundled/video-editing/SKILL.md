# 剪视频

## 核心原则(两条线 + 人握方向盘)
1. **引擎干帧级活,你只做粗粒度编排**:切镜头、代表帧理解、转写、字幕、时间线和渲染由 B 线 `plan_video`/`render_video` 完成。你(A 线)只负责:忠实传递目标 → 调工具 → **按真实 plan_summary 复述方案 → 等确认 → 出片 → 汇报**。不要自己拼 FFmpeg 命令，也不要把技术流程当成剪辑方案讲给用户。
2. **先看素材、别假设片种**:门店视频三类——① 口播(有人说话)② 环境/氛围(空镜、无口播)③ 口播+环境混。不同片种剪法完全不同,先判再剪。
3. **改前先确认(硬规矩)**:**绝不在用户确认方案前出片**。先出方案、大白话讲清"我打算这么剪",用户点头了再 `render_video`。

## 流程(对话里这么走)
1. **拿素材**:问清/收集用户要剪的**本机视频绝对路径**(可多段)。
2. **出方案**:调 `plan_video`:
   - `video_paths`(必填)、`goal`(自然语言意图,如"剪成30秒抖音、去空镜、配节奏")、`target_duration_s`、`aspect`(9:16竖/1:1方/16:9横)、`mode`("speech"口播/"ambient"氛围,拿不准就不传,让引擎自动判)。
   - 这是后台任务，用返回的 `TaskOutput({task_id,block:true,timeout:120000})` 等待。结果里的 `plan_summary` 是唯一复述依据；不要根据文件名或常识补写没有出现的画面。
3. **复述方案 + 等确认**:`plan_summary` 回来后，用大白话说明系统理解、口播/画面视角、总时长、主要选段与理由、缺失覆盖和候选取舍。不要逐项倾倒内部字段。然后问用户“按这个方案先出一版，还是调整?”——**等确认**。
4. **出片**:用户满意 → 调 `render_video`(`project` = plan 返回的项目名;`preview:true` 可先出快速低清预览)。出片=本地文件,不弹审批,直接做。
5. **汇报**:只有 `render_video` 完成且返回成片 URL 才能说已出片。同步报告时长和质检警告；若缺音视频轨、画幅/时长错误或解码失败，工具会失败，必须明确告诉用户尚未交付。用户要改就回第 2 步重出方案。

每次 plan/render 都保留项目名、任务 id、输入路径和输出路径的对应关系；失败重试不得悄悄换素材或覆盖上一版成片。

## 剪法手艺(借 video-use,按片种)
- **口播路(audio-first)**:服务器语音转写返回时间戳 → 按"说完一句/停顿"切 → 烧字幕。要点:别切在词中间;留 30–200ms 气口;静音≥400ms 是最干净的切点;保住笑点/金句别切掉。
- **环境/氛围路(scene/beat-first)**:切镜头 → 技术筛查黑场/冻结/曝光/运动 → 让视觉模型只看受限数量的压缩代表帧 → 按实际可见主体、动作和镜头关系编排。没有用户确认的文案时不生成卖点字卡。
- **通用**:竖版 9:16 最适合抖音/朋友圈;短视频 15–30 秒最好;每刀切口引擎已自动 30ms 淡入淡出去爆音。

## 组件没就绪时
分析和出片依赖 FFmpeg/ffprobe；口播转写默认走服务器，客户端不下载转写模型。组件没下好时工具会返回“正在准备组件 x%”——**如实告诉用户组件仍在准备，绝不假装已经完成**。

## 边界
- 真人肖像/助教出镜:沿用媒体工具现有的肖像输入授权规则,视频编辑本身不增加审批流程。
- 不承诺"一键出大片";复杂需求分步来,每步让用户看、让用户挑。
