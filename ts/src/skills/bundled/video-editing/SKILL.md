# 剪视频

## 核心原则(两条线 + 人握方向盘)
1. **引擎干帧级活,你只做粗粒度编排**:切镜头/卡点/字幕/渲染是确定性程序(B 线,`plan_video`/`render_video` 内部的本地 ffmpeg+whisper 管线),你不逐帧算。你(A 线)只负责:把用户的话翻成参数 → 调工具 → **用大白话复述方案 → 等确认 → 出片 → 汇报**。
2. **先看素材、别假设片种**:门店视频三类——① 口播(有人说话)② 环境/氛围(空镜、无口播)③ 口播+环境混。不同片种剪法完全不同,先判再剪。
3. **改前先确认(硬规矩)**:**绝不在用户确认方案前出片**。先出方案、大白话讲清"我打算这么剪",用户点头了再 `render_video`。

## 流程(对话里这么走)
1. **拿素材**:问清/收集用户要剪的**本机视频绝对路径**(可多段)。
2. **出方案**:调 `plan_video`:
   - `video_paths`(必填)、`goal`(自然语言意图,如"剪成30秒抖音、去空镜、配节奏")、`target_duration_s`、`aspect`(9:16竖/1:1方/16:9横)、`mode`("speech"口播/"ambient"氛围,拿不准就不传,让引擎自动判)。
   - 这是后台任务,用 `list_background_tasks`/`read_background_task` 轮询拿方案。
3. **复述方案 + 等确认**:方案回来后,**用大白话讲**:判成了口播还是环境片、切了几段、配没配乐/字幕、素材有没有问题(footage 提醒)。然后问用户"这么剪行不行,还是要调?"——**等确认**。
4. **出片**:用户满意 → 调 `render_video`(`project` = plan 返回的项目名;`preview:true` 可先出快速低清预览)。出片=本地文件,不弹审批,直接做。
5. **汇报**:拿到成片路径,告诉用户在哪、多长、怎么样;用户要改就回第 2 步重出方案。

每次 plan/render 都保留项目名、任务 id、输入路径和输出路径的对应关系；失败重试不得悄悄换素材或覆盖上一版成片。

## 剪法手艺(借 video-use,按片种)
- **口播路(audio-first)**:本地 whisper 逐字转写 → 按"说完一句/停顿"切 → 烧字幕。要点:别切在词中间;留 30–200ms 气口;静音≥400ms 是最干净的切点;保住笑点/金句别切掉。
- **环境/氛围路(scene/beat-first)**:切镜头 → 挑好看的镜头(避黑场/糊/发呆)→ 让 AI 看懂每个镜头 → 按音乐节拍卡点排 → 叠门店卖点字卡。要点:纯转写对空镜没料,靠画面+节奏。
- **通用**:竖版 9:16 最适合抖音/朋友圈;短视频 15–30 秒最好;每刀切口引擎已自动 30ms 淡入淡出去爆音。

## 组件没就绪时
出片依赖 ffmpeg / 口播依赖 whisper 权重。没下好时工具会返回"正在准备组件 x%"——**如实告诉用户"组件在后台下,好了自动能剪,稍等",绝不假装剪好了**。

## 边界
- 真人肖像/助教出镜:沿用媒体工具现有的肖像输入授权规则,视频编辑本身不增加审批流程。
- 不承诺"一键出大片";复杂需求分步来,每步让用户看、让用户挑。
