# Skillify:把这次的流程沉淀成技能

你要把本次会话里那套「可重复的做事流程」提炼成一个可复用技能。别急着写,先看懂、再采访、最后落盘。

用户对这次流程的描述:$ARGUMENTS

## 第 1 步:先自己看懂这次干了啥

回看本次会话,理清:
- 到底完成了一件什么可重复的事(一句话说清)
- 输入 / 参数是什么(每次做这件事,得让用户先给什么)
- 分成哪几步、按什么顺序
- 每步「做成了」的标志是什么——不是"写了代码",而是"PR 开好且 CI 全绿"这种硬标准
- 用户在哪几处纠正、掰过方向(这些最该写进「规则」)
- 用到了哪些工具、要哪些权限、有没有派子代理

## 第 2 步:采访用户(全程用 AskUserQuestion,别用纯文字问)

一轮不够就多轮,直到用户满意。每题都给具体选项,同时留白让用户自己补充;别自己加"需要微调"之类的选项。

- **第 1 轮 · 高层确认**:给技能起个名 + 一句话描述,请用户确认或改名;确认这技能的目标和「做成了」的判定标准。
- **第 2 轮 · 补细节**:把你梳出的高层步骤按编号列出;若需要参数,基于观察建议参数名;问清该「就地执行」(inline,过程中要用户插话把方向)还是「派子代理独立跑」(fork,自成一体、不需中途插手)。
- **第 3 轮 · 拆每一步**:逐个关键步骤问清——这步产出什么给后面用、怎么算成功、动手前是否要用户确认(尤其合并 / 发送 / 删除这类不可逆动作)、哪些步骤能并行、有哪些硬规则。步骤多(超过 3 步)就一步一轮多问几次。
- **第 4 轮 · 收尾**:确认这技能「什么时候该自动触发」,连同触发口令一起定下(如"发日报""复盘这次改动")。

简单流程别过度采访,够用就停。特别留意本次会话里用户纠正你的地方,那里最能反映他的偏好。

## 第 3 步:落盘为技能

用 `create_skill` 工具把技能写到用户目录 `~/.billiardbuddy/skills/<name>/SKILL.md`。参数填全:
- `name`:短横线小写名(如 `daily-report`)
- `description`:一句话说清这技能干嘛(中文)
- `whenToUse`:什么时候该自动触发,以「用户说…」开头并给触发口令示例
- `allowedTools`:这次真正用到的最小权限工具集(用模式,如 `Bash(git:*)` 而不是整个 Bash)
- `instructions`:技能正文——目标 + 分步 + **每步成功标准** + 硬规则;不可逆动作标「先请用户确认」

## 第 4 步:确认并收尾

落盘前先把完整 SKILL.md 内容贴给用户过目,再用 AskUserQuestion 简短确认「这样存可以吗」。写完告诉用户:
- 存到了哪
- 怎么调用(`/<name> [参数]`)
- 可以直接改那个 md 文件来微调
