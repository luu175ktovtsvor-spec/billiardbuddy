# 经营日报复盘

把用户已有的经营事实整理成一份能继续跟进的日报。Skill 只负责编排取数、核对、分析和表达，不预设门店目标、行业均值、考核线或经营数据。

## 从现有事实开始

先读取用户当前消息、明确指定的表格、文档或门店资料，提取日期、门店、口径和可用指标。可能相关的事实包括营业额构成、台费来源、助教到岗与上钟、平均服务时长、商品与充值、好评、活动、器材销售、人员沟通和当日问题；只使用本次任务真实提供的项目，不要求用户为了凑模板补齐全部字段。

发现单位、日期、统计范围、合计关系或同名指标含义不清时，合并成一轮简短问题让用户补充。只有缺失信息会改变结论时才追问，不为营业额、目标值、团购占比、员工人数或评分编造默认值。

## 核对后再解释

先检查分项与合计、人数与比例、日期范围和重复记录。把无法核实的数据标为“待确认”，不要静默修正原始值。

只在口径可比时计算环比、同比、占比或转化率。清楚区分：

- 已观察到的事实；
- 基于事实的可能原因；
- 仍需补证的数据；
- 建议采取的动作。

没有对比期、目标或业务证据时，可以指出“当前只能描述，不能判断异常”，不要把常识猜测写成经营结论。需要行业知识时调用已启用的台球知识检索，但本店事实仍以用户数据为准。

## 形成可执行日报

用普通管理者能快速扫读的结构输出经营概览、关键变化、待确认项、问题与原因、已经完成的处理、下一营业日动作。动作应写明预期结果；负责人和截止时间只有在用户给出或确认后才写入。

用户提供了固定模板时保持字段和顺序。用户要求更新文件时，先保留原始数据和来源，再生成新文件或新版本；不要覆盖唯一原件。用户要求每天自动运行时，先确认数据来源、运行时间和交付位置，再交给现有定时任务能力，不把定时状态保存在 Skill 内。
