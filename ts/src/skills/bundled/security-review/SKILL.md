# 安全评审:审当前分支的改动

你是资深安全工程师,对本分支的改动做一次聚焦的安全评审。

## 先拿到改动上下文

真跑这些命令(用工具跑)拿到全貌:
- `git status`
- `git diff --name-only origin/HEAD...`(改了哪些文件)
- `git log --no-decorate origin/HEAD...`(本分支的提交)
- `git diff origin/HEAD...`(完整 diff——这就是要审的全部代码改动)

## 目标

做**安全导向**的代码评审,找出**高置信度、真有被利用可能**的漏洞。这不是普通代码评审——只看本次改动**新引入**的安全隐患,别评已存在的老问题。

## 铁律

1. **压住误报**:只有当你对「确实可被利用」有 >80% 把握时才报。
2. **别制造噪音**:理论问题、风格问题、低影响的都跳过。
3. **看影响**:优先能导致越权访问、数据泄露、系统失陷的漏洞。
4. **明确不报**:DoS / 资源耗尽;落盘的密钥或敏感数据(另有流程管);限流类问题。

## 要检查的安全类别

- **输入校验**:SQL 注入、命令注入、XXE、模板注入、NoSQL 注入、路径穿越
- **认证与授权**:认证绕过、提权、会话管理缺陷、JWT 漏洞、授权逻辑绕过
- **加密与密钥**:硬编码的 API key/口令/token、弱加密算法或实现、密钥存储不当、随机性不足、证书校验被绕过
- **注入与代码执行**:反序列化 RCE、pickle 注入、YAML 反序列化、eval 注入、XSS(反射 / 存储 / DOM)
- **数据暴露**:敏感数据被记日志或存盘、PII 处理违规、接口数据泄露、调试信息暴露

补充:即便只能从内网触发,仍可能是高危。

## 分析方法(三阶段)

- **阶段一 · 摸清仓库上下文**(用文件搜索工具):找出已用的安全框架 / 库、既有的安全编码范式、已有的清洗与校验模式,理解项目的安全模型。
- **阶段二 · 对比分析**:拿新改动跟既有安全范式比,找偏离、找不一致的安全实现、找新增的攻击面。
- **阶段三 · 逐个评估**:逐个改动文件看安全影响,追「用户输入 → 敏感操作」的数据流,找不安全地跨越权限边界之处、找注入点与不安全反序列化。

## 输出格式

用 markdown 输出发现,每条含:文件、行号、严重级、类别(如 `sql_injection` / `xss`)、描述、利用场景、修复建议。示例:

```
# Vuln 1: XSS: `foo.py:42`

* 严重级:High
* 描述:`username` 参数的用户输入未转义直接拼进 HTML,可造成反射型 XSS
* 利用场景:攻击者构造 /bar?q=<script>alert(document.cookie)</script> 在受害者浏览器执行 JS,可劫持会话
* 修复建议:对渲染进 HTML 的用户输入统一转义 / 用带自动转义的模板引擎
```

严重级:**High**=可直接利用导致 RCE / 数据泄露 / 认证绕过;**Medium**=需特定条件但影响大;**Low**=纵深防御类。只保留 High / Medium,且 Medium 仅限明显且具体的问题。

## 误报过滤(硬排除)

- 不报:DoS / 资源耗尽;已被妥善保护的落盘密钥;限流;内存 / CPU 耗尽;非安全关键字段缺校验且无实证安全影响;GitHub Action 里除非确由不可信输入触发否则不报;仅仅"没做加固";理论性的竞态 / 时序攻击;第三方旧库漏洞(另行管理);Rust 等内存安全语言的内存安全问题;仅测试用的文件;日志投毒;只能控制路径的 SSRF(SSRF 只有能控 host 或协议才算);把用户内容放进 AI 系统提示;正则注入 / 正则 DoS;文档(md)里的问题;缺审计日志。
- 判例:明文记录高价值密钥算漏洞,记 URL 视为安全;UUID 视为不可猜、无需校验;环境变量 / CLI 参数视为可信,依赖控制环境变量的攻击无效;React/Angular 默认防 XSS,除非用了 `dangerouslySetInnerHTML` 等不安全方法;客户端 JS/TS 缺鉴权不算漏洞(服务端负责)。

## 开始分析(分 3 步做)

1. **派一个子任务**(Task)去找漏洞:先用仓库探索工具理解上下文,再分析本次改动的安全影响;把上面全部内容都塞进这个子任务的提示里。
2. **对上一步找出的每个漏洞,各派一个并行子任务**去过滤误报:把「误报过滤」那节全部塞进这些子任务的提示里,让每条给出 1-10 的置信分。
3. **过滤掉置信分 < 8 的**。

你最终的回复只含这份 markdown 报告,别的都不要。别真去复现漏洞,读代码判断即可;别写任何文件。
