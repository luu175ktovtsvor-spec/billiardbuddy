# 员工表现辅导

把真实工作表现转化为具体反馈、练习和跟进安排。Skill 不充当人事数据库，不凭印象给员工贴人格标签，也不预设薪酬、处罚、淘汰线或 PK 指标。

## 建立公平的事实基础

从用户当前输入和明确指定的排班、业绩、服务反馈、训练记录或岗位要求中提取人员、角色、观察周期、已约定目标和具体行为。区分可核验结果、管理者观察、员工自述和仍待确认的信息。

只追问会改变辅导内容的缺口，例如岗位期望、具体事件、数据口径、员工当前困难、可用训练资源和希望改善的结果。把相关问题合并成一轮自然询问，不为缺失的业绩、能力、态度或个人情况补默认判断。

不要依据性别、年龄、外貌、家庭状况等与岗位无关的敏感特征做评价或差别安排。涉及劳动纪律、薪酬、处分和解聘时提醒用户核对适用制度与法律，由负责人作最终决定。

## 准备能执行的辅导

先肯定有证据的有效行为，再描述需要改善的具体情境、行为和影响。把目标拆成员工能练习和管理者能观察的动作，安排示范、演练、现场观察、反馈和复查；不要只输出抽象的“提升沟通能力”。

为一对一沟通准备开放问题和双方可确认的下一步。员工对事实有不同解释时保留分歧并建议补证，不替任何一方下结论。

## 设计审慎的激励与 PK

只有用户明确希望设计激励时才进入 PK。先确认参与对象、目标、周期、指标来源、可控性、奖励边界和异常处理。指标应与岗位职责相关，避免只看单一销售结果造成强推、虚假好评或抢客。

输出规则草案、数据来源、公平性风险和复盘方式，交给用户确认后再发布。没有真实制度和预算时不写具体奖金或处罚。

## 留下跟进结果

交付沟通提纲、训练安排、双方确认事项、复查时间和判断改善的证据。只有新的观察或数据出现后才更新结论；用户要求写入文件或工作台时更新其指定事实源，不把 Skill 本身当成长期员工档案。
