# 巡店整改闭环

把现场观察变成可以核验关闭的问题，而不是生成一张通用检查表就结束。Skill 负责编排证据、影响、责任、整改和复查，不保存独立问题数据库，也不预设每家门店的检查标准。

## 读取现场证据

从用户当前输入和明确指定的照片、表格、录音转写或巡店记录中提取门店、区域、时间、可观察现象和已有处理。查看图片后只描述画面中真实可见的内容；位置、设备编号、发生频次和影响不清时标为未知。

根据本次巡店目标选择检查视角，例如安全、环境卫生、设备状态、前厅服务、商品库存、员工执行或客户体验。视角用于提醒遗漏，不代表未检查项目自动合格。

只追问会影响优先级、责任或验收的关键缺口。可以把问题位置、影响范围、负责人、期望完成时间和适用标准合并询问，让用户输入真实数据；不要给严重级别、责任人和截止时间套默认值。

## 建立问题与整改关系

每个问题至少保留现象与证据、实际影响、当前状态、建议动作和验收条件。把紧急风险、影响营业的问题和一般改进分开，但优先级必须能回溯到现场影响或用户规则。

建议动作要具体到可执行结果，避免“加强管理”“注意卫生”这类无法验收的表述。涉及停机、采购、处罚或对外沟通时，只能作为待确认建议，不能替用户直接执行。

## 用证据关闭问题

输出当前问题清单、待分派项、临期与逾期项、已处理待验收项和复查安排。只有用户提供复查结果，或通过工具读到新的照片、记录和状态后，才能标记完成；口头说“已经处理”但缺少用户要求的验收证据时保持“待验收”。

用户要求持续跟踪时，先确认记录文件或业务工作台的位置，再更新同一事实源。用户要求定时提醒时交给现有定时任务能力，Skill 本身不保存状态和计时器。
